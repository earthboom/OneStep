# OneStep 개발 용어집 (시범)

OneStep 자체의 개발과 테스트에 쓰는 용어다. 동작의 기준은 각 항목에 연결한 원문에 있으며, 계약이 바뀌면 해당 항목을 다시 확인한다.

| 용어와 적용 범위 | 테스트에서의 의미 | 실제로 중요했던 이유 |
| --- | --- | --- |
| 개별 검색 응답 시간 · 색인이 준비된 세션 벤치마크 | 호출자에서 질문 한 건씩 잰다. 매 회차 첫 질문은 새 인터프리터를 띄우기 직전부터, 이후 질문은 질문 인코딩 직전부터 시작한다. 응답 전체를 수신하고 JSON 해석을 끝낸 직후 멈춘다. 최초 색인 구축은 별도로 측정한다. | 실제 측정에서 도우미 내부 P95와 호출자 P95가 달랐다. 일찍 타이머를 멈추면 프로세스 시작·전송·응답 해석에서 생긴 초과를 놓친다. [측정 경과](research/2026-11-23-korean-retrieval-at-30000.kr.md) · [세션 타이머](../skills/vegabond-knowledge/tests/benchmark_scale.py) |
| 2초 이내 · 회차당 50개 질문을 5회 실행할 때 | 기존 P95 목표는 **회차별** 응답 시간을 빠른 순서로 정렬한 48번째 값으로 판정한다. 이후의 **전건** 목표는 호출자에서 잰 반올림 전 개별 값이 모두 2초 이하여야 한다. 정확히 2초면 통과하고, 한 건이라도 넘으면 실패한다. 보고할 때는 어느 목표인지 명시한다. | 앞선 실행은 다섯 회차 모두 P95를 통과하면서도 총 250건 중 7건이 2초를 넘었다. 후속 요청에서 합격 기준이 강화됐다. [앞선 결과](research/2026-11-23-search-session-measurements.json) · [전건 판정 기록](research/2026-11-23-search-tail-measurements.json) |
| 피드백 접수·제출 · 개발 도구의 전달 상태 | 접수함의 전달 기준을 따른다. 해당 사안의 문서 쌍이 설정된 체크아웃의 접수함에 도착해야 한다. 작업 프로젝트에만 두 파일이 있으면 준비 상태를 보고할 수 있다. 관리자의 검토·수락은 별도 결정이다. | 실제로 세션 보고서에는 피드백이 적혔지만 지정된 접수함에는 문서가 없었다. 도구가 실제 목적지를 검사하는지, 부분 전달 후 재시도하면 상태가 바뀌는지 본다.
