# 레이싱과 퍼즐의 Unity·Unreal 설계 예시

[게임 개발 기본 전략](game-development-strategy.md)에 따라 같은 장르의 플레이 계약을 두 엔진에 배치한다. 목표 플랫폼과 프레임 예산, 엔진·패키지 버전은 실제 프로젝트에서 확정한다. [새 게임의 기반 설계 지침](../../skills/vegabond-code-design/references/gameplay-framework.md#plan-a-new-game-foundation)

| 장르 | 예시의 전제 | 프레임워크를 결정하는 계약 |
| --- | --- | --- |
| 레이싱 | 싱글플레이 아케이드 차량, 폐쇄 트랙 타임 트라이얼, 로컬 최고 기록 | 차량은 물리 스텝으로 움직인다. 방향과 순서가 맞는 체크포인트를 모두 통과한 랩만 기록한다. |
| 퍼즐 | 싱글플레이 격자 방, 상자를 압력판에 올려 문을 열고 출구에 도달, 한 수씩 되돌리기 | 승인된 한 수가 퍼즐의 원자적 진행 단위다. 되돌리면 플레이어·상자·문 상태가 그 수 이전으로 함께 돌아간다. |

## 1. 레이싱의 대표 플레이와 계약

- **대표 흐름** — 출발 신호가 난 뒤 차량이 출발선을 정방향으로 지나면 랩 시계를 시작한다. 주행 중 체크포인트를 정해진 순서로 통과한다. 마지막 체크포인트까지 확인한 뒤 결승선을 정방향으로 지나면 기록을 확정한다. 출발선과 결승선이 같은 위치일 때는 랩의 진행 상태로 두 교차의 의미를 구분한다.
- **실패 흐름** — 체크포인트를 건너뛰거나 역주행하면 랩 진행이 그 교차로 증가하지 않는다. 차량 리셋은 마지막으로 승인한 체크포인트의 복귀 위치에서 차량을 초기화한다. 타임 트라이얼의 시계는 계속 가고, 승인된 체크포인트까지의 진행은 유지한다. 순간이동 직전 위치와 복귀 위치 사이에서 새 체크포인트가 인정되지 않도록 위치 샘플을 새로 시작한다.
- **시간과 상태** — 차량 컨트롤러가 입력을 물리에 전달한다. 월드의 물리 스텝이 끝날 때 이전·현재 위치와 시각을 레이스 규칙에 전달한다. 두 위치 사이에서 정방향으로 게이트의 실제 범위를 통과했는지 확인하고, 한 스텝에 여러 게이트를 넘으면 교차한 순서대로 확인한다. 통과 시각은 스텝 안에서 보간하고, 랩 시계는 일시정지 시간을 제외한 게임 시간을 사용한다. UI는 승인된 진행도와 기록을 읽는다.

```text
조작 ──> 차량 물리 ──> 완료된 스텝의 위치·시간 ──> 레이스 판정 ──> 랩 HUD·최고 기록
```

차량은 위치·속도·조작 상태를 소유한다. 레이스 세션은 출발 여부, 다음 체크포인트, 시계와 유효 랩 결과를 소유하고 레이스를 나갈 때 해제된다. 프로필은 검증된 최고 기록을 트랙 ID와 코스·판정 규칙 버전으로 저장한다. 트랙의 이름을 바꿀 때는 ID를 유지한다. 코스나 판정이 바뀌어 이전 기록과 비교 조건이 달라지면 새 버전의 기록으로 분리한다.

### Unity에서의 선택

| 결정 | 설계 |
| --- | --- |
| 프레임워크 | **GameObject와 `Rigidbody`·`WheelCollider`, 순수 C# 랩 규칙.** `MonoBehaviour` 차량 제어가 입력과 물리 갱신을 연결한다. 트랙 씬의 조립점이 차량 프리팹, 게이트 표식과 랩 규칙을 연결한다. 랩 규칙은 완료된 물리 스텝의 교차 정보로 진행한다. |
| 상태 소유권 | 차량 프리팹이 물리 상태를, 레이스 씬의 세션 객체가 체크포인트와 랩 시간을 소유한다. 차량을 복귀시키거나 다시 생성해도 진행 중인 세션은 유지된다. 유효 랩 결과가 확정되면 프로필의 기록 저장 경로로 전달한다. |
| 콘텐츠 추가 경로 | **공단 순환로 A → 능선 순환로 B.** B의 트랙 씬에 노면, 정방향 게이트 표식, 출발·복귀 위치를 저작한다. `ScriptableObject` 트랙 정의에서 트랙 ID와 게이트 순서, 씬을 연결한다. 표식·순서·복귀 지점이 유효한지 확인하고 트랙 목록과 빌드에 등록한다. |

목표 차량의 거동을 확인한 뒤 서스펜션·접지 모델을 조정한다. 휠 기반 물리가 목표 감각을 만들기 어렵다면 차량 제어 방식을 재검토한다. 입력에서 차량 물리로, 차량 물리에서 랩 규칙으로 가는 계약은 그때 필요한 만큼 유지한다. [Unity WheelCollider](https://docs.unity.com/en-us/engine/6000.3/manual/physics-section/physics-overview/collision-section/collider-shapes/wheel-colliders/introduction) · [Unity 고정 갱신](https://docs.unity.com/en-us/engine/6000.3/manual/scripting/managing-time-and-frame-rate/fixed-updates)

### Unreal에서의 선택

| 결정 | 설계 |
| --- | --- |
| 프레임워크 | **Chaos Vehicles와 Unreal Gameplay Framework.** `PlayerController`가 조작을 차량 Pawn에 전달한다. Chaos 차량 컴포넌트가 이동을 처리하고, `GameMode`가 트랙 정의, 차량과 랩 규칙을 조립한다. 일반 C++ 랩 규칙이 완료된 이동 샘플에서 승인할 교차를 판정한다. |
| 상태 소유권 | 차량 Pawn과 움직임 컴포넌트가 현재 물리 상태를 맡는다. `GameMode`가 레이스 세션과 랩 판정 상태를 소유하므로 차량 복귀나 Pawn 교체 뒤에도 현재 레이스 진행이 이어진다. 트랙 월드를 종료하면 레이스 세션을 해제하고, 확정된 최고 기록은 프로필 저장에서 읽는다. |
| 콘텐츠 추가 경로 | **공단 순환로 A → 능선 순환로 B.** B의 Level과 체크포인트 Actor를 배치한다. 트랙 Data Asset에 트랙 ID, 게이트 순서, 출발과 복귀 지점을 기록한다. 표식과 정의를 검증하고 트랙 목록과 패키징 대상에 포함한다. `GameMode`가 같은 랩 규칙으로 B를 조립한다. |

트랙 형상, 체크포인트 배치와 차량 튜닝은 에셋에서 구성한다. 갈림길에 따라 유효 체크포인트 순서가 달라지는 트랙을 추가하면 다음 게이트를 판정하는 규칙과 기록의 호환성을 다시 정한다. [Unreal Chaos Vehicles](https://dev.epicgames.com/documentation/unreal-engine/chaos-vehicles) · [Unreal 차량 설정](https://dev.epicgames.com/documentation/unreal-engine/how-to-set-up-vehicles-in-unreal-engine) · [Unreal GameMode](https://dev.epicgames.com/documentation/en-us/unreal-engine/game-mode-and-game-state-in-unreal-engine)

## 2. 퍼즐의 대표 플레이와 계약

- **대표 흐름** — 플레이어가 상자를 밀어 압력판에 올린다. 한 수 안에서 이동과 상자 위치를 확정하고, 압력판의 상태로 문을 연다. 출구에 도달하면 해결 상태를 표시하고 되돌리기와 다음 방 진행을 선택할 수 있게 한다. 다음 방 진행을 확정할 때 프로필에 완료를 기록한다.
- **실패와 되돌리기** — 상자 뒤가 막힌 수를 거부하면 플레이어 위치, 상자, 문, 수 번호를 유지한다. 상자가 압력판을 떠나도 열린 문 칸에 플레이어나 상자가 있으면 빈 칸이 될 때 문을 닫는다. 되돌리기는 한 수의 전체 상태를 복원하며, 문이 닫히는 시점도 함께 복원한다.
- **시간과 상태** — 퍼즐은 이동·밀기·되돌리기·재시작 요청을 순서대로 받는다. 보드 규칙이 유효성을 확인하고 한 수의 결과와 되돌리기 기록을 확정한다. 뷰의 이동 연출 동안 다음 입력을 잠시 제한할 수 있다. 새 보드 표시를 구성하면 현재 좌표와 문 상태를 다시 읽는다.

```text
이동·밀기·되돌리기 ──> 격자 규칙 ──> 확정된 보드 상태 ──> 표시·애니메이션
                          │
                   방 상태와 되돌리기 기록
```

방 세션이 격자 점유, 문 상태, 현재 수와 되돌리기 기록을 소유한다. 프로필은 완료한 방의 안정적인 ID와 다음에 열 방을 저장한다. 진행 중인 방을 앱 재실행 뒤 열 때는 해당 방의 초기 배치에서 시작하는 것으로 정했다. 연속 플레이가 필요해지면 저장 스냅샷에 현재 보드와 되돌리기 이력을 얼마나 포함할지 결정한다.

### Unity에서의 선택

| 결정 | 설계 |
| --- | --- |
| 프레임워크 | **순수 C# 격자 규칙과 `MonoBehaviour` 입력·표시 연결.** 보드 입력기는 셀 이동과 되돌리기 명령을 전달한다. `Tilemap`이나 셀 프리팹은 보드의 확정 상태를 렌더링한다. |
| 상태 소유권 | 방 세션이 규칙 객체와 되돌리기 기록을 갖는다. 표시 오브젝트가 교체돼도 좌표와 문 상태는 세션에 남는다. 재시작은 초기 정의로 방 상태를 초기화하며, 다음 방으로 이동하면 기존 방 세션을 폐기한다. |
| 콘텐츠 추가 경로 | **압력판 연습실 A → 상자 두 개를 쓰는 창고 B.** `ScriptableObject` 방 정의에 벽, 출구, 상자·압력판·문 좌표와 연결을 지정한다. 범위, 중복 점유, 누락된 스위치 연결을 검증하고 챕터의 방 목록에 B를 등록한다. 일관된 보드 표시 프리팹이 B를 표시한다. |

격자 규칙을 독립 어셈블리로 분리하는 시점은 에디터 실행이나 표시 코드와의 의존을 실제로 통제할 필요가 생겼을 때로 잡는다. [Unity ScriptableObject](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/scriptableobject) · [Unity Prefab](https://docs.unity.com/en-us/engine/6000.3/manual/working-with-gameobjects/prefabs)

### Unreal에서의 선택

| 결정 | 설계 |
| --- | --- |
| 프레임워크 | **일반 C++ 격자 규칙과 Unreal Gameplay Framework.** `PlayerController`가 방향과 되돌리기 입력을 명령으로 바꾼다. `GameMode`는 방 정의를 선택해 세션과 표시를 조립하고, 보드 Actor와 Blueprint가 결과를 연출한다. |
| 상태 소유권 | 해당 월드의 `UWorldSubsystem`이 활성 방의 C++ 규칙 객체를 소유한다. 같은 월드에서 다음 방을 열면 그 객체를 교체한다. 표시에 사용하는 상자와 문 Actor를 재생성할 때는 현재 방 상태를 읽어서 연결한다. |
| 콘텐츠 추가 경로 | **압력판 연습실 A → 상자 두 개를 쓰는 창고 B.** B의 방 Data Asset에 격자와 상자·문·압력판 연결을 저작한다. 필요한 표현 Blueprint를 지정하고 좌표·참조·중복 ID를 검증한다. 방 목록에 B를 등록하면 `GameMode`가 기존 규칙을 사용하는 새 보드를 조립한다. |

상자 배치나 기존 스위치 조합이 달라지는 방은 정의에서 구성한다. 일정 시간이 지나면 닫히는 문을 추가하는 경우에는 시간의 출처, 한 수 처리 중 만료 우선순위, 되돌리기에서 시간 상태도 복원할지 결정한다. [Unreal Gameplay Framework](https://dev.epicgames.com/documentation/unreal-engine/gameplay-framework-in-unreal-engine) · [Unreal Subsystem](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/USubsystem) · [Unreal Data Validation](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-validation-in-unreal-engine)

## 3. 설계에서 확인할 내용

| 조건 | 기대하는 동작 |
| --- | --- |
| 레이싱에서 체크포인트를 건너뛰거나 역주행 | 다음 게이트 순서가 유지되고 유효 랩과 최고 기록이 추가되지 않는다. |
| 레이싱에서 고속 교차와 차량 복귀 | 스텝 사이에 지나간 정방향 게이트는 순서대로 처리된다. 차량 복귀의 위치 이동에서는 체크포인트가 승인되지 않고 시계는 이어진다. |
| 레이싱에서 트랙 정의 교체 | 트랙 이름만 바꾸면 해당 기록을 찾을 수 있다. 코스·판정 버전이 바뀌면 올바른 버전의 기록을 표시한다. |
| 퍼즐에서 막힌 수와 되돌리기 | 막힌 수는 점유·문 상태와 수 번호를 보존한다. 문이 열리거나 닫힌 수를 되돌리면 이전 보드 상태를 읽을 수 있다. |
| 퍼즐에서 해결 판정 후 되돌리기 | 다음 방 진행을 확정하기 전에는 되돌리기가 가능하다. 프로필 완료 기록은 방 진행을 확정했을 때 반영된다. |
| 두 장르에서 두 번째 콘텐츠 등록 | 능선 순환로와 창고의 저작·검증·등록 위치를 설명할 수 있다. 기존 규칙을 쓰는 콘텐츠와 규칙 변경을 요구하는 변형의 영향 범위를 지목할 수 있다. |

위 표는 설계에서 기대하는 관찰과 실패 조건이다. 실제 프로젝트에서 엔진과 플랫폼, 조작 방식, 저장 범위가 정해지면 해당 항목을 확인 계획으로 가져간다.
