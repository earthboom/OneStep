# 지식 기록과 검색의 설계 결정

상태: 구현된 설계 기록. 이 문서는 기존 저장·검색 구조를 선택한 이유를 설명합니다. [지식 스킬](../../skills/vegabond-knowledge/SKILL.md)이 검색과 저장을, [저장 가이드](../../skills/vegabond-knowledge/references/storage.md)가 현재 형식과 유지관리 규약을 담당합니다.

## 세 단계 검색 구조를 선택한 이유

루트 색인은 분야로 안내하고, 분야별 카탈로그는 검색 가능한 요약을 제공하며, 각 상세 문서는 독립적으로 재사용할 수 있는 질문 하나에 답하거나 점검 방법 하나를 제공합니다. 본문을 읽기 전에 후보를 좁힐 수 있습니다. 전체 로그, 원본 자료와 긴 이력은 원래 위치에 둡니다.

상세 문서가 항목 메타데이터의 기준이며 카탈로그는 그로부터 생성됩니다. 사실의 기준은 프로젝트 원본 자료이므로, 지식 항목이 별도의 설정집이나 규약으로 경쟁하지 않습니다. 주 저장 위치 하나와 관련 항목 링크를 사용하면 사본이 서로 달라지는 문제를 줄일 수 있습니다. 범위·맥락 메타데이터로 버전과 작품을 구분하고, 깊은 폴더 계층을 미리 만들지 않습니다.

## 구조화된 상세 문서와 생성형 카탈로그를 선택한 이유

짧은 헤더로 본문 전체를 읽지 않고도 식별자, 적용 조건, 검색어, 수명 상태와 근거의 최신성을 확인합니다. 지침, 예외, 점검 방법과 출처 근거는 상세 문서에 둡니다. 알 수 없는 값은 명시하여 수정 날짜나 그럴듯한 제목을 검증 근거로 오인하지 않도록 합니다.

[카탈로그 도구](../../skills/vegabond-knowledge/scripts/catalog.py)는 검색 행을 생성하고 구조적 일관성을 확인합니다. 같은 메타데이터를 두 곳에서 관리하지 않으며 데이터베이스나 검색 서비스가 필요하지 않습니다. 사용자 번역본은 AI 검색에서 제외하고, 유지관리 시 내용을 읽지 않고 존재 여부만 확인합니다. 기존 형식의 자료는 정규화가 허용될 때까지 읽을 수 있게 두어 출처와 이력을 보존합니다.

스키마, 예시와 CLI 순서는 저장 가이드 한 곳에서 관리합니다. [항목 형식](../../skills/vegabond-knowledge/references/storage.md#entry-header-and-body), [카탈로그 유지관리](../../skills/vegabond-knowledge/references/storage.md#refresh-and-validate-catalogs), [저장·수명 판단](../../skills/vegabond-knowledge/references/storage.md#capture-consolidate-and-promote)을 참조합니다. 이 기록에는 해당 규칙을 중복하지 않습니다.

## 검색 범위 제한과 선별 저장을 선택한 이유

카탈로그부터 검색하면 관련 없는 본문과 긴 이력이 작업 맥락에 들어오는 것을 줄입니다. 정보 요약은 문서 묶음 대신 적용 가능한 지침, 출처 위치, 조건, 점검 방법과 공백을 전달합니다. 유효한 요약은 재사용하고, 출처나 범위가 바뀌면 영향을 받는 정보만 다시 확인합니다. 지식이 없을 때는 시작용 항목을 지어내지 않고 필요한 조사를 진행할 수 있습니다.

저장 여부와 중복 판단은 현재 스킬이 담당하며, 모든 불확실성을 기록으로 남겨야 한다는 뜻이 아닙니다. 재사용 지침과 사건 이력은 역할을 구분하고 서로 연결합니다. 실행 기준은 스킬의 [검색 절차](../../skills/vegabond-knowledge/SKILL.md#find-and-synthesize)와 [지식 공백 처리](../../skills/vegabond-knowledge/SKILL.md#close-a-knowledge-gap)에 있습니다.

## 평가의 범위

도구는 형식과 로컬 참조의 일관성을 확인하며, 사실 여부, 적용 적합성, 문학적 완성도나 방지책의 효과를 증명하지 않습니다. 검색 품질은 호환되지 않는 버전, 작가별 선택, 충돌하는 출처, 지식 부재, 기존 형식 자료를 포함한 실제적인 작업으로 평가해야 합니다. 관련 항목 검색, 불필요한 본문 읽기, 반복 조사 방지, 유보 조건 유지 등을 관찰할 수 있습니다. 처리 시간이나 대규모 저장소에 대한 주장은 측정이 필요하며, 이 설계 기록만으로 입증되지 않습니다.
