# 지식 기록·조회 형식 설계

상태: 구현 완료. 실제 형식과 CLI의 기준은 [저장 절차](../../skills/vegabond-knowledge/references/storage.md)이며, 이 문서는 설계 근거를 유지합니다. 기존 분야별 폴더, 프로젝트 경계, 사람 전용 번역본, 정보 요약의 요청·반환 형식을 유지합니다.

## 조회 단계

세 단계를 사용합니다. 루트 색인은 분야로 연결하고, 분야별 목록은 짧은 검색용 요약을 제공하며, 상세 항목은 독립적으로 재사용할 질문 하나에 답하거나 검증 하나를 제공합니다. 적용 조건이나 질문이 다른 내용은 나누고, 같은 방법이나 원인의 사례는 합칩니다. 전체 로그, 원문, 긴 사례 이력은 원래 위치에 둡니다.

항목 메타데이터의 기준은 상세 문서입니다. 목록의 행은 그로부터 생성하는 정보이며, 별도로 수작업 관리하는 두 번째 설명이 아닙니다. 프로젝트 원문은 해당 사실의 기준으로 유지합니다. 지식 요약이 두 번째 스토리 바이블이나 계약이 되지 않습니다.

## 공통 항목 머리말

새로 만들거나 갱신하는 영문 지식 상세에는 작은 YAML 머리말을 사용합니다. 기존 산문 항목도 계속 조회할 수 있게 유지하고, 허용된 관리 작업에서 ID와 근거를 보존하면서 정규화합니다.

| 필드 | 목적 |
| --- | --- |
| id | 제목이 바뀌어도 유지하는 식별자. |
| title | 구체적인 질문·방법·주제. |
| summary | 핵심 적용 조건과 바로 쓸 내용을 한두 문장으로 요약. |
| kind | 참고자료·방법·관례·교훈 구분. 개별 선택을 보편 사실로 오해하지 않도록 함. |
| scope | 프로젝트·구성요소·작품·적용 범위. |
| keywords | 유용한 영문 검색어·동의어·정확한 기술 식별자. |
| status | 기존 지식 상태인 active·enforced·superseded. |
| checked_at | 실제 근거를 마지막 확인한 날짜. 모르면 null이며, 편집 날짜를 자동으로 넣지 않음. |

버전·엔진·형식·장르·시점 등 적용 조건이 필요할 때만 context를 추가합니다. 관련 없는 빈 필드를 만들지 않습니다. 상세한 예외와 근거는 본문에 둡니다.

예시이며 실제 지식 항목을 등록하는 것은 아닙니다.

```text
id: K-FIC-001
title: 제한적 시점의 정보 접근 확인
summary: 제한적 서술에서는 문장을 다듬기 전에 각 진술이 초점 인물의 정보 접근 범위에 들어가는지 확인한다.
kind: method
scope: naru-novel; 서린 중심 제한적 서술
keywords: viewpoint, POV, character-knowledge
status: active
checked_at: 2026-11-04
context: 3인칭 제한적 시점
```

이 머리말은 데이터이며 스킬 탐색용 메타데이터가 아닙니다. 사람 전용 번역본은 탐색 프런트매터를 복제하지 않고 같은 정보를 독자에게 제시하며 조회에서는 계속 제외합니다.

## 상세 본문

짧은 네 항목을 사용합니다.

1. **수행 지침:** 막연한 주의보다 적용할 수 있는 행동으로 무엇을 하거나 이해해야 하는지 설명합니다.
2. **적용 조건과 예외:** 언제 사용하고 사용하지 않는지, 어떤 현재 원문·버전에 의존하는지 설명합니다.
3. **검증:** 관찰 가능한 수용·재발 방지 검증을 제시하고 자동 강제와 편집적 판단을 구분합니다.
4. **근거:** 원래 출처와 위치, 확인한 사례나 사건 링크, 근거를 확인한 맥락을 제공합니다.

내용의 길이는 질문에 맞춥니다. 바로 쓸 지침은 짧게 두고 긴 예시는 복제하지 않고 연결합니다. 근거 없는 진단은 교훈으로 등록하지 않고 문제 기록에 남깁니다.

문제 상세도 같은 검색용 머리말 필드를 사용하되 유형은 오류·제안·가설 등으로, 상태는 기존 open·resolved·superseded로 둡니다. 본문에는 기대와 관찰의 차이, 원인 확신 수준, 수정, 재검토, 방지 링크를 담습니다. 재사용 지침은 knowledge에, 사건 이력은 records에 두고 서로 연결합니다.

## 생성하는 분야별 목록

머리말과 파일 경로에서 항목별 한 행을 생성합니다. **ID·제목·유형 | 요약 | 범위·맥락 | 검색어 | 상태·확인 날짜 | 상세**를 사용합니다. 루트 색인은 계속 분야만 안내합니다. 목록 전체 대신 일치하는 행을 읽습니다.

[로컬 보조 도구](../../skills/vegabond-knowledge/scripts/catalog.py)가 영향받는 목록을 재생성하고 중복 ID, 누락 필드, 잘못된 상태, 로컬 파일 참조, 누락된 번역본을 검증합니다. 기존 항목의 모르는 정보를 꾸며내거나 항목을 조용히 누락하지 않고 보존합니다. 데이터베이스나 검색 서비스는 필요하지 않습니다. 번역 생성은 지식 스킬이 담당하고 보조 도구는 내용을 열지 않은 채 존재 여부를 확인합니다.

## 조회와 전달

1. 호출한 스킬의 프로젝트·프로필과 현재 정보 요약을 재사용합니다. 한국어 질문은 영문 검색 개념으로 바꾸되 정확한 원본 이름과 기술 식별자는 유지합니다.
2. 관련 분야를 고르고 범위·맥락·상태로 좁힙니다. 최신순만 보지 않고 질문과 근거의 적용 가능성을 우선합니다. 구체적인 필요가 있을 때만 공통 자료나 관련 항목을 추가합니다.
3. 일치하는 목록 행만 출력 범위를 제한해 가져옵니다. 유력한 상세 항목 최대 세 개로 시작하여 머리말과 필요한 본문을 읽습니다. 질문에 필요하면 근거나 의존 자료를 따라갑니다. 세 개는 시작 기준이며 필수 조사의 한도가 아닙니다.
4. 기존 정보 요약 형식으로 반환합니다. 적용할 지침과 출처 ID·경로, 조건·예외, 구체적인 검증, 공백·충돌을 함께 제공합니다. 권고의 유형과 범위를 유지하고 문서 모음 전체를 전달하지 않습니다.
5. 질문·범위·항목 내용·기준 원문이 바뀌기 전까지 그 요약을 재사용합니다. 필요하면 작업 근거에 조회한 ID와 내용 버전·해시를 남기며 프로젝트 사실을 전역 캐시에 저장하지 않습니다.

목록이 없거나 오래되었다는 근거가 있으면 선택한 분야 안에서 메타데이터를 표적으로 조회합니다. 쓰기가 허용된 범위에서만 재생성하고 읽기 전용 작업은 목록 문제를 보고합니다. 조회 실패는 정보 공백이며 지식이 없다는 증거가 아닙니다. 실제로 부족한 정보는 기존 research 연결로 조사합니다.

## 저장과 확인

먼저 같은 주제·원인을 검색합니다. 기준 상세 문서를 갱신하거나 실제로 구별되는 항목을 만든 뒤 관련 목록과 사람 전용 번역본을 함께 갱신합니다. 관련 근거를 확인한 뒤에만 새 확인 날짜를 기록합니다. 대체된 항목의 출처와 ID를 보존하고, 무관한 작업 뒤에 모든 이력을 다시 읽지 않습니다.

코딩·소설·발표자료·기획서의 대표 요청과 버전 불일치, 저자별 예외, 지식 없음, 출처 충돌, 기존 형식, 커진 목록으로 설계를 검증합니다. 필요한 항목을 올바르게 찾는지, 무관한 본문을 얼마나 읽는지, 반복 읽기를 줄였는지, 조회 시간·출력량, 목록·상세의 일관성을 살핍니다. 빠르게 조회하더라도 중요한 조건과 미해결 근거를 유지해야 합니다.
