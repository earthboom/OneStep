# 문제 기록 검색의 설계 결정

상태: 구현된 설계 기록. 선택의 이유와 최초 구현 근거를 보존하는 문서입니다. [지식 스킬](../../skills/vegabond-knowledge/SKILL.md)이 검색·저장을, [저장 가이드](../../skills/vegabond-knowledge/references/storage.md)가 현재 형식과 CLI 규약을 담당합니다. 이 문서의 상태가 아니라 사용자의 명시적 피드백으로 수락 여부를 확정합니다.

## 목표와 대안

작업 전에는 발생 조건으로, 실패 후에는 관찰된 증상으로 관련 사건을 찾아 근거의 한계와 함께 예방 점검을 전달하는 것이 목표였습니다. 본문에만 있는 양식은 이 신호를 드러내지 못했습니다. 문제 기록 전용 헤더 필드를 추가하면 작은 도구 변경으로 기존 카탈로그에 신호를 노출할 수 있었습니다. 별도 사건 데이터베이스는 필요성이 확인되지 않은 기반시설을 추가하므로 기존 저장소와 여섯 열 카탈로그를 유지했습니다.

## 결정과 이유

- 발생 조건과 증상은 서로 다른 시점의 검색에 쓰입니다. 원인 확신도와 예방 상태는 사건 해결 상태와 분리하여, 결과물 수정이 곧 예방 검증을 의미하지 않도록 합니다.
- 미확인 값과 기존 형식 경고를 명시하여 누락 정보를 지어내지 않습니다. 문제 기록 전용 필드를 두어 일반 지식 항목을 가볍게 유지합니다. 현재 [문제 필드와 기존 형식 처리 규칙](../../skills/vegabond-knowledge/references/storage.md#problem-retrieval-fields)은 한 곳에서 정의합니다.
- 해결된 사건도 검색 가능하게 하고 대체된 자료의 출처도 보존합니다. 증상이 같다는 것만으로 같은 원인이라고 판단하지 않으며, 호환성이 불확실한 후보를 조용히 제외하지 않습니다.
- 재발은 점검 미실행, 불충분한 점검 또는 조건 변화에 따른 무효화를 뜻할 수 있습니다. 의미가 서로 다르므로 긴 로그를 복제하는 대신 간결한 근거를 연결합니다.
- 도구는 영문 기준 항목의 메타데이터를 읽고 드러난 로컬 참조 대상의 존재 여부를 확인합니다. 참조 대상의 내용이나 사용자 번역본을 읽거나 기준 상세 문서를 수정하지 않습니다. 구조 검증은 진단이나 방지책의 사실 여부를 판단할 수 없습니다.

## 최초 구현과 근거

검색 신호, 잘못되거나 미확인인 필드, 기존 형식 호환성, 상태 독립성, 범위별 카탈로그에 대한 동작 테스트를 추가했습니다. 검증과 문제 기록 행 생성을 확장하고, 스킬·저장 지침과 번역본을 갱신했으며 영향받는 카탈로그를 재생성했습니다. 현재 절차는 해당 가이드에서 관리하고 이곳에 세션별 체크리스트를 중복하지 않습니다.

다음은 당시 구현의 과거 결과이며 현재 테스트 수나 이번 실행 결과가 아닙니다.

- 최초 테스트는 문제 신호가 무시되고 카탈로그에 반영되지 않아 실패했습니다. 구현 후 카탈로그 테스트 19개가 통과했습니다.
- 독립적인 네 분야 모의 사례에서 제안·검증·무효화된 예방 상태, 버전이 불확실한 후보, 재발 유형 구분을 점검했습니다. 기준 상세 문서를 보존하고 엄격한 카탈로그 검사를 통과했습니다. 실제 제품을 실행하거나 실제 프로젝트 사건을 생성한 검증은 아니었습니다.
- 독립 검토에서 보존된 카탈로그 메모와 루트 안내 본문이 로컬 참조 검사에서 빠지는 문제가 발견되었습니다. 회귀 테스트로 두 종류의 잘못된 성공을 재현했습니다. 해당 위치에 기존 참조 검증을 적용한 뒤 테스트 20개가 통과했습니다. 당시 프로젝트 엄격 검사, 반복 빌드의 동일성, 영문 참조와 번역 쌍 존재 여부도 확인했으며 번역 내용은 읽지 않았습니다.

현재 테스트 소스는 [test_catalog.py](../../skills/vegabond-knowledge/tests/test_catalog.py)입니다. 이후 변경과 현재 검증은 과거 테스트 수가 아니라 해당 소스와 실제 실행 근거로 판단해야 합니다.

## 한계

새 서비스나 전역 저장소를 도입하거나 의존성을 설치하지 않았습니다. 형식 테스트와 카탈로그 검사는 의미상 검색 적합성, 원인 판단이나 예방 효과를 입증하지 않습니다. 전문 스킬이 원래 근거와 적용 조건을 확인해야 합니다. 읽기 전용 검색은 과거 항목 수정 권한을 뜻하지 않으며, 프로젝트 밖의 로컬 참조는 허용된 출처 범위에서 별도로 확인해야 합니다.
