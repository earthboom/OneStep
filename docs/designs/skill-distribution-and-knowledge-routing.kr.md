# 배포본에 최신 스킬을 반영하고 작업에 맞는 지식을 찾도록 하는 설계

OneStep 수정 제안 · 2026-11-25

## 무엇이 문제인가

현재 작업 트리의 영문 스킬 진입점과 바로 아래 참조 문서 35개를 ZIP·웹 배포본과 대조했다. 양쪽 모두 이미지 스킬 본문, `2d-game-characters.md`, `style-and-review.md`가 오래됐고, `2d-effects-and-motion.md`, `stationery-characters.md`가 빠졌다. 빌더의 수집 패턴에는 다섯 경로가 이미 포함된다. 기존 검사는 ZIP에 들어 있는 파일에서 시작하고 일부 스킬만 원본과 대조해, 두 배포본이 똑같이 빠뜨린 파일을 발견하지 못한다. [빌더](../../portable/build.py) · [배포 검사](../../portable/test_portable.py)

기획·발표 지식 카탈로그는 각각 0건이다. 전체 저장소에서 ‘기획안 목표 성과지표’를 검색하면 소설 장면이, ‘발표 슬라이드 청중 정보 밀도’를 검색하면 게임 볼륨 기법이 1위다. 같은 질문에 기획 또는 발표 도메인을 지정하면 정상적으로 0건을 반환한다. 검색기는 이미 복수 도메인과 빈 결과를 지원한다. 기능 스킬에는 지식·작업 프로젝트 원문·필요시 조사를 사용하는 경로가 있다. 앞선 이미지 검증에서도 직접 호출과 Scout 경유 모두 캐릭터 규칙과 납품처 사양을 찾았다. [기획 지식](../../knowledge/planning/index.md) · [발표 지식](../../knowledge/presentation/index.md) · [검색 계약](../../skills/vegabond-knowledge/references/retrieval.md)

## A. 배포 전에 원본과 두 결과물을 대조한다

1. 기존 배포 검사에서 **저장소 원본을 출발점으로** 반드시 포함할 파일 목록을 구한다. 대상은 `skills/vegabond-*/SKILL.md`와 `skills/vegabond-*/references/*.md`의 영문 정본이다. 사람용 번역은 제외한다. 빌더의 출력 목록을 그대로 기대값으로 쓰지 않는다. ZIP 내부 경로와 웹 문서의 섹션 목록을 각각 대조해 누락·중복·삭제 후 잔존을 찾고, 경로별 본문도 대조한다. 줄바꿈과 웹 섹션 구분 형식은 정규화한다. 다른 영역의 의도적인 변환, 선별된 게임 지식, 로컬 데이터 제외 검사는 유지한다.
2. **재생성하기 전에** 새 검사를 기존 ZIP과 웹 문서에 실행해 각각 다섯 차이가 경로별로 드러나는지 확인한다. 같은 원본 시점에서 기존 빌더로 두 산출물을 함께 재생성하고 전체 배포 변경분을 검토한다. 그 후 같은 검사가 통과해야 한다. 이미지 이름 하나만 검사 목록에 추가하면 다음 스킬이나 참조 문서에서 문제가 재발한다.
3. 설치 후 다른 경로로 옮긴 프로젝트에서 이미지 스킬을 열어 문구 캐릭터와 모션 참조 문서까지 따라간다. 웹 문서에서도 같은 이름의 섹션에 원본 지침이 있어야 한다. 임시 사본에서 양쪽에 같은 참조 문서를 누락시키기, 웹에만 낡은 본문 남기기, 섹션 중복시키기를 각각 시도해 검사가 해당 경로에서 실패하는지 확인한다. 기존 설치·이동·게임 지식 검사도 통과할 때 두 배포본을 함께 배포한다.

수정 대상은 [기존 배포 테스트](../../portable/test_portable.py)와 ZIP·웹 산출물이다. 정상 재빌드 후에도 원본과 차이가 남을 때만 빌더 수정이 필요하다.

## B. 실제 질문을 해결하는 기획·발표 지식을 저장한다

| 반복되는 질문 | 저장할 내용과 근거 | 인수 사례 |
| --- | --- | --- |
| 기획안에서 무엇을 재야 목표 달성을 알 수 있는가? | 기획 지식에 대상자, 기대 변화, 기준값·목표값, 기간, 자료 출처, 활동량과 결과의 차이를 담는다. [기획 검토 지침](../../skills/vegabond-planning/references/review.md)에서 시작하고 재사용할 방법의 1차 출처를 확인한다. | 교육 참석 인원만으로 실제 업무 성공률이 높아졌다고 결론 내릴 수 없다. 빠진 기준값이나 사후 관찰을 식별해야 한다. |
| 의사결정 슬라이드에 어느 정도의 정보를 남길 것인가? | 발표 지식에 청중이 내릴 결정, 이를 지지할 주장·비교 근거, 실제 표시 크기에서의 가독성을 담는다. [발표 스킬](../../skills/vegabond-presentation/SKILL.md)의 기준을 출발점으로 삼고 수치 측정과 청중 이해의 증거를 구분한다. | 구매 결정에 필요한 권고·비교 수치·판단을 바꿀 조건을 함께 남기고 보조 자료는 필요에 따라 주석이나 부록으로 보낸다. 고정된 줄 수만으로 적정 밀도를 판정하지 않는다. |

기존 지식 절차로 중복부터 조회한다. 같은 결정을 다루는 항목이 있으면 보강하고, 없으면 영문 정본과 한국어 번역을 작성한다. 실제 한국어 질문의 표현과 원문 출처를 포함하고, 영향받은 카탈로그를 재생성·검사한다. 감사 실험의 가상 프로젝트 수치와 납품 조건은 개별 사례에만 적용한다. 로컬 지식의 추가와 게임 전용 배포 지식 목록의 확대는 별개 결정이다.

## C. 기능 스킬에서 결과까지 다시 검증한다

작업 분야가 정해졌으면 기존 정보 개요를 재사용하거나 관련 도메인을 지정해 검색한다. 게임 경제 기획처럼 복합 작업이면 기획과 게임을 함께 지정한다. 검색 후보의 적용 조건과 근거를 읽고, 쓸 만한 항목이 없으면 작업 프로젝트 원문과 승인된 사양을 확인한다. 중요한 공백이 남으면 필요한 질문만 조사 스킬에 전달하고, 근거·적용 조건 또는 아직 확인하지 못한 부분을 원래 작업에 돌려준다. 납품처 수치가 없으면 확인 전까지 미정으로 두고, 단순 문구 수정은 바로 처리한다.

| 재검증할 요청 | 합격 조건 |
| --- | --- |
| 실제 한국어 질문 2개를 전체 검색 및 도메인 검색으로 실행 | 각각 올바른 지식이 1위여야 한다. 두 질문을 회귀 검사에 남기고 각 주제의 바꿔쓰기 표현도 확인한다. 선택한 본문이 실제 결과에 반영됐는지도 본다. |
| 대상 도메인은 비어 있고 다른 도메인에만 비슷한 단어가 있는 임시 프로젝트 | 도메인 검색은 0건을 반환한다. 기능 스킬은 적용 가능한 원문을 찾거나 미확인 조건을 밝힌다. 무관한 분야의 자료로 결론을 내리면 실패다. |
| 게임 경제 기획과 단순 띄어쓰기 수정 | 복합 기획은 두 도메인의 지식을 사용하고 띄어쓰기는 조사 없이 끝낸다. |
| 프로젝트 캐릭터 규칙과 납품처 사양이 필요한 이미지 브리프 | 직접 호출과 Scout 경유 모두 올바른 캐릭터 지식과 해당 납품처 원문을 사용한다. 사양을 뺀 사례에서 임의 수치를 제시하면 실패다. |
| 외부 공식 기준이 필요한 발표 문구 | 직접 호출과 Scout 경유 모두 프로젝트 맥락을 유지하고 조사 단계를 통해 공식 원문을 대조한다. 파일을 열거나 숫자만 맞히는 것으로 통과시키지 않는다. |

기존 [검색 회귀 검사](../../skills/vegabond-knowledge/tests/retrieval_cases.json)의 필수·금지 ID도 유지한다. 기본 전체 검색과 응답 형식은 보존한다. 지식 추가 후에도 두 질문이 빗나가면 어떤 필드와 한국어 표현이 매칭됐는지 확인하고 해당 항목부터 보강한다. 내용과 도메인 선택으로 해소되지 않는 실패를 재현한 뒤에만 순위 알고리즘 변경을 검토한다. 기능 스킬이 기존 경로를 실제로 건너뛸 때는 그 진입점이나 공통 인계 지침만 보완하고 직접 호출과 Scout 경유를 재검사한다.

A는 독립적으로 완료할 수 있다. B에서 저장할 근거와 검색 결과를 먼저 확인한 뒤 C에서 실제 적용을 평가한다. 문서에 적은 실패 주입, 지식 등록과 인수 검사는 구현 단계의 완료 기준이다.

## 구현 및 인수 검사 결과 · 2026-11-25

수정 전 ZIP과 웹 문서에서 각각 오래된 파일 3개와 누락된 파일 2개를 재현했다. 재생성 후 영어 스킬 본문·참고 문서 35개가 각 배포본과 일치했다. 양쪽에 같은 파일이 빠진 경우, 웹에만 구버전이 남은 경우, 웹 섹션이 중복된 경우, 설치본 이전 후 이미지 참고 문서 두 개로 이동하는 경우를 포함해 배포 검사 7건이 통과했다. 기존 빌더가 게임 지식 원본 7개와 색인의 선행 변경분도 담았다. ZIP 검색 도구에서는 줄바꿈이 갱신됐다. 게임 자료의 수록 목록은 유지됐다.

기획·발표 지식과 색인이 엄격 검사를 통과했다. 기획 바꿔쓰기는 처음에 전체 검색에서 코드 지식이 나왔고 기획 검색에서는 0건이었다. 질문에 붙은 조사와 어미가 검색어에 남는 것을 확인하고, 수혜자의 변화와 사업 효과를 가리키는 자연스러운 표현을 기획 지식에 추가했다. [실제 저장소 회귀 사례](../../skills/vegabond-knowledge/tests/retrieval_cases.json) 37건이 모두 통과했고 금지된 결과는 0건이었다. 두 원문과 바꿔쓰기 두 개 모두 전체 검색과 지정 도메인 검색에서 1위였다. 해당 도메인이 비어 있고 다른 도메인에만 그럴듯한 항목이 있는 임시 프로젝트에서도 지정 범위의 결과가 0건이며 근거가 비었다는 표시가 있는지 확인했다.

| 이전 대화 없이 수행한 작업 | 관찰한 판단 |
| --- | --- |
| 신입 교육 기획 | 기획 지식을 적용해 참석 인원은 도달 지표로 두고, 교육 전후 도움 없이 등록을 정확히 끝낸 비율을 성공 기준으로 제안했다. 분모, 누락 인원, 기록 방법을 적었고 미합의 목표치는 비워 뒀다. |
| 구매위원회 슬라이드 문안 | 직접 호출과 Scout 경유 모두 프로젝트 글자 서식과 W3C 원문을 확인했다. 주어진 14pt 보통 굵기의 3.9:1 캡션에 대해 승인을 보류하고 수정 후 4.5:1 이상을 확인하도록 작성했다. 직접 호출은 신규 발표 지식 사용도 보고했고, Scout 경유는 프로젝트 발표 지식 사용을 보고했다. |
| 스티커 발주 문안 | 첫 직접 호출에서는 사양 판단은 정확했지만 공통 절차 사용이 확인되지 않았다. 이미지 스킬에 조건부 연결을 추가한 뒤 직접 호출과 Scout 경유를 새 맥락에서 재시험했다. 두 경로 모두 캐릭터 표시 폭 19 mm와 내부 타공을 포함한 실물 칼선 간격 2.7 mm를 구분했다. 사양서를 뺀 경우에는 두 경로 모두 조사 절차를 사용하고 칼선 수치를 미확정으로 남겼다. |
| 복합 기획과 단순 교정 | 게임 기획은 경제와 제작 여력 지식을 함께 사용했다. 대기 시간이 0이라는 가정에서 시간당 보상 3,000→6,000을 계산하고 실제 소비량은 미확정으로 뒀다. 단순 교정은 도메인 지식 조회나 조사 없이 띄어쓰기 한 곳만 수정했다. |

행동 시험은 독립된 AI 맥락과 시험용 프로젝트를 사용했다. 인쇄물 품질, 실제 청중의 이해도, 게임 밸런스는 측정 범위 밖이다. 자동 검사를 다시 실행할 명령은 [영문 설계서 마지막 절](skill-distribution-and-knowledge-routing.md)에 있다.
