# Game data formats and the content production pipeline

2026-11-22 · Choosing among JSON, engine assets, spreadsheets and CSV, binary formats, and databases

**JSON suits structured content and interchange files that several editors can read and write.** Puzzle boards, stage lists, and encounter definitions edited in multiple tools are good candidates. When authors edit a stage's layout and asset references together in one engine, a Unity scene or asset, or an Unreal map or Data Asset, can serve as the authoring source. Choose formats for saves, server state, and distributed data according to how each is read and written. [JSON standard](https://www.rfc-editor.org/rfc/rfc8259.html) · [LDtk JSON structure](https://ldtk.io/docs/game-dev/json-overview/) · [Unity ScriptableObject](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/scriptableobject) · [Unreal Data Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-assets-in-unreal-engine)

Building on the [stage framework research](2026-11-22-stage-content-framework.md) and the [game development practices study](2026-11-22-game-development-practices.md), this report describes where to keep different kinds of data and how to add, change, and remove them. The choices below are design criteria. Verify performance and distribution compatibility in the actual project on its target platforms.

## 1. Define the role of the data before choosing a format

| Data | Who writes it and when | Starting point |
| --- | --- | --- |
| **Content authoring source** | Designers edit stages, waves, items, and dialogue. They need change history and review. | JSON for structured interchange, CSV or spreadsheets for bulk column-based editing, and engine assets for scenes and object references |
| **Import and distribution artifacts** | Import tools or builds read the source and produce catalogs, assets, bundles, and packages. | Typed assets and engine packages that can be regenerated from source. Introduce a separate binary format when measurements establish the need. |
| **State during play** | The state owner, such as a puzzle session, simulation, or server, changes state in response to input. | In-memory structures that fit the game rules. Extract only persistent state when needed. |
| **Local saves and replays** | The save module writes as play progresses. It handles older versions, interrupted writes, and recovery. | A versioned save file or the engine's save API for small profiles. Also evaluate SQLite for repeated partial updates and queries across many objects. |
| **Online state and live configuration** | An authoritative server updates accounts, ownership, and currency. Operators publish catalog availability or configuration snapshots. | A server database for state that requires concurrent writes, constraints, and auditing. Versioned documents and a distribution manifest can also serve read-heavy content settings. |

**Edit each fact in one place.** If a board lives in an LDtk project, for example, the exported JSON and the asset generated in the engine are both reproducible outputs of that input. You can maintain `StageId` and chapter order separately, but manually maintaining the same order in a spreadsheet, JSON, and an engine asset leaves it unclear which edit takes effect. [LDtk export and loading](https://ldtk.io/docs/game-dev/loading/) · [Build Systems à la Carte](https://simon.peytonjones.org/assets/pdfs/build-systems-original.pdf)

## 2. Choosing a format and deciding when to change it

| Option | Good fit | Costs and conditions |
| --- | --- | --- |
| **JSON** | Hierarchical boards, quests, and waves, interchange with external tools, and reviewing changes stage by stage | The standard has no comments. Types and relationships need separate validation. If people edit files line by line, establish formatting and file-splitting conventions. [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html) · [JSON Schema validation standard](https://json-schema.org/draft/2020-12/json-schema-validation) |
| **CSV and spreadsheets** | Comparing the same columns across many rows, such as item values, enemy stats, or per-item localization keys | Establish policies for encoding, quoting, headers, and empty cells. Check numeric-looking string IDs, automatic date conversions, and meaning implicit in row order. For sheets with formulas, manage the calculated values used as distribution inputs and when they are exported. [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180.html) · [W3C tabular data model](https://www.w3.org/TR/tabular-data-model/) |
| **YAML, TOML, JSON5, XML** | YAML and JSON5 for human editing with comments, TOML for relatively simple settings, and XML for interchange with an existing XML toolchain | Align YAML parser versions and scalar interpretation, and verify JSON5 parser support. When many tools are involved, first check supported formats and conversion costs. Treat Unity-generated YAML as Unity's asset representation. [YAML 1.2.2](https://yaml.org/spec/1.2.2/) · [TOML](https://toml.io/en/v1.0.0) · [JSON5](https://spec.json5.org/) · [W3C XML](https://www.w3.org/TR/xml/) |
| **Unity and Unreal assets** | Scenes, terrain, collision, lighting, prefabs and Blueprints, drag-and-drop references, and in-editor validation | Tooling and asset references are tied to the engine. Split assets that people often edit concurrently. Define ownership and checkout procedures for files that are difficult to merge. [Unity asset metadata](https://docs.unity3d.com/6000.0/Documentation/Manual/AssetMetadata.html) · [Unreal Data Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-assets-in-unreal-engine) · [Unreal Perforce guide](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-perforce-as-source-control-for-unreal-engine) |
| **Protobuf, FlatBuffers, MessagePack** | Cases where compressed distribution size, parsing, unnecessary copies, or network transfer are costly | Diffs are difficult for people to review. Schema and field evolution rules vary by format. Compare compressed size, decoding, and object initialization costs using a real collection of stages. [Protobuf evolution practices](https://protobuf.dev/best-practices/dos-donts/) · [FlatBuffers schema evolution](https://flatbuffers.dev/evolution/) · [MessagePack](https://msgpack.org/) · [Binary format comparison study](https://arxiv.org/abs/2201.03051) |
| **SQLite** | Querying or updating subsets of many local records, or grouping several changes in one transaction | A database file has one writer at a time. Using a binary database as the Git authoring source for several designers makes changes difficult to review and merge. Where appropriate, generate the database for distribution from reviewable files. [When to use SQLite](https://www.sqlite.org/whentouse.html) · [Application file format](https://www.sqlite.org/appfileformat.html) · [SQLite atomic commit](https://www.sqlite.org/atomiccommit.html) |
| **Server relational database and JSON columns** | Concurrent updates, relational constraints, duplicate prevention, and transactions for accounts, currency, or inventories. JSON columns can also hold variable-shaped supplementary information such as settings. | Consider columns and relations for frequently queried or constrained values. Storing a large JSON document in one row can cause row-level contention even for partial updates. [PostgreSQL transactions](https://www.postgresql.org/docs/current/tutorial-transactions.html) · [JSON and JSONB](https://www.postgresql.org/docs/current/datatype-json.html) |
| **Definitions assembled by scripts** | Authoring that requires behavior, such as mods that read and extend existing definitions or compute multiple definitions | Include execution order, callable capabilities, error propagation, and result validation in the contract. Factorio distinguishes the data stage that creates prototypes from the game runtime. [Factorio data lifecycle](https://lua-api.factorio.com/latest/auxiliary/data-lifecycle.html) |

Similar data volumes can involve different tasks. A spreadsheet is convenient for a designer comparing and changing the prices of 200 items side by side. When each stage has several waves and conditions, a structured file per stage makes the relationships clear. Keep board or monster state that changes with every input in memory. Convert it to the chosen format at the loading and saving boundaries.

## 3. The contract for authoring a stage in JSON

This example defines one puzzle using existing pushing rules. It assumes the board rules specify the coordinate origin, boundaries, and interpretation of integer tile coordinates.

```json
{
  "schemaVersion": 1,
  "stageId": "warehouse-03",
  "rulesId": "puzzle.push-box",
  "board": {
    "width": 5,
    "height": 4,
    "spawn": [1, 1],
    "walls": [[0, 0]],
    "boxes": [[2, 1]],
    "goals": [[3, 1]]
  }
}
```

- **IDs and references.** Give `stageId` a lifetime independent of filenames, spreadsheet row numbers, and engine object names, so saves remain accessible after moves and renames. When sharing data across engines, let each engine map `rulesId` and the game IDs of required assets to its own rules and assets. If 3D coordinates are shared as well, specify axes, units, and rotation representation in the data contract. [Unity internal asset IDs](https://docs.unity3d.com/6000.0/Documentation/Manual/AssetMetadata.html) · [Unreal Asset Manager](https://dev.epicgames.com/documentation/en-us/unreal-engine/asset-management-in-unreal-engine)
- **Parsing rules.** Adopt UTF-8, fixed key names, and rejection of duplicate keys as project rules. Give key order no gameplay meaning. Represent ordered waves and checkpoints as arrays. Agree on numeric ranges across tools. Store large integer IDs as strings when they pass through JavaScript tools to avoid value changes during conversion. [RFC 8259 on objects and numbers](https://www.rfc-editor.org/rfc/rfc8259.html) · [I-JSON message format](https://www.rfc-editor.org/rfc/rfc7493.html)
- **Structure and game validation.** Use JSON Schema to check required fields, types, and allowed ranges. Game-specific checks cover coordinates within the board, forbidden piece overlaps, the existence of rule IDs and assets, and duplicate IDs across stages. Playing a solution's inputs through the real rules also checks that a structurally valid board can reach its goal. Catch duplicate JSON keys in the parser before overwritten values are lost to schema validation. [JSON Schema validation standard](https://json-schema.org/draft/2020-12/json-schema-validation) · [Stage validation design](2026-11-22-stage-content-framework.md#6-automated-validation-and-production-review)
- **Failure policy.** During authoring, report the stage ID, source file, field path, and condition the author needs to correct. In a release build, report errors in required references or formats and stop that publication. Start with strict unknown-field checks during production to catch typos. If live data readable by older Players needs new fields, specify which fields are safe to ignore and which versions support them. [JSON Schema object constraints](https://json-schema.org/understanding-json-schema/reference/object) · [Paper on JSON schema compatibility](https://software-lab.org/publications/issta2021_JSON.pdf) · [GDC talk on loading imperfect data during development](https://media.gdcvault.com/gdc2013/slides/822192Fredriksson_Andreas_Loading_Imperfect_Data.pdf)
- **Unit of collaboration.** Keep a stage typically edited by one person in one file. Reference reusable rules and presets by their own IDs. If spreadsheet or level-editor exports are version-controlled, fix their ordering and formatting so diffs show meaningful changes. Introduce a byte-level canonicalization contract only when file contents contribute to a signature or distribution identifier. [Tiled JSON format](https://doc.mapeditor.org/en/stable/reference/json-map-format/) · [LDtk JSON structure](https://ldtk.io/docs/game-dev/json-overview/) · [JSON canonicalization standard](https://www.rfc-editor.org/rfc/rfc8785.html)

## 4. Choosing an authoring and import path in Unity and Unreal

| Situation | Unity | Unreal Engine |
| --- | --- | --- |
| **The editor holds the source** | Edit rules and content definitions in `ScriptableObject` assets, and maps and placements in Scenes and Prefabs. Manage assets and their `.meta` files together. [ScriptableObject](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/scriptableobject) · [Asset metadata](https://docs.unity3d.com/6000.0/Documentation/Manual/AssetMetadata.html) | Edit rules and content definitions in `UDataAsset` assets, and maps and placements in Maps and Blueprints. Consider `UPrimaryDataAsset` and Asset Manager when discovery, loading, and cooking need separate management. [Data Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-assets-in-unreal-engine) · [Asset Manager](https://dev.epicgames.com/documentation/en-us/unreal-engine/asset-management-in-unreal-engine) |
| **External board or encounter structures are the source** | Unity can read JSON as a `TextAsset`. Validate it in a separate import step and generate typed assets, or parse it at a defined load point if the product requires runtime reading. A `ScriptedImporter` cannot register for extensions handled by Unity's built-in importers. Use a dedicated extension or an explicit import tool if needed. [Text assets](https://docs.unity3d.com/6000.0/Documentation/Manual/class-TextAsset.html) · [ScriptedImporter](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AssetImporters.ScriptedImporter.html) | For balance data with a shared row schema, use `FTableRowBase`-derived types and the Data Table CSV or JSON import path. For custom structures such as puzzle boards or encounter trees, convert them into definition assets in the editor or design a dedicated loader for the data contract. [Data Driven Gameplay Elements](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-driven-gameplay-elements-in-unreal-engine) · [UDataTable JSON import](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UDataTable?application_version=5.8) |
| **Verify that definitions reach the game** | `JsonUtility` follows Unity serialization rules and is unsuitable for directly handling a `Dictionary` or a root array. Choose a library that supports the data structure and the target Player. If Addressables content updates are needed, retain that Player's content state and build paths. [Unity JSON serialization](https://docs.unity3d.com/6000.0/Documentation/Manual/json-serialization.html) · [Addressables content updates](https://docs.unity3d.com/Packages/com.unity.addressables%402.7/manual/content-update-builds-overview.html) | Use Data Validation to check assets and references and run validation in CI. Verify that the release catalog's maps and references resolve in the actual cook and packaged build. [Data Validation](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-validation-in-unreal-engine) · [Cooking](https://dev.epicgames.com/documentation/en-us/unreal-engine/cooking-content-in-unreal-engine) |

The `walls` and `boxes` in the JSON example are nested arrays and do not map directly to Unity's native serialization format. To keep a shared interchange format, parse the coordinates at import and convert them to lists of Unity coordinate structures. If the interchange format is also under your control, another option is to give each coordinate named fields such as `{ "x": 2, "y": 1 }`. Unity and Unreal each map imported rule IDs to their own engine assets and presentation. [Unity serialization rules](https://docs.unity3d.com/6000.0/Documentation/Manual/script-serialization-rules.html)

## 5. Additions, changes, removals, and older saves

| Change | Data management rule | Existing inputs to check |
| --- | --- | --- |
| **Add** | Issue a new content ID and validate the definition and references. Add it to the catalog and set unlock conditions. When adding a schema field, define how the new reader handles its absence from older data. | How new unlock conditions apply to older saves and whether the stage opens in the new build |
| **Modify** | Retain the ID when changing the display name, path, or order. For changes to completion criteria or layout, review the effect on records, replays, and resuming mid-stage. | Previous completion history, older ghosts and in-progress saves for the same ID, and other stages' references to shared components |
| **Remove or replace** | Define what an ID referenced by existing saves now means. For example, hide or retain completion history and provide an ID migration rule if a replacement is necessary. Avoid reusing IDs for new entities while their compatibility period remains active. | Completion and resume records for the retired stage, unlock conditions pointing to that ID, and older offline data |
| **Replace after release** | If independent updates are needed, publish a validated catalog version and its artifacts together. Switch when the compatible set is ready and pin the version used by an active session. Define when the previous compatible set can continue to run after a download failure. | An older Player receiving the new catalog, a partial download failure, and publication of a new version during play |

Use `schemaVersion` to determine whether the read format has changed. Track a `contentRevision` or content hash when layout or rule changes within the same format affect resuming or comparing records. Add a catalog publication version when independent distribution is needed. Define read compatibility at each step. Keep the old save until the converted result has been read successfully, then replace it. Even with an engine save API, check recovery conditions, battery power loss, and insufficient disk space on the target platform. [Factorio migrations](https://lua-api.factorio.com/latest/auxiliary/migrations.html) · [Mojang DataFixerUpper](https://github.com/Mojang/DataFixerUpper) · [Unreal SaveGame](https://dev.epicgames.com/documentation/en-us/unreal-engine/saving-and-loading-your-game-in-unreal-engine) · [OneStep save design and existing verification](../../knowledge/game/K-GAME-TECH-SAVE.md)

If patches, DLC, and mods can modify the same definition, specify load precedence and the meaning of conflicts. Decide whether duplicate IDs are errors or explicit replacements, whether a list is replaced wholesale or merged by ID, and whether `null` is a value or a deletion. Standard JSON Merge Patch treats an object's `null` value as deletion and can replace arrays in full. Check whether those semantics suit a game that needs partial changes to pieces or waves. [JSON Merge Patch](https://www.rfc-editor.org/rfc/rfc7396.html) · [Factorio mod data stage](https://lua-api.factorio.com/latest/auxiliary/data-lifecycle.html)

## 7. First decisions to record on a project

1. **Choose representative content.** Select the applicable examples from a grid puzzle, a course with its own environment, and a column-oriented balance table. For each type, identify where one person edits it and what changes another person reviews.
2. **Record ownership and how to add content.** Document the authoring source, persistent ID, import, validation, registration, runtime reads, save version, and deletion policy for each kind of data. `vegabond-code-design` has existing design guidance for these decisions, and the verification guidance in `vegabond-code` requires exercising the actual entry point. [Content extension path](../../skills/vegabond-code-design/references/gameplay-framework.md#give-content-an-extension-path) · [Verification guidance](../../skills/vegabond-code/references/verification.md)
3. **Measure the reason to change.** Before moving from JSON to a binary format or database, measure representative content's disk size and compressed distribution size. Break down cold and warm loads into I/O, parsing, reference resolution, and object initialization, and measure peak memory. For local saves, examine write latency, partial update costs, and recovery after failure. Production criteria include the time to add a stage, the number of shared-code changes, and review and merge costs. [Binary format comparison study](https://arxiv.org/abs/2201.03051) · [Bungie asset pipeline case study](https://www.gdcvault.com/play/1025285/Tools-Tutorial-Day-Bungie-s)
