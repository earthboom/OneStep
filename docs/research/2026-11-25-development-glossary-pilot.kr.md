# 개발 용어집을 주면 AI가 잡는 인수 테스트 기준이 달라지는가?

이전 대화를 모르는 AI 네 개가 각각 인수 테스트 기준을 작성했다. 기존 자료만 받은 두 AI와 [OneStep 개발 용어집](../development-glossary.kr.md)까지 받은 두 AI 모두 11개 기준을 충족했다. 용어집을 받은 둘은 답변에 용어집을 근거로 인용했다. 이번 비교에서 테스트 기준의 정확도 차이는 관찰되지 않았다.

## 세 용어를 고른 근거

- **개별 검색 응답 시간.** 측정 기록에는 검색기 내부에서 잰 시간과 호출자가 잰 시간이 함께 나온다. 첫 요청에 프로세스 시작 비용을 포함하는지, 응답 JSON을 해석할 때까지 재는지에 따라 테스트가 측정하는 값이 달라진다. [측정 기록](2026-11-23-korean-retrieval-at-30000.md)
- **2초 이내.** 과거 측정에서 5회 모두 P95 기준을 통과했지만 개별 응답 7건은 2초를 넘겼다. 이후 요청에서 250건 전부 2초 이내라는 기준이 추가됐다. 두 표현은 서로 다른 시점의 실제 요구를 가리킨다. [당시 측정값](2026-11-23-search-session-measurements.json)
- **피드백 접수.** 세션 보고서에는 피드백이 기록됐지만 지정 접수함에 보고서가 없었던 사례가 있다. 접수함 운영 문서는 작업 프로젝트에 파일을 준비한 상태, 지정 접수함에서 도착을 확인한 상태, 담당자가 검토한 상태를 구분한다. [당시 기록](../../feedback/2026-11-20-feedback-lines-not-submitted.md) · [도착 확인 규칙](../../feedback/README.md#confirm-delivery-at-handoff)

## 비교 방법과 결과

네 AI에게 같은 한국어 요청과 같은 프로젝트 파일 8개를 제공했다. 벤치마크 코드와 기존 측정값, 접수 누락 기록, 접수함 규칙과 검사 도구의 테스트가 포함됐다. 한쪽에만 용어집 한 파일을 추가했다. 각 AI는 이전 대화와 채점표를 보지 않고 주어진 자료를 찾아볼 수 있었다. 답변 수집 전에 11개 기준을 정하고, 각 답변에 해당 기준이 명시되어 있는지 수동으로 채점했다. [동일 요청 전문·파일 해시·채점표·개별 점수·답변 발췌](2026-11-25-development-glossary-trial.json)

| 테스트 항목 | 기존 자료만 받은 AI 2개 | 용어집도 받은 AI 2개 |
| --- | --- | --- |
| 호출자 응답 시간 4개 기준 | 둘 다 미리 구축한 색인을 사용했다. 매 회차 첫 요청은 프로세스 실행 직전, 이후 요청은 인코딩 직전에 측정을 시작했다. 응답을 모두 받고 JSON 해석까지 마친 시점에 종료했다. | 둘 다 같은 시작점과 종료점을 골랐다. |
| 2초 판정 3개 기준 | 둘 다 회차별 50건 중 48번째 값을 P95로 삼고 반올림 전 값에 2초 이하를 적용했다. 예시에서 P95 합격, 전건 기준 불합격으로 판정했다. | 둘 다 통계량, 경계값, 최종 판정이 같았다. |
| 피드백 접수 4개 기준 | 둘 다 지정 접수함의 같은 이름 영문·한국어 일반 파일 두 개가 비어 있지 않은지 검사했다. 재시도 전에는 준비됨, 재검사 성공 후에는 접수됨으로 표시했다. 담당자 검토 여부는 별개로 봤다. | 둘 다 같은 위치와 파일 조건을 확인하고 접수와 검토를 구분했다. |
| AI별 합계 | 11/11, 11/11 | 11/11, 11/11 |

비교용 예시의 첫 요청은 인코딩 전까지 0.23초, 응답 수신까지 추가로 1.76초, JSON 해석에 0.0104초가 걸려 총 **2.0004초**였다. 별도의 정확히 2초인 요청은 통과했다. 다섯 회차의 P95는 각각 0.8초였고 총 250건 중 249건이 2초 이내였다. 접수 예시에서는 네 AI 모두 지정 접수함의 한국어 파일이 비어 있을 때 종료 코드 1, 파일을 채운 뒤 재검사했을 때 종료 코드 0을 기대했다. 이번 실험은 주어진 사례의 테스트 기준을 비교했고 검색 성능을 새로 측정하지 않았다.

## 시범 적용 범위

테스트 기준에 영향을 주는 용어가 나올 때 개발 설계·구현 스킬이 세 항목을 참조하도록 한다. 기존 자료만으로도 두 AI가 같은 기준을 찾아냈다. 이번 실험은 사례 두 개와 AI 네 개에 한정됐고, 요청이 구체적이었으며 관련 자료를 미리 추려 제공했다. 전체 저장소에서 짧은 요청을 받을 때의 탐색 시간, 구현 품질, 재작업 감소 효과는 아직 측정하지 않았다. 이후에는 실제 개발 작업에서 해석 차이로 테스트가 달라진 경우에 항목을 추가하고, 동작을 정의하는 원문을 연결한다.
