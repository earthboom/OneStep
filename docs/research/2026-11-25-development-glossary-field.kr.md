# 전체 OneStep 저장소에서 인수 테스트 근거를 찾는 데 용어집이 도움이 됐는가

독립적으로 작업한 AI 여섯 개가 모두 검색과 피드백 접수의 핵심 합격 조건을 같게 잡았다. 용어집이 있는 쪽은 세 번 모두 세부 기준 11개를 적었고, 없는 쪽은 각각 11개·9개·10개를 적었다. 근거 탐색 시간의 중앙값은 각각 40.3초와 50.2초였다. 용어집을 실제로 사용한 AI는 한 개였다. 이 결과만으로 두 집단의 차이를 용어집의 효과로 돌리기는 어렵다.

## 요청과 측정 방법

여섯 AI 모두에게 자료 목록이나 계산 예시 없이 다음 한 문장을 주었다.

> 3만 건 세션 검색의 개별 응답 2초 목표와 피드백 접수 표시를 검증할 인수 테스트 기준을 잡아줘.

작업 중인 저장소 사본 두 개를 만들고 공통 파일 1,716개의 SHA-256이 일치하는지 확인했다. Git에서 추적 중인 파일과 무시되지 않은 미추적 프로젝트 파일을 포함했다. 기존 스킬의 용어집 참조 문구, 코드, 보고서와 테스트는 양쪽에 똑같이 있었다. Git 내부 정보, 로컬 캐시, 이전 용어집 실험 산출물 세 개는 제외했다. 실험군에만 영문·한국어 용어집 파일을 추가했다. 대조군의 배포 패키지에도 용어집 본문이 들어 있지 않은지 확인했다.

매회 이전 대화를 모르는 새 AI가 탐색 위치를 정하고 근거 파일을 답변에 남겼다. 시작 전에 실행 순서와 11개 채점 항목을 정했다. 채점표와 실험 결과는 AI가 탐색하는 저장소 밖에 두었다. 시간은 첫 저장소 조회 직전부터 답변에 필요한 근거가 충분하다고 판단한 시점까지 같은 컴퓨터의 단조 시계로 쟀다. 도구 응답을 기다리는 시간과 탐색 중 판단 시간은 포함했고 최종 답변 작성 시간은 제외했다. 여섯 번의 탐색은 겹치지 않게 진행했다.

## 테스트 기준에서 달라진 점

여섯 AI 모두 매 세션 첫 요청에는 프로세스 실행 시간을 포함하고, 이후 요청은 인코딩 직전부터 재며, 응답 전체를 받아 JSON 해석을 마친 시점에 측정을 끝냈다. 250건 각각의 호출자 측정값이 2초 이하이고 표시 ID와 순서가 보존돼야 합격이라고 했다. 피드백은 로컬에 준비한 상태와 지정 접수함에서 해당 건의 비어 있지 않은 영문·한국어 파일을 확인한 상태를 구분했다. 담당자의 검토·승인도 별개로 보았다.

용어집이 없는 쪽의 두 답변은 P95를 기록한다고 했지만 회차별 50건을 정렬해 48번째 값을 취한다는 계산법을 생략했다. 그중 한 답변은 피드백이 불완전한 상태와 완전한 상태를 각각 검사했지만, 누락 파일을 보완하고 **같은 건을 재검사한 뒤** 표시가 바뀌는지 확인하는 테스트를 생략했다. 점수는 답변에 드러난 기준의 완전성을 뜻한다. 검색이나 접수 자체의 합격 판정은 여섯 답변이 같았다.

가장 빨랐던 29.4초의 AI는 용어집 파일명만 봤다고 답했다. 같은 조건의 다른 AI도 용어집을 근거로 쓰지 않았다. 실제로 용어집을 읽은 AI는 원문과 함께 인용했고 40.3초가 걸렸다. 대조군에서는 100.9초가 걸린 회차도 있었다. 한 요청을 조건별 세 번씩 수행했고 도구 대기 시간과 근거가 충분하다고 판단하는 시점이 달랐다. 채점자는 조건을 알고 수동으로 채점했다. 현재는 개발 스킬이 용어집을 선택적으로 참조하는 방식을 유지할 근거가 있으며, 의무 열람이나 일정한 시간 단축을 뒷받침할 근거는 부족하다.
