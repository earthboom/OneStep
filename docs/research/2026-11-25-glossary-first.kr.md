# 개발 용어집을 먼저 읽으면 테스트 기준과 탐색 시간이 어떻게 달라지는가

이전 대화를 모르는 AI 여덟 개를 네 쌍으로 비교했다. 용어집을 먼저 읽은 네 답변은 사전에 정한 인수 기준 11개를 모두 충족했다. 용어집 없이 찾은 네 답변 중 세 개도 모두 충족했고 한 개가 8개를 충족했다. 근거 탐색 시간의 중앙값은 용어집을 먼저 읽을 때 40.44초, 없이 찾을 때 33.09초로 7.35초 차이가 났다.

## 요청과 회차별 결과

여덟 답변 모두 검색은 호출자 기준으로 응답 250건 각각이 2초 이내여야 한다고 판정했다. 피드백은 지정 접수함에서 해당 건의 영문·한국어 파일을 확인한 뒤 접수로 표시했다. 일부 파일만 도착했을 때 보완 후 재검사하는 절차와, 전달 여부를 담당자 검토와 구분하는 기준도 여덟 답변에 모두 있었다.

누락은 3회차의 용어집 없는 답변 한 개에서 나왔다. 이 답변은 첫 요청을 “프로세스 시작부터” 잰다고 했지만 호출자가 프로세스를 **실행하기 직전**에 타이머를 시작한다는 경계를 명시하지 않았다. P95를 보고한다고 했지만 회차별 50건을 정렬한 **48번째 값**을 쓴다는 계산법을 생략했다. **2초 이하**라는 판정은 맞았지만 **반올림 전 실측값**에 적용한다고 명시하지 않았다. 나머지 일곱 답변은 이 세 항목까지 적었다. 이 점수는 작성한 테스트 기준의 완전성을 평가한다.

## 실험 방법과 해석

요청, 11개 채점 기준, 실행 순서를 미리 고정했다. 각 AI는 독립된 대화에서 전체 저장소 사본 하나를 탐색했다. 두 사본의 공통 파일 1,720개가 동일한지 해시로 확인했다. 한쪽에만 영문·한국어 용어집을 추가했고, 탐색 대상은 영문 정본으로 통일했다. 양쪽 모두 Git 내부 정보, 캐시, 이전 실험 산출물 여섯 개를 제외했으며 스킬의 기존 참조 문구는 유지했다. 관련 근거 파일 목록은 제공하지 않았다. 별도의 AI가 실행 순서·조건·시간을 보지 않고 용어집 이름을 가린 답변 여덟 개를 무작위 순서로 채점했다.

같은 컴퓨터의 단조 시계로 첫 조회 직전부터 근거가 충분하다고 판단한 시점까지 측정했다. 선열람 조건에서는 첫 명령이 타이머를 시작한 뒤 영문 용어집 전문을 열었다. AI가 전문 끝의 확인 코드를 반환해야 다음 탐색으로 넘어갈 수 있었다. 이 구간의 중앙값 11.98초는 총 탐색 시간에 포함되며, 읽는 시간과 도구 응답 대기를 함께 반영한다. 시작 전 순번 대기와 최종 답변 작성 시간은 제외했다. 여덟 번의 탐색 시간은 서로 겹치지 않았다.

네 쌍 중 세 쌍에서는 용어집을 먼저 읽은 쪽이 더 오래 걸렸다. 누락 세 개는 한 답변에 몰렸고 나머지 세 쌍에서는 양쪽의 완전성이 같았다. 지금 결과로는 시간 경계·백분위 계산·반올림이 합격 판정을 바꿀 수 있는 작업에서 용어집을 먼저 읽는 방법이 적절하다. 한 요청을 조건별 네 번 비교했으므로 모든 개발 작업에 의무화할 근거는 제한적이다. [답변 여덟 개 전문·채점 이유·타이머 원자료](2026-11-25-glossary-first-measurements.json)
