# How much design does this change need, and where should implementation pause?

2026-11-24 · Software and game development

Design earns its cost when a choice changes what someone can do, which behavior other work must preserve, or what the team can safely commit to next. Delivery can still fit in one pass. Conversely, a well-understood design may require multiple stages because independently deployed readers and writers must coexist. These two decisions belong in the same task brief and can have different answers.

## Game design needs two kinds of evidence

Hunicke, LeBlanc and Zubek's MDA framework connects rules, behavior during play and the player's experience. The *Outer Wilds* GDC session illustrates why the experience belongs in the scope. Its designers describe how clues motivate players to choose where to explore. In a new game, “the hint played” can be checked in a build. “A first-time player followed the hint for the intended reason” needs observation of play. A wrong turn or an explanation pointing to an unrelated cue can overturn the design even when every event fired. This test is our application of the sources. The talk was reviewed through its published slides and session description. [MDA paper](https://users.cs.northwestern.edu/~hunicke/MDA.pdf) · [GDC session and video](https://gdcvault.com/play/1027008/Independent-Games-Summit-Sparking-Curiosity) · [Speakers' slides](https://media.gdcvault.com/GDC%2B2021/beachum_gdc_2021%281%29.pdf)

Rami Ismail distinguishes the prototype that tests the idea from a vertical slice that tests the ability to produce representative finished content. For a game with twelve rooms, a greybox junction can test whether an unfamiliar cue works. An authored room built, loaded and played through the real pipeline can test production risks. If the pipeline is already established and the cue is the only uncertainty, reuse the pipeline and spend the experiment on the cue. Evidence from one room supports extending the approach. It does not complete twelve rooms or establish their individual readability. [Ismail, Prototypes & Vertical Slice](https://ltpf.ramiismail.com/prototypes-and-vertical-slice/)

## Worked decisions from this repository

- **Existing content contract.** The native C++ tactics example ran a baseline encounter before introducing a second optional pack. Its comparison records an unchanged build script and gameplay source when the second encounter was added. The checkpoint established whether a content author could add a variant through the agreed extension point. Once that contract has been demonstrated, another ordinary encounter can fit one author-and-play cycle. These are existing fixture results. [Workflow and recorded observations](../examples/cpp-gameplay-workflow/native-tactics/WORKFLOW.md) · [File comparison](../examples/cpp-gameplay-workflow/native-tactics/evidence/baseline-vs-extension.json)
- **A metric changes the boundary.** The retrieval benchmark passed a per-round P95 target while seven individual responses exceeded two seconds. A later task explicitly required every response to fit that limit. Profiling the broad query before extending the index changed the implementation decision. Replaying the same ranked results measured a separate obligation, relevance preservation. Reusing only the earlier P95 check would have answered the wrong scope. [Earlier session measurements](2026-11-23-search-session-measurements.json) · [Individual response evidence](2026-11-23-search-tail-measurements.json)

The reusable [skill criteria](../../skills/vegabond-code-design/references/scope-and-delivery.md) carry these decisions into implementation and planning. Design-only work ends with the choice and its proposed evidence. In implementation work, an actual intermediate result can reopen a decision before dependent effort is spent. The published research, studio cases and local fixtures inform this judgment. They do not measure a change in this project's team productivity.

## Forward trials on the guidance

A fresh evaluator received four hypothetical briefs and their constraints. It kept a two-track clip move inside one undoable document transaction and proposed failure injection after removal. For a mobile save migration it kept the shared old format writable during coexistence and proposed an old→new→old→new round trip. For a twelve-room escape game it described all twelve rooms and proposed testing the shadow cue at one junction before committing to detailed production. These were design responses. The evaluator did not execute a transaction, migrate saves or observe players.

The label-only case exposed excess verification: the evaluator proposed exercising an unrelated export command and shortcut. The guide was amended to follow the binding controlled by the edited resource. A second fresh evaluator received a plain search-result string and a separate menu string whose markup determines an access key. It chose a text diff and rendered empty state for the first, and a rendered mnemonic plus new/old key behavior for the second. This small trial checks routing and proposed verification scope.
