# Game data management methods and production examples

2026-11-22 · Spreadsheets and code generation, engine assets, content languages, procedural generation, transactions, and versioned distribution

**Choose a data management method according to the work you want to change.** A team adjusting hundreds of values at a glance, a team editing a stage while viewing the scene, and a team giving players tools to create expansion packs each need different authoring methods. Even within one game, the team might balance values in spreadsheets, author spaces as engine assets, and update account state in a database. [Epic Tavern and Darkwater production talk](https://gdcvault.com/play/1035719/Spreadsheets) · [Unity ScriptableObject production example](https://unity.com/how-to/architect-game-code-scriptable-objects) · [Roblox player data design example](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing)

This report applies the options in the [game data format comparison](2026-11-22-game-data-formats-and-pipeline.md) to production workflows. It covers each method's scope, production costs, and potential conflicts with existing stages and saves.

## 1. Spreadsheets and typed data generation

**When it fits.** Item prices, enemy stats, reward tables, dialogue, and localization repeat columns across rows that designers need to compare, filter, and edit in bulk. A single row can also summarize a stage. Use columns for `stage ID`, `board reference`, `objective rule ID`, and `reward ID`. Keep variable-length data such as waves or unit placements in a separate table keyed by stage ID or in an editable asset. Assign ownership of both localized text and the keys referenced by game rules.

**How to operate it.** An importer reads the input exported from a designated spreadsheet revision. It checks column types, units, required values, duplicate IDs, references to other tables, and value ranges. From the result, generate the necessary artifacts, such as engine assets, typed lookup code, or binaries. When shipping calculated values from a sheet, retain the exported input so those values can be reproduced. Keep simulations and graphs for comparison, and identify experimental and approved values in the tables you distribute. The team should be able to trace `attack power 20` in a shipped file to its source row and column. [Luban features, validation, and target-specific exports](https://www.datable.cn/en/docs/reference/features) · [Unreal Data Tables and Curve Tables](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-driven-gameplay-elements-in-unreal-engine)

This illustrates designing key management and whole-story review together when editing dialogue and quests. [Developer talk](https://gdcvault.com/play/1035719/Spreadsheets) |
| **Darkwater, Guillaume Pierre, GDC 2026** | The team simulated procedurally generated spaces and item drops in spreadsheets. ## 2. Engine assets and dedicated editors

**When it fits.** Consider this for stages, dialogue graphs, and encounter layouts in which position, collision, lighting, previews, and asset references matter. Unity can combine scenes and Prefabs with `ScriptableObject`, and Unreal can combine Maps and Blueprints with `UDataAsset`. For example, place checkpoints and respawn points on a race course, then specify lap rules and unlock IDs in a separate definition. Retain references so it is possible to find the stages affected by a shared preset change. [Unity production guide](https://unity.com/how-to/architect-game-code-scriptable-objects) · [Unreal Data Assets](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-assets-in-unreal-engine) · [Unreal Reference Viewer](https://dev.epicgames.com/documentation/en-us/unreal-engine/reference-viewer-in-unreal-engine)

**How to operate it.** Split the authoring source into units whose contents typically change together. Unreal's One File Per Actor separates actor files in the editor so people can work on the same level concurrently. Cooking embeds the actors in the level. Choose version-control editing units and runtime streaming units separately. In Unity, track source assets and their `.meta` files together. If a stage appears twice in the catalog or lacks a required reference, let the author open the affected asset in the editor and fix it. [Unreal OFPA](https://dev.epicgames.com/documentation/en-us/unreal-engine/one-file-per-actor-in-unreal-engine) · [Unity asset metadata](https://docs.unity3d.com/6000.0/Documentation/Manual/AssetMetadata.html) · [Unreal Data Validation](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-validation-in-unreal-engine)

Ryan Hipple's Unite talk presents asset-based design patterns. Witch Beam's *Unpacking* talk shows tools tailored to placement zones and authoring objects and boxes. Identify recurring edits in the current workflow first. For example, adding validation that shows checkpoint order and missing spawn positions can surface errors early while keeping the stock editor. [Unite talk](https://www.youtube.com/watch?v=raQ3iHhE_Kk) · [Unpacking developer talk](https://youtu.be/2j7AJj1oRSQ)

## 3. Declarative content languages and restricted scripts

**When it fits.** Stage authors may need to compose behavior beyond arranging data, such as `send reinforcements when the door opens` or `branch if rescued within three turns`. External creators may also need a defined set of content capabilities. Start with a list of conditions and actions in an editor or table. As the range of combinations and number of packages grow, evaluate a dedicated language or scripts. Let the rules module own decisions where timing and authority matter. Each stage selects from the published conditions and actions. [GDC talk on gameplay scripting design](https://www.gdcvault.com/play/1023204/Sculpting-a-Gameplay-Scripting)

| Example | Where authoring and execution diverge |
| --- | --- |
| **WML in Battle for Wesnoth** | Authors declare a scenario ID, map file, and the ID of the scenario that follows a victory. They use events and preprocessing to author scenario networks at a scale that warrants them, and can open a specific scenario directly in test mode. [ScenarioWML](https://wiki.wesnoth.org/ScenarioWML) · [WML campaign authoring guide](https://wiki.wesnoth.org/MakingCampaignInWML) |
| **NML and NewGRF in OpenTTD** | Creators author resources and code in a domain-specific language, compile them, and distribute a GRF the game reads. The language and distribution artifact serve distinct purposes. The game separately specifies which changes a game in progress supports. [Official NML source and compiler](https://github.com/OpenTTD/nml) · [NewGRF usage guide](https://wiki.openttd.org/en/Manual/NewGRF) |
| **Lua prototypes in Factorio** | Mods create or adjust prototypes during defined data stages. Runtime handles events and state changes during play. The documentation describes load order for definitions that multiple mods can change and migration rules for existing saves. [Data lifecycle](https://lua-api.factorio.com/latest/auxiliary/data-lifecycle.html) · [Migrations](https://lua-api.factorio.com/latest/auxiliary/migrations.html) |

**How to operate it.** Maintain the function and type list, execution order, defaults, error locations, and version compatibility alongside the tools. If content packs are supported, check references and required capabilities per pack. Products that run user-authored scripts should enforce allowed operations and execution budgets in the runtime and provide a way to test required mechanics from actual stage entry through exit. Compare the cost of developing, documenting, and debugging a DSL with a small list of conditions and actions, given the volume of content the team will produce.

## 4. Procedural generation and content builds

If hundreds of terrain layouts follow a similar assembly sequence, people can author templates, connection points, and placement constraints, and a generator can produce the results. **When the results become final** changes how saving and debugging work. [Goals and design challenges in PCG research](https://drops.dagstuhl.de/entities/document/10.4230/DFU.Vol6.12191.61)

| Method | Role and maintenance costs |
| --- | --- |
| **Generate during authoring** | A design tool proposes rooms or city blocks, and a reviewed layout becomes final. For fixed stages, this makes human edits and the history of decisions easier to trace. [Insomniac's Marvel’s Spider-Man production paper](https://history.siggraph.org/wp-content/uploads/2022/09/2019-Talks-Santiago_Procedural-System-Assisted-Authoring.pdf) · [Tanagra paper](https://cdn.aaai.org/ojs/12379/12379-52-15907-1-2-20201228.pdf) |
| **Generate during the build** | Regenerate tiles, precomputed placements, search catalogs, and other artifacts for release. Track which outputs become invalid when sources, tools, referenced assets, or platforms change. Check that a clean build and a rebuild after a change both reflect the same inputs. [Bungie asset pipeline talk](https://www.gdcvault.com/play/1025285/Tools-Tutorial-Day-Bungie-s) · [Build Systems à la Carte paper](https://simon.peytonjones.org/assets/pdfs/build-systems-original.pdf) |
| **Generate at runtime** | Generate spaces or visual elements as conditions require. When terrain affects the game rules, generation order, compatibility, and reproducibility matter. Decorative placements that do not affect play outcomes can be regenerated more freely. [No Man’s Sky continuous world generation talk](https://www.gdcvault.com/play/1024265/Continuous-World-Generation-in-Noby) · [Horizon Zero Dawn GPU runtime placement talk](https://www.gdcvault.com/play/1024700/) |

When the same seed must produce the same stage, verify the generator version, input packs, order of random calculations, and behavior across targets together. To guarantee revisits from older saves, preserve a compatible generator or store the required layout and the changes the user made. Use separate measures for whether the rules allow generated stages to be completed and whether output types or difficulties cluster too heavily at one end. [Paper on measuring the expressive range of procedural generation](https://cdn.aaai.org/ojs/13012/13012-52-16529-1-2-20201228.pdf) · [Grid puzzle and racing validation methods](2026-11-22-stage-content-framework.md#6-automated-validation-and-production-review)

## 5. Relational data, snapshots, and event history

In live games and large simulations, it matters **which changes must succeed together** and **what happens when two writers change the same value**. This may be less of a concern for read-heavy data such as content catalogs. Rewards and trades processed concurrently by multiple servers require authority, transactions, and a retry policy. [PostgreSQL transactions](https://www.postgresql.org/docs/current/tutorial-transactions.html) · [Roblox player data example](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing)

| Method | Application and failures to check |
| --- | --- |
| **Relational tables and constraints** | Consider an embedded database such as SQLite when there are many relationships among units, recipes, and rewards and the game needs joins or partial queries. Even a small profile may need to update several values together. A server economy needs protection against duplicate grants and support for transactions. Verify deletion rules for references, whether the actual database enforces foreign keys, and consistency after a failed update. [SQLite foreign keys](https://www.sqlite.org/foreignkeys.html) · [PostgreSQL transactions](https://www.postgresql.org/docs/current/tutorial-transactions.html) |
| **Versioned snapshots** | Save current stage progress, inventory, and world state at the points needed for recovery. Read older versions, convert them, and check the successful result. If multiple devices can update the same data, use save versions or write locks to detect conflicts and specify which state wins. [Wube development article on Factorio saving and loading](https://www.factorio.com/blog/post/fff-270) · [Unity Cloud Save write locks](https://docs.unity.com/en-us/cloud-save/concepts/write-locks) |
| **Change history and event sourcing** | Recording completion events alongside snapshots can support incident analysis and checks for duplicate rewards. Evaluate event sourcing when the product needs to rebuild state from past events. This adds responsibility for event order, duplicates, versioning, external side effects during replay, and rebuilding query data. [Martin Fowler on Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html) · [Industry study by Overeem et al.](https://arxiv.org/abs/2104.01146) |

In Roblox's public example, the server takes a session lock when activating a profile and uses a processing ID for purchase requests. This illustrates race conditions in a product that can open the same profile on several servers or retry before a response arrives. Drawing on 25 engineers and 19 event-sourced systems, Overeem et al. reported challenges such as event schema evolution, learning costs, and rebuilding query data. Before adopting this method for a game, establish replay and auditing requirements and how long writes actually need to remain useful. [Roblox implementation example](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing) · [Event sourcing study](https://arxiv.org/abs/2104.01146)

When simulating many facilities or NPCs, separately evaluate an in-memory structure that groups state read together each frame. Unity Entities and Unreal MassEntity illustrate processing entities that share a data composition in groups. Record persistent IDs and the values needed for reconstruction in saves, leaving session-allocated entity handles and memory layout out. Measure whether this actually reduces frame costs compared with the existing object-based approach. [Archetypes in Unity Entities](https://docs.unity3d.com/Packages/com.unity.entities%401.0/manual/concepts-archetypes.html) · [Unreal MassEntity](https://dev.epicgames.com/documentation/unreal-engine/overview-of-mass-entity-in-unreal-engine)

## 6. Content packs and versioned distribution

For optional stage packs or seasonal data, specify the **ID ranges, pack dependencies, versions, and permitted overrides** for base content and optional packs. Use a list or registry suited to the project for registration and lookup. Unreal Data Registry can use multiple sources in a specified search order to support overrides and fallback lookups. Authors should be able to predict which value is used when several packs contain the same ID. Define how far a new game or existing save can progress when a pack is missing. [Unreal Data Registries](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-registries-in-unreal-engine) · [Unreal Game Features](https://dev.epicgames.com/documentation/en-us/unreal-engine/game-features-and-modular-gameplay-in-unreal-engine)

**How to operate it.** Publish release content as a fixed set. Pin lookup and load paths so all files in an update belong to the same release version. Decide when a session already in play sees the new set and how long older versions remain readable. If a new version changes a save, separately check that the save can still be read after reverting the content distribution pointer. Unity CCD provides badges that point to releases. CCP uses transformation rules to publish artifacts derived from its game client's static data. Its public API provides FlatBuffers, per-release URLs, change lists, and ETags. To use the same arrangement for game updates, decide save compatibility and release retention separately. [Unity CCD releases and badges](https://docs.unity.com/en-us/ccd/dashboard) · [CCP's EVE static data transformation pipeline](https://developers.eveonline.com/blog/reworking-the-sde-a-fresh-start-for-static-data) · [CCP's versioned distribution API](https://developers.eveonline.com/blog/the-sde-over-http-static-data-dynamically)

## 7. Starting points by genre

| Task | Suitable combination and actual path for adding content | When to change |
| --- | --- | --- |
| **Add a stage to a grid puzzle** | Build the board in a board editor's source file or a typed engine asset. Add its new ID to the catalog and progression table, and check the solution inputs in the editor and the actual game. | If several people frequently edit the same board, improve spatial and property editing. If new condition combinations multiply, evaluate a tool for authoring rule combinations. |
| **Add a map to a racing or turn-based tactics game** | Edit the space and markers in the engine. Select existing race rules or tactical objectives. Maintain speed limits, unit stats, and rewards in tables that are easy for the team to compare. | If map editing conflicts recur, separate actors or assets that change frequently. If several missions use the same terrain, give the space and objective definitions separate lifetimes. |
| **Add a facility to a management simulation** | Validate relationships among facilities, production recipes, costs, and upgrades in typed spreadsheets. The simulation maintains facilities and inventory during play. Saves contain the required facility IDs and state. | When partial queries, updates, and recovery become more demanding across many objects, compare a database with the existing save system using its actual query and update load. |
| **Add a chapter to a dungeon or cooperative action game** | Author room assets with traversable connections and encounter presets. Generate them during the build or finalize them at runtime. Record optional chapter scope and version in the pack. The authoritative session finalizes rewards. | Evaluate independent publication when content packs change from release to release. Before switching to runtime generation, define the versions and placements needed for reconnection, replay, and saving. |

For example, to add `warehouse-04` to a pushing puzzle authored in the engine editor, create a new board `ScriptableObject` in Unity or a new board `UDataAsset` in Unreal. Select the same pushing rules and a row from the existing reward table, register the ID in the catalog and chapter progression, then verify retry and completion. Saves still read the same completion IDs when existing stages change order. Adjust reward values in bulk in the table. [Stage state ownership design](2026-11-22-stage-content-framework.md#2-shared-framework-and-state-ownership)

### Decisions to document at the start of development

- Record who edits the source and where, and the path from authoring a new stage through preview, validation, registration, and build. Check which files and how much shared code an author modifies to create the second stage.
- Trace the changes the project supports, including renaming a stage, removing a stage referenced by an existing save, or omitting an optional pack that previously shipped. Decide which IDs to preserve, how to handle older data, and which state to recover after a failed import, publication, or update.
- Review the maintenance costs the project can sustain. For spreadsheets, consider edit history and review costs. For assets, consider merge conflicts and reference errors. For generators, consider the cost of reproducing and discarding results. For databases, consider write conflicts and schema changes.
