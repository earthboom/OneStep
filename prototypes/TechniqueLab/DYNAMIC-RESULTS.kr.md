# 동적 장애물·국소 회피·전체 프레임 검증 — 2026-11-08

기존 프로토타입에 별도 DynamicLab 장면을 추가했다. 장애물 변경 때 이동 개체를 초기화하지 않는다. 최종 PlayMode와 Windows release 독립 실행 3회에서 각각 **회귀 검사 12개와 시나리오 기대 6개**를 통과했다(안전 시나리오 5개·실패 감지 비교군 1개). 안전 시나리오는 겹침·벽 침투·순간이동·예약 오류·낡은 필드 소비 없이 완료했다. 실제 렌더링한 전체 프레임도 측정했다. 16.67ms p95 목표를 세 실행 모두 충족한 조합은 **6개 중 6개**다. 이 구간의 결과이며 상용 게임의 안정 60 FPS 보장은 아니다.

## 지식에서 선택한 구현

[PATH](../../knowledge/game/K-GAME-TECH-PATH.kr.md)의 공유 목표·무효화와 [CROWD](../../knowledge/game/K-GAME-TECH-CROWD.kr.md)의 경로·국소 회피·렌더링 분리를 적용했다. 단일 소유 월드, 상하좌우 격자, 반경 0.20의 같은 원판, 속도 3단위/초, 이동 비용 1, 오른쪽 출구 영역, 벽의 한 칸 문 두 개를 사용한다. 출구 각 칸을 공통 싱크에 비용 0으로 연결해 거리장을 만들지만 실제 개체가 비인접 간선으로 이동하지는 않는다.

개체는 현재 칸과 목적 칸을 예약하고, 비어 있는 내리막 이웃으로 움직이거나 양보한다. 처리 시작 순서를 순환한다. 원판 크기보다 넉넉한 약 한 칸 간격을 유지하므로 통과량·자유로운 움직임을 희생하는 보수적인 협력 방식이다. ORCA 구현이 아니며 속도 공간의 보장을 가져오지 않는다. 양방향 교행·서로 다른 반경·대각 이동·연속 이동 장애물·힘·애니메이션 몸체는 별도 설계/검사가 필요하다. [ORCA 저자 자료](https://gamma-web.iacs.umd.edu/ORCA/)는 대안 구분에 참고했으며 그 구현·성능을 재현하지 않았다.

폐쇄 요청 즉시 새 경로에서 해당 칸을 제외하고 필드를 재계산한다. 기존 예약 개체가 빠져나갈 때까지 물리 콜라이더 폐쇄를 기다린다. 열면 즉시 경로를 갱신한다. 상자는 기존 장애물 칸을 없애고 새 칸에 요청하는 방식으로, 연속 강체 속도 예측이 아니다. 모든 변경에서 ID·위치를 보존한다. 도착 시에는 출구 영역에서 제거하지만 문 변경 때문에 재생성하지 않는다. 원래 장면의 문 변경 시 초기화 데모는 과거 비교용으로 남겼다.

## 전체 프레임 결과

Unity 6000.0.77f1, Windows 11, i7-12700KF, RTX 3080, Direct3D11, Mono release. 실제 **1280×720**, vSync 0, MSAA 2, 측정 중 FPS 제한 없음. 64×40 장면의 Unlit 원기둥·바닥·벽/문/상자·출구·OnGUI를 렌더한다. 스키닝·상용 에셋·그림자 부하·다른 게임/네트워크 시스템은 없다. 빌드 GUID `e99bbee9006c4aae9df6459b830c168d`. 비교 순서는 예약/회피 없음, 역순, 원래 순서이며 인원은 64/256/512 순이다.

경우마다 1초 준비 후 6초를 기록했다. 전체 프레임 간격 **149,913개를 모두 보존**했다. 활성 인원은 측정 내내 정확히 64/256/512였고 도착·재생성은 없었다. 문 닫기·상자 추가·다시 열기는 측정 구간 안에 포함한다. 게임 루프·이동·네이티브 물리/Transform 동기화·렌더링·출력 대기·계측·OS 스케줄링이 전체 간격에 들어간다. JSON·초기 장면 설정·이미지 저장은 구간 밖이다. 프레임 간격은 처리량 시간이며 입력에서 화면 출력까지의 지연은 아니다. CPU와 GPU는 겹쳐 실행되므로 더하지 않는다.

범위는 독립 실행별 통계의 최솟값~최댓값이며 합친 신뢰구간이 아니다. 백분위수는 nearest rank다. 느린 프레임·GC·예산 초과 표본을 버리지 않았다. 16.67ms를 넘은 표본은 1개, 최대 19.11ms였다. p95 충족이 모든 프레임의 마감 충족은 아니다. 회피 없음은 같은 인원·표현이지만 안전한 대체 구현이 아니다.

제어 타이머에는 장애물 처리·고정 틱 이동·Transform/네이티브 동기화·이벤트 계측이 들어가며 Unity 전체 렌더 비용은 제외된다. FPS 무제한에서는 60Hz 이동 틱이 없는 렌더 프레임도 많다. 실제 이동 틱을 하나 이상 수행한 부분의 통계를 별도 열로 제시했다. 틱 예산에는 그 열을 쓰고 틱 없는 렌더 프레임과 혼동하지 않는다. 전체 간격은 어느 프레임도 제외하지 않으며 요약에는 틱 수행 뒤의 전체 간격도 연결했다. 장애물 논리 트랜잭션 최대값은 0.275ms였다. 이벤트 프레임 번호로 다음 전체 간격과 연결할 수 있지만 모든 정체가 재계산 때문이라고 단정할 수 없다. 최대 누적 지연은 0.016667초이며 남는 시간을 버리지 않고 제한된 따라잡기로 처리한다. 작은 제어 비용만으로 게임 전체 프레임 예산을 보장하지 않는다.

**GPU 한계:** 149,913개 중 11,887개의 GPU 값이 없었고(0), 경우별 유효 범위는 90.5–93.9%였다. 원본 0은 남기고 요약의 유효 부분 통계를 따로 표시한다. 0을 무료 프레임으로 계산하거나 GPU 꼬리 지연을 검증했다고 주장하지 않는다. 렌더/CPU 시간과 전체 간격은 모두 보존했다. Unity는 비동기 지연과 자원 부족 등으로 반환이 실패할 수 있다고 설명한다([Frame Timing Manager](https://docs.unity.com/en-us/engine/6000.0/manual/analysis/graphics-performance-profiling/profile-rendering/frame-timing-manager/manager)). 타임스탬프를 중복 제거하며 GPU 값을 현재 이벤트 프레임과 직접 맞추지 않는다.

최종 여섯 조합은 세 실행의 짧은 구간에서 모두 p95 목표를 충족했다. 이전 렌더 측정의 512개 예약 회피 p95는 24.61–31.24ms였다. 그 사이 성능 최적화를 입증한 것은 아니다. 몸체 점유 검사·대기 표시를 바꿨고 호스트 부하는 통제하지 않았다. 두 결과를 보존하며 그 변경이 프레임을 개선했다고 단정하지 않는다.

데스크톱·다른 앱·GPU 부하·클럭·온도를 격리하거나 통제하지 않았다. 출력 대기·프레임 변동은 관찰했지만 정확한 원인은 이 실험만으로 확정하지 않았다. 따라서 채택은 **조건부**다. 실제 대상 장면·기기에서 전체 프레임/출력 경로를 조사하고 다시 측정한 뒤 안정 60 FPS를 약속해야 한다. 6초 시험으로 보편적인 지원 인원을 정하지 않는다.

## 재현과 적용 조건

이 디렉터리에서 실행하고 CLI 전에는 해당 프로젝트의 에디터를 닫는다. Unity 경로는 Run-Editor.ps1에 있다. 기존 로컬 라이선스 초기화 때문에 샌드박스 밖 실행이 필요했으며 자격 증명·설정은 바꾸지 않았다.

```powershell
./Run-Editor.ps1 -Method DynamicBatch.Play -Graphics -Report dynamic-editor-final.json -Log dynamic-editor-final.log
./Run-Editor.ps1 -Method DynamicBatch.Build -Log dynamic-build-final.log
./Run-Dynamic.ps1 -Session dynamic-run-1 -Visible -Order 0
./Run-Dynamic.ps1 -Session dynamic-run-2 -Visible -Order 1
./Run-Dynamic.ps1 -Session dynamic-run-3 -Visible -Order 0
python ./analyze_dynamic.py
./Run-Dynamic.ps1 -Session dynamic-ui -Interactive
```

측정에는 **-Visible 필수**다. 숨김/배치 파일럿은 렌더/GPU 0이라 기각했으며 원본은 무손실 gzip으로 최종 세션과 구별해 보관한다. 과거 파일을 보존하려면 새 세션 이름과 분석 입력을 함께 지정한다. Python assertion을 끄지 않는다. 수동 실행은 Assets/DynamicLab.unity 또는 Interactive를 쓰며 일시정지·문·상자·재시작·종료 버튼이 있다.

단일 권한의 격자 개체가 같은 출구/비용 프로필을 공유하고 양보·폐쇄 지연을 허용할 때 검토한다. 실제 반경·변경 소유권·폐쇄 정책·진행성과 프레임 예산을 다시 확인한다. 즉시 닫혀야 하는 문은 밀기·압박·취소 정책을 별도로 정한다. 일반적인 기아 방지 증명·다중 권한·연속 군중 솔버는 제공하지 않는다. PATH·CROWD·안내서에 결과와 조건을 반영했다. 누적 로컬 엔진 근거는 제한된 원리 기준 4개 항목이며 나머지 39개는 미검증이다.
