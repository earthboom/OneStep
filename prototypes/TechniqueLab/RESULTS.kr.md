# 기술 실험 결과 — 2026-11-07

저장된 지식에서 대표 기술 세 가지를 골라 Unity 6000.0.77f1에 구현했다. 시간 기준 카메라 감쇠, 조준 의도와 총구 제약을 결합한 히트스캔, 가중치 역방향 다익스트라 경로장이다. 최종 에디터 PlayMode와 독립 실행 프로세스 세 번에서 각각 검사 27개와 실제 Update 시간 시험 3개를 통과했다. Windows Mono 빌드 오류는 0개였다. 작은 실험 장면에 관한 결과이며 상용 게임이나 플레이 경험의 검증은 아니다.

- 빌드 GUID `1fbb60d030dd4a7b81305edd3a7fc38c`, 크기 86,307,080바이트. [빌드 기록](Results/build.json).
- [최종 에디터](Results/editor-play-final.json), [실행 1](Results/player-run-1.json), [실행 2](Results/player-run-2.json), [실행 3](Results/player-run-3.json). 각각의 `*-process.json`은 실제 종료 코드·실행 파일 SHA-256·C# 해시·시작/종료 UTC를 보관한다. 세 실행 모두 종료 코드 0이며 바이너리와 소스 해시가 일치한다.
- [분석 스크립트](analyze_results.py)는 표본 정규화·중앙값·p95·작업량·물리 질의 수·경로 비용 체크섬·검사 결과·현재 소스 해시를 독립 확인한다. [요약 JSON](Results/summary.json). Python assertion을 비활성화하지 않고 실행한다.

다른 데스크톱 앱을 격리하지 않았고 CPU 클럭·온도·OS 스케줄링을 통제하지 않았다. 세 측정은 서로 겹치지 않게 순차 실행했다. 이 PC·백엔드·장면·작업량의 수치이며 모바일·IL2CPP·멀티플레이·복잡한 실제 장면·다른 엔진의 예상값이 아니다.

## 동작과 수정 사항

처음 의도적으로 미완성인 구현에서 [21개 중 13개 실패](Results/red-checks.json)를 확인한 뒤 [21/21 통과](Results/green-checks.json)를 얻었다. 추가 검사에서는 서로 다른 그래프의 리비전 숫자가 같으면 캐시가 유효하다고 잘못 판단하는 결함을 재현했다([22개 중 1개 실패](Results/red-graph-identity.json)). 그래프 객체까지 결합한 뒤 [22/22 통과](Results/green-final-checks.json). 실제 장면 제어를 통한 검사 5개를 더해 모든 최종 실행에서 27/27을 통과했다.

초기 런타임 오류를 주입했을 때 뒤의 검사 실패 수 대입이 기존 오류를 지워 버리는 하네스 결함도 발견했다([이전 보고: 실패 0](Results/red-error-sentinel.json)). 누적하도록 수정해 [실패 1](Results/green-error-sentinel.json)과 실제 Unity 종료 코드 2를 확인했다. 오류 주입은 실패를 검출하기 위한 의도된 실행이다. 파일럿 보고·이미지는 수정과 배치 보정 이전 기록이므로 현재 결과에는 최종 에디터와 독립 실행 3개만 사용한다.

방향·0비용 간선을 포함한 고정 시드 10노드 그래프 16개에서 필드와 A*를 각각 Floyd-Warshall과 비교했다(알고리즘별 시작점/목표 비교 160개). 모든 부동소수 비용·그래프의 완전 증명은 아니다. 32×32 장면에서는 소비자 64개가 후속 노드를 따라 이동한다. 문을 바꿀 때 필드를 무효화·재계산하며 **소비자도 안전한 초기 칸으로 되돌린다**. 따라서 경로 중단·재개는 확인했지만 닫히는 문을 통과 중인 개체의 안전한 복구는 검증하지 않았다. 국소 회피도 없다.

실제 Windows 창에서 세 데모와 OnGUI 버튼의 표시를 확인했다. `Cycle cover`로 카메라 목표 감지는 true를 유지하고 안전 차단은 true → false → true로 바뀌었다. `Toggle grid door`는 false → true → false로 바뀌고 소비자들이 멈추고 다시 이동했다. `Reset followers` 입력은 받아들여졌으나 순간 초기화 상태는 이 UI 검사에서 계측하지 않았다. `Quit` 뒤 종료 코드 0과 창 사라짐을 확인했다([프로세스 기록](Results/interactive-check-process.json)). 이는 이 대화의 AI 관찰이며 사용자 승인·사용성 연구가 아니다. 자동 PNG는 `Camera.Render`로 만들어 **OnGUI를 포함하지 않는다**. [최종 장면 이미지](Results/player-run-3.png)는 실제 조작 창과 따로 검사했다. UI는 완성된 게임 HUD가 아닌 실험용이다.

## 카메라의 시간 기준 응답

시작 0, 정지 목표 10, 감쇠율 4, 적분 구간 정확히 2초. 기대값은 `10*(1-exp(-8)) = 9.99664497`. 마지막 dt를 남은 구간으로 제한하며 실제 간격 배열을 보관했다. 실측 FPS는 요청값이 아닌 실제 경과 시간으로 구했다.

| 요청 FPS | 실측 FPS 범위 | 프레임마다 10% 보간 최종값 | 지수 감쇠 최대 절대 오차 |
| --- | --- | --- | --- |
| 30 | 29.993–30.001 | 9.98203182 | 보고된 float 정밀도에서 0 |
| 60 | 59.973–59.998 | 9.99996853 | 0.000000954 |
| 144 | 143.888–143.983 | 9.99999619 | 0.000001907 |

모든 오차가 사전 허용값 0.0001 이하였다. 이 결과는 정지 목표와 기록된 시간 간격에만 해당한다. 매 프레임 샘플링하는 이동 목표의 완전한 불변성, 입력 지연·구도·충돌·편안함은 검증하지 않았다.

## CPU 연산 비용

변형마다 8회 준비 실행 후 반복 수를 두 배씩 늘려 약 3ms 배치를 목표로 보정했다(최대 1,048,576회). 표본 31개에서 변형 순서를 정방향/역방향으로 번갈아 측정하고 반복 수로 정규화했다. p95는 정렬한 31개 중 30번째 값이다. 표의 범위는 **독립 프로세스별 중앙값과 프로세스별 p95의 최솟값~최댓값**이며 합친 표본의 신뢰구간이 아니다. 보정 목표가 3ms여도 이후 배치는 짧아질 수 있다. 독립 실행 최소 실제 배치는 2.1794ms였다. 표본은 버리지 않았다.

Stopwatch에는 반복 연산·체크섬·델리게이트 작업이 포함되고 설정·에셋·파일 I/O·렌더링은 제외된다. 정규화 p95는 반복 배치 처리량이며 개별 연산의 최악 지연 분포가 아니다. 전체 프레임·GPU 시간은 측정하지 않았다. 그룹별 GC 수집 횟수는 모두 0이었지만 무할당 증명이 아니며 별도 할당 프로파일러는 사용하지 않았다. 작은 데이터·동일 포즈의 반복은 실제 게임의 캐시 상황과 다를 수 있다.

| 카메라: 호출당 스칼라 추종 100,000개 | 중앙값 범위 ms | p95 범위 ms |
| --- | --- | --- |
| 고정 10% 보간 | 1.708–1.751 | 1.938–2.194 |
| 개체마다 지수 계산 | 2.429–2.813 | 2.849–3.419 |
| 같은 rate/dt에서 alpha 공유 | 1.711–1.755 | 1.920–2.086 |

rate와 dt가 실제로 같은 경우에만 alpha를 한 번 계산해 공유한다. Transform·렌더링이 없는 수학 연산 실험이므로 카메라 시스템 전체 비용이 아니며 단일 카메라에 대량 최적화가 필요하다는 뜻도 아니다.

| 네이티브 물리: 호출당 사격 판정 1,024회 | 중앙값 범위 ms | p95 범위 ms | 사격당 물리 질의 |
| --- | --- | --- | --- |
| 카메라만, 총구 엄폐 | 0.274–0.298 | 0.309–0.379 | 1 |
| 안전 판정, 총구 엄폐 | 0.973–0.997 | 1.166–1.306 | 5 |
| 카메라만, 개방 | 0.278–0.349 | 0.325–0.415 | 1 |
| 안전 판정, 개방 | 0.932–1.104 | 1.100–1.399 | 5 |
| 안전 판정, 총구가 엄폐 내부 | 0.396–0.498 | 0.506–0.643 | 2, 조기 차단 |

카메라 단독 방식은 이 엄폐 상황에서 틀린 피해 규칙이므로 빠르다는 이유로 대체할 수 없다. 정상·엄폐 포즈에서는 카메라 광선·총구/뿌리 겹침·뿌리→총구·총구→조준점으로 5회다. 겹침 반경 0.025는 실험값이며 단위·자기 충돌 제외·원점 정책·움직이는 콜라이더·권한 포즈에 맞게 조정해야 한다. Unity는 콜라이더 안에서 시작한 광선이 그 콜라이더를 검출하지 않는다고 명시한다([Unity 6000.0 Raycast, Remarks](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/physics/raycast)). 총구에서 나가는 광선 하나만으로는 내부 상태를 막을 수 없다.

| 32×32 가중 그래프: 같은 출구 거리 응답 512개 | 중앙값 범위 ms | p95 범위 ms |
| --- | --- | --- |
| 개별 A* 512회 | 18.803–19.967 | 20.455–21.145 |
| 필드 1회 재계산 + 거리 조회 | 0.06784–0.06898 | 0.08364–0.09039 |
| 이미 유효한 필드 거리 조회 | 0.000863–0.000878 | 0.001009–0.001158 |

캐시 항목은 배열 읽기와 체크섬만 측정한다. 재계산·질의별 유효성 확인·후속 노드 이동·경로 복원·충돌·회피·조향 비용은 제외한다. A*는 작업 공간을 재사용하고 이 격자에서는 맨해튼 하한, 일반 그래프에서는 0 휴리스틱을 쓴다. 세 방식의 거리 합 체크섬은 같다. 가장 작은 시험값 32개부터 필드가 빨랐지만 보편적인 손익분기 인원은 구하지 않았다. 동일 목표·호환 그래프와 비용 프로필을 공유할 때 사용하고, 실제 예산에는 재계산 빈도·목표/프로필 수·메모리·이동 비용을 포함한다. 서로 다른 소수 목적지에는 개별 검색이 더 적합할 수 있다.

그래프 변경은 `AddEdge`/`SetBlocked`를 사용한다고 가정한다. 공개 배열·리스트를 직접 바꾸면 리비전 추적을 우회할 수 있다. 유한한 비음수 비용·감쇠율·시간 간격, 유효 인덱스가 전제다. 입력 검증·캡슐화·동시 변경 처리는 상용화 전에 보완해야 한다.

## 재현

이 디렉터리에서 PowerShell로 실행한다. 설치 경로가 다르면 `Run-Editor.ps1`의 Unity 경로를 조정한다.

```powershell
./Run-Editor.ps1 -Method LabBatch.Checks -Report checks-new.json -Log checks-new.log
./Run-Editor.ps1 -Method LabBatch.Prepare -Log prepare-new.log
./Run-Editor.ps1 -Method LabBatch.Play -Graphics -Report editor-new.json -Log editor-new.log
./Run-Editor.ps1 -Method LabBatch.Build -Log build-new.log
./Run-Player.ps1 -Session player-run-1
./Run-Player.ps1 -Session player-run-2
./Run-Player.ps1 -Session player-run-3
python ./analyze_results.py
./Run-Player.ps1 -Session interactive-check -Interactive
```

기존 근거 보존에는 새 세션 이름을 사용한다. 분석기는 의도적으로 `player-run-1/2/3`와 `editor-play-final.json`을 읽으므로 이름이 다르면 분석 입력도 명시적으로 바꿔야 한다. CLI 전에는 이 프로젝트의 에디터를 닫는다. Prepare는 작은 장면·머티리얼, Build는 Git 제외 Build 폴더를 만든다. PlayMode 캡처에는 `-Graphics`가 필요하다. Play에 `-InjectError`를 주면 의도적으로 종료 코드 2가 된다. 샌드박스 내에서는 시스템 식별 조회가 막혀 기존 로컬 라이선스 초기화가 실패했고 샌드박스 밖 실행으로 해결했다. 자격 증명이나 라이선스 설정은 바꾸지 않았다.

이번 실험은 `vSyncCount=0`과 요청 FPS를 사용한다. Unity는 데스크톱의 소프트웨어 프레임 조절에 미세 끊김이 있을 수 있고 에디터에서는 Game view만 영향을 받는다고 설명한다([targetFrameRate, Remarks](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/application/targetframerate)). 기록된 시간에 대한 응답 검증이며 화면 출력의 부드러움 검증은 아니다.

## 지식 반영

CAMERA·HITSCAN·PATH에 로컬 결과·조건을 추가했고 GUIDE·RESEARCH-USE에서 세 기술의 엔진 실험과 나머지 40개 기술, 이전 가상 평가를 구별했다. 구현은 독립 프로토타입으로 남긴다. 상용 통합·네트워크·GPU 프로파일·플레이어 연구는 수행하지 않았다.

반영 후 게임 목록 69개 엄격 검사는 오류·경고 0개였다. 기존 검색 회귀는 공통 23/23·게임 적용 11/11·추가 20/20을 통과했다([공통](Results/retrieval-common.json), [게임](Results/retrieval-game.json), [추가](Results/retrieval-extended.json)). 검색 가능성 검사이며 런타임 정확성·미지 요청의 자율 판단과 구분한다. 독립 코드·근거 검토에서도 명시한 범위 안의 차단 결함은 없었고 검토의 제한 조건을 위에 반영했다.
