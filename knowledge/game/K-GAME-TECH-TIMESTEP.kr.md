# 고정 시간 간격·점프 적분·서브픽셀

기준 항목: K-GAME-TECH-TIMESTEP · 확인일: 2026-11-07 · 참고 지식. 실제 엔진 구현·성능·플레이테스트는 수행하지 않았다.

## 원리와 구현 요점

안정적인 물리·리플레이가 필요하면 누적기로 고정 시뮬레이션 간격을 유지하고 화면을 보간한다. 밀린 계산량은 제한한다. 반암시적 오일러는 v+=a*dt 뒤 x+=v*dt를 계산하며 명시적 오일러는 이전 속도를 쓴다. 점프의 상승·하강 가속도는 다르게 설계할 수 있다. 정수 픽셀로 표시해도 소수 위치나 잔여량은 보존한다.

구현 선택과 점검은 출처를 바탕으로 한 실무적 종합이며 특정 게임의 정확한 구현을 보증하지 않는다.

## 적용 조건과 한계

델타 타임을 곱하는 것만으로 모든 물리가 안정적·결정론적으로 바뀌지 않는다. 화면 FPS·시뮬레이션 틱·네트워크 틱은 별개다.

## 적용 전 점검

적용 전 점검: 동일 입력을 30·60·144 렌더 FPS와 순간 멈춤 조건에서 재생해 최고점·착지·이벤트 순서를 비교한다.

## 실제 언리얼 시간 스텝 비교 — 2026-11-11

[V02/V49 결과](../../prototypes/UnrealTechniqueLab/TIMESTEP-RESULTS.kr.md)는 독립 이동·점프 모델의 검증이다. 정책78개, 실제PIE30/60/144FPS의36방법·상황, 프로필별 패키지3회와 정상1배속 영상을 확인했다. 기존 군중/검증 도구의 시계나Chaos/CharacterMovement·네트워크를 수정한 작업은 아니다.

고정60Hz의180개 상태는 FPS와 실제50/100/250ms 지연에도 같았다.3초당 입력6개를1회씩 소비하고 점프수락2·공중거부2·착지2·마지막x540cm를 유지했다. 두 정점은145cm다. 연속식150cm와 같다는 뜻은 아니다. 가변 스텝은 입력 시각에서만 나눠 처리하므로 입력 지연과 적분 간격의 영향을 구분한다. 첫 점프의 손실이 나중 점프의 전체 최대값에 가려질 수 있어 비행별 정점과 착지를 확인한다.

한 업데이트에 최대8고정틱을 처리하고 잔여 시간을 유지한다.250ms 지연은 이후 업데이트에서 따라잡을 수 있지만 실제 멈춤이 없어지는 것은 아니다.1e-10초 수치 여유를 포함한 허용오차 내 시간 보존이며 비트 단위 벽시계 보존이 아니다.3초/12초 실험 지평 이후 시간은 excess로 별도 기록한다. 지속 과부하의 일반적인 회복 보장은 미검증이다.

충돌 몸체는 현재 시뮬레이션 상태, 표시 구체만 이전/현재 보간을 따른다. 보간은1고정틱 지연이고 잔여 시간이1틱 이상이면 현재 상태를 유지해 외삽하지 않는다.144FPS의 정지 표시 횟수와 x(t-h) 오차로 확인했으며 실제 조작감/입력 지연 개선을 측정한 것은 아니다.30FPS 정상 영상으로144FPS의 매끄러움이나 실제 지연 장면을 증명하지 않는다.

아주 짧은 상승을 바닥 오차로 취급해 착지시키던 문제를 재현했다. 바닥 근처라는 조건에 하강 여부도 요구해 수정했고 회귀 검사가 통과했다. 실제 바닥/캡슐 대조군과 스윕 목적지 확인은 단순 장면 통합 근거이며 접지는 직접 모델이다.

성능은 같은1280×720패키지·선택한 방법1개·2초 준비+10초 측정·각3회다. 전체12초의720고정틱/24입력과 측정10초의 프레임 평가 수를 섞지 않는다. 부분 타이머는 모델·실제 몸체 이동·표시 반영을 포함하고 전체 프레임/GPU와 구분한다. 최종JSON·캡처는 제외한다.19개 결과 검사는 누락된 프레임 방법 데이터와 첫 정점 위장을 포함해 검출한다.

남은 제한: 회복ms는 잔여 시간을 해소하는 업데이트의 시작까지다. 해당 작업/렌더/화면 표시의 완료 시간이 아니다. 보간·복구 조건을 실제 게임의 부하와 입력 정책에 맞춰 다시 확인한다.
