# 서버 되감기·지연 보상

기준 항목: K-GAME-TECH-LAGCOMP · 확인일: 2026-11-07 · 참고 지식. 실제 엔진 구현·성능·플레이테스트는 수행하지 않았다.

## 원리와 구현 요점

시각별 충돌 이력을 보관하고 허용된 사격을 제한된 과거 상태에서 질의한다. 시계 대응과 표시 보간 지연을 반영하고 현재 권한 세계와 임시 과거 질의를 구분한다.

구현 선택과 점검은 출처를 바탕으로 한 실무적 종합이며 특정 게임의 정확한 구현을 보증하지 않는다.

## 적용 조건과 한계

되감기는 사격자 시점을 돕지만 이미 엄폐한 사람에게 불리할 수 있다. 모두가 이를 선호한다는 보편 주장은 입증되지 않았다. 공정성 기준과 최대 되감기를 명시한다.

## 적용 전 점검

적용 전 점검: 엄폐 전환·고속 표적·비대칭 지연에서 양 클라이언트 시점과 서버 이력을 함께 기록한다.

### lag compensation

**서버 되감기(server rewind)**는 권위 서버가 보관한 과거 충돌 자세에서 입력을 판정한다. 조회 시각은 클라이언트와 서버 시계의 대응, 상대 표시 상태의 보간 지연에 좌우된다. 사용 가능한 이력으로 제한하고 누락 시 처리 규칙을 정한다. 조회 뒤 현재 충돌 상태도 확인한다. Riot의 설명은 특정 게임에서 지연과 공정성의 절충을 보여준다. ## 언리얼 서버 되감기 검증 — 2026-11-20

이 실험에서는 실제 리슨 서버와 별도 클라이언트를 같은 지연과 판정 틱으로 비교했다. 전체 요청 일치는 현재 위치 12/36, 되감기 28/36이다. 되감기는 400ms를 포함해 기록을 조회하고 초과 및 누락을 명시적으로 거부했다. 현재 충돌은 보존됐고 중복은 처리하지 않았다. 엄폐 후 인정 시간 50ms·200ms는 이 장면의 관측값이다. 현재 위치/되감기의 판정 p95는 각각 2.200–2.500µs와 3.500–14.600µs였다. 서버 전체 프레임은 29.605–29.934ms와 29.570–29.656ms, 클라이언트 전체 프레임은 8.551–9.017ms와 8.602–9.134ms였다. 전체 요청과 실제 판정 일치율을 함께 기록하고, 서버·클라이언트 프레임과 판정 자체 비용을 구분한다.
