# 결정론적 록스텝

기준 항목: K-GAME-TECH-LOCKSTEP · 확인일: 2026-11-07 · 참고 지식. 실제 엔진 구현·성능·플레이테스트는 수행하지 않았다.

## 원리와 구현 요점

모든 물체 상태 대신 틱 번호가 있는 입력을 교환한다. 초기 상태·난수 스트림·처리 순서·수치 연산·시간 간격을 재현 가능하게 만든다. 상태 해시로 불일치를 추적하고 재생 버퍼로 도착 지터를 흡수하되 지연 비용을 기록한다.

구현 선택과 점검은 출처를 바탕으로 한 실무적 종합이며 특정 게임의 정확한 구현을 보증하지 않는다.

## 적용 조건과 한계

시드만 같다고 결정론이 보장되지 않는다. 부동소수점·스레드 순서로 달라질 수 있다. 클라이언트 공통 시뮬레이션은 숨겨야 할 정보를 노출할 수 있다.

## 적용 전 점검

적용 전 점검: 지원 플랫폼·빌드 사이에서 동일 입력의 장시간 틱별 해시를 비교한다.

## 근거

- 공식 문서·논문·저자 글은 확인한 본문 범위에 한정한다. 초록·영상 설명만 확인한 경우와 미열람 자료는 영문 정본 Evidence에 명시했다. 예제 코드·영상·제품 성능은 실행 검증하지 않았다.

### deterministic lockstep

**결정론적 록스텝(deterministic lockstep)**에서는 n번째 틱에 필요한 입력이 모두 도착해야 해당 틱을 진행한다. **재생 지연 버퍼(playout delay buffer)**는 입력을 잠시 보관해 도착 주기 변동을 흡수한다. 지연 비용이 있고 끝내 오지 않은 틱은 채울 수 없다. 지원 빌드에서 같은 시뮬레이션 상태의 틱별 해시를 비교해 처음 어긋난 틱과 시드·갱신 순서·산술 차이를 찾는다. [Glenn Fiedler — Deterministic Lockstep](https://gafferongames.com/post/deterministic_lockstep/)


## 입력 버퍼 적용

필수 입력이 모두 모인 다음 틱까지 순서대로 진행한다. 순서가 뒤바뀌거나 중복 도착해도 같은 입력을 두 번 적용하지 않는다. 두 피어의 진행 위치가 다를 수 있으므로 공통 구간의 같은 틱끼리 해시를 대조해 최초 불일치를 찾는다.

입력 도착 편차, 조작 반응 예산, 정지 허용량을 함께 보고 버퍼 길이를 정한다. 의도적으로 추가한 지연과 재생 시작 후 입력 누락으로 발생한 정지를 구분해 측정한다. 입력이 끝내 도착하지 않을 때의 세션 정책을 정하고, 참가하는 빌드와 연산 방식에 결정성 조건을 적용한다.
