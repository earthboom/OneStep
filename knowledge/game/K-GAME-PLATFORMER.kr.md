# 도전 구간을 조합하기 전에 플랫포머의 이동·충돌 규칙 정하기

**K-GAME-PLATFORMER** · 참고 자료 · 사용 중 · 근거 확인 2026-11-19

충돌, 움직이는 발판과의 상호작용, 이동 상태의 표현을 먼저 예측 가능하게 만든다. 이후 스테이지의 도전 순서를 설계한다. 타일 기반 2D 이동과 레벨 프로토타입에 직접 적용하며, 3D 적용에는 별도 검토가 필요하다. 주요 검색어는 이동, 충돌, moving platform, axis-aligned bounding box(AABB), 축 정렬 경계 상자, 레벨 설계, 애니메이션이다. 작성자의 물리 해설과 닌텐도 인터뷰, GDC 초록을 확인했고 컨트롤러나 레벨을 실행하지 않았다.

## 지침

Maddy Thorson은 이동하는 개체와 지형, 발판이 개체를 실어 나르는 경우와 밀어내는 경우, 개체별 압착 처리를 구분한다. 같은 축에서 두 처리가 겹치면 밀어내기가 우선한다. 닌텐도 개발진은 애니메이션으로 상태를 전달할 때 표정과 이동 방향의 가독성을 함께 검토했다. Celeste GDC 발표의 초록에서는 스테이지 제작, 지역 배치, 이야기 통합을 다룬다고 밝힌다. 구체적인 학습 순서는 초록에서 확인할 수 없다.

콘텐츠를 제작하기 전에 접지 판정, 발판이 개체를 운반하거나 미는 조건, 공간이 부족할 때의 결과를 정한다. ‘의도 → 입력 → 이동 → 접촉 → 피드백 → 재시도’ 순으로 한 장면을 추적한다. 지형 하나가 바뀌어도 접촉 시점, 카메라 시야, 위험 인지와 재시도 비용이 함께 변할 수 있다.

**Axis-aligned bounding box(AABB, 축 정렬 경계 상자)**는 2차원에서 변이 월드 좌표축과 평행한 직사각형으로 충돌 형상을 표현한다. Thorson의 구현은 충돌체의 좌표를 정수로 두고 소수 이동량을 누적한 뒤, 한 축에서 한 픽셀씩 이동 가능 여부를 확인한다. 발판이 한 개체를 받치면서 같은 축에서 밀어야 하는 경우, 겹침을 해소하는 밀어내기만 적용되어 이중으로 이동하지 않는지 확인한다. 경사면이나 회전하는 표면을 지원하는 게임은 해당 접촉을 별도로 점검한다.

평지 점프와 함께 측면 접촉, 방향 전환, 천장, 이동 발판, 여러 접촉이 겹치는 장면을 프로토타입에 넣는다. 결과를 예측할 수 있게 된 후 하나의 판단이 분명한 방을 만들고, 같은 이동 규칙을 조합해 도전을 확장한다. 이는 여기서 제안하는 구성 방법이며 GDC 발표의 인용이 아니다.

애니메이션, 카메라 선행 이동, 소리와 착지 피드백으로 현재 이동 상태와 다음 행동을 읽을 수 있게 한다. 선택 경로는 본 경로의 요구가 이미 이해될 때 추가 숙련의 기회를 줄 수 있다. 새 능력이 도달 거리나 접촉 규칙을 바꾸면 이동 규칙을 재검토한다.

## 적용 범위와 예외

정밀한 2D 이동에서 가장 직접적으로 적용된다. 원문의 정수 좌표와 AABB는 특정 구현이다. 경사, 회전, 연속 충돌 검출, 3D 이동에 일반적인 구현 요건은 아니다. 미끄럽거나 혼란스러운 움직임을 의도한다면 즉각 제어할 수 있는지와 별개로 결과를 이해할 수 있는지 본다. 접근성 옵션이 실행 난도를 바꾸더라도 경로 논리는 유지될 수 있다.

## 확인

서 있기, 매달리기, 밀림, 압착을 포함하는 짧은 시험 구간을 두고 컨트롤러 변경 후 재생한다. 처음 접하는 플레이어가 예상한 착지 위치와 발판 동작을 실제 결과와 비교한다. 방의 요구를 이해했는지와 완료했는지를 따로 기록한다. 지형 수정 후 재시도 거리, 카메라 구도, 선택 경로의 시인성을 확인한다. 여기서는 이 시험들을 실행하지 않았다.
