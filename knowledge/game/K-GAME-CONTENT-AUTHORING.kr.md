# 편집 원본과 재현 가능한 게임 콘텐츠 빌드를 정한다

## 지침

데이터마다 편집 담당자, 편집 원본, 제작·빌드·세션·저장 중 어느 시점까지 유지되는지를 정한다. 평평한 밸런스·현지화 표는 시트나 CSV에서 편집하고 가져올 때 타입이 있는 데이터로 변환한다. 중첩 구조, 변경 비교, 도구 간 이동이 필요하면 버전을 붙인 JSON을 쓴다. 에디터에서 참조를 연결하거나 공간을 편집할 때는 Unity ScriptableObject나 Unreal Data Asset을 쓴다. 에디터 밖에서도 읽는 콘텐츠라면 경로나 엔진 객체 참조를 임포터나 카탈로그에서 해석한다.

스키마를 검사한 뒤 ID의 유일성, 에셋 참조, 조건 그래프, 출구 도달 가능성 같은 장르 규칙을 검사한다. 오류에 파일과 객체 ID, 필드를 표시한다. 편집 원본에서 배포용 에셋과 매니페스트를 재생성한다. 절차 생성은 씨드, 생성기 버전과 입력 설정도 결과와 함께 기록한다.

## 적용 범위와 예외

제작, 렌더링, 저장에는 각각 맞는 형식을 쓸 수 있다. 지속적인 조회나 상태 재구성이 필요하면 데이터베이스나 이벤트 이력을 검토한다. 조건이나 분기가 표로 표현하기 어려워지면 제한된 스크립트나 선언형 언어를 검토하고 가능한 연산과 부수 효과를 기록한다. 선택 팩은 의존성과 호환 버전을 매니페스트에 넣고 제외·해제 경로를 확인한다.

## 확인

깨끗한 체크아웃에서 가져오고 같은 변경을 증분으로도 가져온다. ID와 참조, 재생성 결과를 비교하고 대상 빌드에서 배포 목록을 연다. 형식은 맞지만 ID가 중복되거나 참조가 없는 데이터를 거부하는지, 선택 팩을 빼고 작동하는지 확인한다. 저장과 기록은 [스테이지 식별과 호환성](K-GAME-STAGE-COMPATIBILITY.kr.md)을 따른다.

## 근거

형식 보고서는 JSON 구조·의미 검증과 Unity·Unreal의 임포트 경로를 정리한다. 관리 방식 보고서는 타입 시트, 엔진 에셋, 스크립트, 절차 생성, 이벤트 이력과 팩을 비교한다. 채택할 때는 대상 프로젝트에서 제작·임포트 비용을 확인한다.
