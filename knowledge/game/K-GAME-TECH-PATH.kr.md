# 질의 구조에 맞춰 A*와 공유 경로장 선택

기준 항목 K-GAME-TECH-PATH · 활성 참고 지식 · 확인일 2026-11-08. 일반 원리와 실행한 환경·조건을 구분한다.

## 지침

비음수 비용 거리맵에는 다익스트라, 단일 목적지 검색에는 f=g+h인 A*를 쓴다. 허용 휴리스틱·재개방·종료 조건이 최단 경로 보장에 중요하다. 여러 시작점이 목표를 공유하면 역방향 거리장 T를 만든다. 후속 노드는 합법적인 이웃 중 c(u,v)+T(v)가 최소인 것으로 정하거나 역방향 검색의 트리를 보존한다. T(v)만 최소로 고르면 이웃까지 비용을 놓친다. c(S,A)=100,T(A)=1과 c(S,B)=1,T(B)=2는 B(총3)를 골라야 하며 A(101)가 아니다.

방향 간선은 원래 비용을 유지해 역전한다. 반대 방향 비용은 다를 수 있다. 0비용에서는 동거리 노드가 연결되므로 엄격한 거리 감소만 요구하면 최적 경로를 거부하고 임의 동점 선택은 순환할 수 있다. 확정 노드로의 엄격한 개선으로 생긴 비순환 후속 트리나 검증한 진전 규칙을 쓴다. 연결·비용이 바뀌면 거리·후속을 함께 무효화한다. 특정 게임의 정확한 코드 재현 보장은 아니다.

### 첫 엔진 실험 — 2026-11-07

[원래 결과](../../prototypes/TechniqueLab/RESULTS.kr.md)에서 Unity 6000.0.77f1 PlayMode·Windows Mono 3회로 가중·방향·0비용·도달 불가·무효화를 검사했다. 방향 그래프 16개(각10노드)에서 알고리즘별 시작점/목표 160개를 독립 Floyd-Warshall과 비교했다. 모든 float 그래프의 증명은 아니다. 서로 다른 그래프의 리비전 숫자만으로 캐시를 유효하다고 보던 결함을 수정해 객체와 리비전을 함께 결합했다. AddEdge/SetBlocked 변경이 전제이며 공개 배열·리스트 직접 변경은 추적을 우회할 수 있다. 단일 스레드 프로토타입이다.

32×32 격자 같은 출구의 거리 512개 응답 중앙값은 A* 18.803–19.967ms, 필드 재계산+조회 0.06784–0.06898ms, 캐시 배열 0.000863–0.000878ms였다. 캐시는 유효성 확인·후속 이동·경로 복원·조향·회피 비용을 제외한다. 전체 게임 향상률·보편 인원 임계값이 아니다. 시험한 32/128/512개에서 필드가 빨랐으나 손익분기점은 찾지 않았다. 목표/비용 프로필·재계산 빈도·목표 수·메모리·실제 이동 비용으로 판단한다. 원래 64개 시각 데모는 문 변경 시 개체를 초기화했으며 그 과거 장면은 그대로 남겼다.

### 동적 이동 확장 — 2026-11-08

[후속 결과](../../prototypes/TechniqueLab/DYNAMIC-RESULTS.kr.md)는 이동 개체를 초기화하지 않는다. 월드 하나가 그래프·현재/목적 칸 예약·물리 상태를 소유한다. 폐쇄 요청은 새 경로를 즉시 막고 재계산하지만 기존 통과 개체가 나갈 때까지 콜라이더는 기다린다. 실제 문 부피 안의 원판이 0.4167 시뮬레이션 초 후 빠져나가 폐쇄됐고 뒤의 개체는 다른 문으로 우회했다. 두 경로를 닫으면 기다리고 다시 열면 재개한다. 일시정지 제어도 화면/네이티브 상태를 즉시 갱신한다.

사용 가능한 내리막 상하좌우 칸으로 이동하거나 양보하고 처리 순서를 순환한다. 출구 영역을 공통 싱크에 연결하지만 비인접 간선으로 이동하지 않는다. 최종 PlayMode와 release 3회에서 회귀 12개·시나리오 기대 6개를 통과했다. 64/256개 합류가 60/120 시뮬레이션 초 제한 안에 끝났고 겹침·벽·순간이동·예약 오류가 없었다. 일반적인 기아 방지·교행·서로 다른 반경·대각·즉시 압박 문을 보증하지 않는다.

새 64×40 장면의 512개 활성 개체에서 전체 프레임 p95는 2.87–3.15ms, 제어/네이티브 Transform 동기화 p95는 0.130–0.144ms였다. 최종 모든 조합은 세 실행의 짧은 구간에서 16.67ms p95를 충족했지만 이전 측정에는 미달이 있었고 부하는 통제하지 않았다. 과거 거리 배열 측정으로 전체 프레임 예산을 예측하면 안 된다. GPU 누락을 표시하고 꼬리 지연은 미검증으로 남겼다. 실제 장면·기기·폐쇄 정책을 확인한 조건부 채택이다.

## 적용 조건과 예외

길찾기와 국소 충돌 회피는 다르다. 반경·대각 모서리·동적 장애물·불균등 비용을 명시한다. 셀 예약 확장은 같은 반경·단일 권한·한 출구·폐쇄 지연을 허용하는 격자용이며 연속 군중 솔버가 아니다.

## 검사

독립 최단 비용 비교, 0비용 진전, 도달 불가, 필드/후속 동시 무효화와 객체 식별을 검사한다. 후속에서는 실제 문 부피 점유·모든 경로 차단/재개·상자 변경·64/256 합류·위험 비교군·일시정지 네이티브 동기화·도착 구간 감사 감지를 실행했다. 실제 내비게이션·반경·교행·갱신 빈도·이동/회피와 전체 프레임 예산은 대상 환경에서 다시 검사한다.

## 무차선·지속 유입·개별 진전 확장 — 2026-11-08

[StreamLab 결과](../../prototypes/TechniqueLab/STREAM-RESULTS.kr.md)는 무방향 상하좌우 지형에서 각 요청의 경로를 계산하고 반경별 쓸린 시간 예약·불변 완전 경로·외부 FIFO 진입을 결합했다. 차선 태그나 미리 정한 경유점은 없다. 생성 전 대기도 ID별 응답에 포함한다. 일반7개는 무충돌 배출·240초 응답을 통과했지만 과부하480개 중61ID는 이를 초과했고 최대280.0초였다. 최신 우선은 다른538개 도착 중 요청0을310초 미생성 상태로 남겼다. 전체 처리량으로 특정 개체의 기아를 판단하면 안 된다.

FIFO 머리가 막히면 젊은 진입을 막고 기존 유한 경로가 빠진 뒤 정적 경로를 찾는 조건부 논증이다. 유한 실행이 무한 시간의 증명은 아니며 과부하에서는 일정한 지연 상한을 주지 않는다. 생성 통제·정적 지형·고정 반경·계획대로 이동·도착 후 제거가 필요하다. 기존 임의 개체·점유 입구 강제 생성·갑작스런 정지·동적 벽/반경·가속·분산 권한은 범위 밖이다.

병목 초당8요청 전체 프레임 p953.52–6.10ms, 탐색 다음 전체 프레임 p9520.23–20.52ms. 실제 활성/표시 인원·대기열·온라인 탐색/생성/소멸·프레임 초과·GPU 누락을 기록했다. 목표 수요와 고정 개체 수를 혼동하지 않는다. [PlayMode23검사/10기대](../../prototypes/TechniqueLab/Results/Stream/editor-final.json)·[분포](../../prototypes/TechniqueLab/Results/Stream/summary.json). 원저 [RHCR](https://arxiv.org/abs/2005.07371)·[PIBT](https://arxiv.org/abs/1901.11282)·[온라인 작업](https://arxiv.org/abs/1705.10868)은2026-11-08초록만 확인했으며 그 알고리즘/정리를 구현한 것은 아니다.
