# 롤백 네트워킹을 위한 상태 복원과 재시뮬레이션

`K-GAME-TECH-ROLLBACK` · 참고 지식 · 활성 · 확인일 2026-11-08

누락된 원격 입력을 예측하고 시뮬레이션 스냅샷을 저장한 뒤 실제 입력이 도착하면 비교한다. 롤백은 애니메이션의 앞부분을 건너뛰는 기법이 아니다. 엔진과 무관한 원리를 다루되 엔진 예시는 버전에 따라 달라진다. 외부 원문을 확인한 참고 조사이며 실제 엔진 구현이나 성능 검증을 뜻하지 않는다.

## 지침

입력 예측이 틀리면 이전 스냅샷으로 돌아가 중간 프레임을 모두 그리지 않고 다시 시뮬레이션한다. 입력 지연을 롤백과 함께 사용해 보정 범위를 제한할 수도 있다.

롤백이 관리하는 상태, 되돌릴 수 있는 표시, 되돌릴 수 없는 외부 효과를 구분한다. 시뮬레이션 상태는 복원하고, 예측 음향·파티클·UI는 중복을 막거나 취소한다. 예측 이벤트를 단 한 번만 내보내더라도 플랫폼 업적·재화·외부 보상을 확정하면 안 된다. 해당 이벤트와 자격 조건이 프로토콜의 신뢰 가능한 경계에서 확정된 뒤 지급한다. 피어 프로토콜에서는 최종 입력 합의나 검증된 상태, 권위 구조에서는 담당 권위의 확정이 그 경계가 된다. 시간 경과나 애니메이션 재생 완료는 확정 근거가 아니다. 해당 구조를 사용한다면 [권위와 예측](K-GAME-TECH-AUTHORITY.kr.md)을 참고한다.

확정된 효과에는 세션·경기, 이벤트 식별자와 수령자를 포함한 안정적인 멱등 키를 부여한다. 재실행·재시도에도 키를 유지하되 서로 다른 이벤트가 합쳐지면 안 된다. 확정은 잘못된 지급을 막고 멱등성은 중복을 막는다. 메모리의 처리 완료 집합만으로 장애 이후 전달을 보장할 수 없다. 외부 보상에는 영속적인 확정·재시도 계약과 수신 측의 중복 제거 또는 트랜잭션도 필요하다.

구현 선택과 점검은 공학적 종합이며 출처 게임의 실제 구현을 그대로 재현한다는 약속이 아니다.

## 적용 조건과 예외

복원 가능한 결정적 상태, 재시뮬레이션 CPU 예산과 최대 롤백 정책이 필요하다. 단순히 애니메이션 시작 부분을 생략하는 것과 다르다.

## 점검

실제 엔진·프로토콜에서는 잘못된 예측, 순서가 뒤바뀐 입력과 긴 지연을 강제로 만들고 최종 상태 해시를 확인한다. KO 예측이 방어로 보정되면 외부 지급은 0건이어야 한다. 미확정·신뢰하지 않는 이벤트도 0건, 확정된 적격 이벤트의 재실행·재시도는 1건이어야 한다. 같은 틱의 서로 다른 이벤트, 수령자와 경기는 구분한다. 신뢰성 있는 외부 전달을 주장하려면 실제 영속 전달·수신 계약으로 재시작과 응답 유실도 시험한다.

[통제된 이벤트 추적 검사](../../skills/vegabond-knowledge/tests/game-application/check_rollback_rewards.py)는 중복 제거만 하는 음성 대조군과 확정 조건·안정적인 키를 비교한다. 장난감 계약 모델이며 GGPO·Photon, 게임, 네트워크, 보상 서비스를 실행하지 않는다. 결정성·신뢰·영속성·성능을 검증하지 않는다.
