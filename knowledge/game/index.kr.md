# 게임 개발 지식

기획에서는 플레이어가 무엇을 보고 판단해야 하는지에서 시작해 근거와 플레이테스트 방법을 찾는다. 구현에서는 해결할 증상을 설명하는 기법을 찾는다. 개발자의 공개 자료는 해당 게임에서의 선택을 보여 준다. 다른 게임으로 옮길 때는 목표 기기와 플레이 조건에서 다시 확인한다. [근거 조회 지침](K-GAME-RESEARCH-USE.kr.md) · [게임 구현 기법 안내](K-GAME-TECH-GUIDE.kr.md)

[전체 지식 분야](../index.kr.md) · [저장 및 관리 절차](../../skills/vegabond-knowledge/references/storage.kr.md) · [영문 색인](index.md)

상황·제약 → 관련 지식 조회 → 채택·조건부·기각 → 변경·검사 → 관찰 결과 기록 순서로 활용한다. 모든 기술을 한꺼번에 적용하지 않는다. 엔진·버전·플랫폼·권한과 근거 한계를 확인한다. 실제 구현 근거는 각 항목의 실험 범위에 한하며 원작 구현·완성 게임 검증을 대신하지 않는다.
