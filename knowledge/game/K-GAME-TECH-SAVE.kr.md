# 저장·백업·비트 플래그·패스워드

기준 항목: K-GAME-TECH-SAVE · 확인일: 2026-11-07 · 참고 지식. 엔진 실행·성능·실제 플레이 검증은 별도다.

## 원리와 구현 요점

런타임 포인터 대신 영속 상태·안정적인 객체 ID·스키마 버전을 저장한다. 필요하면 독립 플래그를 비트로 압축한다. 패스워드는 작은 복원 상태를 제한된 문자 집합과 오류 검출 정보로 인코딩한다. 내구성 설계안: 새 저장본을 검증한 뒤 정상 슬롯을 교체하고 복구 세대를 남긴다.

### 추가 조사로 보완한 구현

에메랄드 공개 재구성 코드는 저장 카운터로 슬롯을 선택하고 정상 쓰기 상태를 보존하며 섹터를 기록한다. 읽을 때 데이터 유효성과 세대를 판정한다. 닌텐도 원본 코드나 이번 작업에서 시험한 저장 시스템은 아니다. 새 구현은 세대 ID·데이터 검증·확정 및 복구 순서를 설계하고 파일 두 개만으로 원자성을 가정하지 않는다. 악마성 II의 직접 역공학 FAQ는 상태 7바이트·가산 검사 2바이트·스크램블 1바이트를 16문자로 인코딩한다고 설명한다. 전체 정지 화면 대신 아이템·경험·일수 등 선택 상태를 복원한다.

## 적용 조건과 한계

체크섬은 일부 손상을 검출하지만 위변조 방지 인증은 아니다. 8비트는 독립된 예/아니오 플래그 8개를 저장한다. 두 슬롯만으로 파일시스템 원자성이 보장되지는 않는다.

## 적용 전 점검

적용 전 점검: 쓰기 단계별 중단·데이터 손상·구버전 저장본·객체 참조를 시험하고 대상 플랫폼에서 복구를 확인한다.

## 게임 상태 저장·복원과 손상 복구 — 언리얼 실제 검증

실험은 V20 게임 상태 저장에 한정된다. 비밀번호 방식 V54는 아직 구현하지 않았다.

UE5.8.3 Win64 Development/DX11, 기준일 2026-11-14(한국시간), 실행 기록은 UTC다. **AI 검증 완료, vagabond 테스트·리뷰 대기** 상태다. 보관된 측정 기록, 보관된 측정 기록을 함께 확인한다.

### 구현과 복구 정책

게임 스레드 하나가 체력·체크포인트·아이템 32개·스위치 8개를 캡처한다. 정렬된 고정 ID와 값으로 구성한 상태는 348바이트다. USaveGame의 SaveGame 속성 바이트 배열에 넣으면 패키지 직렬화 결과는 2,393바이트이고, 40바이트 검사 헤더를 포함한 파일은 2,433바이트다. 모든 성능 실행에서 같았다. 기본 방식은 A 파일 하나, 복구 방식은 같은 검사를 사용하는 A/B 파일 두 개를 유지하므로 총 디스크 사용량은 다르다.

매직·버전·스키마·정확한 길이·헤더 CRC32·페이로드 CRC32를 엔진 역직렬화 전에 검사하고, 이후 개수·ID·값을 검증한다. 유효한 최신 세대를 선택하고 최신 파일이 잘리거나 손상되면 이전 세대를 복구한다. 모두 없으면 Missing, 존재하는 파일이 모두 무효면 Invalid, 유효 세대가 같으면 Conflict다. 실패한 불러오기는 현재 상태를 보존하며 파일을 자동 수리하지 않는다.

저장은 무효 또는 오래된 슬롯을 선택하고 세대를 증가시켜 쓴 뒤 읽어 검증한다. 양쪽 무효·동일 세대 충돌·세대 번호 소진 시 기존 바이트를 보존하며 저장을 거부한다. 호출 성공이 보고되기 전에 완성된 유효 최신 파일도 다음 실행에서 선택될 수 있다. 성공 응답의 트랜잭션 보장은 아니다.

복원 전에 모든 안정 ID 연결을 검사한다. 실제 아이템 메시 가시성, 스위치 회전, 아바타 위치·체력 크기와 게임 필드를 확인했다. 재실행 시 개체를 역순으로 생성해 포인터·생성 순서에 의존하지 않음을 검사했다. Python은 실제 파일의 헤더·CRC와 내부 단일 바이트 배열의 상태, 실제 월드 개체를 독립 대조한다. UE 직렬화 전체를 독립 구현한 것은 아니다.

### 동작 검증

정책 89개와 실제 USaveGame·파일 저장 검사 23개가 통과했다. 기본·복구 각각 실제 PIE 12사례와 패키지 12사례, 총 48사례를 실행했다. 누락, A 왕복, 최신 B, 파일 잘림, 바이트 손상, 지원하지 않는 스키마, 양쪽 무효, 무효 후 저장 거부, 쓰기 대상이 디렉터리인 실패, CRC는 맞지만 잘못된 상태, 월드 ID 누락, 중복 저장 ID를 확인했다. 쓰기 대상 차단과 파일 잘림은 별도 검사이며 부분 쓰기 장애 주입으로 표현하지 않는다.

실제 별도 프로세스 6개에서 정상 B 복원, 기본 방식의 잘린 파일 거부, 복구 방식의 잘림·손상 시 A 복원, 양쪽 무효 시 변경된 현재 D 보존을 확인했다. 원본 생성 파일은 보존하고 소비자별 경로에 복사했다. 원본·복사 전후 해시, 서로 다른 PID, 실행 순서를 대조했다. 동일 세대와 최대 세대 거부도 실제 단위 검사 파일로 확인했다.

초기 실패 모델 34개 중 22개 실패를 보존했다. 독립 근거·변이 검사 7개와 전체 실험실 738개가 건너뜀 없이 통과했다. 기존 수면 222개, 핵심 PIE·패키지 각 73개 회귀 검사도 최종 버전에서 통과했다. 이전 소스 아카이브 30개와 애셋 62개를 보존했으며 새 애셋·의존성은 없다.

### 화면과 촬영 조건

실제 생성 프로세스 6초와 별도 재실행 프로세스 8초를 시간 순서로 연결한 14초 영상이다. A/B 저장 → 새 프로세스 D → B 복원 → 최신 파일 잘림 후 A 복구 → 양쪽 무효와 D 보존을 보여준다. 원본 420프레임, 시뮬레이션·재생 각 30으로 1배속이며 시작·끝 여백만 잘랐다. 모든 원본·디코딩 프레임 표식과 각각 16,800개 상태 셀을 독립 상태와 대조했고 대표 6장을 직접 확인했다. 실시간 저장 정지나 실제 30FPS 처리량을 증명하는 영상은 아니다.

### 적용 조건과 한계

이전의 유효 진행 상태로 돌아가는 것이 진행 전체 손실보다 나을 때 A/B 세대를 선택한다. 안정 ID와 전체 검증 뒤 적용을 유지하고, 양쪽 무효 시 명시적으로 실패시킨다. 실패를 기본값 저장 성공으로 숨기지 않는다. CRC는 우발 손상 검출이며 인증 수단이 아니다. 로컬에서 생성한 신뢰할 수 있는 UE 클래스·형식만 검사했다. 고정 스키마 1·아이템 32개·스위치 8개이며 마이그레이션·엔진 버전 간 호환성은 보장하지 않는다.

정상 종료 후 재실행과 통제된 잘림·손상만 검사했다. 강제 종료·정전·fsync·디스크 가득 참·장치 장애의 안전성은 미검증이다. 동기 정지는 남아 있다. 비밀번호 V54·비동기 최적화·자동 저장 도구·클라우드·렌더러·검증 도구로 확대하지 않았다. 이전 비동기 진단 로그 저장과 이번 게임 상태 복원은 목적이 다르다. 원래 59쇼츠·43기술 중 최신 25개 부분 구현, 18개 전용 구현 없음이다. 기존 실제 FPS 누락은 유지하며 커밋·푸시는 하지 않았다.

## V20 단계적 저장과 NTFS 공간 부족 대응

후보를 같은 디렉터리의 임시 파일에 쓰고, 플러시와 닫기 뒤 다시 읽어 검증한 후 비활성 슬롯에 게시한다. 재시작은 게시된 슬롯만 대상으로 한다. 단계별 프로세스 종료 후 두 슬롯과 복원된 월드를 비교한다. 이전 스키마는 현재 후보로 변환하고 새 필드의 기본값을 정한다. 전체 월드 바인딩을 확인한 후 적용하고, 실패하면 기존 상태를 보존한다. 프로세스 종료, 공간 부족, 물리 전원 차단의 검증 범위를 각각 판단한다.

분리된 볼륨에서 실제 쓰기 실패를 재현하고, 실패 직후 OS 오류 코드와 요청·완료 바이트를 기록한다. 공간 부족 중 재실행으로 이전 정상 세대가 복원되는지 확인하고, 공간을 확보한 뒤 같은 저장 경로로 재시도한다. 쓰기·플러시·교체 실패 시 게시된 슬롯과 현재 월드를 보존한다.

## V54 버전형 진행 코드

안정적인 식별자와 고정 필드 순서로 재현 가능한 상태를 표현한다. 문자 집합, 비트 순서, 예약 비트와 체크섬 적용 범위를 정한다. 길이·문자·예약 비트·체크섬·버전·범위를 검증하고, 월드 바인딩을 확인한 뒤 상태를 적용한다. 유효한 체크섬을 가진 미지원 버전과 범위 밖 값도 시험하고, 거부 시 현재 월드를 보존한다. 콘텐츠가 바뀌어도 기존 코드의 식별자 순서를 유지한다.
