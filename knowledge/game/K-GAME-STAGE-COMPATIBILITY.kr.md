# 콘텐츠와 진행 순서가 바뀌어도 스테이지 식별을 유지한다

## 지침

표시 순서, 이름, 에셋 경로와 독립적인 StageId를 사용한다. 정의는 편집할 콘텐츠와 참조를, 카탈로그는 조회와 배포를 맡는다. 진행 규칙은 이용 가능 여부와 해금을 결정한다. 실행기는 새 세션을 만들고 결과를 전달한다. 저장 계층은 완료·보상·기록을 안정적인 ID로 확정한다. 플레이 중 가변 상태는 공유 정의 밖에 둔다.

스테이지를 추가할 때 정의를 만들고 장르 규칙을 검사한 뒤 등록한다. 실제 목록 → 해금 → 진입 → 재시도 또는 퇴장 → 완료 경로를 실행하고 결과가 한 번만 확정되는지 확인한다. 순서나 이름이 바뀌어도 ID를 유지한다. 종료한 스테이지의 기록 표시, 대체, 이관 규칙을 정한다. 리플레이를 지원하면 스테이지와 콘텐츠 버전, 필요한 경우 생성기·씨드·입력열을 남긴다.

## 적용 범위와 예외

충돌이나 타이밍 변경으로 과거 기록이 무효가 될 수 있으면 저장 호환성과 기록·리플레이 호환성을 별도로 결정한다. 리플레이를 재생할 수 없어도 유효한 완료 기록은 남길 수 있다. 지원하는 출시 버전의 저장 표본으로 이관과 선택 팩 누락을 시험한다. 플랫폼별 저장은 [세이브 구현 지식](K-GAME-TECH-SAVE.kr.md)을 참고한다.

## 확인

기존 스테이지 순서를 바꾸고 완료 기록을 확인한 뒤, 이전 저장으로 실제 메뉴에서 새 스테이지에 진입해 끝낸다. 장르에 따라 막힌 퍼즐 이동, 건너뛴 레이싱 체크포인트, 잘못 배치한 전술 유닛을 입력한다. 재시도와 재진입, 이관 뒤 다시 불러오기를 확인한다. 배포 빌드에서 누락 에셋과 선택 팩, 종료한 ID의 처리 정책을 확인한다. [검증 범위](K-GAME-REGRESSION-SCOPE.kr.md)

## 근거

스테이지 프레임워크는 상태 소유권과 장르별 제작 단위 및 검증을 다룬다. 데이터 보고서는 버전이 있는 스테이지 데이터, 저장, 절차 생성, 콘텐츠 팩을 다룬다. 사례는 대상 프로젝트에서 확인할 제안이다.
