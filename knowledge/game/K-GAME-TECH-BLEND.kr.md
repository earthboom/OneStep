# 알파·가산·곱하기 블렌딩

기준 항목: K-GAME-TECH-BLEND · 확인일: 2026-11-07 · 상태: 참고 지식. 실제 엔진 구현·성능·플레이테스트는 수행하지 않았다.

## 원리와 구현 요점

일반 알파는 C=alpha*S+(1-alpha)*D, 가산은 밝기 누적, 곱하기는 색상 곱으로 이해한다. 선형 색 공간에서 계산하고 프리멀티플라이드 알파와 일반 알파를 구분한다. 마스크 재질은 연속 혼합 대신 픽셀을 버린다.

구현 선택과 점검은 출처를 바탕으로 한 실무적 종합이며 특정 게임의 정확한 구현을 보증하지 않는다.

## 적용 조건과 한계

블렌드 모드는 정렬·깊이 기록·조명 지원에 영향을 준다. 색을 더해도 모든 배경에서 가독성이 보장되지는 않는다.

## 적용 전 점검

적용 전 점검: 밝고 어두운 배경·중첩 파티클·스프라이트 경계를 보고 텍스처와 블렌드 식이 맞는지 확인한다.

## 근거

로컬 시험의 원시 측정과 매체는 해당 실험 기록에 보관돼 있다.

- [Epic — Material Blend Modes](https://dev.epicgames.com/documentation/en-us/unreal-engine/material-blend-modes-in-unreal-engine) — 확인 범위는 영문 정본의 Evidence에 기록. 추가 읽기로 표시된 자료는 본문 전체를 확인하지 않았다.
- 출발 영상: V45. [전체 대응표](K-GAME-TECH-GUIDE.kr.md).

## AlphaComposite의 적용과 확인

언리얼의 `AlphaComposite`에서는 원본 RGB에 알파 가중치가 이미 들어 있다. 알파를 다시 곱하면 반투명 경계가 어두워진다. Masked 모드의 `Opacity Mask Clip Value`는 픽셀을 버리는 임계값이다. 밝은 배경과 어두운 배경에서 반투명 경계를 비교하고 마스크 임계값은 따로 검사한다.

검색어 · AlphaComposite, premultiplied alpha, Opacity Mask Clip Value

[Epic, Material Blend Modes](https://dev.epicgames.com/documentation/unreal-engine/material-blend-modes-in-unreal-engine?lang=en-US)은 용어와 적용 조건의 근거다. 제안한 검사는 대상 환경에서 수행한다.

## 실제 언리얼 블렌딩 — 2026-11-12

과거 Unreal 실험 결과: 최종34정책, 실제PIE/패키지120방법·상황, 전경600/배경30표본, 네 방식 각3회비용과 정상영상이다. 최신16부분구현/27직접구현없음이다.

일반 알파는 aS+(1−a)D, 사전 곱셈은 P+(1−a)D다. P는 선형 공간에서 이미 곱한 RGB이고 전체 페이드 때 색과 알파를 함께 조정한다. 잘못 교환하면 이중 알파나 투명영역 RGB누출이 생긴다. 언리얼 가산은 셰이더에서 알파를 반영해 D+aS다. 원래 곱셈은 D×S로 Opacity만으로 페이드되지 않아, 여기서는 D×((1−a)+aS)로 흰색에 페이드하도록 명시했다.

숫자 선형 텍스처와 같은바이트 sRGB 원본을 구분하고 실제 픽셀 중심으로 원본/알파·양자화·쌍선형필터·sRGB 디코드·겹침순서를 독립 계산했다. 실제 HDR배경2.4가 약2.39844로 유지돼 톤매핑 전 선형값임을 확인했다. 최종 화면은 별도 톤매핑된 이미지다. 가까운 표본이 같은 픽셀에 걸릴 수 있어 서브픽셀 정확도를 주장하지 않는다.

에디터에서 읽던 기본평면 CPU 데이터가 패키지에서 제거돼 충돌한 실패를 보존했다. CPU보존 조건1/34실패를 재현하고 CPU읽기가 가능한 동일크기/UV의 런타임4정점 평면으로 수정해34통과했다. 준비 때1번만 만들며 렌더러최적화나새자산은 아니다. 재빌드 실행물로 최종동작/성능/영상을 다시 실행했다. 이어 기존노멀5자산이빠진기록을지문검사가거부해목록을고치고같은소스/바이너리/재질로전체측정을재기록했다. 이전기록도보존했다. 결과변형31개, 기존Normal33/실제PIE73/패키지73과21보관본/41이전자산을 보존했다. 새자산12개로 총53개다.

성능은1280×720·4영역각16겹·총64개·동일알파.25/카메라/배경/원본/패스에서 선택방식1개씩 준비2초+측정8초·각3회다. 비용에는캡처/읽기/배열검사/변환갱신이없다. 전체CPUwall/간격과지연된전체RHI GPU값을분리한다. 단독블렌딩패스나같은CPU프레임비용이아니며 동일보고값이반복될수있다.0은미제공,비유한/음수는실패다. 전체화면64겹·파티클·보편적성능으로확대하지않는다.

가산은 밝은배경/HDR표시가독성을 확인한다. 사전곱셈은 준비·필터·재질규약을 함께 맞춘다. 알파0곱셈을 항등으로 하려면 흰색으로 페이드한다. 여기의 명시적순서/가림은 임의교차투명체의 자동정렬 검증이 아니다. 밉/아틀라스·조명/안개/굴절·혼합방식간순서·Niagara·다른RHI는 별도다. 지식과검색162문항을연결했으며 렌더러/정렬/검증도구최적화나커밋/푸시는하지않았다.

검색 보완: 넓은 가장자리 키워드 때문에 일반 UI 배치 요청3개가 블렌딩으로 연결됐다. 모호한 메타데이터 단어를 제거하고 검은 알파 테두리의 기존 증상별 별칭은 유지해 같은162문항을 통과했다. 검색 프레임워크를 변경한 것은 아니다.
