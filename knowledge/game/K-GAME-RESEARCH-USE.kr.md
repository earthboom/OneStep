# 게임 개발 전 과정에서 조건에 맞는 근거 조회

기준 항목: K-GAME-RESEARCH-USE · 확인일: 2026-11-07. OneStep의 게임 개발 및 이 저장소 사용이 명시적으로 설정·허가된 다른 프로젝트에 적용한다. 현재 프로젝트의 의도와 공식 설계·코드 계약을 우선한다.

## 지침

게임 기획·아키텍처·구현·디버깅·최적화에 앞서 실제 결정, 기능 또는 관찰한 증상을 정의한다. 관련 프로젝트·리비전, 엔진·패키지 버전, 플랫폼·입력, 의도한 경험, 프레임·자원 예산, 네트워크·상태 권한을 기록한다. 결함은 재현 조건과 측정한 증상을 보존한다. 모르는 값은 공백으로 남기되 독립적으로 유용한 조사는 진행한다.

[게임 목록](index.kr.md)을 [지식 조회 절차](../../skills/vegabond-knowledge/references/retrieval.kr.md)로 검색하고 관련 코드 지식과 문제 기록도 확인한다. 처음에는 유용한 세부 항목 1~3개를 읽고 의존성·충돌·미해결 질문에 따라 확장한다. 검색이 빗나가면 증상·원리의 다른 표현과 [기술 안내서](K-GAME-TECH-GUIDE.kr.md)를 사용한다. 검색 순위는 적용 결정이 아니며 매번 전체 지식을 읽을 필요는 없다.

개념·복합 장르는 경험 프레임워크, 불확실한 경험은 프로토타입·플레이테스트, 자원 상호작용은 경제, 상호작용 장벽은 접근성·온보딩 항목을 활용한다. 장르 명칭보다 실제 설계 요소로 선택한다. 협동 로그라이크는 액션·협동 페이싱·반복 구조·자원 설계를 함께 검토할 수 있다.

후보의 지침·적용 조건·점검·근거를 읽는다. 엔진 버전, 데이터 소유권, 하드웨어, 게임플레이 조건을 비교한다. 과거 게임 사례는 현재 엔진 API의 보장이 아니다. 중요한 제안은 **채택·조건부·기각**과 이유를 명시한다. 요약이 중요한 세부를 뒷받침하지 못하면 원문 확인이나 추가 조사 후 의존 작업을 진행한다. 출처의 관찰·전이 가능한 종합안·로컬 미검증 가정을 구분한다.

기존 작업 브리프나 설계에 **문제·제약 → 항목 ID와 관련 절·출처 위치 → 결정·이유 → 변경 → 점검과 관찰 결과·공백**을 간단히 연결한다. 인용만으로 끝내지 않는다. 점프 입력 누락은 CONTROLLER의 입력 버퍼를 검토하면서 TIMESTEP의 시뮬레이션 계약을 보존한다. 숲 장면 비용은 지오메트리·픽셀·그림자를 측정한 뒤 FOLIAGE의 인스턴싱·LOD를 판단한다. 대표 장면의 작은 실험이나 회귀·성능 검사를 연결하고 예정 검사를 통과했다고 쓰지 않는다.

구현·조사 후 실제 결과, 기각한 유추, 실패 조건, 재사용 가능한 수정을 지식 절차로 반환한다. 근거가 개선되면 기존 항목을 갱신하고 프로젝트별 사건은 문제 기록에 둔다. 실제 입증한 로컬 결과만 교훈·검증된 예방책으로 남긴다. 재현·플랫폼·권한·의도가 바뀌면 관련 조회만 갱신한다.

큰 계획은 기존 계획 계층과 의존 시스템·완료 검사에 연결한다. 프로젝트 자체 설계와 플레이테스트가 우선한다. 유효한 정보는 유지하며 전체를 다시 읽지 않는다.

## 적용 조건과 예외

사용자가 요청한 게임 작업용 조회 규칙이다. 무관한 소프트웨어에 게임 기술을 강제하거나 다른 프로젝트의 변경을 허가하지 않는다. 확립된 로컬 패턴은 기존 조회가 여전히 유효한 이유를 밝히고 재사용할 수 있다. 복합 장르의 상충하는 조언은 의도한 경험과 실제 검사로 판단한다. ARPG 전리품·산업 경영·단일 4X 사례가 해당 상위 장르 전체를 대표하지 않는다.

이 지식은 출발점이며 완전하거나 영구히 최신인 백과사전이 아니다. 특정 스포츠·격투 형식·VR·MMO·플랫폼 정책 등은 필요할 때 추가 조사한다. 검색 일부·열지 못한 영상·미실행 제안은 반복 인용해도 검증된 방법이 되지 않는다.

입력 자료만으로 변경 내용과 보존할 필드가 완전히 결정되는 오탈자·서식 수정안은 그 로컬 입력을 근거로 사용한다. 게임에 속한 파일이라는 이유만으로 기술 검색을 시작하지 않는다. 실제 계약·의존성·불확실성이 요청한 행동을 바꿀 수 있을 때만 추가로 검색하고, 정확한 차이와 나머지 필드 보존을 확인한다.

## 점검

- 실제 결정·재현 증상, 엔진·버전, 하드웨어, 권한, 장르와 제작 조건에 맞는가?
- 기존 브리프에 근거가 영향을 준 행동·검사가 있는가?
- 채택·조건부·기각이 명시되고 원작 결과와 새 게임 가설·미실행 검사를 구분했는가?
- 프로젝트의 권위, 의도한 모호함, 접근성, 경쟁 공정성, 다른 시스템과 충돌하는가?
- 공백과 그에 의존하는 미해결 결정이 보이는가?

목록·스키마 검사는 저장과 발견 가능성을 확인한다. 게임성·밸런스·사용성·흥행을 검증하지 않는다.

## 근거

2026-11-07 사용자는 장르별 기획·쇼츠 기반 구현 지식 수집, 미확인 세부 보완, 향후 상황에 맞는 기술 조회·활용을 요청했다. 이는 범위가 정해진 조회 규칙의 근거이며 특정 게임 구현의 승인은 아니다.

공통 지식 절차가 조회·근거 한계를 관리한다. Scout·기획·코드·코드 설계 지침이 이 규칙으로 연결하며 실행과 검증은 호출한 작업이 담당한다. 개별 항목이 URL·위치·출처 유형·접근 한계를 보존한다. 초기 연구 뒤 Unity의 CAMERA/HITSCAN/PATH와 DynamicLab/TrafficLab의 제한된 PATH/CROWD 실험을 실행했다. 누적4개 항목 근거·39개 로컬 미검증이며 상용 게임/플레이어 연구는 아니다.

[동적 결과](../../prototypes/TechniqueLab/DYNAMIC-RESULTS.kr.md)와 [양방향/반경 결과](../../prototypes/TechniqueLab/TRAFFIC-RESULTS.kr.md)를 실제 선택 추적으로 연결한다. 후자는 PATH의 목표/반경 호환 장과 CROWD의 이웃 검사/진입 스케줄을 결합했다. 충돌 없는 교착 비교로 단순 양보만의 진전 해법을 기각하고 작성한 차선/대기 공간·고정 원판·한 권한 조건에서 임대를 조건부 채택했다. 실제 완주/전체 비용/GPU 누락/검색 누락을 기존 지식에 반영했다. 새 게임에서도 조건과 검사를 재확인하며 보편적 교착 방지를 복사하지 않는다.

## 무차선·지속 유입·개별 진전 확장 — 2026-11-08

[StreamLab 결과](../../prototypes/TechniqueLab/STREAM-RESULTS.kr.md)는 무방향 상하좌우 지형에서 각 요청의 경로를 계산하고 반경별 쓸린 시간 예약·불변 완전 경로·외부 FIFO 진입을 결합했다. 차선 태그나 미리 정한 경유점은 없다. 생성 전 대기도 ID별 응답에 포함한다. 일반7개는 무충돌 배출·240초 응답을 통과했지만 과부하480개 중61ID는 이를 초과했고 최대280.0초였다. 최신 우선은 다른538개 도착 중 요청0을310초 미생성 상태로 남겼다. 전체 처리량으로 특정 개체의 기아를 판단하면 안 된다.

FIFO 머리가 막히면 젊은 진입을 막고 기존 유한 경로가 빠진 뒤 정적 경로를 찾는 조건부 논증이다. 유한 실행이 무한 시간의 증명은 아니며 과부하에서는 일정한 지연 상한을 주지 않는다. 생성 통제·정적 지형·고정 반경·계획대로 이동·도착 후 제거가 필요하다. 기존 임의 개체·점유 입구 강제 생성·갑작스런 정지·동적 벽/반경·가속·분산 권한은 범위 밖이다.
