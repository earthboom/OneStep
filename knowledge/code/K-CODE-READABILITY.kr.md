# 구체적인 유지보수 질문으로 가독성을 검토한다

- ID: K-CODE-READABILITY
- 요약: 독자가 동작을 설명하고 예상 변경 위치를 안전하게 찾는지 판단합니다. 크기·이름·주석 지표는 검토 단서이며 보편 합격선이 아닙니다.
- 종류: 참고 지식 / 상태: 활성 / 근거 확인일: 2026-11-07
- 범위: 소스 코드 검토·유지보수. 실제 언어·팀 관례를 확인해야 합니다.
- 검색어: readability, maintainability, code review, comprehension, naming, comments, cognitive load, 가독성, 유지보수성, 이름짓기, 주석
- 확인 및 적용 맥락: 일차 지침과 연구 전문의 일부 구간을 확인했습니다. OneStep 구현·독자 실험 없이 제안 점검을 제공합니다.

## 지침

결과 설명·가정 식별·새 요구로 바뀔 결정 위치 찾기 같은 가능한 유지보수 과제로 코드를 판단합니다. 가독성은 독자의 성공적인 이해와 관련됩니다. 짧은 표현이 상태 변화를 숨길 수 있고 긴 설명이 필요한 조사를 줄일 수도 있습니다.

이름과 제어 흐름에 도메인 구별을 드러냅니다. 가까운 개념을 구별하고 혼동할 수 있는 단위를 표시하며 같은 범위에서 이름 의미를 유지합니다. 중요한 조건·계산에 의미를 부여할 때 중간 값을 도입합니다. 따라가도 유용한 개념·독립 책임이 추가되지 않는 간접 참조는 줄입니다.

제약의 출처·뜻밖의 상충·호환성 이유처럼 코드가 경제적으로 설명하기 어려운 정보에 주석을 씁니다. 변경 뒤에도 설명이 참인지 확인합니다. 연산을 반복하는 주석은 유지할 문장을 더하며 주석 수·이름 길이만으로 이해가 입증되지는 않습니다.

## 적용 조건과 예외

사람이 읽고 수정할 코드에 적용합니다. 독자에게 도메인 교육이 필요할 수 있으며 익숙하지 않은 알고리즘이 자동으로 나쁜 코드는 아닙니다. 생성 코드·수학 표기·성능 민감 루프·프레임워크 관례는 다른 표현을 정당화할 수 있습니다. 기계적으로 풀어 쓰기보다 생성 원본·설명·측정 제약을 확인합니다.

가독성 모형으로 보편 함수 길이·이름 길이·서식 기준을 만들지 않습니다. 결함 지표와의 상관관계가 지표 편집에 의한 결함 감소를 입증하지는 않습니다.

## 점검

다음은 제안이며 입증된 보호장치가 아닙니다.

- 정상 경로와 중요한 예외 경로를 따라 결과 값·부작용을 설명합니다.
- 가능한 변경 하나의 규칙 위치를 찾고 설명을 막은 숨은 가정·이름·불필요한 파일 이동을 기록합니다.
- 같은 질문으로 수정안을 비교하고 실제 모호함을 줄이면 추가 줄·주석을 허용합니다.

## 근거

- [Buse와 Weimer, Learning a Metric for Code Readability](https://web.eecs.umich.edu/~weimerw/p/weimer-tse2010-readability-preprint.pdf), 2010 저자 영문 사전 논문 2·5~7절. Java 조각 평가의 예측적 연관을 보이는 기술적 모형이며 참여자 한계가 있습니다. 일부 전문을 읽었으며 보편 지표·인과적 개입을 확립하지 않습니다.
