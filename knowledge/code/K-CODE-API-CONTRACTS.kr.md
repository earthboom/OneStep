# 의존성을 교체하기 전에 인터페이스의 의무와 보장을 명시한다

- ID: K-CODE-API-CONTRACTS
- 요약: 구현·제공자를 바꾸기 전에 허용 입력, 관찰 결과, 실패와 자원 수명을 비교합니다. 메서드 시그니처 일치만으로 대체 가능성이 입증되지는 않습니다.
- 종류: 참고 지식 / 상태: 활성 / 근거 확인일: 2026-11-07
- 범위: 내부·외부 소프트웨어 인터페이스. 실제 보장은 언어·라이브러리·배포 버전에 따릅니다.
- 검색어: API contract, precondition, postcondition, invariant, error semantics, resource lifetime, compatibility, 인터페이스, 계약, 사전조건, 사후조건, 수명
- 확인 및 적용 맥락: Python 3.14 io와 Rust std Vec 공식 문서를 확인했습니다. 계약 검토 제안이며 의존성 교체·실행 검사는 수행하지 않았습니다.

## 지침

인터페이스를 사용·교체하기 전에 호출자가 제공할 것과 의존할 보장을 적습니다. 유효 입력·상태, 결과 의미·단위, 상태 변화, 실패, 소유권·수명, 관련 순서·동시성 조건을 검토합니다. 미규정 동작은 명시하고 현재 구현의 습관을 약속으로 취급하지 않습니다.

호출 전 필요한 자원·범위 같은 사전조건과 성공 후 결과·상태인 사후조건을 구분합니다. 오류 계약은 부분 완료, 상태 변경, 정리 필요와 재시도 안전성을 포함해 실패 후 무엇이 유효한지 설명해야 합니다. 불변식은 명시한 관찰 경계에서 유지할 조건입니다.

사용자가 인터페이스를 만나는 곳에 호출자 의무와 제공자 보장을 기록합니다. 타입으로 표현할 구별과 검증·문서·예시로 보완할 구별을 나눕니다. 내부 구현을 복제하지 않고 최소한의 유용한 계약을 둡니다.

## 적용 조건과 예외

래퍼·라이브러리 갱신·모의 구현·대체 제공자·모듈 경계 리팩터링에 사용합니다. 같은 시그니처만으로 의미 호환은 판단되지 않습니다. 자동 메모리 관리에서도 파일·잠금·구독·비동기 작업의 유용한 수명은 객체 도달 가능성과 다릅니다.

모든 인터페이스에 모든 차원이 필요한 것은 아닙니다. 순수 계산에는 정리 의무가 없을 수 있습니다. 호출자가 정당하게 의존할 때만 시간·할당 조건을 계약에 둡니다. 아래 사례는 방법 설명이며 다른 언어에 Python·Rust 의미를 강제하지 않습니다.

## 점검

다음은 실제 환경에서 적용해야 할 제안입니다.

- 정상·경계 사례와 중요한 실패·수명 전이를 찾고 호출 의무와 관찰 보장을 따로 적습니다.
- 부분 완료·정리를 포함해 이전·새 제공자를 비교하고 이전 전에 모호한 보장을 해결합니다.
- 위험에 맞는 타입 검사·계약 테스트·직접 검토를 선택하고 버전·미확인 차원을 남깁니다.
