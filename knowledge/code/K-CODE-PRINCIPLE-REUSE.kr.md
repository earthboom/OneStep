## 활용 지침

- 이해·수정에는 필요한 [가독성](K-CODE-READABILITY.kr.md), [유지보수 근거](K-CODE-MAINTAINABILITY-EVIDENCE.kr.md), [동작을 보존하는 변경 점검](K-CODE-CHANGE-TESTS.kr.md)을 결합한다.
- 구조에서는 [정보 은닉](K-CODE-INFORMATION-HIDING.kr.md), [의존 방향](K-CODE-DEPENDENCY-DIRECTION.kr.md), [외부 의존 선택](K-CODE-DEPENDENCY-SELECTION.kr.md), [추상화 비용](K-CODE-ABSTRACTION-COST.kr.md)을 구별한다.
- 값·상태는 [설정 정책](K-CODE-CONFIGURATION-POLICY.kr.md), [불변식](K-CODE-DATA-INVARIANTS.kr.md), [API 계약](K-CODE-API-CONTRACTS.kr.md)을 참고한다.
- 수명·비용은 [자원 소유권](K-CODE-RESOURCE-OWNERSHIP.kr.md), [GC·정리](K-CODE-GC-LIFETIMES.kr.md), [동시·비동기 수명](K-CODE-CONCURRENCY-LIFETIMES.kr.md), [성능 근거](K-CODE-PERFORMANCE-MEASUREMENT.kr.md)를 구별한다.

적용할 행동, 출처·위치, 조건, 상충점, 제안 점검을 기존 브리프에 반영한다. 코드 예제·지침·실증 상관·현지 재현 결과는 각각 뒷받침하는 주장이 다르다. 중요한 세부 사항이 요약만으로 뒷받침되지 않으면 원문을 읽는다. 가설은 불확실하게 두며 반복된 조언을 입증된 방지 장치로 바꾸지 않는다.

## 적용 조건과 예외

한 언어의 의미나 한 저자의 스타일을 어디에나 강제하지 않는다. import 감소가 낮은 결합도를, 인터페이스 증가가 모듈화를, 모든 상수의 설정화가 유연성을 입증하지는 않는다. GC·스마트 포인터도 모든 정리·동시성 보장이 아니다.

원칙이 충돌하면 구체적인 계약·비용을 밝히고 실제 변경·수명 위험 아래 최소 대안을 비교한다. 작은 국소 작업에 새 추상화·설정 파일·실험·큰 검토 양식을 붙일 필요는 없다. 임시 시제품과 장기간 쓰는 공용 API는 필요한 정확성을 훼손하지 않는 범위에서 다른 선택을 할 수 있다.
