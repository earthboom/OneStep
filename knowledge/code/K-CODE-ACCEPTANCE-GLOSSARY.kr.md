# 용어의 뜻에 따라 인수 판정이 달라질 때 개발 용어집 활용하기

해석이 갈리는 용어를 골라 담당 원문에서 책임 주체, 테스트 범위와 반례를 확인한다. 이 프로젝트의 시험에서는 간혹 세부 기준이 누락됐으며 의무 조회의 시간 이점은 일관되지 않았다.

ID `K-CODE-ACCEPTANCE-GLOSSARY` · 방법 · 활성 · 근거 확인 2026-11-25

적용 범위 — 용어의 뜻에 따라 관찰 가능한 인수 테스트가 달라지는 개발 설계와 구현

## 지침

두 가지 그럴듯한 해석이 서로 다른 테스트로 이어질 때 용어를 등록한다. 뜻이 갈리면 해당 용어명 열을 선택한 뒤 동작을 소유한 원문에서 확인한다. 전체 행을 검색하면 설명에 같은 단어가 들어갔다는 이유만으로 다른 정의까지 선택될 수 있다. 표시 문구만 바뀌면 해당 바인딩과 표시를 확인한다. [OneStep development glossary](../../docs/development-glossary.md)

## 적용 범위와 예외

시간 제한은 누가 재는지, 무엇으로 시작·종료하는지, 통계량·기준값·비교 정밀도가 무엇인지 확인한다. 전달 상태는 목적지와 상태 전이를 허용하는 관찰을 정한다. 해석에 따라 결과가 갈리는 입력 하나로 둘 다 테스트할 수 있다. 같은 단어가 카드 제목에 들어가도 실제 판정식은 그대로일 수 있다.

## 확인 방법

구성한 응답 250개 예에서 인코딩 전 0.23초, 수신까지 1.76초, 디코딩 0.0104초의 합은 **2.0004초**다. 경계를 포함하면 정확히 2.0초는 통과한다. 회차별 P95 다섯 개가 모두 0.8초여도 개별 통과는 249/250이다. 피드백은 지정 수신함의 영문 파일만 비어 있지 않고 한글 파일은 비우면 검사기가 1을 반환한다. 한글 파일을 채운 뒤 같은 쌍을 재검사해 0을 받아야 준비에서 접수로 전환한다. 담당자 검토는 그 다음 판단이다. ## 근거

아래 AI 독자 실험은 명시된 같은 인수 기준 11개를 사용했다. 점수는 작성한 테스트 설계에 기준이 명시됐는지를 센 값이다. 구현 품질이나 재작업량을 측정하지 않았다.
