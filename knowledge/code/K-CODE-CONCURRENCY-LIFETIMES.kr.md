# 비동기 수명·동기화·종료를 별도 계약으로 검토한다

- 범위: C++ shared_ptr, Rust Send/Sync와 소멸자, Go 메모리 모델에 근거한 동시·비동기 API 검토.

- 적용 상태: 출처 종합과 제안 검토 절차입니다. 스케줄러·경쟁 탐지기·취소·종료 시나리오는 실행하지 않았습니다.

## 지침

유효한 데이터 접근, 충돌 접근의 조정, 미완료 작업이 있는 종료를 따로 검토합니다. 로컬 RAII 래퍼만으로 콜백·워커가 자원 사용을 멈췄다고 입증되지 않습니다. 작업 소유권과 정리 순서도 인터페이스의 일부입니다.

C++ 초안은 데이터 경쟁에서 shared_ptr의 관리 정보와 가리키는 상태를 구분합니다. 참조 횟수가 가변 필드를 보호하지는 않습니다. 같은 포인터 변수의 접근과 서로 다른 소유자 접근을 따로 검토합니다. 별칭 생성자의 공유 소유권은 무관한 저장 대상의 수명을 늘리지 않습니다. 역참조에는 유효한 대상이 필요합니다. 참조 횟수는 동기화 규약이 아닙니다.

Rust의 Send는 스레드 간 소유권 이전, Sync는 각 트레이트 계약에 따른 공유 참조 접근을 허용합니다. Rc는 이 동시성 보장을 제공하지 않으며 트레이트 수동 구현에는 unsafe 추론이 필요합니다. Reference는 의도적인 소멸 억제와 스택 풀기 없는 프로세스 종료도 허용합니다. 컴파일 시 안전성이 누수·교착 상태의 부재나 언젠가의 작업 완료까지 보장하지는 않습니다.

Go 메모리 모델은 동기화를 통한 공개와 가시성을 규정하며 고루틴 종료만으로 다른 사건보다 먼저 동기화되지 않는다고 명시합니다. 다른 참여자가 효과를 관찰해야 한다면 해당 채널·잠금·원자 연산 계약을 사용합니다.

## 적용 조건과 예외

특정 언어 계약을 비교한 것이며 서로 대체 가능한 보장이 아닙니다. 프레임워크의 취소는 협조 요청·결과 폐기·future 제거·작업 중단 중 무엇인지 실제 API로 확인합니다. 객체 생존은 스레드 친화성·엔진 유효성·모든 메서드 호출 권한을 입증하지 않습니다. unsafe와 외부 인터페이스는 일반 안전 참조 외의 의무를 추가합니다.

## 점검

다음은 제안하는 구현 점검입니다.

- 큐 등록·중단·콜백·재시도·소유자 소멸 사이의 캡처 참조와 소유자를 추적하고 정리를 허용하는 완료 사건을 식별합니다.
- 공개와 충돌 접근 순서를 그리고 채널·mutex·atomic·실행기 보장을 식별합니다. 잠금 순서와 대기는 별도로 검토합니다.
- 시작 전·실행 중·해제 중 취소를 실행해 완료 대기 여부, 정리 주체와 이후 콜백 가능성을 확인합니다.
- 경합 중 종료를 재현하고 가능한 경쟁 진단과 시간 제한 있는 완료 단언을 사용합니다. 통과한 실행은 일부 스케줄의 표본이며 모든 교차 실행의 증명이 아닙니다.
