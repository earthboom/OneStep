# 안정적인 동작 경계에서 변경을 검증한다

- ID: K-CODE-CHANGE-TESTS
- 요약: 내부 구조 변경을 허용하면서 실제로 가능한 동작 실패를 탐지할 검사를 고릅니다. 리팩터링은 보존 동작과 의미 있는 단언을 먼저 정합니다.
- 종류: 참고 지식 / 상태: 활성 / 근거 확인일: 2026-11-07
- 범위: 소프트웨어 변경·리팩터링. 관찰 계약·통합 위험·실행 비용에 따라 검사를 선택합니다.
- 검색어: behavior testing, regression, refactoring, test boundary, test pyramid, contract test, 회귀 테스트, 리팩터링, 동작 검증, 테스트 경계
- 확인 및 적용 맥락: Google 테스트 원문과 Fowler 지침을 확인했습니다. 검증 방법 제안이며 프로젝트 테스트·통제된 결함 주입은 수행하지 않았습니다.

## 지침

호출자가 관찰해야 할 결과·실패·부작용·자원 전이라는 구체적 의무에서 시작합니다. 무관한 내부 선택은 자유롭게 바꿀 수 있고 의무는 드러나는 경계를 고릅니다. 단위는 비공개 메서드 하나보다 협력하는 함수·클래스 묶음일 수 있습니다.

요구·계약·독립적으로 아는 예·불변식으로 기대 결과를 정하고 단언에서 운영 계산을 복제하지 않습니다. 시간·난수·외부 응답이 실패를 가리면 통제합니다. 대체물이 관련 호환성을 입증하지 못하면 실제 통합을 사용합니다.

동작 보존 리팩터링은 통과 기준선을 확보하고 계속 유효할 단언을 식별합니다. 검토 가능한 단계로 바꾸고 영향 검사를 반복합니다. 생성자·자료 준비 수정은 필요할 수 있지만 기대 결과 변경은 조사해야 합니다. 의도적 동작 변경은 새로운 기대와 보존 호환성을 구분합니다.

## 적용 조건과 예외

기능·중요 수정·의존성 변경·구조 변경에 적용합니다. 실제 위험·속도·신뢰성·유지비로 좁거나 넓은 검사를 고르며 보편적인 검사 개수·계층 비율을 정하지 않습니다.

금지된 외부 쓰기 회피처럼 내부 상호작용 자체가 의무면 검사할 수 있습니다. 성능·동시성·자원 안전은 출력 단언 외에 벤치마크·스트레스·정적 분석·직접 추론이 필요할 수 있습니다.

되돌릴 수 있는 문서 수정은 실행 테스트보다 링크·독해 검사가 적합할 수 있습니다. 충분한 기존 검사가 있으면 중복 테스트 없이 재실행합니다. 이 항목은 모든 변경의 테스트 우선 개발을 요구하거나 통과가 완전한 정확성을 입증한다고 주장하지 않습니다.

## 점검

다음은 로컬에서 실증하지 않은 제안입니다.

- 가능한 실패와 탐지할 단언·관찰을 연결하고 중요한 경계·실패를 검사합니다.
- 중요하고 현실적으로 가능하면 알려진 고장 사례가 실패함을 확인한 뒤 회귀 검사를 신뢰합니다.
- 구조 변경 뒤 실패가 동작·준비·불필요한 구현 결합 중 무엇인지 구분하고 실행 결과·공백을 남깁니다.

## 근거

2026-11-07 관련 영문 원문을 읽었습니다.

- [Andrew Trenk, Google Testing Blog](https://testing.googleblog.com/2013/08/testing-on-toilet-test-behavior-not.html), 2013-08-05 계산기 예·마무리. 공개 동작을 권장하되 의미 있는 내부 검사·준비 변경을 허용합니다.
- [Martin Fowler, Refactoring](https://refactoring.com/), 날짜 없는 도입. 동작 보존 단계로 구조를 바꾸는 저자 지침이며 실증 보장이 아닙니다.
- [Fowler, Test Pyramid](https://martinfowler.com/bliki/TestPyramid.html), 2012-05-01 본문·각주 2. 비용·취약성으로 집중 검사를 설명하며 저렴하고 신뢰할 넓은 검사의 예외도 다룹니다. 로컬 검사 모음은 평가하지 않았습니다.
