# 사람이 읽기 쉽고 AI가 근거와 시점을 조회할 수 있는 캐릭터 관계도

영문 원본: [K-FIC-CRAFT-RELATION-MAP.md](K-FIC-CRAFT-RELATION-MAP.md). ID: K-FIC-CRAFT-RELATION-MAP. 유형: 방법. 상태: 활성. 확인일: 2026-11-17.

사람에게는 짧은 관계도를, AI에는 인물 ID·관계 방향·장면 단계·근거 구절이 연결된 기록을 제공한다. 함께 등장함, 대화함, 믿음, 문서의 주장, 제안과 합의를 구분한다. 관계선이 없으면 불명/미기록이지 자동으로 무관계나 적대가 되는 것은 아니다.

적용 범위는 소설 설계와 원고에 근거한 관계 주석이다. 한국어 장면 하나를 실제로 도식화했지만, 한국어 추출 모델이나 독자 이해도 실험으로 검증한 방법은 아니다. 기존 [관계 설계](K-FIC-CRAFT-RELATIONSHIPS.kr.md)와 [개연성 검토](K-FIC-PLAUSIBILITY-REVIEW.kr.md)를 바탕으로 한다.

## 지침

### 선을 그리기 전에 관계의 뜻을 정한다

인물망 연구는 인물 식별, 상호작용 정의, 네트워크 분석을 구분한다(M01·M02). 대화선, 동시 등장, 신뢰는 서로 다른 질문에 답한다. 정보 전달도 함께 있었다는 사실만으로 설명되지 않으며, 내용·방향·접근 경로가 필요하다(M03).

먼저 이번에 파악할 질문을 정한다. 누가 누구를 필요로 하는가? 누가 무엇을 아는가? 어떤 행동으로 의무가 바뀌었는가? 무엇이 협력을 가능하게 했는가? 관계도 자체가 인물의 동기를 입증하지는 않는다.

### 도식과 구조화 기록을 연결한다

아래 절차는 논문에서 그대로 가져온 검증된 작법 모형이 아니라, 자료를 참고해 구성한 편집 방법이다.

1. **인물을 식별한다.** 이름이 없어도 고유 ID를 부여하고 표시 이름·별칭을 분리한다. 생략된 주어, 호칭, 친족어, 대사 속 일인칭과 대명사는 문맥에서 연결한다. 모든 ‘그’를 같은 남자의 별칭으로 만들거나 대사 속 모든 ‘나’를 화자로 연결하지 않는다. 공지시는 별도의 주석 문제이고(M04), 추출 오류는 관계망에도 영향을 준다(M05).
2. **종류와 방향을 기록한다.** 출발 ID, 대상 ID, 관계 종류, 짧은 설명, 단계, 주장 상태, 근거 ID를 보존한다. A가 B를 믿는 것과 B가 A를 믿는 것은 별개다. 소속·자원 의존·감정·발화·정보 접근도 구분한다. 수치를 쓴다면 측정 대상을 명시하며 대화 횟수를 신뢰나 사랑의 양으로 바꾸지 않는다.
3. **다자 사건을 별도로 둔다.** 세 사람의 협상이라면 합의 사건 하나에 각 참여자의 조건을 연결한다. 제안·거절·승인·실행은 분리한다. 다항 관계 패턴(M07)을 응용해 세 사람의 협력을 무조건적 우정 삼각형으로 오해하지 않도록 한다.
4. **출처와 시간을 남긴다.** 원고 버전·해시, 정확한 구절과 위치, 발화자·관찰자·문서를 연결한다. 이야기 안에서 성립한 시점과 독자가 알게 된 시점이 다르면 따로 기록한다. 이번 사례는 순차적인 장면 단계 네 개면 충분하다. 출처 구분은 PROV-O(M08)에서 발상을 가져왔지만 출처가 있다고 사실이 입증되는 것은 아니다.
5. **질문별 보기로 그린다.** 현재 질문에 필요한 인물과 관계만 배치하고 선에 구체적인 동사나 조건을 쓴다. 비교하는 시점 사이에는 인물의 위치와 이름을 일관되게 유지한다. 색만으로 의미를 구분하지 않는다. 배경 관계와 변화 순서는 별도 보기로 둔다. 선이 너무 얽히면 인접 행렬이나 장면·장별 필터를 고려한다. 가독성은 과업과 그래프에 따라 달라지므로(M06), 보편적인 인원수 경계는 없다.
6. **두 표현을 모두 확인한다.** 실제 크기의 그림을 직접 읽고, 데이터로 답한 질문을 원고와 대조한다. 방향·시점·주장 주체·불확실성을 확인한다. 보기 좋은 그림이 사실성을, 올바른 JSON 문법이 가독성을 보장하지 않는다.
7. **수정 후 동기화한다.** 원고에 근거한 기록과 구절을 다시 검토한 뒤 보기를 재생성한다. 도식만 따로 고쳤다면 AI가 사용하기 전에 대조한다. 해시 불일치는 재검토 신호이며 오프셋만 자동으로 옮기지 않는다.

### 최소 기록 항목

| 기록 | 필요한 내용 |
| --- | --- |
| 인물·조직 | 고유 ID, 종류, 표시 이름, 문맥이 한정된 지칭·별칭 |
| 관계 | ID, 출발·대상, 종류, 단계, 주장 상태, 근거; 믿음이라면 그 믿음의 주체 |
| 사건 | ID, 참여자·역할, 조건과 승인 연결, 제안/승인/실행 상태 |
| 정보 접근 | 인물, 명제, 단계, 앎/믿음/전해 들음/미열람/불명과 근거 |
| 근거 | 원고 경로·버전·해시, 구절, 오프셋 규칙 또는 행 번호, 발화자·문서·관찰자 |
| 보기 | 목적, 선택한 ID와 단계, 라벨, 그림 원문; 생략한 관계는 데이터에 유지 |

작은 작품이라면 원고와 JSON으로 시작할 수 있다. 그래프 데이터베이스나 별도 검색 프레임워크를 먼저 구축할 필요는 없다. 미기록을 무지로, 보고서의 혐의를 유죄로, 협력을 확정된 신뢰로 바꾸지 않는다. 작가가 계획한 미래 사실, 현재 원고의 사실, 인물의 지식, 독자가 아는 사실도 구분한다. 유용한 추론이라면 근거와 대안 해석을 남긴다.

### 집필에 활용하기

집필할 때에는 이 방법과 해당 작품의 현재 기록을 조회한다. 예를 들어 ‘P0에서 화자는 무엇을 알고 강 선장은 무엇에 동의했는가? 관계·근거 ID를 제시하라’고 질문한다. 답에 인용된 구절을 읽고 새 장면에 적용한다. 뒤 단계의 지식을 앞당기거나, 이 사례의 인물·장치·협상을 다른 작품에 그대로 가져가지 않는다.

## 적용 조건과 예외

이 방법은 사람과 AI가 가정과 근거를 검토하기 위한 것이다. LLM 이해도, 자동 추출 정확도, 한국어 독자의 이해나 재미가 개선됐다는 실험 결과는 없다. 인용한 NLP 연구는 주로 영어 자료와 각자의 과업을 다루므로 한국어 생략과 호칭은 별도 확인이 필요하다. 중심성 수치를 서사적 중요성·도덕성·시점으로 치환하지 않는다.

설계 초안에는 미결정 선택지나 충돌하는 대안이 있을 수 있다. 모두 동시에 정사로 다루지 말고 대안으로 표시한다. 신뢰할 수 없는 화자, 오해, 비밀, 역할 변화와 병렬 시간선은 주장 주체와 시간 범위가 필요하다. 큰 작품에는 여러 보기가 필요하며 이 소규모 배치가 보편적 틀은 아니다.

이번 사례는 수작업 주석이다. 자동 추출 시스템, RDF/OWL 온톨로지, PROV-O 구현이 아니며 정밀도·재현율 향상이나 독립 평가를 주장하지 않는다. 원고가 권위를 갖고 JSON은 편집용 파생 기록이다. Mermaid와 SVG도 선택한 일부를 보여 주는 보기다.

## 확인 사항

- 보이는 모든 선의 종류·방향·대상·근거를 설명할 수 있는가?
- 중요한 관계의 단계와 구절이 있고 원고 해시가 일치하는가?
- 제안·거절·승인·실행을 분리했는가? 조회 허락을 공개 동의로 바꾸지 않았는가?
- 추정·혐의·관찰을 색 없이도 구분할 수 있는가?
- 대사 속 일인칭과 대명사를 문맥에서 연결했는가? 이름 없는 인물도 ID로 찾을 수 있는가?
- AI가 나중의 정보를 가져오지 않고 현재 단계의 지식에 답하는가?
- 도식과 데이터가 일치하고 실제 화면에서 겹침·잘림 없이 읽히는가?
- 자동 추출을 도입한다면 인물·공지시, 관계 종류·방향, 단계·상태, 근거 충실도를 각각 원문과 평가하는가? JSON 파싱 성공은 정확도 평가가 아니다.
