# 소프트웨어 설계 리뷰

사람용 번역입니다. AI 기준 문서는 `code-design.md`입니다.

설계의 요구사항, 인터페이스, 소유권, 상태 전이, 실패 처리 메커니즘을 평가합니다. 기존 [설계 리뷰](../../vegabond-code-design/references/review.md)의 관련 부분을 사용하며 구현을 시작하지 않습니다.

- 주요 요구사항을 이를 강제하는 메커니즘, 가정, 관찰 가능한 완료 검사에 연결합니다. 보장의 선언과 실제 메커니즘을 구분합니다.
- 중요한 경계에 부분 완료, 결과 불명, 재시도, 취소, 소유권 변경, 혼합 버전 호출 등 구체적인 사건 순서를 대입합니다. 로컬 잠금이나 DB 유일 키가 외부 효과까지 제어하지는 않습니다.
- 선택이 중요하면 같은 제약으로 유효한 대안을 비교합니다. 비용, 복잡성, 운영 부담, 권고를 바꿀 조건을 설명합니다. 이미 결정된 작은 선택에 억지로 대안을 만들지 않습니다.
- 후속 작업 전에 필요한 전제와 구현 후 가능한 검사를 구분합니다. 향후 테스트 계획이 빠진 설계 전제를 해결하지는 않습니다.

영향받는 불변조건·결정, 반례·출처, 절충, 범위가 정해진 다음 단계를 보고합니다. 수정 제안에서 요구된 보장을 보존하고, 보장을 약화하는 대안은 명시합니다. 설계의 일관성은 동작 코드·측정된 처리량·운영 준비의 증거가 아닙니다.
