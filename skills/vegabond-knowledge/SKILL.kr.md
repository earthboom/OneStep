# Vegabond 지식

활성 작업의 지식과 문제 기록을 검색·관리합니다. scout의 프로필을 재사용하고, 호출한 작업 또는 전문 스킬이 적용 적합성을 판단하여 실제 결과물을 검증합니다. 문서 경계와 완료 기준은 [에이전트 지침](../../agents/vegabond-agent.md)을 따릅니다. 이 스킬은 정보를 제공하며 생성·수정·조사를 대신 맡지 않습니다. 읽기만으로 에이전트를 생성하지 않습니다.

## 요청과 반환

요청에는 작업 프로젝트, 질문, 관련 분야, 대상과 제약, 필요한 환경·버전 또는 이야기 맥락을 담습니다. 기존 요약을 재사용하고 같은 정보를 다시 묻지 않습니다. 저장 요청은 발견 사항, 근거, 해결, 재사용할 점검, 의도한 재사용 조건과 실제 검증 맥락을 추가합니다.

짧은 정보 요약을 반환합니다.

- 적용 지식: 이번 단계에 유용한 내용과 주요 주장별 출처 ID·경로·링크.
- 조건과 예외: 적용 범위, 과거 사건이 맞는 이유, 원인 확신도와 검증 맥락, 현재 요청·출처와 충돌하는 점.
- 점검: 작업에 반영할 구체적인 예방·수락 점검, 원래 기록 ID, 예방 상태와 근거. 사건 해결만으로 예방 검증이 성립하지 않습니다.
- 공백: 누락·낡음·충돌·미확인 정보와 그로 인해 남는 질문.

## 검색과 종합

1. 질문·범위·참조 항목 내용·기준 출처가 유효한 동안 기존 정보 요약을 재사용합니다. 그중 하나가 바뀌거나 새 근거가 공백을 드러내면 다시 검색합니다. 필요하면 작업 근거에 참조 ID와 리비전·해시를 남기되 프로젝트 사실의 전역 캐시는 만들지 않습니다.
2. 작업 프로젝트의 알려진 저장소부터 사용합니다. 이 저장소의 기본 위치는 [knowledge](../../knowledge/index.md)와 [records](../../records/index.md)입니다. 다른 프로젝트에서는 그곳의 경로를 해석하고 OneStep 사실을 자동 사용하지 않습니다. 적절한 기존 저장 체계를 재사용합니다. 공유 OneStep 자료는 명시적으로 설정되거나 요청된 경우에만 추가 출처로 사용하고, 무관한 프로젝트를 검색하지 않습니다.
3. 프로필에서 관련 분야 색인을 선택하고 복합 작업은 분야를 조합합니다. 한국어 질문을 유용한 영문 개념·동의어로 바꾸되 정확한 출처명과 기술 식별자를 유지합니다. 작은 안내 색인으로 위치를 정하고 질문·범위·맥락·상태에 맞는 카탈로그 행만 제한적으로 검색합니다. 최신성보다 적용 적합성을 우선합니다. 검색에 성공하면 카탈로그 전체를 열지 않습니다. 검색 전에 `*.kr.md`를 제외하고, `shared`는 관련 있는 분야 간 필요에만 사용합니다.
   작업 전에는 증상을 몰라도 예정 행동과 조건으로 `trigger`를 검색합니다. 실패 후에는 `symptom`과 정확한 식별자로 찾고 조건·원인 근거를 비교합니다. 해결된 사건도 후보에 남깁니다. 명확히 호환되지 않는 범위는 제외하고, 호환성 미확인은 유보 조건으로 유지합니다. 같은 증상이 같은 원인을 뜻하지 않습니다. 발생 조건 누락은 검색 공백이며 무관함의 증거가 아닙니다. 이는 도구를 사용하는 범위별 검색이지 자동 순위 서비스가 아닙니다.
4. 선택한 저장소 전체에서 관련 상세 파일 최대 세 개로 시작하여 헤더와 유용한 절부터 읽습니다. 적용 조건과 필요한 원래 근거를 확인합니다. 요약은 증명이 아닙니다. 출처 사실, 확인된 수정, 작가·프로젝트 선택, 편집 판단과 가설을 구분합니다. 열린 기록은 위험을 알려 주며 기존 형식 텍스트나 미기록 원인·예방 정보는 미검증입니다. 제안된 점검은 검증에 참고할 수 있지만 입증된 방지책으로 표현하지 않습니다. 무효화된 점검은 재조사 후 사용합니다. 폐기되거나 버전이 맞지 않는 항목이 조용히 작업 기준이 되지 않게 합니다. 카탈로그가 없거나 낡았음이 드러나면 선택 분야의 메타데이터를 제한적으로 검색하고 공백을 보고합니다. 재생성은 허용된 쓰기 범위에서만 합니다.
5. 중요한 불일치를 유지하며 출처를 정보 요약으로 종합합니다. 구체적인 의존성·충돌·관찰된 실패가 있을 때만 범위를 넓힙니다. 유용한 결과가 없으면 대체 검색어나 인접 범위를 한 번 시도하고 공백을 보고합니다. 지식을 지어내거나 검색 실패를 과거 사건 부재의 증거로 취급하지 않습니다. 새 조사 필요는 활성 작업의 조사 단계로 돌려보내며, 필수 조사에는 이 검색 기본 한도를 적용하지 않습니다.

요약할 때 권고의 범위와 유보 조건을 함께 유지합니다. 저장된 지식이 현재 사용자 의도, 설정, 규약이나 직접 근거를 덮어쓰지 않습니다. 적용과 검증의 책임은 호출자에게 있습니다.

주장에 필요한 등록 `SRC-...` 출처는 [이식 가능한 출처 절차](references/storage.md#portable-source-references)를 따릅니다. ID, 관련 위치, 동일성·접근 확인 결과와 남은 공백을 반환합니다. 카탈로그 링크만으로 원본이 검증되지는 않습니다. 허용된 출처 범위에서 필요한 ID만 해석하고, 조회 중 기기 설정이나 과거 근거를 바꾸지 않습니다.

## 지식 공백 해소

비어 있는 저장소나 불충분한 검색 결과는 정상적인 시작점입니다. 공백을 현재 결정에 필요한 최소 질문으로 바꾸고 조건·필수 근거를 붙입니다. 주제 전체를 미리 수집하지 않습니다. 질문을 활성 작업의 [조사 단계](../vegabond-research/SKILL.md)에 전달합니다. 기존 요약을 재사용하여 scout를 재시작하거나 같은 검색을 재귀적으로 반복하지 않습니다. 모델 기억은 검색어를 제안할 수 있지만 확인된 출처 근거가 아닙니다.

답을 정보 요약으로 가져오면서 출처가 뒷받침하는 주장, 실제 작업에서 확인한 방법, 추론·미해결 질문을 구분합니다. 출처 기반 참고 지식은 구현을 기다릴 필요가 없지만 출처 확인이 로컬 실행을 입증하지는 않습니다. 호출 전문 스킬이 적용 후 실제 결과를 점검하고 근거·예외를 돌려줍니다. 필요한 근거 공백은 공통 규칙에 따라 종속 작업을 차단합니다.

허용된 저장 전에 반복되는 결정, 비용이 큰 조사, 중요한 제약이나 유용한 점검처럼 다시 찾을 가치를 선별합니다. 사건 없이 성공한 방법도 포함합니다. 독립적으로 답할 질문 하나를 항목 하나로 두고 사용할 만큼만 개념을 설명합니다. 필요한 전제만 연결합니다. 새 용어를 전부 저장하거나 조사 보고서를 복제하지 말고 저장 가이드의 통합 규칙을 적용합니다. 후속 추적이 필요한 범위별 가설 기록 외에 근거 없는 후보는 작업 발견 사항에 남깁니다. 읽기 전용 작업에서는 갱신안을 반환합니다. 기존 필드·본문 절을 재사용하고 근거 절에서 출처 확인과 작업 확인을 구분합니다.

다음 관련 작업에서 질문과 조건으로 검색하고 적용 적합성을 확인한 뒤 구체적인 행동·점검에 반영합니다. 인용만 하지 않습니다. 재사용을 평가할 때 기존 작업 근거에 참조 ID, 유용했던 결정, 공백과 잘못 맞은 결과를 기록합니다. 반복 누락·부적합 검색·불필요한 본문 열람·반복 조사를 근거로 해당 요약·검색어·범위·안내를 개선합니다. 사용 장부를 추가하거나 매 작업 후 전체 저장소를 읽지 않습니다. 검색 효용은 이 피드백으로 평가하며 카탈로그 검증만으로 입증되지 않습니다.

## 저장과 유지관리

항목을 쓰거나 재구성할 때 [저장과 수명 관리](references/storage.md)를 읽습니다. 새 항목을 만들기 전에 [저장·통합 판단](references/storage.md#capture-consolidate-and-promote)으로 재사용할 가치, 기존 항목에 넣을 내용, 원본·작업 이력에 남길 내용을 결정합니다. 이 문서가 헤더·본문과 [카탈로그 도구](scripts/catalog.py) 절차를 정의하며 형식·근거·중복·승격·퇴역의 단일 기준입니다. 일상 조회에 전체 재생성·검사를 수행하지 않습니다.

작업이 허용한 범위에서만 씁니다. 읽기 전용·발견 사항만 요청된 작업은 저장소를 바꾸지 않고 제안을 반환합니다. 저장이 허용되면 상세 문서와 사용자 번역본을 갱신하고, 영향받는 카탈로그를 생성하며, 바뀐 영문 카탈로그의 번역본을 재작성하고 검사합니다. 새 분야는 루트 안내도 갱신합니다. 생성 행을 직접 편집하거나 기존 자료의 누락 메타데이터를 추정하지 않습니다. 조회만을 위해 빈 저장소를 만들거나 시작용 지식을 지어내지 않습니다.
