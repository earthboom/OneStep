# Vegabond Knowledge

사람용 번역본입니다. AI는 읽거나 검색하지 않습니다. 영문 SKILL.md가 실행 기준입니다.

현재 작업의 지식·문제 기록을 검색하고 관리합니다. scout의 프로필을 재사용하며 호출한 작업·전문 스킬이 적용 가능성을 판단하고 실제 결과물을 검증합니다. 문서 경계·완료 기준은 [에이전트 지침](../../agents/vegabond-agent.md)을 따릅니다. 정보를 제공하며 생성·수정·조사를 대신하지 않습니다. 읽는 것만으로 에이전트를 생성하지 않습니다.

## 요청과 응답

요청은 **작업 프로젝트, 질문, 관련 분야, 대상·제약, 필요한 환경·버전이나 이야기 맥락**을 담습니다. 기존 요약의 내용을 다시 묻지 않습니다. 저장 요청은 발견·근거·해결·재사용 점검 제안도 제공합니다.

다음을 짧게 반환합니다.

- **적용 지식:** 유용한 내용과 중요한 주장별 출처 ID·경로·링크.
- **조건·예외:** 적용 범위, 사례가 맞는 이유, 원인 확신·검증 맥락, 요청·출처와의 충돌.
- **점검:** 구체적인 예방·수용 점검, 원래 기록 ID, 예방 상태·근거. 사건 해결은 예방 검증을 뜻하지 않습니다.
- **공백:** 누락·노후화·충돌·미확인 정보와 남은 질문.

## 검색과 취합

1. 질문·범위·참조 내용·기준 출처가 유효하면 요약을 재사용합니다. 변경되거나 새 근거가 공백을 드러내면 다시 찾습니다. 필요하면 ID·수정본·해시를 작업 근거에 남기되 전역 사실 캐시는 만들지 않습니다.
2. 작업 프로젝트의 기존 저장소부터 사용합니다. 이 저장소는 [knowledge](../../knowledge/index.md)와 [records](../../records/index.md)를 사용합니다. 다른 프로젝트는 해당 경로를 찾으며 OneStep 사실을 자동 사용하지 않습니다. 적절한 기존 시스템은 재사용합니다. 공유 자료는 명시적으로 설정·요청된 경우에만 추가 출처로 사용하며 무관한 프로젝트는 검색하지 않습니다.
3. 프로필에 맞는 분야 색인을 선택하고 복합 작업은 결합합니다. 한국어 질문은 영문 개념·동의어로 바꾸되 정확한 출처명·식별자를 유지합니다. 작은 경로 색인에서 위치를 정한 뒤 질문·범위·맥락·상태로 제한된 행을 검색합니다. 최신성보다 적용 가능성을 우선합니다. 성공한 검색 수준을 유지하고 전체 색인을 열지 않습니다. 검색 전 `*.kr.md`를 제외하며 shared는 실제 공통 정보가 필요할 때만 봅니다.

   작업 전에는 증상을 몰라도 계획한 작업·조건을 trigger와 비교합니다. 실패 후에는 symptom·정확한 식별자로 찾은 뒤 조건·원인 근거를 비교합니다. 해결 사건도 후보입니다. 명확한 비호환은 제외하지만 호환 여부가 미확인이면 주의 사항으로 남깁니다. 같은 증상이 같은 원인은 아닙니다. 조건 누락은 검색 공백이지 무관함의 증거가 아닙니다. 사용 가능한 도구로 수행하는 범위 제한 검색이며 자동 순위 서비스가 아닙니다.

4. 우선 관련 상세 최대 세 개의 헤더·필요 구획을 읽습니다. 적용 조건을 확인하고 원본 근거를 따라갑니다. 요약은 증명이 아닙니다. 사실·확인된 수정·저자나 프로젝트의 선택·편집 판단·가설을 구분합니다. 열린 기록은 위험이며 과거 색인 문구·미기록 원인·예방은 미확인입니다. 제안 점검을 입증된 예방으로 소개하지 않고 무효화된 점검은 재조사 후 의존합니다. 폐기·호환 불가 항목을 현재 기준으로 삼지 않습니다. 색인이 없거나 낡았다는 근거가 있으면 해당 분야 메타데이터를 제한적으로 찾아 공백을 보고하고 허용 범위에서만 재생성합니다.
5. 중요한 차이를 보존하며 취합합니다. 실제 의존성·충돌·실패가 있을 때만 확장합니다. 결과가 없으면 대체 검색어나 가까운 범위를 한 번 시도하고 공백을 보고합니다. 지식을 꾸미거나 검색 실패를 과거 사건 부재로 단정하지 않습니다. 새 조사 필요는 현재 작업의 조사 단계에 전달하며 필수 조사는 초기 검색 제한에 묶이지 않습니다.

요약에도 조건·주의 사항을 유지합니다. 저장 지식은 사용자 의도·설정·계약·직접 근거보다 우선하지 않습니다. 적용·검증 책임은 호출한 작업에 있습니다.

## 저장과 유지 관리

작성·재구성 시 [저장과 수명주기](references/storage.md)를 읽습니다. 형식·근거·중복·승격·폐기와 [색인 도구](scripts/catalog.py)의 build/check 절차에 대한 단일 기준입니다. 일반 검색마다 전체 재생성·검사를 실행하지 않습니다.

허용 범위에서만 씁니다. 읽기 전용·발견 보고에서는 저장소를 바꾸지 않고 제안합니다. 저장이 허용되면 상세·번역을 갱신하고 영향 색인을 생성한 뒤 변경 영문 색인의 번역을 생성하고 검사합니다. 새 분야는 루트 경로도 갱신합니다. 생성 행을 직접 고치거나 과거 메타데이터를 추정하지 않습니다. 검색만을 위해 빈 저장소를 만들거나 초기 지식을 꾸며 넣지 않습니다.
