# Vegabond 지식

현재 작업에 필요한 지식과 문제 기록을 조회·관리한다. 정찰의 작업 프로필을 재사용하고, 호출한 작업 절차나 전문가는 적용 여부와 실제 결과물을 검증한다. 문서 경계와 완료 기준은 [에이전트 지침](../../agents/vegabond-agent.md)을 따른다. 이 스킬은 정보를 제공하며 창작·수정·조사를 대신하지 않는다. 읽었다고 에이전트를 생성하지 않는다.

## 요청과 반환

요청에는 **작업 프로젝트, 질문, 관련 분야, 대상과 제약, 필요한 환경·버전 또는 작품 맥락**을 담는다. 이미 작업 요약에 있는 내용을 다시 묻지 않는다. 저장 요청은 발견 사항, 근거, 해결, 재사용 점검안, 재사용 조건과 실제 검증 범위를 추가한다.

공통 [정보 필요성 판단](../vegabond-scout/references/information-needs.md)에 따라 질문과 그 답변이 뒷받침할 결정을 연결하고 조회에서 드러난 전제 공백을 밝힌다. 후보 근거와 한계를 반환하며, 소비 전문가는 중요한 채택·조건부 사용·기각·보류를 남기고 실제 행동을 검증한다. 검색 coverage는 완전성 판단이 아니다.

짧은 정보 요약에 다음을 담는다.

- **적용 가능한 지식:** 이번 단계에 유용한 내용과 중요 주장별 출처 ID·경로·링크.
- **조건과 예외:** 적용 범위, 과거 사건이 맞는 이유, 원인 확신도·검증 맥락, 현재 요청·출처와의 충돌.
- **점검:** 실제 작업으로 가져갈 예방·수락 검사와 원래 기록 ID·예방 상태·근거. 사건 해결만으로 예방이 검증되지는 않는다.
- **공백:** 누락·노후·충돌·미확인 정보와 남는 질문.

## 찾고 취합하기

1. 질문·범위·조회 항목 내용·지배 출처가 유효하면 기존 요약을 재사용한다. 변경되거나 새 근거가 공백을 드러내면 다시 조회한다. 필요하면 사용 ID와 판본·해시를 작업 근거에 남기되 프로젝트 사실의 전역 캐시를 만들지 않는다.
2. 작업 프로젝트의 알려진 저장소를 우선한다. 이 저장소의 기본 경로는 [knowledge](../../knowledge/index.md)와 [records](../../records/index.md)다. 다른 프로젝트에서는 그곳의 경로를 해석하고 OneStep의 프로젝트 사실을 자동 적용하지 않는다. 적합한 기존 체계를 재사용한다. 공용 OneStep 자료는 명시 설정·요청 시 추가 출처로 사용하며 무관한 프로젝트를 찾지 않는다.
3. 프로필에서 분야를 고르고 혼합 작업은 결합한다. [조회·취합 절차](references/retrieval.md)로 양쪽 저장소를 질문·식별자·범위·맥락·상태에 따라 찾고 간결한 일치 이유와 본문 위치를 받는다. 관리하는 한영 별칭을 확장하고 `*.kr.md`는 제외한다. 엄격한 읽기 전용 작업은 `--no-cache`를 쓴다. 도구가 없거나 기존 체계가 더 적합하면 동등 조건의 한정된 정본 검색을 사용하고 기능 공백을 알린다. 최신성보다 적용성을 우선하며 `shared`는 관련된 공통 필요에만 조회한다.
   작업 전에는 증상이 없어도 예정 행동·조건을 `trigger`와 대조한다. 실패 후에는 `symptom`과 정확한 식별자를 찾고 발생 조건·원인 근거를 비교한다. 해결된 사건도 후보에 둔다. 명백한 범위 불일치는 제외하되 호환성 미상은 주의사항으로 남긴다. 같은 증상은 같은 원인의 증명이 아니다. trigger 부재는 조회 공백이지 무관함의 증거가 아니다. 어휘 순위는 적용성·근거 품질을 보장하지 않는다.
4. 선택한 저장소를 합쳐 관련 상세 최대 3개부터 헤더와 유용한 절을 읽는다. 적용성을 확인하고 필요한 원본 근거를 따른다. 요약은 증거가 아니다. 출처 사실·확정 수정·작가 및 프로젝트 선택·편집 판단·가설을 분리한다. 열린 기록은 위험이며 레거시와 미기록 원인·예방은 미검증이다. 제안 점검을 입증된 예방으로 표현하지 않고 무효화된 점검은 재조사한다. 대체되었거나 버전이 맞지 않는 항목이 조용히 작업을 지배하게 하지 않는다. 카탈로그가 없거나 낡으면 선택 분야의 메타데이터를 한정 조회하고 공백을 알리며 허용된 쓰기 범위에서만 재생성한다.
5. 중요 답변을 ID·원본 근거·조건·검사에 연결한다. 관련 유입·유출 관계와 본문 링크를 따르고 이견을 유지한다. 잘린 충돌·대체 후보를 확인한 뒤 의존 결론을 내린다. 넓은 요청은 질문별로 답변됨·조건부·충돌·공백을 표시한다. 미답·의존성·충돌·실패 때문에 필요한 만큼 확장하며 최초 3개는 완료 한도가 아니다. 유용한 결과가 없으면 대체 표현이나 가까운 범위를 한 번 시도하고 공백을 보고한다. 검색 실패로 부재를 단정하지 않으며 새 조사 필요는 진행 중 작업의 조사 단계로 돌린다.

요약할 때 권고 범위와 주의사항을 유지한다. 저장 지식은 현재 사용자 의도·정본·계약·직접 근거를 덮어쓰지 못한다. 적용과 검증은 호출자의 책임이다.

주장에 필요한 등록 `SRC-...` 출처는 [이동 가능한 출처 절차](references/storage.md#portable-source-references)를 따른다. 요청 ID 각각, 관련 위치, 분리한 접근·동일성 상태와 공백을 반환하고 요청·결과 ID를 대조한다. 명시 검증 전 검색은 원본을 미검증으로 표시한다. 허용된 출처 범위의 필요한 ID만 확인하고 기계 설정·과거 근거를 조회 중 변경하지 않는다.

## 지식 공백 메우기

빈 저장소나 부족한 일치는 정상적인 시작 상태다. 현재 결정에 필요한 최소 질문과 조건·근거로 공백을 바꾼다. 주제 전체를 미리 모으지 않는다. 기존 요약을 재사용하여 진행 중 작업의 [조사 단계](../vegabond-research/SKILL.md)로 전달하고 정찰·동일 조회를 재귀적으로 반복하지 않는다. 모델 기억은 검색어를 제안할 수 있지만 확인된 근거가 아니다.

답변을 요약으로 가져올 때 **출처가 뒷받침한 주장**, **실제 작업에서 확인한 방법**, **추론·미해결 질문**을 구분한다. 출처 기반 지식은 구현을 기다릴 필요가 없지만 출처 검사는 현지 실행 증명이 아니다. 전문가가 적용하고 실제 결과를 점검한 근거·예외를 이 스킬에 돌려준다. 필수 근거 공백은 공통 규칙에 따라 종속 작업을 막는다.

허용된 저장 전에 재조회 가치가 있는 반복 결정, 비용 큰 조사, 의미 있는 제약·점검을 고른다. 사건 없는 성공 방법도 포함한다. 항목당 독립적으로 답할 질문 하나를 우선하고 사용할 만큼만 설명하며 필요한 선행 지식만 연결한다. 새 용어마다 항목을 만들거나 조사 보고서를 복제하지 말고 저장 지침의 통합 규칙을 따른다. 미지원 후보는 추적할 가설 기록이 필요하지 않으면 작업 결과에 남긴다. 읽기 전용 작업은 갱신안을 반환한다. 기존 필드와 절을 재사용하고 Evidence에서 출처 검사와 작업 검사를 나눈다.

다음 관련 작업에서는 질문·조건으로 조회하고 적용성을 확인한 뒤 구체 행동·검사로 가져간다. 조회 ID·해시, 판단, 공백·오검색을 기존 작업 근거에 남긴다. 확인된 누락·오검색으로 요약·별칭·범위·경로를 개선하고 [검색 평가 사례](tests/retrieval_cases.json)를 확장한다. 전역 사용 장부나 매 작업 전체 저장소 재독은 만들지 않는다. 카탈로그 유효성은 검색 유용성의 증명이 아니다.

## 저장과 유지

항목 작성·재정리는 [저장·수명주기](references/storage.md)를 읽는다. 새 항목 전에 [기록·통합·승격 판단](references/storage.md#capture-consolidate-and-promote)으로 새로 저장할 것, 기존 항목에 합칠 것, 원자료·작업 이력에 둘 것을 결정한다. 형식·근거·중복·승격·폐기와 [카탈로그 도구](scripts/catalog.py)의 build/check는 이 문서에서 관리한다. 일반 조회 때 전체 재생성·검사를 실행하지 않는다.

허용된 범위에서만 쓴다. 읽기 전용·결과 보고 작업은 저장소를 바꾸지 않고 제안한다. 저장이 허용되면 상세와 번역을 수정하고 영향받는 카탈로그를 생성한 뒤 변경 영어 카탈로그의 번역을 다시 만들고 검사한다. 새 분야는 루트 안내를 갱신한다. 생성 행을 직접 수정하거나 레거시 공백을 추정하지 않는다. 조회만 하려고 빈 저장소나 가짜 시작 지식을 만들지 않는다.
