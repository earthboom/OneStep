# Vegabond Knowledge

현재 작업에 필요한 지식과 문제 기록을 찾고 관리한다. Scout의 작업 개요를 재사용하고, 이 스킬을 호출한 작업 스킬이나 전문 스킬이 적용 가능성을 판단하고 실제 결과물을 검증한다. 문서 경계와 완료 기준은 [에이전트 지침](../../agents/vegabond-agent.kr.md)을 따른다. 이 스킬은 정보 제공을 맡는다. 제작, 수정, 조사 실행과 에이전트 생성은 각 작업의 절차를 따른다.

## 요청과 반환

요청에 **작업 프로젝트, 질문, 관련 분야, 대상과 제약, 필요한 경우 환경·버전이나 이야기 문맥**을 담는다. 기존 작업 요약에 이미 있는 정보를 활용한다. 저장 요청에는 발견 사항, 증거, 해결 내용, 재사용할 검사, 재사용 조건, 실제 검증 문맥을 추가한다.

[필요 정보 판단](../vegabond-scout/references/information-needs.kr.md)에 따라 각 질문을 뒷받침할 결정과 연결하고 검색에서 발견한 누락 전제를 드러낸다. 근거 후보와 한계를 반환한다. 사용하는 전문 스킬은 중요한 근거의 채택, 조건부 적용, 기각 또는 연기 결정을 기록하고 실제 조치를 검증한다. 검색의 적중 범위와 질문에 대한 답의 충분성은 각각 확인한다.

짧은 정보 요약에 다음을 담는다.

- **적용 가능한 지식** — 이 단계에서 도움이 되는 정보와 주요 주장별 출처 ID 및 경로 또는 링크.
- **조건과 예외** — 적용 범위, 이전 사건이 관련되는 이유, 원인 확신도와 검증 맥락, 현재 요청이나 출처와 충돌하는 지점.
- **검사** — 실제 작업에서 쓸 예방·수용 검사, 관련 기록 ID, 예방 상태와 증거. 해결된 사건의 예방 상태는 별도로 검증한다.
- **공백** — 누락됐거나 오래됐거나 충돌하거나 미확정인 정보와 남은 질문.

## 찾고 종합하기

1. 질문, 범위, 참조한 항목의 내용과 적용 근거가 유효한 동안은 기존 정보 요약을 재사용한다. 이 중 하나가 바뀌거나 새 증거에서 공백이 드러나면 다시 검색한다. 필요하면 작업 근거에 확인한 ID와 리비전 또는 해시를 남긴다. 프로젝트 사실은 작업에서 관리한다.
2. 작업 프로젝트의 자료부터 확인한다. 문서 경로나 카탈로그가 따로 주어지지 않아도 [프로젝트 원문 탐색](references/project-sources.kr.md) 절차로 명세, 설계 결정, 정본 설정 등 적용 근거가 되는 원문을 찾아 관련 작업 전에 읽는다. 프로젝트가 자체 저장소를 운영하면 원문과 함께 알맞게 사용한다. 스킬을 다른 체크아웃에서 읽어도 기본 경로 `knowledge/index.md`와 `records/index.md`는 작업 프로젝트 루트에서 찾는다. 공유 OneStep 자료는 명시적으로 설정되거나 요청된 범위에서 추가 출처로 사용한다. 관련 프로젝트로 탐색 범위를 한정한다.
3. 작업 개요에서 관련 분야를 고르고 복합 작업은 분야를 조합한다. [검색 도우미와 종합 절차](references/retrieval.kr.md)를 사용해 질문, 식별자, 범위·문맥, 상태로 두 저장소를 검색한다. 결과에 간단한 일치 근거와 위치가 나온다. 관리 중인 한·영 동의어를 확장하며 검색 대상에서 `*.kr.md`를 제외한다. 읽기 전용 검색에는 `--no-cache`를 사용한다. 도우미를 쓸 수 없거나 프로젝트 자체 저장소가 더 적합하면 범위를 좁혀 정본 카탈로그와 본문을 같은 조건으로 검색하고 도구상 공백을 알린다. 적용 가능성을 최신성보다 우선하며 관련 있는 분야 공통 질문에 `shared`를 사용한다.

   착수 전에는 알려진 증상이 없어도 계획한 조치와 조건에 해당하는 `trigger`로 검색한다. 실패 후에는 `symptom`과 정확한 식별자로 검색하고 조건과 원인 증거를 비교한다. 해결된 사건도 후보에 포함한다. 맞지 않는 범위는 제외하고 호환성을 판단할 수 없는 항목에는 단서를 단다. 증상이 일치하면 원인도 같은지 검증한다. 트리거가 없는 경우에는 검색에 공백이 있음을 드러낸다. 단어 일치 순위와 적용 가능성 및 증거 품질은 별도로 판단한다.

4. 후보를 사용하기 전에 실제 질문에 답하는지 확인한다. 명령 성공, 검색 결과나 `retrieval_ok`는 실행 상태를 뜻한다. 여러 부분으로 구성된 자연어 요청에는 [질문을 검색식으로 바꾸는 절차](references/retrieval.kr.md#recover-a-natural-language-lookup)를 사용한다. 원래 질문을 유지하고 주요 결정별로 검색한다. 항목이 누락되면 집중 검색어나 관련 안내를 이용한다. 먼저 두 저장소에서 관련 상세 파일을 세 개 정도 골라 헤더와 필요한 절을 읽는다. 적용 가능성을 확인하고 필요한 경우 원래 증거까지 따라간다. 출처의 사실, 확정된 수정, 저자·프로젝트 선택, 편집 판단, 가설을 각각 구분한다. 미해결 기록을 위험 검토에 사용하고, 이전 목록 문구와 기록이 없는 원인·예방 항목은 미검증 상태로 다룬다. 제안된 검사와 입증된 방어책을 구분하고, 무효화된 검사는 다시 조사한 뒤 의존한다. 폐기되었거나 환경이 맞지 않는 항목은 현재 기준에서 제외한다. 목록이 없거나 오래됐음이 드러나면 해당 분야의 메타데이터를 좁혀 찾고 공백을 알린다. 재생성에는 쓰기 권한이 필요하다.
5. 위 요약 형식으로 자료를 종합한다. 주요 답에 ID, 원래 증거, 조건, 검사를 연결한다. 관련 역방향·정방향 관계와 본문 링크를 따라간다. 이견을 보존하고 판단에 영향을 주는 충돌·대체 후보가 잘렸으면 본문까지 확인한다. 넓은 요청의 세부 질문마다 답변, 조건부, 충돌 또는 미확인 상태를 정리한다. 첫 상세 문서 수는 출발점이다. 미해결 질문, 의존성, 충돌, 실패를 확인하면 탐색을 넓힌다. 유용한 결과가 없으면 다른 용어나 가까운 범위를 한 번 시도하고 공백을 알린다. 검색에 실패한 경우 부재 여부는 미확인 상태로 유지한다. 새 조사가 필요한 질문은 현재 작업의 조사 단계로 전달한다.

권고를 요약할 때 적용 범위와 주의점을 함께 전달한다. 현재 사용자 의도, 정본 설정, 계약, 직접 증거에 따라 저장 지식의 적용 여부를 판단한다. 실제 적용과 검증은 호출한 스킬이 맡는다.

주장에 필요한 출처가 `SRC-...`로 등록돼 있으면 [이식 가능한 출처 절차](references/storage.kr.md#portable-source-references)를 따른다. 요청한 모든 ID에 대해 관련 위치, 접근 상태, 동일성 상태, 남은 공백을 각각 반환한다. 명시적으로 검증하기 전 검색 결과의 원본은 미확인 상태다. 찾는 동안 머신 설정과 과거 증거를 유지하며 허용된 범위에서 필요한 ID만 해석한다.

## 지식 공백 해소

빈 저장소나 부족한 검색 결과가 나오면 이번 결정에 꼭 필요한 작은 질문과 조건, 필요한 증거를 정한다. 현재 [조사 단계](../vegabond-research/SKILL.kr.md)로 질문을 전달하고 기존 작업 요약으로 Scout 판단과 조회 결과를 이어 쓴다. 모델 기억은 검색어 후보에 쓸 수 있다. 검증된 출처는 실제로 확인한다.

답을 정보 요약에 반영하고 **출처로 뒷받침한 주장**, **현재 작업에서 확인한 방법**, **추론과 미해결 질문**을 구분한다. 출처 기반 지식은 구현 전에 정리할 수 있고, 실제 동작은 별도로 검증한다. 호출한 전문 스킬이 적용과 결과를 검증한 뒤 증거와 예외를 전달한다. 필수 증거가 빠져 있으면 공통 규칙에 따라 그 증거에 의존하는 작업을 보류한다.

저장이 허용되면 반복되는 결정, 비용이 큰 조사, 중요한 제약, 재사용 가능한 검사처럼 나중에 찾아볼 가치가 있는 것부터 고른다. 한 항목에 독립적으로 답할 수 있는 질문 하나를 담고, 이해하고 적용하는 데 필요한 만큼만 설명한다. 전제는 필요할 때 링크한다. [저장 안내](references/storage.kr.md)에서 기존 항목에 합칠 내용, 새 항목, 원문이나 작업 기록에 남길 내용을 고른다. 범위가 명확한 가설을 남길 이유가 있는 경우에 한해 후보로 기록한다. 읽기 전용 작업은 변경 제안으로 반환한다. 기존 필드와 본문 구조를 재사용하고 Evidence에서 출처 검사와 결과물 검사를 따로 표시한다.

다음 관련 작업에서 질문과 조건으로 찾아 적용 가능성을 확인하고, 조치와 검사에 연결한다. 확인한 ID·해시, 결정, 공백, 오인하기 쉬운 후보는 기존 작업 근거에 남긴다. 실제 누락이나 부적절한 결과가 드러나면 영향받은 요약, 동의어, 범위나 검색 경로를 고치고 [검색 평가 사례](tests/retrieval_cases.json)를 보강한다. 검색 개선은 확인된 문제에 집중한다. 카탈로그 무결성과 검색 유용성은 각각 검증한다.

## 저장 및 관리

게임 개발 작업에서는 저장할 내용이 없다고 판단하기 전에 [게임 개발 용어 검토](references/storage.kr.md#game-development-terms)를 적용한다. 특정 프로젝트의 결과에서도 공개 엔진 API, C++ 기능, 정립된 기법을 배울 수 있다. 처음 접한 용어라도 관련성이 있으면 출처로 확인한 뜻과 함께 허용된 재사용 저장소에 포함한다.

항목을 작성하거나 재편할 때는 [저장과 수명주기](references/storage.kr.md)를 읽는다. 새 항목을 만들기 전에 [기록·통합·승격 결정](references/storage.kr.md#capture-consolidate-and-promote)을 적용해 재사용할 지식, 기존 항목에 합칠 내용, 계속 원문이나 작업 이력에 둘 내용을 정한다. 이 안내의 헤더와 본문 형식, 근거, 중복 제거, 승격, 폐기 규칙을 따른다. [카탈로그 도우미](scripts/catalog.py)의 생성·검사 절차는 저장소 관리에 사용한다.

쓰기 작업은 허용된 범위에서 진행한다. 읽기 전용이나 발견 사항만 요청된 작업에서는 변경안을 반환한다. 저장이 허용되면 영문 상세와 사용자용 번역본을 갱신하고 관련 카탈로그를 생성한다. 바뀐 영문 카탈로그의 번역본을 다시 만들고 검사한다. 새 분야가 추가되면 루트 경로를 갱신한다. 생성 행은 카탈로그 도우미로 관리하며 기존 메타데이터의 공백을 유지한다. 일반 조회에 필요한 기존 자료를 활용하고, 빈 저장소나 초기 지식을 임의로 만들지 않는다.
