# Vegabond Knowledge

현재 작업에 필요한 지식과 문제 기록을 검색하고 관리합니다. scout의 작업 프로필을 재사용하며, 호출한 작업 스킬이나 전문 스킬이 적용 여부를 판단하고 실제 결과물을 검증합니다. 문서 경계와 완료 기준은 [에이전트 지침](../../agents/vegabond-agent.md)을 따릅니다. 이 스킬은 정보를 제공하며 생성·수정·조사를 대신하지 않습니다. 스킬을 읽는다고 에이전트가 생성되지는 않습니다.

## 요청과 반환

요청에는 관련된 **작업 프로젝트, 질문, 분야, 대상과 제약, 환경·버전 또는 작품 맥락**을 포함합니다. 기존 요약을 재사용하고 같은 정보를 다시 묻지 않습니다. 저장 요청에는 발견 사항, 근거, 해결 내용, 제안된 재사용 점검, 의도한 재사용 조건, 실제 검증한 맥락도 포함합니다.

다음 내용을 짧은 정보 요약으로 반환합니다.

- **적용 가능한 지식:** 이번 단계에 도움이 되는 내용과 중요한 주장별 출처 ID·경로 또는 링크.
- **조건과 예외:** 적용 범위, 이전 사건과 일치하는 이유, 원인 확신도와 검증 맥락, 현재 요청이나 출처와 충돌하는 사항.
- **점검:** 작업에 반영할 구체적인 예방·완료 점검과 원래 기록 ID, 예방 상태, 근거. 사건이 해결되었다고 예방이 검증된 것은 아닙니다.
- **빈틈:** 누락되거나 오래되었거나 충돌하거나 확인되지 않은 정보와 남은 질문.

## 검색과 취합

1. 질문, 범위, 조회한 항목 내용, 기준 원출처가 유효한 동안 기존 정보 요약을 재사용합니다. 이 중 하나가 바뀌거나 새로운 근거가 빈틈을 드러내면 다시 검색합니다. 필요한 경우 조회한 ID와 개정·해시를 작업 근거에 남기되 프로젝트 사실의 전역 캐시를 만들지 않습니다.
2. 작업 프로젝트의 알려진 저장소를 먼저 사용합니다. 이 저장소의 기본 경로는 [knowledge](../../knowledge/index.md)와 [records](../../records/index.md)입니다. 다른 프로젝트에서는 OneStep의 프로젝트 사실을 자동으로 사용하는 대신 해당 프로젝트에서 경로를 찾습니다. 적합한 기존 저장 체계가 있으면 사용합니다. 공통 OneStep 자료는 명시적으로 설정되거나 요청된 경우에만 추가 출처로 사용합니다. 관련 없는 프로젝트는 검색하지 않습니다.
3. 작업 프로필에서 관련 분야 색인을 선택하며 혼합 작업에서는 분야를 결합합니다. 한국어 질문을 유용한 영어 개념과 동의어로 바꾸되 원출처 이름과 정확한 기술 식별자를 유지합니다. 작은 경로 안내 색인을 읽고 검색 위치를 정합니다. 질문, scope/context, 상태에 맞는 색인 행을 제한적으로 가져오며 최신성보다 적용 가능성을 우선합니다. 검색에 성공했으면 전체 색인을 열지 않고 이 수준에서 조회합니다. 조회 전에 `*.kr.md`를 제외합니다. 관련된 분야 간 필요가 있을 때만 `shared`를 확인합니다.
   작업 전에는 증상이 없어도 예정된 행동과 조건을 `trigger`와 대조하여 문제 기록을 검색합니다. 실패 후에는 `symptom`과 정확한 식별자로 검색하고 조건과 원인 근거를 비교합니다. 해결된 사건도 후보에 포함합니다. 명확히 맞지 않는 범위는 제외하되, 호환 여부를 모르면 맞지 않는 것으로 단정하지 않고 주의 사항으로 남깁니다. 증상 일치가 원인 일치를 입증하지는 않습니다. trigger 부재는 검색 정보의 빈틈이며 사건이 무관하다는 근거가 아닙니다. 이는 사용 가능한 도구를 이용한 범위 제한 색인 검색이며 자동 순위 서비스가 아닙니다.

4. 선택한 저장소 전체에서 우선 최대 세 개의 관련 상세 파일을 읽되 헤더와 유용한 절부터 확인합니다. 적용 가능성을 확인하고 필요하면 원래 근거를 따라갑니다. 요약은 증거가 아닙니다. 출처의 사실, 확인된 수정, 저자·프로젝트 선택, 편집적 판단, 가설을 구별합니다. 열린 기록은 위험을 나타내며 이전 형식의 색인 문구와 미기록 원인·예방 정보는 검증되지 않은 상태입니다. 제안된 점검은 검증에 참고할 수 있지만 입증된 방지 장치로 표현하지 않습니다. 무효화된 점검은 의존하기 전에 다시 조사합니다. 대체되었거나 버전이 맞지 않는 항목을 조용히 적용하지 않습니다. 색인이 없거나 오래되었다는 근거가 있으면 선택한 분야에서 메타데이터를 좁혀 검색하고 빈틈을 보고합니다. 재생성은 허용된 쓰기 범위에서만 수행합니다.
5. 중요한 불일치를 보존하면서 출처를 위 정보 요약으로 취합합니다. 구체적인 의존성, 충돌, 관찰된 실패가 있을 때만 범위를 넓힙니다. 유용한 결과가 없으면 대체 검색어나 가장 가까운 범위로 한 번 더 시도하고 빈틈을 보고합니다. 지식을 만들어내거나 검색 실패를 과거 사건이 없다는 증거로 삼지 않습니다. 새 조사 필요는 현재 작업의 조사 단계로 돌려보냅니다. 필요한 조사 자체가 이 조회 기본 범위로 제한되는 것은 아닙니다.

요약할 때 권고의 적용 범위와 주의 조건을 유지합니다. 저장된 지식은 현재 사용자 의도, 정본 설정, 계약, 직접 근거보다 우선할 수 없습니다. 적용과 검증의 책임은 호출한 스킬에 있습니다.

## 지식의 빈틈 해소

빈 저장소나 충분하지 않은 검색 결과는 정상적인 출발점입니다. 현재 판단에 필요한 최소 질문으로 빈틈을 구체화하고 조건과 필요한 근거를 붙입니다. 주제 전체를 미리 수집하지 않습니다. 질문은 현재 작업의 [조사 단계](../vegabond-research/SKILL.md)로 반환합니다. 기존 작업 요약을 재사용하여 scout를 다시 시작하거나 같은 검색을 재귀적으로 반복하지 않습니다. 모델의 기억은 검색어를 제안할 수 있지만 확인된 출처 근거는 아닙니다.

조사 답변을 정보 요약에 반영하면서 **출처가 뒷받침하는 주장**, **실제 작업에서 점검한 방법**, **추론 또는 미해결 질문**을 구별합니다. 출처 기반 참조 지식은 구현을 기다리지 않고 남길 수 있지만, 출처 확인이 로컬 실행을 입증하지는 않습니다. 호출한 전문 스킬이 조사 내용을 적용하고 실제 결과를 점검하며 그 근거와 예외를 이 스킬에 반환합니다. 필요한 근거의 빈틈은 공통 규칙에 따라 의존 작업을 계속 막습니다.

허용된 저장 전에 다시 찾을 가치가 있는 내용을 고릅니다. 반복되는 판단, 비용이 큰 조사, 중요한 제약, 유용한 점검이 해당하며 문제가 없었던 성공적인 방법도 포함합니다. 항목 하나는 독립적으로 답할 수 있는 질문 하나를 중심으로 하고 활용에 필요한 만큼만 개념을 설명합니다. 선행 지식은 필요할 때만 연결합니다. 새 용어마다 저장하거나 조사 보고서를 복제하지 말고 저장 지침의 통합 규칙을 적용합니다. 근거가 없는 후보는 후속 추적이 필요한 범위 한정 가설 기록에 해당하지 않는 한 작업의 발견 사항에 남깁니다. 읽기 전용 작업에서는 갱신안을 반환합니다. 기존 필드와 본문 절을 재사용하고 Evidence에서 출처 확인과 작업 점검을 구분합니다.

다음 관련 작업에서는 그 질문과 조건으로 검색하고 적용 가능성을 확인한 뒤, 지식을 인용하는 데 그치지 않고 구체적인 행동이나 점검에 반영합니다. 재사용을 평가할 때 조회 ID, 도움이 된 판단, 빈틈, 잘못 유도한 검색 결과를 기존 작업 근거에 남깁니다. 반복 누락, 조건이 맞지 않는 결과, 불필요한 상세 열람, 반복 조사를 근거로 해당 요약·키워드·범위·경로 안내를 개선합니다. 사용 이력 장부를 추가하거나 작업마다 전체 저장소를 읽지 않습니다. 이 피드백은 검색의 유용성을 평가하며 색인 검증만으로는 이를 확인할 수 없습니다.

## 저장과 유지보수

항목을 쓰거나 재구성할 때 [저장과 수명주기](references/storage.md)를 읽습니다. 새 항목을 만들기 전에 [기록·통합 판단](references/storage.md#capture-consolidate-and-promote)을 적용하여 재사용할 가치가 있는 내용, 기존 항목에 넣을 내용, 원출처나 작업 이력에 남길 내용을 결정합니다. 이 문서는 항목 헤더·본문과 [색인 도우미](scripts/catalog.py)의 build/check 절차를 정의하며 형식, 근거, 중복 제거, 승격, 정리의 단일 기준입니다. 일반 조회 과정에서 전체 저장소 재생성이나 점검을 실행하지 않습니다.

작업에서 허용된 범위에만 작성합니다. 읽기 전용 또는 발견 사항만 요청받은 작업에서는 저장소를 수정하지 말고 항목 제안을 반환합니다. 저장이 허용되면 상세와 사용자 번역본을 갱신하고 영향받는 색인을 생성한 뒤 바뀐 영문 색인의 번역본을 다시 만들고 인계 전에 점검합니다. 새 분야는 루트 경로 안내를 갱신합니다. 생성된 행을 직접 편집하거나 빠진 이전 메타데이터를 추론하지 않습니다. 조회만을 위해 빈 저장소를 만들지 않으며 초기 지식을 꾸며내지 않습니다.
