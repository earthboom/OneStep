# Find the working project's sources before production

Start from the working project named in the task, or the current project when none is named. The checkout containing these skills and any installed `onestep-strategy/` library supply shared guidance. Resolve project document paths from the working project and follow its source and access rules. Exclude `*.kr.md` before searching or opening files. In `rg`, place `-g '!*.kr.md'` after any include globs so a later pattern cannot bring translations back into scope.

1. **Name what the source must settle.** Use the actual request, target and preservation conditions to identify what could change the result. Check existing inputs and knowledge in the brief. If they already settle the consequential questions, go straight to the work.
2. **Open the linked originals in the next read.** Use project instructions and the nearest relevant README or index. When the instructions name the entry point, open that entry point directly as the first project-content read. After reading it, match each requested case or decision to its relevant source links. Include likely owners whose link labels describe the broader operation. Read the linked originals for all mapped cases in the next tool round, batching independent reads. If batching is unavailable, read them consecutively. Use searches, directory listings and separate status lookups only after opening the relevant links. A case is ready for the search step once it has no relevant link, its link cannot be opened, or the original leaves a material question unanswered. Reuse relevant sections already in the brief.
3. **Choose one lookup for each remaining question.** Start this step after reading the available linked originals. Identify the missing fact and where its owner is likely to record it. If the question is where to find a result report, start with a single file-name lookup. Scope it to an evidence directory when the project points to one, or to the working project when the directory is unknown. For example, use `rg --files -g '*validation*' -g '*verification*' -g '*report*' -g '!*.kr.md'` with terms appropriate to the project, or filter the file listing in the available reader. Open a plausible original from that result. Use heading or content search as a fallback when the filename lookup misses, or as the first lookup when the missing fact is inside a likely source. For example, `rg -l -i -g '!*.kr.md' -e 'receipt_id|receipt status' operations/` searches a likely source area. Use a second lookup only to address a specific miss or newly exposed gap. Keep generated output, vendored copies and unrelated areas out of the scan. Use the relevant reader for formats that need it.
4. **Read and use the governing text.** Open the relevant original sections before drafting or editing the dependent work. When links or earlier reads give section locators, select the passages for the requested decisions, exceptions and checks in the first batch. Keep the combined output within the reader's limit. Check ownership, approval, version and scope where they matter, especially when a draft, example or old copy also matches. Use search output to locate the original. In the existing brief, record the path and section or line, the decision it governs, and how you will check the result. Reuse confirmed findings during execution. When a source turns out to be essential and access or focused discovery cannot resolve it, state the affected decision and the missing evidence while completing independent work.

For a link to a mixed-topic Markdown file, select sections by heading in its first read, even when the link has no anchor or line range. Include selectors for the governing decision, input handling and exceptions, the full workflow to the requested outcome, constraints that change allowed actions, and needed verification status. Use heading words for the artifact and its lifecycle, since a procedure heading may name preparation, review or storage while approval and depletion rules appear in its body. For a production handover, include those input sections and the production-to-delivery sequence in the operating plan, even when a separate source covers delivery. If the brief restricts paid fallback, include budget and limits headings in the first read. Example Korean heading terms include `결정|권고|권장|추천` for a governing decision, `대본|준비|검수|보관` for input handling, `(제작|생성).*(예약|업로드|게시|공개)` for workflow, and `비용|예산|한도` for constraints.

[The section reader](../scripts/read_sections.py) takes known file paths and heading patterns in one tool call and returns original text with file names and line numbers. A matching document title returns the introduction up to its first subsection. For example, from the working project run `python -X utf8 <installed-reader-path> --section handbooks/process.md 'final recommendation|approved inputs|production.*delivery|failure recovery|verification status'`. Repeat `--section FILE PATTERN` for independent documents. An available heading-aware reader can do the same. Narrow overly broad selectors or use an exact source range when necessary. A missing match remains an evidence gap.

When a batch is clipped, keep the missing passage at the known path pending and identify any other required read. If a verification question already identifies what was to be tested, locate its result report next using the filename lookup above. Then open the report and the pending passage in one call. Use a separate reread first only if the missing passage supplies a fact needed to identify the report, such as an experiment ID or version. A plan's omitted procedure and the actual result for an already identified operation can normally be read together.

Before opening another document, name the unresolved question that could change the deliverable and the title, index entry, heading or link that points to evidence for that exact question. Use the result report for the relevant operation when the task needs current verification status. When the governing documents cover the requested cases and a direct report states what was tested or is still unverified, start drafting from those sources. The stated unverified status completes that status check. For example, a report that records a successful sample render and untested publication supports both statements. A later review of the same sample's appearance addresses visual quality. Reopen the publication question only on a concrete pointer to a later publication test or a superseding operating decision. Apply the same rule to broad histories and keyword hits. Close discovery when material questions have evidence or a stated gap and no focused lookup is likely to resolve that gap.

For the final wording check, use the original sections already consulted. Reopen a cited section when necessary to check the wording. Open a new document if the draft exposes a consequential evidence gap that the document could resolve.

At handoff, connect the material source to what the result does and the check you ran. A short inline reference is enough for a small task.
