# 저장 및 수명주기

## 위치와 분야

경로는 작업 프로젝트 기준입니다. 범위 제한 조회와 출처 추적이 가능한 기존 시스템이 있으면 재사용합니다. 기본 구조는 다음과 같습니다.

```text
knowledge/index.md              # 분야 경로만 제공
knowledge/<domain>/index.md     # 검색 가능한 지식 요약
knowledge/<domain>/<id>.md      # 재사용할 주제·교훈 하나
records/index.md                # 분야 경로만 제공
records/<domain>/index.md       # 검색 가능한 문제 요약
records/<domain>/<id>.md         # 문제·수정·재검증 이력
```

초기 분야 code·fiction·presentation·planning·shared는 닫힌 목록이 아닙니다. 작업 종류나 확장자보다 내용을 기준으로 분류합니다. 실제 내용에 필요할 때 분야를 추가합니다. 더 깊은 폴더를 만들기 전에 언어·엔진·장르·형식·구성요소·작품 ID·세부 작업을 메타데이터로 표현합니다.

여러 분야의 항목은 주된 위치 하나에 두고 다른 분야 목록에서 연결합니다. shared는 분야 공통 적용 근거가 있을 때만 사용합니다. 프로젝트 사건과 정본 설정은 해당 프로젝트에 남기며 일반 방법의 공유 승격에는 그 범위의 근거가 필요합니다.

lessons와 knowledge 저장소를 병행하지 않습니다. 기존 교훈 시스템을 재사용하거나 허용 범위에서 ID와 근거를 보존해 이전합니다. 새로 쓰거나 변경한 영문 목록·지식·문제·보관 문서에는 영문에서 생성한 `<stem>.kr.md` 사람용 번역을 제공합니다. 번역은 다시 읽지 않습니다. 기록도 이 규칙의 예외가 아닙니다. 인계 전 영문 링크와 상태 일치를 검사하고 번역 파일의 존재만 확인합니다.

## 항목 헤더와 본문

상세 문서마다 독립적으로 재사용할 주제·점검 하나를 담고 YAML 헤더를 둡니다.

| 필드 | 규칙 |
| --- | --- |
| `id` | 프로젝트에서 유일한 안정적 ID. 영문자·숫자·점·밑줄·하이픈을 쓰며 비교 시 대소문자를 구분하지 않습니다. |
| `title` | 구체적인 질문·방법·주제입니다. |
| `summary` | 사용할 핵심과 필수 조건을 1~2문장으로 씁니다. |
| `kind` | 지식은 reference·method·convention·lesson, 문제는 error·suggestion·hypothesis입니다. |
| `scope` | 프로젝트·구성요소·작품과 적용 경계를 문자열로 표시합니다. |
| `keywords` | 유용한 영어 개념·동의어·정확한 기술 식별자의 비어 있지 않은 목록입니다. |
| `status` | 지식은 active·enforced·superseded, 문제는 open·resolved·superseded입니다. |
| `checked_at` | 실제 근거 확인일 YYYY-MM-DD 또는 모르면 null입니다. 편집 날짜로 자동 채우지 않습니다. |

선택 필드 `context`는 문자열 또는 문자열 값만 갖는 평면 매핑입니다. 관련 버전·엔진·형식·장르·시점 등을 담고 버전과 YAML 예약어는 따옴표로 감쌉니다. 무관한 빈 필드는 만들지 않습니다. 헤더는 스킬 탐색용 프런트매터가 아닙니다. 번역은 사람이 읽는 정보로 제시하며 탐색 입력으로 쓰지 않습니다.

선택 필드 `relations`는 requires·derived_from·prevention·supersedes·conflicts_with를 기존 항목 ID의 비어 있지 않은 목록에 연결합니다. 다른 저장소·분야도 가능합니다. 실제 조회를 개선할 관계만 추가합니다. [관계 의미와 탐색](retrieval.kr.md)을 참고합니다. 도구는 형식과 대상 ID를 검사합니다. 연결이 인과관계·독립 근거·호환성·예방 검증을 입증하지는 않습니다. 본문 근거 링크와 역사적 날짜를 보존합니다. 조회 관계 추가는 새로운 원본 조사가 아닙니다.

형식 예시이며 실제 항목은 아닙니다.

```yaml
---
id: K-FIC-001
title: Check information access in limited viewpoint
summary: Under limited narration, check each claim against the focal character information access before line polishing.
kind: method
scope: naru-novel; Seorin-limited narration
keywords: [viewpoint, POV, character-knowledge]
status: active
checked_at: null
context:
  viewpoint: third-person limited
---
```

영문 정본 본문에는 다음 네 H2 절을 비어 있지 않게 둡니다.

- 지식: Guidance, Applicability and exceptions, Checks, Evidence.
- 문제: Expected and observed, Cause and resolution, Recheck and prevention, Evidence.

유용한 행동은 짧게 쓰고 예외를 설명합니다. 출처 사실·방법·관례·편집 판단을 구분하고 원본 출처에 위치와 확인 맥락을 붙입니다. 문제 기록에는 원인 확신도·수정 또는 제안·해결 및 재검증·예방 링크를 남깁니다. 모르는 원인은 모르는 상태로 유지합니다. enforced에는 작동이 입증된 보호장치가 필요하며 교훈 저장만으로 강제되지는 않습니다.

이슈·보고서·테스트·구절·스크린샷·로그는 복제보다 원본 참조를 사용합니다. 원인이 같은 작은 문제는 유용할 때 묶습니다. 프로젝트 사실은 원본이, 항목 메타데이터는 상세 문서가 기준이며 목록 행은 파생물입니다.

### 문제 검색 필드

새로 작성하거나 정규화한 records 상세에는 다음 다섯 필드도 모두 필요합니다. knowledge에는 추가 요구하지 않습니다.

| 필드 | 규칙 |
| --- | --- |
| `trigger` | 발생 조건·행동의 짧은 설명, 모르면 null. 증상 발생 전에도 찾을 수 있게 합니다. |
| `symptom` | 구별 가능한 실제 실패 설명. 제안·가설은 확정 결함으로 단정하지 않고 우려를 설명합니다. |
| `cause_status` | unknown·suspected·confirmed 중 하나이며 원인·해결 절의 근거가 필요합니다. 결함이 확정돼도 원인은 모를 수 있습니다. |
| `prevention` | 필수 조건을 포함한 구체적 행동·점검 또는 미확립이면 null. 세부 절차·예외·근거는 본문에 둡니다. |
| `prevention_status` | none·proposed·verified·invalidated. none이면 prevention은 null, 그 외는 행동이 필요합니다. verified에는 실제 확인일과 입증 근거가 필요합니다. |

목록 행으로 쓸 수 있게 짧게 적고 로그·모든 사례를 반복하지 않습니다. 검색어에는 동의어와 정확한 식별자를 둡니다. summary는 전체 헤더 반복 대신 발견 사항과 필수 조건을 설명합니다. 버전·설정·형식 차이가 적용 가능성을 바꾸면 scope·context에 명시합니다.

예시 사건 헤더의 추가 필드는 다음과 같습니다. 실제 사건이 아닙니다.

```yaml
trigger: Drafting third-person limited narration
symptom: Focal character states another character private decision without access
cause_status: confirmed
prevention: Trace each private-knowledge assertion to a source available to the focal character
prevention_status: proposed
```

resolved는 사건 상태이지 예방 상태가 아닙니다. 지정한 점검이 원래 실패나 같은 조건의 통제된 동등 실패를 탐지한 것이 입증됐을 때만 verified로 둡니다. 편집 작업의 구체적 검토도 유효한 증거이지만 자동 강제로 표현하지 않습니다. 수정 결과만으로 예방이 입증되지는 않습니다. 본문에 수정 점검과 보호장치 점검의 날짜·결과를 따로 기록합니다. checked_at은 마지막 실제 중요한 근거 확인일입니다. 유효한 헤더와 날짜만으로 실증이 입증되지는 않으므로 전문 스킬이 근거를 확인합니다.

기존 네 절은 유지합니다. 기대·관찰에는 원래 계약·실제 발견·조건·위치를, 원인·해결에는 진단 확신도·근거·수정·미확인을, 재검증·예방에는 수정 결과 점검과 미래 보호장치의 상태·조건·예외를 구분해 기록합니다. Evidence는 원래 산출물·버전·보고서에 연결합니다. 기록됐다는 이유로 제안·가설이 오류가 되지는 않습니다.

### 이전 구조화 기록

공통 헤더만 있고 새 다섯 필드가 모두 없는 기존 기록은 읽을 수 있습니다. 도구는 legacy_record_fields 경고와 미기록 표시를 제공하고 원문을 바꾸지 않습니다. --strict는 이를 오류로 취급합니다. 일부만 추가한 헤더는 예전 형식의 예외가 아니라 오류입니다. 새로 쓰거나 수정하는 기록에는 모두 필요합니다. 도구는 편집 시점을 추론할 수 없으므로 작성 규칙도 함께 적용합니다. 허용된 유지보수에서만 ID·경로·근거·미확인 상태를 보존해 정규화합니다. 제목이나 과거 행으로 값을 추정하지 않습니다.

## 목록 갱신과 검증

[catalog.py](../scripts/catalog.py)는 Python 3.9 이상과 기존 PyYAML 실행 환경을 사용하며 아무것도 설치하지 않습니다. 다른 프로젝트에서는 도구의 절대 경로와 해당 작업 프로젝트의 --project를 사용합니다.

```text
python skills/vegabond-knowledge/scripts/catalog.py build --project . --domain fiction
python skills/vegabond-knowledge/scripts/catalog.py check --project . --domain fiction
```

--store knowledge·records·기본 both로 저장소를 선택하고 --domain을 반복해 영향을 받는 분야를 고릅니다. 분야 생략은 프로젝트 전체 중복 ID 검사를 포함한 명시적 전체 유지보수입니다. 제한 실행은 선택 상세와 명시적 관련 항목만 검증합니다. 일상 조회는 제한 검색을 사용하며 요청마다 재생성하지 않습니다.

도구는 관리 표식 안에 ID·제목·종류, 요약, 범위·맥락, 검색어, 상태·확인일, 상세 링크의 여섯 열을 생성합니다. 문제 행은 요약 열에 발생 조건·증상, 상태 열에 원인 확신도·예방 상태·행동을 추가합니다. 지식 행은 기존 형식을 유지합니다. 해결 사건은 활성 목록에서 계속 찾을 수 있으며 superseded만 archive로 이동합니다. 표식 밖 프로젝트 메모를 유지하고 다른 분야 참조는 원본 상세 하나를 연결합니다. 최상위 목록은 작은 분야 경로로 유지합니다.

저장 순서는 정본과 번역 작성 → build → catalogs_written에 나열된 영문 목록의 번역 재생성 → check입니다. build는 준비 단계이므로 번역·경로 부재를 경고해 영문 목록 생성을 허용합니다. check는 목록 최신성·유효 메타데이터와 상태·ID 유일성·필수 본문·로컬 링크·분야 경로·번역 존재를 요구합니다. 중복 YAML 키와 잘못된 구조화 헤더는 오류입니다. 메타데이터·참조 오류가 있으면 쓰기 전에 중단합니다. 각 변경 목록은 원자적으로 교체하지만 파일 시스템 실패로 일부만 갱신될 수 있으므로 다시 검사·수정합니다. 도구는 상세 정본이나 번역을 직접 쓰지 않습니다.

프로젝트 밖 링크와 절 앵커 정확성은 별도 확인합니다. 도구는 로컬 대상 존재만 확인하며 참조 내용은 열지 않습니다. 번역은 존재만 확인하므로 변경 번역을 영문에서 다시 생성하고 열지 않습니다. 진단은 첫 20개와 전체·오류 건수를 반환하므로 필요하면 범위를 좁힙니다.

### 이식 가능한 출처 참조

프로젝트 밖 원본은 [출처 등록부](../../../knowledge/sources.kr.md)로 안정적인 출처 ID와 컴퓨터별 위치를 분리합니다. sources 매핑의 SRC-... ID마다 소문자 프로젝트 ID project, 슬래시 기반 프로젝트 상대 정본 경로 path, 기존 소문자 SHA-256 또는 null인 sha256만 둡니다. ID마다 H2 제목을 둬 일반 Markdown 링크로 참조합니다. 구절·절 위치와 근거 맥락은 참조하는 항목에 남깁니다. 알려진 지문은 보존하며 버전을 추정하거나 역사적 확인일을 갱신하거나 변경 가능한 현재 파일로 과거 원고를 인증하지 않습니다.

해시가 기록된 ID는 해당 내용 스냅샷을 식별합니다. 근거상 다른 버전에는 새 ID를 주며 과거 인용을 재지정하지 않습니다. 같은 스냅샷의 위치만 옮길 때는 로컬 루트만 변경합니다.

로컬 루트는 Git에서 제외한 knowledge/sources.local.json에만 설정합니다. 예를 들어 {"novel0": "D:/Writing/Novel_0"}의 값은 이 작업에서 명시적으로 설정한 절대 루트여야 합니다. 예시는 기본 위치가 아닙니다. 로컬 설정을 커밋하거나 루트를 추정하거나 무관한 프로젝트를 검색하거나 원본 라이브러리를 통째로 복사하지 않습니다. 다른 작업 프로젝트도 로컬 설정을 Git에서 제외해야 합니다.

필요한 등록 링크를 따라간 뒤 허용 범위 내의 ID만 조회합니다.

```text
python skills/vegabond-knowledge/scripts/sources.py resolve --project . --id SRC-NOVEL0-ATTAINMENT
```

도구는 선택 원본을 바이트로 읽어 SHA-256을 비교합니다. 내용을 출력하거나 번역을 읽거나 설정·항목을 쓰거나 관찰한 해시를 자동 승격하지 않습니다. 경로 이동과 설정 루트 밖으로 해석되는 경로를 거부합니다. 해시 일치는 내용 동일성이지 진실·적용 가능성·품질·저자 수용의 증거가 아닙니다. 필요한 원본 구간은 별도로 검토합니다.

종료 코드 0은 matched, 1은 unconfigured·missing·unavailable·mismatch·unversioned, 2는 등록부·ID·설정·경로 오류입니다. unversioned는 파일을 찾아 해시를 계산했으나 기대 해시가 없다는 뜻입니다. 정보 요약에 상태와 영향을 남깁니다. 필수 원본의 접근이나 동일성이 불확실하면 의존 검증이 막히지만 조건부 지식은 독립 작업에 사용할 수 있습니다. 컴퓨터별 접근 가능성은 사건 해결이나 예방 상태가 아닙니다.

## 비구조화 기존 자료

이전 산문 항목은 사용할 수 있습니다. 기존 행과 조건은 명시적인 미검증 Legacy entries에 보존하고 목록 밖 파일은 메타데이터 미확인 링크로 표시합니다. ID·날짜·규칙·상태를 추정하지 않습니다. 허용된 유지보수 때 경로·ID·근거를 보존해 이전하고 재생성합니다. 기본 실행은 경고하고 --strict는 이미 정규화한 범위에서 오류로 다룹니다. 새로 쓰거나 바꾼 항목은 이웃이 예전 형식이어도 헤더를 사용합니다. 엄격 검사 자체가 과거 근거나 무관한 파일의 재작성 허가는 아닙니다.

## 포착·통합·승격

저장 전에 [검색 도구](retrieval.kr.md)로 제안할 질문·동의어·근본 원인을 두 저장소에서 검색합니다. 가까운 후보와 관계를 검토한 뒤 기존 항목 갱신·별도 사건·새 지식 중 목적지를 선택합니다. 유사성은 후보를 제안할 뿐 자동 병합을 허용하지 않습니다.

저장 전에 미래의 결정·행동·점검과 적용 조건을 식별하고 가장 작은 적합한 목적지를 선택합니다.

- 지식: 사용할 원칙·방법·이유·점검·예외를 담습니다. 제목과 요약은 작업 일지보다 재사용할 질문·행동을 설명합니다.
- 문제 기록: 발생 조건·증상·원인 확신도·수정·재검증을 구분할 최소 근거를 보존하고 공통 지식의 절차를 복제하지 않고 연결합니다.
- 원본·작업 이력: 유일한 프로젝트 사실·작품 설정·저자 취향·일회성 진행은 원래 출처에 남깁니다. 반복 조회 이익이 있을 때만 범위를 한정한 참조·관례를 추가합니다. 재사용·추적 가치가 없으면 작업 결과에 남길 수 있지만 추적이 필요한 미해결 문제는 기록합니다.

쓰기 전에 같은 원칙·질문·근본 원인이 있는지 검색합니다. 프로젝트별 사본보다 기존 항목의 조건·예외·근거·재발 이력 보완을 우선합니다. 하나의 지식에 여러 사건을 연결할 수 있습니다. 원인과 발생 조건이 같은 예방을 지지할 때만 사건을 통합하며 증상 유사성만으로 합치지 않습니다. 미확인 일치는 연결하되 진단을 병합하지 않습니다. 새 자료라는 이유만으로 기존 버전을 덮지 않고 불일치를 명시합니다. 문제와 예방, 교훈과 원래 근거 사이의 연결을 유지합니다.

설명을 일반화해도 근거 경계는 지우지 않습니다. 필수 버전·수명주기·장르·시점·독자 조건과 재현용 식별자는 유지하고 우연한 이름·긴 로그는 생략합니다. 실제 확인 조건과 기전·이유에서 추론한 범위를 구분하고 미검증 범위를 표시합니다. 성공 한 번이 다른 환경의 검증을 뜻하지 않습니다. 작품 설정·취향을 보편 규칙으로 만들거나 일반화만으로 제안 예방책을 승격하지 않습니다. 일반화가 프로젝트 이동이나 shared 분류를 자동 허용하지 않으며 기존 스키마·저장소를 사용합니다.

재발 이력은 발생일 또는 미확인, 위치·버전, 근거 링크, 수정·재검증 결과, 이전 예방책 결과를 짧게 남깁니다. 미실행·실행했으나 불충분·조건 변경으로 무효화를 구분합니다. 반대 근거가 예방 주장을 무효화하면 invalidated로 표시하고 기존 실증 맥락을 보존한 채 대안을 조사합니다. 점검을 빠뜨렸다고 점검 자체가 반증되지는 않습니다. 조건·해법이 실질적으로 다르면 사건을 분리하고 긴 로그는 원본에 둡니다.

확인됐고 중요한 교훈은 반복·재사용 가능성·유용한 보호장치 근거가 있을 때 승격합니다. 사건은 records, 간추린 재사용 지식은 knowledge에 두고 양방향으로 연결합니다. 전문 스킬이 진단·분야 점검을 제공하며 지식 스킬이 해결 원인이나 결과를 만들어 인증하지 않습니다. 구조·타입·입력 검증·린트·회귀 검사로 재발을 막는 방식을 우선하고 원래 실패나 통제된 동등 사례를 탐지한 근거를 유지합니다. 판단 의존 작업은 조건부 검토와 이유를 명시하며 저장 자체로 예방이 입증되지는 않습니다.

## 출처를 잃지 않고 폐기

일상 활용 중 중복과 오래된 조건을 정리합니다. 대체할 때 정본 상태를 superseded로 바꾸고 이유·대상을 기록합니다. 재생성하면 필요할 때만 만드는 archive로 행이 이동하며 다시 활성화하면 복귀합니다. 상세 경로와 근거는 안정적으로 유지하고 생성 행을 직접 고치지 않습니다. 기존 시스템은 자체 보관 방식을 사용합니다. 오래됐다는 이유만으로 유용한 지식을 무효화하지 않습니다.

출처·버전·설정·예방 조건이 바뀌면 관련 항목을 다시 확인하고 무효화된 정보 요약도 갱신합니다. 제한 검색이 반복해서 무관한 결과를 많이 반환하면 실제 프로젝트 구분으로 분야 목록을 나누고 작은 경로 목록을 유지합니다. 실제 검색 마찰에 따라 확장하며 매 작업 뒤 전체 이력을 재독하는 작업을 예약하지 않습니다.

## 첫 목록 생성

새 저장소·분야는 유효한 상세와 번역, 최상위 분야 경로와 번역을 먼저 씁니다. 이번 생성에서 만들 목록으로 경로 링크를 걸 수 있으며 빈 목록이나 특별 초기화 명령은 필요하지 않습니다. build→번역→check를 따릅니다. 모든 선택 출력이 계획된 뒤 파일 존재를 검증하며 그 계획에 있는 미생성 목록만 허용합니다. 다른 누락 파일이나 선택 밖 목록은 쓰기를 막습니다. check는 첫 생성 때도 파일을 쓰지 않고 실제 목록 존재를 요구합니다.
