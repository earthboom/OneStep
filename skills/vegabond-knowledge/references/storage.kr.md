# 저장과 수명 관리

## 위치와 분야

경로는 작업 프로젝트 기준입니다. 범위별 검색과 출처 추적이 가능한 기존 체계가 있으면 재사용하고, 그렇지 않으면 다음 구조를 사용합니다.

```text
knowledge/index.md              # 분야 안내만
knowledge/<domain>/index.md     # 검색 가능한 지식 요약
knowledge/<domain>/<id>.md      # 재사용할 주제·교훈 하나
records/index.md                # 분야 안내만
records/<domain>/index.md       # 검색 가능한 문제 요약
records/<domain>/<id>.md        # 문제·수정·재점검 이력
```

초기 분야는 `code`, `fiction`, `presentation`, `planning`, `shared`이며 완결된 목록이 아닙니다. create/revise/research나 확장자가 아니라 주제로 분류합니다. 실제 내용에 필요할 때 분야를 추가합니다. 더 깊은 폴더를 만들기 전에 언어·엔진·장르·형식·구성요소·작품 식별자·작업 하위 유형을 메타데이터로 표현합니다.

분야를 가로지르는 자료는 주 저장 위치 하나를 정하고 다른 관련 색인에서 연결합니다. `shared`는 분야 간 적용 근거가 있을 때만 쓰며 기본 잡동사니 저장소로 쓰지 않습니다. 프로젝트 사건과 작품 설정은 해당 프로젝트에 둡니다. 일반 방법을 공유 지침으로 승격하려면 그 범위의 근거가 있어야 합니다.

`lessons/`와 `knowledge/`를 병행하여 만들지 않습니다. 기존 교훈 체계가 있으면 재사용하거나 허용된 범위에서 관련 항목·참조를 옮기되 ID와 근거를 보존합니다.

관리 대상 저장 문서에는 색인, 지식·문제 상세 문서와 보관 자료가 포함됩니다. 영문 문서를 새로 쓰거나 바꾸면 영문에서 `<stem>.kr.md` 사용자 번역본을 작성·갱신하고 기존 번역 내용을 읽지 않습니다. 기록이라고 번역 규칙에서 제외하지 않습니다. 인계 전에 영문 링크와 상태 일관성, 번역 쌍 존재 여부를 확인하며 번역 내용은 열람하지 않습니다.

## 항목 헤더와 본문

기본 마크다운 저장소에서는 독립적으로 재사용할 주제·점검 하나를 상세 문서 하나로 작성하고 다음 YAML 헤더 필드를 둡니다.

| 필드 | 규칙 |
| --- | --- |
| `id` | 프로젝트에서 고유하고 안정적인 ID. 영문자·숫자·점·밑줄·하이픈. 비교는 대소문자를 구분하지 않음. |
| `title` | 구체적인 질문·방법·주제. |
| `summary` | 활용할 요점과 필수 조건을 한두 문장으로 표현. |
| `kind` | 지식: reference, method, convention, lesson. 기록: error, suggestion, hypothesis. |
| `scope` | 프로젝트·구성요소·작품과 적용 경계를 문자열로 표현. |
| `keywords` | 유용한 영문 개념·동의어·정확한 기술 식별자의 비어 있지 않은 목록. |
| `status` | 지식: active, enforced, superseded. 기록: open, resolved, superseded. |
| `checked_at` | 실제 근거 확인일 YYYY-MM-DD, 미확인은 null. 수정 날짜로 자동 채우지 않음. |

선택 필드 `context`는 버전·엔진·형식·장르·시점 등 적용 조건을 문자열이나 문자열 값의 평평한 매핑으로 표현합니다. 버전과 YAML 예약어는 따옴표로 감싸고 무관한 빈 필드는 두지 않습니다. 헤더는 스킬 검색 메타데이터가 아닙니다. 사용자 번역본은 같은 정보를 독자에게 보여 주되 검색용 프런트매터를 복제하지 않습니다.

헤더 예시:

```yaml
---
id: K-FIC-001
title: Check information access in limited viewpoint
summary: Under limited narration, check each claim against the focal character's information access before line polishing.
kind: method
scope: naru-novel; Seorin-limited narration
keywords: [viewpoint, POV, character-knowledge]
status: active
checked_at: null
context:
  viewpoint: third-person limited
---
```

실제 항목이 아닌 형식 예시입니다. 다음 네 개의 비어 있지 않은 H2 절을 둡니다.

- 지식: **Guidance**, **Applicability and exceptions**, **Checks**, **Evidence**.
- 기록: **Expected and observed**, **Cause and resolution**, **Recheck and prevention**, **Evidence**.

유용한 행동은 짧게 적고 예외를 설명합니다. 출처 사실·방법·관례·편집 판단을 구분하고 위치와 검증 맥락을 포함해 원본을 인용합니다. 문제 기록에는 원인 확신도, 수정·제안, 해결·재점검 근거와 예방 링크를 남깁니다. 모르는 원인은 모르는 상태로 둡니다. enforced에는 입증된 방지책이 필요하며 교훈 저장만으로 강제가 입증되지 않습니다.

원래 문제·보고서·테스트·문단·화면·로그를 복사하지 말고 참조합니다. 사소한 동일 원인 발견은 필요에 따라 묶습니다. 프로젝트 사실의 권위는 원래 자료에, 항목 메타데이터의 권위는 상세 문서에 있으며 카탈로그 행은 생성된 표현입니다.

### 문제 검색 필드

새로 작성하거나 정규화한 `records/` 상세 문서는 다음 다섯 필드를 모두 사용합니다. 이는 사건 메타데이터이며 `knowledge/`의 추가 요건이 아닙니다.

| 필드 | 규칙 |
| --- | --- |
| `trigger` | 발생 조건·행동을 짧게 표현. 미확인은 null. 증상이 생기기 전 검색에 사용. |
| `symptom` | 구별 가능한 관찰 증상을 비어 있지 않게 표현. 제안·가설은 미확인 결함을 단정하지 않고 관찰한 우려를 기술. |
| `cause_status` | unknown, suspected, confirmed. Cause and resolution에서 근거 제시. 확인된 결함도 원인은 모를 수 있음. |
| `prevention` | 필수 조건을 포함한 구체적 행동·점검 또는 미확립 시 null. 상세 단계·예외·근거는 Recheck and prevention에 둠. |
| `prevention_status` | none, proposed, verified, invalidated. none이면 prevention은 null, 나머지는 행동이 필요. verified는 실제 checked_at과 본문 입증 근거도 필요. |

유용한 카탈로그 행이 되도록 짧게 쓰며 로그나 모든 예시를 반복하지 않습니다. `keywords`는 동의어·정확한 식별자에 쓰고 모든 문구를 복제하지 않습니다. `summary`는 전체 헤더 복제 대신 발견과 필수 조건을 요약합니다. 적용을 바꾸는 버전·설정·형식 차이는 scope/context로 명시합니다.

문제 기록 예시이며 실제 사건이 아닙니다.

```yaml
---
id: R-FIC-EXAMPLE
title: Inaccessible private decision in limited narration
summary: A focal character asserted a private decision without an information source; revision restored uncertainty.
kind: error
scope: story-alpha; chapter-3
keywords: [viewpoint, POV, information-access, private-thought]
status: resolved
checked_at: null
context:
  canon: revision-B
trigger: Drafting third-person limited narration
symptom: Focal character states another character's private decision without access
cause_status: confirmed
prevention: Trace each private-knowledge assertion to a source available to the focal character
prevention_status: proposed
---
```

resolved는 사건 상태이지 예방 상태가 아닙니다. 정해진 맥락에서 원래 실패나 통제된 동등 사례를 점검이 실제로 탐지한 뒤에만 verified를 사용합니다. 수정된 결과물만으로는 부족합니다. 편집 작업은 자동 강제로 가장하지 않으면서 결함을 탐지한 문서화된 검수를 근거로 사용할 수 있습니다. 수정과 방지책의 확인 날짜·결과를 Recheck and prevention에 따로 남깁니다. checked_at은 최근의 실제 중요한 근거 확인일이며 지어낸 방지책 날짜가 아닙니다. 유효한 헤더와 날짜만으로 실증이 입증되지 않으므로 전문 스킬이 근거를 확인해야 합니다.

기존 네 본문 절을 유지합니다. Expected and observed에는 원래 규약·실제 발견·조건·위치, Cause and resolution에는 진단 확신도·근거·수정·미확인점, Recheck and prevention에는 수정 결과 점검과 미래 방지책의 상태·적용·예외를 구분하여 기록합니다. Evidence는 원래 결과물·버전·보고서를 연결합니다. 제안이나 가설은 기록했다는 이유로 오류가 되지 않습니다.

### 기존 구조화 기록

공통 헤더만 있고 새 다섯 필드가 없는 기록은 계속 읽을 수 있습니다. 도구는 `legacy_record_fields` 경고를 내며 원본은 바꾸지 않고 새 정보는 **unrecorded**로 표시합니다. `--strict`는 이 이전 공백을 오류로 취급합니다. 일부 필드만 추가한 것은 기존 형식 예외가 아니라 오류입니다. 새로 쓰거나 수정하는 기록은 다섯 필드를 모두 써야 합니다. 도구가 과거 편집 여부를 알 수 없으므로 스킬에도 이 작성 규칙이 필요합니다. 정규화는 허용된 유지관리에서만 하며 ID·경로·근거·미확인점을 보존합니다. 제목이나 이전 카탈로그 행에서 값을 추정하지 않습니다.

## 카탈로그 갱신과 검증

[catalog.py](../scripts/catalog.py)는 Python 3.9+와 기존 런타임의 PyYAML을 사용하며 아무것도 설치하지 않습니다. 명령은 OneStep 체크아웃에서 실행합니다. 다른 프로젝트에서는 도구의 절대경로와 작업 프로젝트의 `--project` 값을 사용합니다.

```text
python skills/vegabond-knowledge/scripts/catalog.py build --project . --domain fiction
python skills/vegabond-knowledge/scripts/catalog.py check --project . --domain fiction
```

`--store knowledge`, `--store records`, 기본값 both로 저장소를 선택하고 분야는 `--domain`을 반복합니다. 분야 생략은 프로젝트 전체 중복 ID 검사까지 포함하는 명시적 전체 유지관리입니다. 범위 지정 실행은 선택한 상세 문서와 명시적 관련 항목만 검증합니다. 일반 검색에는 전체 재생성을 하지 않습니다.

도구는 관리 표식 안에 **ID/제목/종류 | 요약 | 범위/맥락 | 검색어 | 상태/확인일 | 상세** 여섯 열을 생성합니다. 문제 행은 요약에 발생 조건·증상, 상태에 원인 확신도·예방 상태·짧은 행동도 표시합니다. 지식 행은 그대로입니다. 해결 사건도 활성 카탈로그에서 검색 가능하게 두고 superseded만 보관으로 보냅니다. 관리 표식 밖의 프로젝트 메모를 보존합니다. 관련 분야는 주 상세 문서 하나를 참조하고 내용을 복제하지 않습니다. 루트 색인은 분야 변경 시 이 스킬이 관리하는 작은 안내 문서로 유지합니다.

저장 순서는 기준 상세 문서와 번역본 작성 → build → `catalogs_written`에 나온 영문 카탈로그의 번역본 재작성 → check입니다. build는 준비 단계이므로 번역·안내 누락은 경고로 두어 영문 카탈로그를 먼저 만듭니다. check는 최신 카탈로그, 유효한 메타데이터·상태, 고유 ID, 필수 절, 로컬 참조, 안내와 번역 쌍을 요구합니다. 중복 YAML 키나 잘못된 구조 헤더는 오류입니다. 메타데이터·참조 오류가 있으면 쓰기 전에 build를 멈춥니다. 카탈로그는 파일별 원자 교체하며 파일 시스템 오류로 일부만 갱신될 수 있으므로 허용 범위에서 재검사·수정합니다. 도구는 기준 상세 문서나 번역본을 쓰지 않습니다.

프로젝트 밖 링크와 일반 절 앵커 정확성은 별도 확인이 필요합니다. 도구는 참조 내용 없이 로컬 파일 대상을 확인하며 번역 의미·최신성이 아니라 존재 여부만 확인합니다. 바뀐 번역본은 영문에서 작성하고 다시 열지 않습니다. 진단은 앞 20개와 전체·오류 수를 출력하므로 더 큰 결과는 분야를 좁혀 조사합니다.

### 이식 가능한 출처 참조

외부 원본의 안정적 식별 정보와 기기 위치는 [출처 목록](../../../knowledge/sources.md)으로 구분합니다. 영문 YAML sources는 SRC-... ID마다 project(소문자 프로젝트 ID), path(슬래시를 쓰는 프로젝트 내부 기준 원본 상대경로), sha256(기존 소문자 해시 또는 null) 세 필드만 둡니다. ID마다 H2 제목을 두어 일반 로컬 마크다운 링크로 연결합니다. 문단·절 위치와 근거 맥락은 참조 항목에 유지합니다. 알려진 해시는 보존하고 누락된 버전이나 과거 확인일을 추정하지 않습니다. 현재 원고로 과거 원고를 인증하지 않습니다.

해시가 기록된 ID는 해당 내용 시점을 식별합니다. 다른 근거 버전에는 새 ID를 주어 기존 과거 인용을 바꾸지 않습니다. 같은 내용의 위치 이동은 가능하면 로컬 루트만 바꿉니다.

루트는 Git에서 제외되는 `knowledge/sources.local.json`에만 둡니다. 예시는 `{"novel0": "D:/Writing/Novel_0"}`이며 기본 위치가 아닙니다. 작업에 명시적으로 설정한 절대 루트만 사용합니다. 설정 커밋, 루트 추정, 무관한 프로젝트 검색이나 원본 전체 복제로 누락 매핑을 고치지 않습니다. 다른 프로젝트도 자체 설정을 Git에서 제외해야 합니다.

현재 주장에 필요한 ID만 [출처 도구](../scripts/sources.py)로 해석합니다.

```text
python skills/vegabond-knowledge/scripts/sources.py resolve --project . --id SRC-NOVEL0-ATTAINMENT
```

선택한 원본을 바이트로 읽어 SHA-256을 비교하므로 허용된 출처 범위에서만 실행합니다. 내용 출력, 번역본 읽기, 설정·항목 쓰기와 관찰 해시 자동 승격을 하지 않습니다. 상위 경로 이탈과 설정 루트 밖으로 해석되는 경로는 거부합니다. 해시 일치는 내용 동일성만 보여 주며 사실·적용 적합성·출처 품질·작가 수락을 입증하지 않습니다. 필요한 주장은 원본의 관련 절도 확인해야 합니다.

종료 코드 0은 matched, 1은 unconfigured·missing·unavailable·mismatch·unversioned, 2는 잘못된 목록·ID·설정·경로입니다. unversioned는 파일을 찾아 해시를 계산했지만 기대 해시가 없다는 뜻입니다. 정보 요약에 상태와 영향을 남깁니다. 필요한 원본에 접근하지 못하거나 동일성이 불확실하면 종속 검증을 차단합니다. 기존 조건부 지침은 독립 작업에 참고할 수 있습니다. 기기별 접근 상태와 사건 해결·예방 상태를 섞지 않습니다.

카탈로그는 ID 등록과 목록 번역본 존재를 검사한 뒤 source_unverified를 냅니다. 로컬 설정·원문은 읽지 않으므로 목록 링크만으로 근거가 검증되지 않습니다. 미등록 ID와 잘못된 목록은 쓰기를 막습니다. 일반 조회에서는 필요한 ID만 해석하고 전체를 훑지 않습니다. 목록과 사용자 번역본을 함께 갱신하되 번역본은 다시 읽지 않습니다. 현재 Novel_0 참조는 이 목록을 사용하며 다른 외부 참조는 기존 경고를 유지합니다.

기존 산문 자료는 계속 사용할 수 있습니다. 기존 행과 조건은 명시적으로 미검증인 Legacy entries 절에 보존하고 색인 없는 파일에는 메타데이터 미확인 안내를 둡니다. ID·날짜·규칙·상태를 추론하지 않습니다. 허용된 유지관리에서 경로·ID·근거를 보존하며 변환하고 재생성합니다. 기본 실행은 경고, strict는 이미 정규화한 범위의 기존 자료를 오류로 취급합니다. 주변에 기존 형식 자료가 있어도 새로 쓰거나 바꾸는 항목은 헤더를 사용합니다. strict는 무관한 모든 기록을 다시 쓸 권한이 아닙니다.

## 저장·통합·승격

저장 전에 미래의 어떤 결정·행동·점검을 돕고 어떤 조건에 적용되는지 확인합니다. 재사용은 같은 조건의 다른 작업에 유용하다는 뜻이며 보편적 진리를 뜻하지 않습니다. 가장 작은 유용한 목적지를 고릅니다.

- 지식: 활용 원리·방법, 이유, 점검과 예외를 기술합니다. 제목·요약은 프로젝트 연대기보다 재사용할 질문·행동을 중심으로 합니다.
- 문제 기록: 발생 조건·증상·원인 확신도·수정·재점검을 구별할 최소 근거를 둡니다. 공통 절차를 복제하지 않고 지식 항목을 연결합니다.
- 기존 원본·작업 이력: 고유 프로젝트 사실, 설정, 작가 취향과 일회성 진행은 권위 있는 원본에 둡니다. 반복 조회에 이득이 있을 때만 전체 명세 복제 없이 범위별 참고·관례를 추가합니다. 재사용·추적 가치가 없으면 작업 보고에 남기며 후속 추적이 필요한 미해결 문제는 기록합니다.

같은 원리·질문·원인을 먼저 검색합니다. 프로젝트별 복제보다 기존 항목의 조건·예외·근거·재발을 갱신합니다. 지식 하나에서 여러 사건을 연결할 수 있습니다. 같은 증상만으로 합치지 말고 원인·발생 조건이 같은 예방을 뒷받침할 때 통합합니다. 불확실한 일치는 진단을 합치지 않고 연결합니다. 중요한 불일치를 유지하고 최신이라는 이유만으로 이전 버전을 덮어쓰지 않습니다. 문제에서 예방으로, 교훈에서 원래 근거로 이어지는 연결을 보존합니다.

일반화해도 근거 경계를 지우지 않습니다. 버전·수명·장르·시점·독자 등 핵심 조건은 scope/context·본문·출처에 유지합니다. 재현·검색 식별자는 보존하고 부수적 이름·긴 로그는 재사용 지침에서 제외합니다. 실제 확인 조건과 원리에서 추론한 넓은 적용을 구분하며 미검증 범위를 명시합니다. 한 성공 사례로 다른 환경 검증을 주장하지 않습니다. 설정·취향을 보편화하거나 문구 일반화만으로 제안 방지책을 승격하지 않습니다. 일반화는 프로젝트 간 이동 권한이나 shared 분류를 자동 부여하지 않습니다. 기존 스키마·저장소를 사용합니다.

재발 이력은 발생일 또는 미확인, 위치·버전, 근거 링크, 수정·재점검 결과와 기존 방지책 결과로 짧게 유지합니다. 미실행, 실행했지만 불충분, 조건 변화로 무효화를 구분하고 모르는 결과를 지어내지 않습니다. 반대 근거가 예방 주장을 무효화하면 invalidated로 바꾸고 이전 입증 맥락을 보존하며 대안을 조사합니다. 점검 누락만으로 점검이 반증되지는 않습니다. 조건이 달라 다른 해결이 필요하면 별도 사건으로 둡니다. 긴 로그는 원래 위치에 유지합니다.

확인되고 중요한 교훈만 반복·예상 재사용·유용한 방지책의 필요에 따라 승격합니다. 사건은 records, 정제된 재사용 내용은 knowledge에 두고 서술 복제 대신 상호 링크합니다. 전문 스킬이 진단과 분야별 점검을 제공하며 이 스킬은 정리만 하고 원인 해결이나 결과물을 임의 인증하지 않습니다.

반복 방지는 구조·타입·검증·린트·회귀 점검을 우선합니다. 원래 실패나 통제된 동등 사례를 탐지한 근거를 보존합니다. 판단이 필요한 작업은 구체적인 조건부 검수와 이유를 기록합니다. 항목 저장만으로 예방이 입증되지 않습니다.

## 출처를 보존하는 퇴역

일상 사용 중 중복을 합치고 낡은 적용 조건을 고칩니다. 대체할 항목은 기준 상태와 이유·대안을 기록합니다. 재생성하면 도구가 행을 분야 archive.md로 옮기며 필요할 때만 파일을 만듭니다. 재활성화하면 돌아옵니다. 상세 경로·근거를 안정적으로 유지하고 생성 행을 직접 편집하지 않습니다. 기존 외부 체계는 자체 보관 방식을 사용합니다. 오래되었다는 이유만으로 유용한 지식이 무효화되지는 않습니다.

원본·버전·설정·방지책 변경 시 영향받는 항목을 재확인합니다. 기존 정보 요약이 무효화되면 갱신합니다. 제한 검색에서 무관한 결과가 반복되면 실제 영역별로 해당 분야 색인을 나누고 작은 안내 색인을 유지합니다. 관찰된 검색 불편이 있을 때만 구조를 확장하며 작업마다 전체 이력을 다시 읽지 않습니다.

## 첫 카탈로그 생성

새 저장소·분야에서는 유효한 상세 문서와 사용자 번역본을 분야 폴더에 쓰고 루트 안내와 번역본을 작성·갱신합니다. 이번 build가 만들 분야 카탈로그를 미리 링크해도 되며 색인 빈 파일이나 특별 초기화 명령은 필요하지 않습니다. 일반 build·번역·check 순서를 따릅니다. 모든 출력 계획을 정한 뒤 로컬 존재를 검사하므로 이번 계획에 속한 누락 카탈로그만 허용됩니다. 다른 누락 파일이나 선택하지 않은 누락 카탈로그는 쓰기를 막습니다. check는 읽기 전용이며 첫 실행에도 카탈로그가 존재해야 합니다.
