# 검색과 취합

검색 옵션, 관련 기록, 여러 출처의 정보 요약, 검색 평가에 사용합니다. Markdown 상세 문서가 정본이며 목록과 삭제 가능한 검색 캐시는 파생물입니다. 기존 목록 도구의 Python/PyYAML 실행 환경을 쓰며 외부 서비스는 필요하지 않습니다.

## 구체적인 질문 검색

도구의 설치 경로로 실행하며 `--project`는 실제 작업 저장소를 지정합니다.

```text
python skills/vegabond-knowledge/scripts/search.py search --project . --query "메모리 풀링" --domain code --limit 3
python skills/vegabond-knowledge/scripts/search.py search --project . --query "callback shutdown" --store records
python skills/vegabond-knowledge/scripts/search.py search --project . --query "ownership" --context "engine=UE 5.8"
```

기본값은 지식과 문제 기록을 함께 검색합니다. 해결된 사건은 포함하고 폐기된 기본 검색 결과는 제외합니다. `--domain`·`--status`를 반복하면 대안을 선택합니다. `--status superseded`를 명시하면 폐기된 상태도 포함합니다. `--scope`는 범위 부분 문자열을 선택합니다. `--context key=value`는 기존 키의 값을 대소문자 구분 없이 정확히 비교하며 호환성을 판정하지 않습니다. 키가 없으면 적용 가능성 미확인 주의사항과 함께 유지합니다. 실제 메타데이터 값을 사용해야 하며 설명 문구가 다르다는 사실만으로 의미상 비호환이 입증되지는 않습니다.

도구는 [search_terms.json](../scripts/search_terms.json)의 관리되는 한영 표현을 확장하고 메타데이터와 영문 본문 전체를 검색합니다. 식별자·제목·검색어·발생 조건·증상·질문 포함 정도가 순위에 반영됩니다. 반복과 최신 날짜가 권위를 만들지는 않습니다. 점수는 어휘 기반 휴리스틱이며 진실이나 적용 가능성을 뜻하지 않습니다. 알려진 한국어 표현은 부분 문자열로 조사를 허용하지만 일반 번역·의미 검색은 제공하지 않습니다. 실제 누락을 확인한 뒤 표현을 추가합니다.

짧은 결과에는 ID·요약·범위·상태·경로·해시·일치 필드와 표현·질문 포함 정도·실제 줄 번호가 있는 제한된 발췌가 표시됩니다. 메타데이터만 일치하면 헤더를 가리킵니다. 중요한 조언을 적용하기 전에 유용한 절과 원본 근거를 읽습니다. `total_matches`·`truncated`로 잘린 후보를 확인하고 질문·필터·개수 제한을 조정합니다. 빈 결과는 해당 조건에서 어휘 일치가 없다는 뜻이며 정보의 부재를 입증하지 않습니다.

## 의미 있는 관계 따라가기

관계 페이지는 반환한 후보와 연결된 탐색 관계를 유지하며 반대쪽 ID가 다른 페이지에 있어도 표시합니다. 페이지 경계를 넘어 충돌·선행 관계의 종류가 사라지지 않습니다. 필요하면 다른 페이지의 대상 ID를 직접 조회합니다.

결과 제한 뒤쪽은 `--offset N`으로 기본 검색이나 `related` 결과를 이어 조회합니다. 개수 제한은 1~100이며 필요한 후보를 확인할 때까지 진행합니다. 기본 검색에 자동 첨부되는 관계 결과는 기본 검색의 offset과 별개로 0부터 시작합니다. 추가 관계는 특정 ID의 `related` 결과를 이어 조회합니다.

정본 YAML의 선택 필드 `relations`에서 다음 관계를 실제 기존 ID의 비어 있지 않은 목록으로 선언할 수 있습니다.

| 종류 | 의미 |
| --- | --- |
| `requires` | 대상에 필수 선행 개념이나 계약이 있습니다. |
| `derived_from` | 대상이 원래 근거를 제공하며 독립적인 추가 입증은 아닙니다. |
| `prevention` | 문제 기록에서 예방 지식을 연결합니다. 예방 상태를 승격시키지 않습니다. |
| `supersedes` | 명시 범위에서 원본 항목이 대상을 대체합니다. 과거 문서를 보존하고 상태를 적절히 설정합니다. |
| `conflicts_with` | 실제 조건을 비교해 주장들을 조정해야 합니다. 어느 쪽도 자동으로 우선하지 않습니다. |

```yaml
relations:
  requires: [K-EXAMPLE-PREREQUISITE]
  derived_from: [R-EXAMPLE-EVIDENCE]
```

목록 도구는 형식과 대상 ID를 검증하며, 일부 분야만 처리해도 명시된 다른 저장소의 대상을 확인합니다. 검색은 폐기된 후보를 포함해 분야·저장소 사이의 들어오는 관계와 나가는 관계를 모두 따릅니다. 방문 ID를 기록해 순환을 종료합니다. 관계는 편집자가 선언한 주장이지 단어 유사성으로 추정한 연관성이 아닙니다. 필요한 본문 링크도 계속 따릅니다.

```text
python skills/vegabond-knowledge/scripts/search.py related --project . --id K-CODE-CONCURRENCY-LIFETIMES --depth 2 --limit 10
```

기본 검색은 한 단계 관계 결과를 별도로 추가하며 `--depth 0`으로 끕니다. 한 번에 최대 깊이는 3이고 출력 제한으로 잘리면 명시합니다. 관련 후보는 기본 질문의 필터나 적용 가능성을 물려받지 않으므로 범위·상태를 확인합니다. 의존 결정을 하기 전에 잘린 충돌·대체 자료를 조회합니다. 출력 제한은 반대 근거를 생략할 이유가 아닙니다. 필요한 연결은 개별 ID로 계속 조회합니다.

## 정보 요약 취합과 검사

질문 범위를 확정하기 전과 중요한 결과를 적용하기 전에 [필요한 정보의 공통 판단](../../vegabond-scout/references/information-needs.kr.md)을 적용합니다. 질문의 충분성과 채택 판단은 공통 절차가, 해당 질문의 근거를 찾고 취합하는 방법은 이 문서가 담당합니다.

1. 큰 요청은 답할 수 있는 하위 질문으로 나누고 필요한 맥락·근거를 기존 작업 요약에 남깁니다.
2. 관련 저장소에서 질문별로 검색합니다. 소수 상세 문서부터 시작하되 미답 질문·선행 조건·충돌·대체·실패에 따라 확장합니다. 최초 3개는 완료 한도가 아닙니다.
3. 중요한 주장·행동마다 항목 ID와 구간·줄, 원본 근거, 적용 조건, 점검을 연결합니다. 원인·호환성의 불확실성, 저자 선택과 연구 한계를 유지하고 제안 점검과 검증된 예방책을 구분합니다.
4. 파생 요약을 독립 출처로 중복 계산하지 않습니다. 충돌 주장과 해결할 조건을 기록합니다. 대체는 문서에 명시된 범위에서만 유효합니다.
5. 각 질문을 답변됨·조건부·충돌·누락으로 마감하고 추가 조회 필요성을 설명합니다. 상위 결과만 읽었다는 이유로 완료하지 않습니다.

전역 사용 장부 대신 기존 정보 요약을 사용합니다. 여러 질문에는 `질문 | 답변·행동 | ID·근거 | 조건·충돌 | 점검·공백` 표면 충분합니다. 로컬 항목 해시는 조회한 바이트를 식별하며 외부 출처의 진실이나 내용 동일성을 입증하지 않습니다. 필요하면 기존 출처 등록 절차를 사용합니다.

저장 전에는 제안할 질문·동의어·근본 원인을 두 저장소에서 검색하고 기존 후보와 관계를 검토합니다. 같은 답에 근거·예외가 추가되면 기존 항목을 보완하고 조건·원인이 다른 사건은 분리합니다. 유사성만으로 자동 병합하지 않습니다. [저장 절차](storage.kr.md)에 따라 검증하고 영향을 받는 목록과 번역을 갱신합니다.

## 삭제 가능한 색인과 최신성

작업 프로젝트의 `.cache/onestep/search-v1.json`은 이 저장소에서 Git에 포함되지 않습니다. 정본 텍스트와 해시를 담으며 번역·생성 행·외부 원본을 담지 않습니다. 커밋하지 않습니다. 경로·크기·수정 시간이 달라지면 다시 읽고 검증하며 삭제된 파일은 제거합니다. 그대로인 정본은 다시 열지 않고 재사용합니다. 구현·스키마 변경은 캐시를 무효화합니다. 원자적 교체로 부분 JSON을 방지합니다. 동시 검색이 서로의 파생 스냅샷을 교체할 수 있으며 다음 호출에서 갱신합니다.

크기와 수정 시간을 보존하는 외부 작업 뒤 또는 스냅샷이 의심되면 `--refresh`로 모든 정본을 다시 읽고 해시를 확인합니다. 외부 원본까지 재확인하지는 않습니다. 손상된 캐시는 재생성합니다. 잘못된 정본 메타데이터·중복 ID·미해결 선언 관계는 부분 성공 대신 명시적인 오류를 반환합니다. 캐시 저장을 사용할 수 없어도 경고와 함께 정본 검색 결과를 반환할 수 있습니다. 엄격한 읽기 전용 작업은 `--no-cache`로 정본을 직접 읽으며 아무 파일도 쓰지 않습니다.

질문마다 색인 텍스트를 메모리에서 순회합니다. 역색인이나 벡터 색인은 아닙니다. 실제 증가 규모를 측정한 뒤 다른 엔진의 필요성을 판단합니다. 시간과 고정 질문 결과는 미래의 모든 질문에 대한 재현율을 입증하지 않습니다.

## 검색 유용성 평가

```text
python skills/vegabond-knowledge/scripts/search.py evaluate --project . --cases skills/vegabond-knowledge/tests/retrieval_cases.json
python -m unittest discover -s skills/vegabond-knowledge/tests
```

버전 관리되는 사례에 실제 질문·필터·필수 ID·금지 ID·출력 제한을 선언합니다. 평가는 제한 내 필수 ID 재현율, 금지 결과, 반환 ID, 발췌 글자 수와 시간을 보고하고 실패 시 0이 아닌 종료 코드를 반환합니다. 판단 집합은 불완전하며 금지 결과 확인이 전체 정밀도는 아닙니다. 의미 있는 누락·오탐·언어 문제·비호환 맥락·충돌 누락 뒤 사례를 추가합니다. 순위 구현에 맞추려고 기대 결과를 바꾸지 않습니다.

단위·CLI 검사는 본문 전용 일치, 해결·폐기 상태, 알려진·미확인 맥락, 양방향·교차 저장소 관계, 순환·잘림, 잘못된 자료, 캐시 갱신·삭제, 번역 제외와 읽기 전용 사용을 확인합니다. 가상 규모 검사는 1,000개 항목의 초기·반복 실행에서 검색·출력 제한·반복 시 정본 재읽기 0건을 확인합니다. 측정 환경과 한계를 작업 근거에 남깁니다. 저장 구조 검사와 검색 품질 평가는 별개의 수용 검사입니다.
