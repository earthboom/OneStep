# 검색과 종합

검색 옵션, 관련 기록, 여러 출처를 엮은 요약과 검색 평가에 사용합니다. 마크다운 상세 문서가 기준이며 카탈로그와 폐기 가능한 캐시는 파생 자료입니다. 기존 Python·PyYAML 런타임을 사용하고 외부 서비스는 필요하지 않습니다.

## 구체적인 질문 검색

설치된 도구 경로로 실행하고 project는 실제 작업 저장소를 지정합니다.

```text
python skills/vegabond-knowledge/scripts/search.py search --project . --query "메모리 풀링" --domain code --limit 3
python skills/vegabond-knowledge/scripts/search.py search --project . --query "callback shutdown" --store records
python skills/vegabond-knowledge/scripts/search.py search --project . --query "ownership" --context "engine=UE 5.8"
```

기본값은 두 저장소와 해결된 사건을 검색하고 대체된 항목은 주요 결과에서 제외합니다. domain·status는 반복 지정하며 status superseded로 대체 항목을 명시적으로 포함할 수 있습니다. scope는 부분 문자열로 선택합니다. context key=value는 기존 키의 값을 대소문자 무관하게 정확히 비교하는 필터이며 호환성 판단기가 아닙니다. 키가 없으면 적용 미확인 유보와 함께 남깁니다. 실제 메타데이터 값을 사용하고 설명이 다르다는 이유만으로 의미상 비호환을 확정하지 않습니다.

[검색어 파일](../scripts/search_terms.json)의 관리된 한국어·영어 별칭을 확장한 뒤 메타데이터와 영문 본문을 검색합니다. 식별자, 제목·검색어, 발생 조건·증상과 질문 충족 범위가 순위에 기여합니다. 반복·최신성은 권위를 만들지 않으며 점수는 어휘적 휴리스틱입니다. 알려진 한국어 별칭 부분 문자열은 조사를 허용하지만 일반 번역·의미 검색은 제공하지 않습니다. 별칭은 실제 누락을 본 뒤 추가합니다.

간결한 결과는 ID·요약·범위·상태·경로·해시·일치 필드/용어·충족 범위와 1부터 시작하는 줄 위치의 제한된 발췌를 보여 줍니다. 메타데이터만 맞으면 헤더임을 표시합니다. 중요한 조언은 관련 절과 원래 근거를 읽고 적용합니다. total_matches와 truncated로 생략 후보를 확인하고 질문·필터·한도를 조정합니다. 빈 결과는 해당 조건의 어휘 일치 부재이지 지식 부재의 증거가 아닙니다.

offset N으로 주요 검색·related의 다음 페이지를 조회합니다. 한도는 1~100이고 관련 후보를 확인할 때까지 이어갑니다. 자동 관계 페이지는 주요 offset과 별도로 0에서 시작하며 더 많은 관계는 특정 ID에 related를 사용합니다. 반환 후보에 닿는 탐색 간선은 반대쪽 ID가 다른 페이지에 있어도 남겨 충돌·전제 관계를 유지합니다. 필요한 외부 페이지 끝점은 ID로 조회합니다.

## 원본 출처 상태

주요·관련 결과의 evidence_notice는 checked_at이 기록된 근거 날짜이고 sha256이 로컬 항목의 식별값임을 명시합니다. 원본을 새로 확인한 값이 아닙니다. 내부 출처 목록의 실제 링크에는 source_checks가 출처 ID별 access_status와 identity_status를 구분합니다. 일반 검색은 위치 없는 이력에 unbound, 아직 확인하지 않은 연결에 not_checked를 표시하고 유보를 붙입니다. 원문·기기 설정은 열지 않고 목록 메타데이터만 읽습니다. 다른 근거 링크는 별도로 검토합니다.

원본 동일성이 필요하고 접근이 허용되면 반환 페이지가 연결한 등록 ID를 명시적으로 확인합니다.

```text
python <search-helper-path> search --project <working-project> --query "bandaging occupied hands" --domain fiction --verify-sources --source-root <project-ID>=<authorized-absolute-path> --no-cache
```

자리표시자는 기본 위치가 아닙니다. 실제 소비 프로젝트에서 확인된 작업 경로나 알려진 프로젝트 메타데이터를 재사용한 뒤 필요한 루트를 묻습니다. OneStep에는 외부 연결을 만들지 않으며 unbound는 루트 설정을 요구하지 않습니다. 서로 다른 프로젝트에는 source-root를 반복할 수 있으며 verify-sources가 필요하고 이번 호출에만 적용됩니다. 해당 프로젝트의 영구 설정보다 우선하며 설정을 쓰지 않습니다. 반환된 주요·관련 결과에 연결된 ID만 중복 제거해 확인합니다. 빠진 후보를 조회하거나 [출처 도구](storage.md#portable-source-references)로 추가 ID를 해석합니다. 전체 근거나 웹 자동 검증이 아닙니다.

source_verification에는 요청 모드, ID, 완료 결과, 실제 읽은 파일 수와 상태 수를 표시합니다. 필요한 근거와 ID를 대조합니다. retrieval_ok가 참이어도 원본 확인은 미완료일 수 있습니다. 종료 코드 0은 검색과 요청된 등록 출처 확인의 일치, 1은 unbound·unconfigured·missing·unavailable·unversioned·mismatch로 미완료, 2는 잘못된 입력·목록·설정·ID입니다. 등록 ID가 없으면 검증 ok는 null이며 전체 근거 확인의 증거가 아닙니다. 일반 검색은 미확인·연결 없는 이력과 함께 0으로 끝날 수 있으므로 유보를 유지합니다.

available은 바이트를 읽었다는 뜻이고 unversioned는 기대 해시가 없다는 뜻입니다. 현재 읽기는 범위 내 현재 주장을 뒷받침할 수 있지만 과거 내용 시점을 확정하지 못합니다. 해시 일치는 내용 동일성만 보여 주므로 의미·권위·적용 조건도 확인합니다. 검색은 과거 날짜·기대 해시·항목·설정을 바꾸지 않습니다. 원본 상태는 캐시하지 않고 명시적 확인마다 새로 계산합니다.

## 의미 있는 관계 탐색

기준 YAML의 선택 relations는 다음 종류를 실제 ID의 비어 있지 않은 목록에 연결합니다.

| 종류 | 의미 |
| --- | --- |
| requires | 필수 전제·규약을 제공함. |
| derived_from | 원래 근거를 제공하며 독립적 추가 입증은 아님. |
| prevention | 문제에서 예방 지식으로 연결하며 예방 상태는 바뀌지 않음. |
| supersedes | 명시된 범위에서 대체하며 과거 문서·적절한 상태를 유지함. |
| conflicts_with | 조건에 따라 주장을 조정하며 어느 쪽도 자동 승리하지 않음. |

```yaml
relations:
  requires: [K-EXAMPLE-PREREQUISITE]
  derived_from: [R-EXAMPLE-EVIDENCE]
```

카탈로그는 형식과 ID, 범위 지정 실행의 명시적 다른 저장소 대상도 확인합니다. 검색은 저장소·분야를 넘어 선언된 양방향 관계와 대체 항목을 탐색하고 방문 ID로 순환을 끝냅니다. 이는 편집상 주장이지 추론된 연관이 아니며 필요한 본문 링크도 따릅니다.

```text
python skills/vegabond-knowledge/scripts/search.py related --project . --id K-CODE-CONCURRENCY-LIFETIMES --depth 2 --limit 10
```

검색은 기본적으로 별도의 한 단계 관계 결과를 붙이고 depth 0으로 끕니다. 호출당 최대 깊이는 3입니다. 제한과 잘림을 보고하며 관련 후보는 주요 필터·적용 조건을 상속하지 않습니다. 사용 전에 각 후보를 확인합니다.

## 정보 요약 구성과 점검

질문을 확정하기 전과 중요한 결과 적용 전에 [정보 필요 판단](../../vegabond-scout/references/information-needs.md)을 사용합니다. 그 문서가 질문의 완전성과 채택 판단을, 이 문서가 질문별 근거 검색·조립을 담당합니다.

1. 넓은 요청을 답할 질문으로 나누고 기존 요약에 필요한 맥락·근거를 기록합니다.
2. 질문마다 관련 저장소를 검색합니다. 몇 개 상세 문서로 시작하고 미답·전제·충돌·대체·실패에 따라 확장합니다. 최초 세 문서는 완료 한도가 아닙니다.
3. 주요 주장·행동 → ID·유용한 절/줄 → 원래 근거 → 적용 조건 → 점검을 연결합니다. 원인·호환성 불확실성, 작가 선택과 조사 한계를 보존하고 제안 점검과 입증된 방지책을 구분합니다.
4. 파생 요약을 독립 근거로 중복 계산하지 않고 겹침을 조정합니다. 충돌 주장과 해소 조건을 기록하고 대체는 문서화된 범위에만 적용합니다.
5. 모든 질문을 답변됨·조건부·충돌·누락으로 마무리합니다. 상위 결과를 읽었다는 이유로 완료하지 말고 추가 필요를 설명합니다.

기존 요약을 사용하고 전역 사용 장부를 만들지 않습니다. 여러 질문은 질문·답/행동·ID/근거·조건/충돌·점검/공백 표면 충분합니다. 로컬 해시는 참조한 바이트를 식별하며 외부 사실·동일성을 인증하지 않습니다. 필요한 경우 기존 출처 목록을 사용합니다. 저장 전 질문·동의어·원인을 두 저장소에서 검색하여 가까운 후보·관계를 확인합니다. 새 근거·예외는 기존 답에 추가하고 조건·원인이 다르면 사건을 분리합니다. 유사성으로 자동 병합하지 않으며 [저장 절차](storage.md)에 따라 검사·재생성·번역합니다.

## 폐기 가능한 색인과 최신성

작업 프로젝트의 .cache/onestep/search-v1.json은 Git에서 제외되는 캐시이며 영문 기준 텍스트·해시만 담습니다. 번역·생성 행·외부 원문은 담지 않고 커밋하지 않습니다. 경로·크기·수정 시각 변경 시 재독해·검증하고 삭제 파일을 제거합니다. 불변 문서는 다시 열지 않습니다. 구현·스키마 변경은 캐시를 무효화합니다. 원자 교체로 부분 JSON을 피하지만 동시 검색은 캐시를 서로 바꿀 수 있어 다음 호출에서 갱신합니다.

크기·수정 시각을 유지한 변경이나 의심스러운 상태에는 refresh로 전체 기준 문서를 다시 읽고 해시합니다. 외부 원문은 확인하지 않습니다. 손상된 JSON은 재생성합니다. 잘못된 메타데이터·중복 ID·미해결 관계는 부분 성공이 아니라 오류입니다. 캐시를 쓸 수 없으면 경고와 기준 문서 결과를 반환합니다. no-cache는 아무것도 쓰지 않고 기준 문서를 직접 읽습니다.

질의마다 색인된 텍스트를 메모리에서 훑으며 역색인·벡터 색인은 아닙니다. 다른 엔진을 도입하기 전에 대표 규모를 측정합니다. 시간·시험 결과가 모든 미래 검색의 재현율을 입증하지는 않습니다.

## 검색 효용 평가

```text
python skills/vegabond-knowledge/scripts/search.py evaluate --project . --cases skills/vegabond-knowledge/tests/retrieval_cases.json
python -m unittest discover -s skills/vegabond-knowledge/tests
```

버전 관리 사례에는 실제적인 질문, 필터, 필수·금지 ID와 한도를 둡니다. 평가는 한도 내 필수 ID 재현율, 금지 결과, 반환 ID, 발췌 문자 수와 시간을 보고하고 실패 시 0이 아닌 코드로 끝납니다. 금지 결과 검사는 일반 정밀도를 입증하지 않습니다. 실제 누락·잘못된 일치·언어 실패·호환되지 않는 맥락·빠진 충돌에 따라 사례를 확장하고 순위에 맞추려고 기대를 바꾸지 않습니다.

단위·CLI 검사는 본문 일치, 해결·대체 상태, 알려진/미확인 맥락, 양방향·교차 저장소 관계, 순환·잘림, 오류 자료, 캐시 갱신·삭제, 번역 제외와 읽기 전용 사용을 확인합니다. 합성 규모 검사는 1,000항목의 초기·재사용 실행, 제한 출력과 재사용 시 재독해 0을 확인합니다. 환경·한계를 근거에 남기고 저장 검증과 검색 평가를 구분합니다.

## 한국어 질문 확장과 후보 다양성

[검색어 파일](../scripts/search_terms.json)의 concepts는 관찰된 조각 조합을 요구합니다. 코드 안의 값과 박아 넣는 행동, 구현 세부와 은닉, 미스터리·독자·근거와 공개 행동 같은 조합입니다. 단어 경계에서 시작하고 한국어 접미 형태를 허용합니다. 숫자·출처·독자 같은 일반 단어 하나로 개념을 정하지 않으며 resource 안의 source를 원문 개념으로 해석하지 않습니다. inferred_concepts는 맞은 조건을 보고하는 질문 보조이지 의도 확정이 아닙니다. 원래 질문과 결과 근거를 확인하고 실제 누락·오확장 뒤 긍정 변형과 가까운 부정 사례를 함께 추가합니다. 일반 한국어 이해가 아닌 제한된 어휘 확장입니다.

기본 검색은 동일 본문의 반복 사본보다 서로 다른 본문에 먼저 기회를 줍니다. 더 적은 용어에 맞은 다른 답도 포함하며 각 후보의 점수·충족 범위를 보존합니다. 순서 조정 후 점수·충족 범위가 단조 감소할 필요는 없습니다. 원시 순위 일부를 다양성과 바꾸는 것이며 의미적 확신은 아닙니다. 파서의 줄바꿈 정규화만 거친 정확한 동일 본문에 적용하고 대소문자·공백·코드는 추가 정규화하지 않습니다. 저장소·분야·종류·상태·근거일·원인/예방·선언 관계·맥락 유보 유형이 다르면 다른 그룹입니다. 필터 밖의 유입 관계를 포함해 충돌·대체 양 끝은 분리합니다.

이 정렬은 기록을 합치거나 증거의 상호 대체를 인증하지 않습니다. 동일 본문도 범위·맥락이 다를 수 있습니다. 결과의 similar_content는 다른 일치 수·표본 ID·잘림을 제한적으로 표시합니다. 버전·프로젝트·권위에 민감하면 관련 변형을 확인하고 표본 ID를 정확한 ID로 검색해 기준 절을 엽니다. total_matches는 모든 결과를 세고 offset으로 전체에 접근합니다. diversity 요약은 대상 그룹·변형 수이지 의미적 고유성·완전성이 아닙니다.

all-variants로 원시 어휘 순서를 보존하여 변형을 조사할 수 있습니다. 검색에만 적용하며 관계는 모든 ID를 탐색합니다. 비슷해 보여도 본문 다른 곳이 다르면 묶지 않습니다. 파일·과거 날짜·출처 해시는 바꾸지 않으며 반환 페이지에만 300자 이내 실제 위치 발췌를 만듭니다. 용량 판단에는 [규모 예산·측정·이전 기준](search-scale.md)을 사용합니다. 1,000항목 테스트 통과는 자연어 검색·혼합 출처 판단·수만 파일 성능의 증거가 아닙니다.
