# 조회와 취합

검색 옵션, 관련 기록, 여러 출처의 요약과 검색 평가에 사용한다. Markdown 상세가 정본이며 카탈로그와 버릴 수 있는 캐시는 투영이다. 기존 카탈로그용 Python·PyYAML 환경을 사용하고 외부 서비스는 필요 없다.

## 구체적인 질문 검색

설치된 도구 경로로 실행하며 `--project`는 작업 저장소다.

```text
python skills/vegabond-knowledge/scripts/search.py search --project . --query "메모리 풀링" --domain code --limit 3
python skills/vegabond-knowledge/scripts/search.py search --project . --query "callback shutdown" --store records
python skills/vegabond-knowledge/scripts/search.py search --project . --query "ownership" --context "engine=UE 5.8"
```

기본값은 해결된 사건을 포함하여 두 저장소를 검색하고 대체된 항목은 주 결과에서 제외한다. `--domain`·`--status`는 반복할 수 있다. `--status superseded`로 대체 상태를 포함한다. `--scope`는 부분 문자열이고 `--context key=value`는 기존 키의 대소문자 무시 정확 일치다. 호환성 판단기는 아니다. 키가 없으면 적용성 미상 주의사항과 함께 유지한다. 실제 메타데이터 값을 사용하고 다른 표현만으로 의미상 불일치를 단정하지 않는다.

[search_terms.json](../scripts/search_terms.json)의 관리되는 한영 별칭을 확장하고 메타데이터와 영어 본문을 검색한다. ID·제목·키워드·발생 조건·증상·질의 coverage가 순위에 기여한다. 반복·최신 날짜는 권위를 만들지 않는다. 점수는 어휘 기반이며 진위·적용성을 보장하지 않는다. 알려진 한국어 별칭은 조사 결합을 허용하지만 일반 번역·의미 검색은 제공하지 않는다. 확인된 누락 뒤 별칭을 보완하고 모든 어휘를 미리 수집하지 않는다.

결과는 ID·요약·범위·상태·경로·해시·일치 필드와 용어·coverage·한정 발췌 및 1부터 시작하는 행 위치를 제공한다. 메타데이터 일치는 헤더 위치다. 중요한 적용 전 해당 절과 원본을 읽는다. `total_matches`·`truncated`는 생략 후보를 드러낸다. 필요하면 질의·필터·한도를 바꾼다. 무일치는 필터 아래의 어휘 무일치이며 부재 증명이 아니다.

주 검색이나 related 결과는 `--offset N`으로 페이지를 이동한다. 한도는 1~100이며 필요한 후보까지 확인한다. 검색의 자동 관계 페이지는 주 offset과 독립적으로 0에서 시작한다. 추가 관계는 특정 ID로 related를 호출한다.

관계 페이지는 다른 끝 ID가 다른 페이지에 있어도 반환 후보와 접한 탐색 간선을 유지한다. 페이지 경계의 충돌·선행 관계를 보존하며 필요한 다른 끝을 ID로 조회한다.

## 원본 출처 상태

각 주 결과와 관련 결과는 `evidence_notice`를 제공한다. `checked_at`은 기록된 근거 확인일이며 `sha256`은 로컬 항목의 해시이지 최신 원본 검사가 아니다. 내부 등록부를 향한 실제 링크는 `source_checks`에 출처별 `access_status`와 `identity_status`를 나누어 표시한다. 기본 검색은 등록부 메타데이터만 읽고 외부 원본·기계 루트 설정은 열지 않으며 `not_checked`와 주의사항을 붙인다. 그 밖의 근거 링크도 적절한 검토가 필요하다.

원본 동일성이 중요하고 접근이 허용됐으면 반환 페이지에 연결된 등록 출처를 명시 검증한다.

```text
python skills/vegabond-knowledge/scripts/search.py search --project . --query "bandaging occupied hands" --domain fiction --verify-sources --source-root novel0=C:/Projects/Novel_0 --no-cache
```

위 루트는 예시이지 기본값이 아니다. 확인된 작업 경로나 알려진 프로젝트 메타데이터를 재사용하고 없을 때 필요한 루트를 묻는다. 다른 프로젝트는 `--source-root project=absolute-path`를 반복한다. `--verify-sources`가 필요하며 이번 호출에만 적용하고 해당 프로젝트의 영구 매핑보다 우선하지만 설정을 쓰지 않는다. 반환된 주·관련 결과의 등록 ID만 호출 내 중복 제거하여 검증한다. 생략 후보를 조회하거나 추가 필요 ID는 [출처 도구](storage.md#portable-source-references)로 명시 확인한다. 전체 근거나 웹을 자동 검증하지 않는다.

`source_verification`은 요청 모드, ID, 완료 결과 수, 실제 읽은 파일 수와 상태 개수를 반환한다. 결정에 필요한 근거와 ID를 대조한다. 원본 검증이 미완료여도 `retrieval_ok`는 true일 수 있다. 종료 0은 조회 성공 및 요청한 등록 검사가 모두 일치함, 1은 요청 검사의 미완료(`unconfigured`·`missing`·`unavailable`·`unversioned`·`mismatch`), 2는 잘못된 입력·등록부·설정·ID다. 등록 ID가 없으면 검증 `ok`는 null이며 모든 근거를 확인했다는 뜻이 아니다. 기본 조회는 not_checked여도 0으로 끝날 수 있으므로 주의사항을 유지한다.

접근 `available`은 바이트를 읽었음을, 동일성 `unversioned`는 기대 해시가 없음을 뜻한다. 현재 읽기는 범위 안의 현재 주장을 뒷받침할 수 있지만 과거 판본을 확정하지 못한다. 해시 일치는 내용 동일성만 증명하므로 의미·권한·적용성을 직접 확인한다. 어느 모드도 과거 날짜·기대 해시·항목·설정을 갱신하지 않는다. 원본 검사 결과는 캐시하지 않고 정본 검색 캐시가 재사용되어도 명시 검증 때마다 새로 확인한다.

## 의미 있는 관계 탐색

정본 YAML의 선택 `relations`는 다음 유형을 실제 항목 ID의 비어 있지 않은 목록에 연결한다.

| 유형 | 의미 |
| --- | --- |
| requires | 필수 선행 정보나 계약 |
| derived_from | 원래 근거이며 독립적인 재확인은 아님 |
| prevention | 사건에서 예방 지식으로 연결하되 예방 상태는 그대로 유지 |
| supersedes | 명시 범위의 대체 관계이며 이전 상세·적절한 상태 보존 |
| conflicts_with | 조건에 따라 조정할 충돌이며 자동 우열 없음 |

```yaml
relations:
  requires: [K-EXAMPLE-PREREQUISITE]
  derived_from: [R-EXAMPLE-EVIDENCE]
```

카탈로그는 형식·대상 ID와 범위 조회의 명시 교차 저장소 대상을 검증한다. 검색은 저장소·분야를 넘어 양방향 간선을 따르고 대체된 후보도 포함한다. 방문 ID로 순환을 끝낸다. 이는 편집자가 선언한 관계이며 추론한 연관이 아니다. 질문에 필요한 본문 링크도 따른다.

```text
python skills/vegabond-knowledge/scripts/search.py related --project . --id K-CODE-CONCURRENCY-LIFETIMES --depth 2 --limit 10
```

검색은 기본 한 단계 관계 결과를 별도로 붙인다. `--depth 0`으로 끄며 호출당 최대 3단계다. 제한 출력은 잘림을 알린다. 관련 후보는 주 검색의 필터·적용성을 상속하지 않으므로 범위·상태를 읽는다. 생략된 충돌·대체를 종속 결정 전에 조회하고 필요 사슬은 개별 ID로 계속한다.

## 정보 요약 취합과 점검

질문을 확정하거나 중요한 결과를 적용하기 전에 공통 [정보 필요성 판단](../../vegabond-scout/references/information-needs.md)을 사용한다. 공통 문서는 질문의 충분성과 채택 판단을, 이 문서는 근거 조회·취합을 관리한다.

1. 넓은 요청을 답변 가능한 질문으로 나누고 필요한 맥락·근거를 기존 요약에 남긴다.
2. 질문별로 관련 저장소를 찾는다. 소수 상세에서 시작하되 미답·선행·충돌·대체·실패를 따라 확장한다. 처음 3개는 완료 한도가 아니다.
3. 중요 **주장·행동 → 항목 ID와 절·행 → 원본 근거 → 적용성 → 검사**를 연결한다. 원인·호환성 미상, 작가 선택과 조사 한계를 보존하고 제안 점검과 입증 예방을 나눈다.
4. 파생 요약을 독립 증거로 중복 계산하지 않는다. 상충 주장과 해소 조건을 남긴다. 대체는 문서화된 범위만 지배한다.
5. 질문을 답변됨·조건부·충돌·공백으로 닫고 추가 조회 필요를 설명한다. 상위 결과만 읽었다고 완료되지 않는다.

전역 장부 대신 기존 요약을 쓴다. 여러 질문이면 `질문 | 답·행동 | ID·근거 | 조건·충돌 | 검사·공백`이면 충분하다. 로컬 해시는 조회 바이트를 식별할 뿐 외부 원본의 진위·동일성이 아니므로 필요하면 기존 출처 등록부를 사용한다.

저장 전 양쪽 저장소에서 질문·동의어·근본 원인을 찾고 유력 항목·관계를 검토한다. 기존 답에 근거·예외를 보강하며 조건·원인이 다른 사건은 분리한다. 유사도만으로 자동 병합하지 않는다. [저장 절차](storage.md)로 검증·카탈로그·번역을 갱신한다.

## 버릴 수 있는 색인과 최신성

작업 프로젝트의 `.cache/onestep/search-v1.json`은 Git 제외 대상이며 정본 텍스트·해시만 담는다. 번역·생성 행·외부 원본을 담거나 커밋하지 않는다. 경로·크기·수정 시각 변화 때 다시 읽고 검증하며 삭제 파일을 제거한다. 변경 없는 정본은 재개방 없이 재사용한다. 구현·스키마 변화는 캐시를 무효화한다. 원자 교체로 불완전 JSON을 피하며 동시 조회는 서로 캐시를 대체해도 다음 호출에서 갱신한다.

크기·시각을 보존하는 작업이나 의심스러운 캐시는 `--refresh`로 정본 전체를 다시 읽고 해시한다. 외부 원본 검사는 아니다. 깨진 캐시는 재생성한다. 잘못된 정본·중복 ID·미해결 관계는 부분 성공 대신 오류다. 캐시를 쓸 수 없어도 경고와 정본 결과를 제공한다. 엄격한 읽기 전용은 `--no-cache`로 정본을 직접 읽고 아무것도 쓰지 않는다.

매 질문마다 메모리의 색인 텍스트를 훑으며 역색인·벡터 검색이 아니다. 다른 엔진을 붙이기 전에 대표 규모를 측정한다. 시간·고정 사례는 미래 전체 회수율을 보장하지 않는다.

## 검색 유용성 평가

```text
python skills/vegabond-knowledge/scripts/search.py evaluate --project . --cases skills/vegabond-knowledge/tests/retrieval_cases.json
python -m unittest discover -s skills/vegabond-knowledge/tests
```

버전 관리 사례는 현실 질문·필터·필수 및 금지 ID·결과 한도를 선언한다. 평가기는 한도 안 필수 ID 회수, 금지 결과, 반환 ID·발췌 길이·시간을 보고하고 실패 시 비정상 종료한다. 판정은 불완전하며 금지 결과 확인은 일반 정밀도가 아니다. 실제 누락·오검색·언어 실패·맥락 불일치·충돌 누락 뒤 사례를 확장한다. 순위에 맞추려고 기대값을 고치지 않는다.

단위·CLI 검사는 본문 일치, 해결·대체 상태, 알려진·미상 맥락, 유입·교차 저장소 관계, 순환·잘림, 잘못된 데이터, 캐시 갱신·삭제, 번역 제외와 읽기 전용 사용을 다룬다. 합성 규모 검사는 1,000항목의 최초·재사용 실행, 조회·제한 출력·재사용 정본 재독 0을 확인한다. 환경·한계를 작업 근거에 남기며 저장 구조와 검색 유용성은 별도 수락 검사다.
