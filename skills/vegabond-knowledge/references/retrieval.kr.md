# 조회와 취합

검색 옵션, 관련 기록, 여러 출처 요약과 평가에 사용한다. Markdown 상세가 정본이며 카탈로그·검색 캐시는 투영이다. 기존 카탈로그용 Python·PyYAML 환경을 사용한다.

## 구체적인 질문 검색

설치된 도구 경로로 실행하며 project는 작업 저장소다.

```text
python skills/vegabond-knowledge/scripts/search.py search --project . --query "메모리 풀링" --domain code --limit 3
python skills/vegabond-knowledge/scripts/search.py search --project . --query "callback shutdown" --store records
python skills/vegabond-knowledge/scripts/search.py search --project . --query "ownership" --context "engine=UE 5.8"
```

기본값은 해결된 사건을 포함한 양쪽 저장소를 조회하고 대체 항목은 주 결과에서 제외한다. domain·status는 반복할 수 있고 status superseded로 대체 기록을 포함한다. scope는 부분 문자열이다. context key=value는 기존 키의 대소문자 무시 정확 일치이며 호환성 판단기가 아니다. 키가 없으면 적용성 미상 주의사항과 함께 유지한다. 실제 메타데이터 값을 쓰고 다른 표현만으로 의미상 불일치를 단정하지 않는다.

[search_terms.json](../scripts/search_terms.json)의 한영 별칭을 확장하고 메타데이터·영어 본문을 검색한다. ID·제목·키워드·발생 조건·증상·질의 coverage가 순위에 기여한다. 반복·최신 날짜는 권위를 만들지 않는다. 점수는 어휘 휴리스틱이며 진위·적용성을 보장하지 않는다. 알려진 한국어 별칭은 조사 결합을 허용하지만 일반 번역·의미 검색은 제공하지 않는다. 실제 누락 뒤 별칭을 보완하며 모든 어휘를 미리 수집하지 않는다.

결과는 ID·요약·범위·상태·경로·해시·일치 필드와 용어·coverage·한정 발췌·1부터 시작하는 행 위치를 제공한다. 메타데이터 일치는 헤더다. 중요한 적용 전 관련 절과 원본 근거를 읽는다. total_matches·truncated는 생략 후보를 드러내며 필요하면 질의·필터·한도를 바꾼다. 무일치는 필터 아래의 어휘 무일치이지 부재 증명이 아니다.

주 검색·related는 offset으로 계속 조회한다. 한도는 1~100이며 관련 후보를 확인할 때까지 이어간다. 검색의 자동 관계 페이지는 주 offset과 독립적으로 0에서 시작한다. 추가 간선은 특정 ID로 related를 호출한다. 관계 페이지는 다른 끝 ID가 다른 페이지에 있어도 반환 후보에 접한 탐색 간선을 유지한다. 필요한 충돌·선행 관계의 다른 끝을 ID로 조회한다.

## 원본 출처 상태

모든 주·관련 결과는 evidence_notice로 checked_at이 기록된 근거 확인일이며 sha256은 로컬 항목 해시임을 알린다. 최신 원본 검사가 아니다. 내부 등록부를 향한 실제 링크는 source_checks에 출처별 access_status·identity_status를 나누어 표시한다. 기본 검색은 등록 메타데이터만 읽고 외부 원본·기계 설정을 열지 않으며 not_checked와 주의사항을 붙인다. 다른 근거 링크도 별도 검토한다.

원본 동일성이 중요하고 접근이 허용되면 반환 페이지의 등록 출처를 명시 검증한다.

```text
python skills/vegabond-knowledge/scripts/search.py search --project . --query "bandaging occupied hands" --domain fiction --verify-sources --source-root novel0=C:/Projects/Novel_0 --no-cache
```

이 루트는 예시이지 기본값이 아니다. 확인한 작업 경로나 알려진 프로젝트 메타데이터를 재사용하고 없으면 필요한 루트를 묻는다. 다른 프로젝트에는 source-root project=absolute-path를 반복한다. verify-sources가 필요하며 이번 호출에서 해당 프로젝트 영구 매핑보다 우선하지만 설정은 쓰지 않는다. 반환 주·관련 결과의 등록 ID만 호출 내 중복 제거하여 확인한다. 생략 후보나 추가 필요 ID는 [출처 도구](storage.md#portable-source-references)로 조회한다. 전체 근거·웹을 자동 검증하지 않는다.

source_verification은 요청 모드·출처 ID·완료 결과 수·읽기 성공 수·상태 수를 반환한다. 필요한 근거와 ID를 대조한다. 원본 검증이 미완료여도 retrieval_ok는 true일 수 있다. 종료 0은 조회 성공 및 요청한 등록 검사 모두 일치, 1은 unconfigured·missing·unavailable·unversioned·mismatch 등 요청 검사 미완료, 2는 잘못된 입력·등록부·설정·ID다. 등록 ID가 없으면 검증 ok는 null이며 전체 근거 확인의 증명이 아니다. 기본 조회는 not_checked여도 0으로 끝날 수 있으므로 주의사항을 유지한다.

available은 바이트 읽기 성공이며 unversioned는 기대 해시 없음이다. 현재 읽기는 현재 주장을 범위 안에서 뒷받침할 수 있으나 과거 판본을 확정하지 못한다. 해시 일치는 내용 동일성만 확인하므로 의미·권한·적용성을 직접 검토한다. 어느 모드도 과거 날짜·기대 해시·항목·설정을 갱신하지 않는다. 원본 결과는 캐시하지 않고 정본 캐시가 재사용되어도 명시 검증마다 새로 확인한다.

## 의미 있는 관계 탐색

선택 relations는 다음 유형을 실제 ID의 비어 있지 않은 목록에 연결한다.

| 유형 | 의미 |
| --- | --- |
| requires | 필수 선행 정보·계약 |
| derived_from | 원래 근거이며 독립적인 재확인이 아님 |
| prevention | 사건에서 예방 지식으로 연결하며 예방 상태는 유지 |
| supersedes | 명시 범위에서 대체하며 이전 상세·상태 보존 |
| conflicts_with | 조건에 따라 조정할 충돌이며 자동 우열 없음 |

```yaml
relations:
  requires: [K-EXAMPLE-PREREQUISITE]
  derived_from: [R-EXAMPLE-EVIDENCE]
```

카탈로그는 형식·대상 ID와 필터 조회의 명시 교차 저장소 참조를 검증한다. 검색은 저장소·분야를 넘어 선언 간선을 양방향으로 따르며 대체 항목도 포함한다. 방문 ID로 순환을 끝낸다. 이는 편집자가 선언한 관계이지 추론한 연관이 아니다. 필요한 본문 링크도 따른다.

```text
python skills/vegabond-knowledge/scripts/search.py related --project . --id K-CODE-CONCURRENCY-LIFETIMES --depth 2 --limit 10
```

기본 검색은 별도 한 단계 관계 결과를 붙이며 depth 0으로 끈다. 호출당 최대 3단계이고 출력 잘림을 표시한다. 관련 후보는 주 질의의 필터·적용성을 상속하지 않으므로 범위·상태를 읽는다. 의존 결정 전에 생략된 충돌·대체를 확인하고 필요 사슬은 개별 ID로 계속한다.

## 정보 요약 취합과 점검

질문 확정·중요 적용 전에 공통 [정보 필요성 판단](../../vegabond-scout/references/information-needs.md)을 사용한다. 공통 문서는 질문의 충분성·채택 판단을, 이 문서는 근거 조회·취합을 관리한다.

1. 넓은 요청을 답할 질문으로 나누고 필요한 맥락·근거를 기존 요약에 남긴다.
2. 질문별로 관련 저장소를 찾는다. 소수 상세부터 시작하되 미답·선행·충돌·대체·실패를 따라 확장한다. 최초 3개는 완료 한도가 아니다.
3. 중요 주장·행동 → ID와 절·행 → 원본 근거 → 적용성 → 검사를 연결한다. 원인·호환성 미상, 작가 선택·조사 한계를 유지하고 제안 점검과 입증 예방을 분리한다.
4. 파생 요약을 독립 증거로 중복 계산하지 않는다. 상충 주장과 해소 조건을 남기며 대체는 문서화된 범위에만 적용한다.
5. 질문을 답변됨·조건부·충돌·공백으로 닫고 추가 필요를 설명한다. 상위 결과만 읽었다고 완료되지 않는다.

기존 요약을 사용하고 전역 장부를 만들지 않는다. 여러 질문은 질문·답/행동·ID/근거·조건/충돌·검사/공백 표면 충분하다. 로컬 해시는 조회한 바이트만 식별하므로 외부 원본이 필요하면 기존 등록부를 사용한다.

저장 전 양쪽 저장소에서 질문·동의어·근본 원인을 찾고 기존 항목·관계를 검토한다. 기존 답에 근거·예외를 보강하고 조건·원인이 다른 사건은 분리한다. 유사도만으로 자동 병합하지 않는다. [저장 절차](storage.md)에 따라 검증·카탈로그·번역을 갱신한다.

## 버릴 수 있는 색인과 최신성

프로젝트의 .cache/onestep/search-v1.json은 Git 제외 대상이다. 정본 텍스트·해시를 담고 번역·생성 행·외부 원본은 담지 않으며 커밋하지 않는다. 경로·크기·수정 시각 변화 때 다시 읽고 검증하며 삭제 파일은 제거한다. 변경 없는 정본은 재개방 없이 재사용하고 구현·스키마 변화는 캐시를 무효화한다. 원자 교체로 불완전 JSON을 피한다. 동시 검색이 서로의 스냅샷을 대체해도 다음 호출에서 갱신한다.

파일 크기·수정 시각을 보존한 작업이나 의심스러운 스냅샷은 refresh로 정본 전체를 다시 읽고 해시한다. 외부 원본 검사는 아니다. 손상 캐시는 재생성한다. 잘못된 정본·중복 ID·미해결 관계는 부분 성공 대신 오류다. 캐시를 못 써도 경고와 정본 결과를 제공한다. 엄격한 읽기 전용은 no-cache로 정본을 직접 읽고 아무것도 쓰지 않는다.

질의마다 메모리의 색인 텍스트를 훑으며 역색인·벡터 색인이 아니다. 다른 엔진 전에 대표 규모를 측정한다. 시간·고정 사례는 미래의 임의 질문 회수율을 보장하지 않는다.

## 검색 유용성 평가

```text
python skills/vegabond-knowledge/scripts/search.py evaluate --project . --cases skills/vegabond-knowledge/tests/retrieval_cases.json
python -m unittest discover -s skills/vegabond-knowledge/tests
```

버전 관리 사례는 현실 질문·필터·필수 및 금지 ID·한도를 선언한다. 평가기는 한도 내 필수 ID 회수·금지 결과·반환 ID·발췌 길이·시간을 보고하고 실패하면 비정상 종료한다. 판정은 불완전하며 금지 결과 확인은 일반 정밀도가 아니다. 실제 누락·오검색·언어 실패·맥락 불일치·충돌 누락 뒤 확장한다. 순위에 맞추려고 기대값을 바꾸지 않는다.

단위·CLI 검사는 본문 일치, 해결/대체 상태, 알려진/미상 맥락, 유입/교차 저장소 관계, 순환·잘림, 잘못된 데이터, 캐시 갱신·삭제, 번역 제외와 읽기 전용을 다룬다. 합성 규모 검사는 1,000항목의 최초·재사용 실행과 조회·한정 출력·재사용 정본 재독 0을 확인한다. 환경·한계를 남기며 저장 구조와 검색 유용성을 별도로 판단한다.

## 한국어 질문 확장과 후보 다양성

[search_terms.json](../scripts/search_terms.json)의 concepts는 관찰된 표현의 조합을 요구한다. 코드·값·삽입 행동, 내부 구현·은닉 의도, 또는 추리·독자·근거·공개 행동이 함께 있어야 한다. 어절 시작에서 일치하고 한국어 조사·어미를 허용한다. 숫자·소스·독자 한 단어만으로 개념을 추정하지 않으며 리소스 속 소스를 소스 코드로 취급하지 않는다. inferred_concepts는 조회 보조이며 확정 의도 해석이 아니다. 원래 질문과 반환 근거를 확인한다. 일반 한국어 이해 기능이 아니므로 관찰된 누락·오확장 뒤 긍정 변형과 가까운 부정 사례를 함께 추가한다.

기본 검색은 용어 일부만 일치하는 독립 답도 포함하여 본문이 다른 후보를 반복 본문보다 먼저 한 번씩 보여 준다. 모든 후보·어휘 점수·coverage를 유지하므로 결과 점수·coverage가 단조 감소하지 않을 수 있다. 이는 원래 순위 우선권 일부와 답의 다양성을 교환하며 의미적 확실성을 보장하지 않는다. 파서의 기존 줄바꿈 정규화 후 본문이 정확히 같을 때만 묶고 대소문자·공백·코드는 추가 정규화하지 않는다. 저장소·분야·종류·상태·근거 날짜·원인/예방·선언 관계·맥락 주의사항이 다르면 별도 그룹이다. 명시 충돌·대체의 양 끝은 질의 밖 유입 관계까지 별도로 유지한다.

기록을 병합하거나 근거의 동등성을 인증하지 않는다. 본문이 같아도 scope·context가 다를 수 있다. 결과는 context와 similar_content의 다른 일치 수·한정 ID 예시·잘림을 반환한다. 버전·프로젝트·권한에 의존한 결정 전에 필요한 변형을 확인한다. 예시 ID는 정확한 ID 질의로 찾고 정본 해당 절을 연다. total_matches는 여전히 전체 일치 수이며 offset으로 모든 후보에 도달한다. diversity의 그룹·변형 수는 의미상 고유성이나 완전성이 아니다.

개별 변형·순위 감사는 search --all-variants로 원래 어휘 순서를 확인한다. 검색에만 적용하며 관계 조회는 그룹화 없이 모든 선언 ID를 따른다. 본문이 조금이라도 다르면 유사해도 묶지 않는다. 파일·과거 날짜·출처 지문은 고치지 않는다. 발췌는 반환 페이지에 대해서만 생성하고 원문 위치와 300자 한도를 유지한다.

규모 판단은 [검색 예산·측정·전환 기준](search-scale.md)을 따른다. 1,000건 고유 식별자 검사만으로 자연어 조회·여러 출처 판단·수만 파일의 속도를 보장하지 않는다.
