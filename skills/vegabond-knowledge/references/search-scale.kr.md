# 검색 규모와 전환 기준

기록 수·텍스트량·조회 빈도·중복도·관계 차수가 증가할 때 사용한다. Markdown은 정본이며 캐시와 미래 색인은 재생성 가능한 투영이다. 스킬 본문은 짧게 유지한다. 현행 계약은 [조회 지침](retrieval.md), 실제 결과·한계는 [검증 기록](../tests/information-needs/retrieval-scale-results.md)을 참고한다.

## 현재 늘어나는 비용

각 CLI 호출은 질의 필터 전에 JSON 캐시 전체를 읽고 검증하며 모든 정본 경로와 ID·관계를 확인한다. read_files=0은 바뀌지 않은 상세를 재파싱하지 않았다는 뜻이지 일정 비용 조회가 아니다. 선택 텍스트를 선형 검색하고 일치 전체를 정렬한다. 결과 3개는 출력 한도이며 전체 처리 한도가 아니다. 한 항목 변경도 그 항목을 재파싱한 뒤 JSON 전체를 다시 쓴다. 본문 지문과 반환 페이지만의 발췌는 반복 비용을 줄이지만 역색인은 아니다.

동일 본문 다양화는 서로 다른 답이 중복 경쟁에서 살아남게 돕는다. 권한·임의 의역·의미상 유사 중복을 자동 판단하지는 않는다. 맥락 미상·상충 근거·접근 불가 원본을 계속 표시한다. 공통 선행 항목에 참조가 몰리면 일반 조회보다 관계 비용이 커질 수 있다. 현행 탐색은 전역 간선을 훑고 선택 간선을 리스트로 추적한다.

## 결정 전 측정

새 격리 프로젝트나 읽기 전용 사본을 사용하고 운영 저장소에 벤치마크 기록을 만들지 않는다. 원본과 정답 판정 대상을 유지한다. 번역은 읽기 전에 제외하며 필요하면 존재 확인용 빈 파일만 둔다. 코드·설정 해시, 자료 출처, 항목·텍스트·캐시 크기, 상태·분야 분포, 중복도·관계 차수, 환경·런타임·측정 경계를 보존한다.

무캐시·첫 색인, 반복 재사용 CLI, 흔한 용어·범위 질의, 한 항목 변경과 최대 작업 메모리를 나누어 측정한다. 원본 검증은 필요할 때 별도 측정하며 기본 메타데이터 안내는 외부 원본을 해시하지 않는다. 시작 비용과 도구 내부 시간을 구분한다. 3회 반복은 중앙값·범위 근거이며 P95·P99가 아니다. 새 경로의 첫 접근, OS 캐시·백신·다른 부하가 비교에 큰 영향을 줄 수 있으므로 더 따뜻한 두 번째 실행을 알고리즘 개선으로 부르지 않는다.

실제 결과 한도 내 필수 ID 회수와 관련성·정밀도 판단을 함께 평가한다. 한영·의역·정확 식별자·복수 필수 답·미상 및 불일치 맥락·활성/해결/대체 상태·유입 충돌·대체 사슬·같은 증상의 오도 기록을 포함한다. 튜닝에 쓰지 않은 질문과 가까운 부정 사례도 둔다. 템플릿 반복 실험은 규모·순위 경쟁의 시험이며 독립적인 미래 지식의 의미 정확도가 아니다. 카탈로그·등록부·긴 문서·그래프·동시성도 늘렸는지 밝힌다.

## 제안 운영 기준

조정 가능한 프로젝트 예산이며 사용자 합의 SLA나 보편 건수 한도가 아니다. 건수와 바이트를 함께 본다.

| 관찰 | 대응 |
| --- | --- |
| 중요한 질문에서 필수 출처가 빠지거나 맥락·원인이 잘못 전이됨 | 규모와 무관하게 즉시 조사. 실패 입력·기대값을 유지하고 경로·용어·다양성·소비 판단을 고친 뒤 긍정·부정 사례 재검증. |
| 약 1천~5천 건, 또는 긴 본문·잦은 조회 | 실제 작업 질문 50~100개와 별도 평가 질문 마련. 내용군 독점과 맥락 공백을 관찰하고 메타데이터 선필터·정규화 재사용·페이지 발췌·관계 인접 색인을 비교. |
| 약 5천 건에서 계속 성장하거나 일상 조회가 1만 건에 접근 | 색인 방식 비교 착수. 감사 조건에서는 이미 수초가 들었으므로 3만 건까지 기다리지 않음. |
| 대표 요청 50회 이상에서 재사용 P95 2초 초과, 또는 반복 조회가 작업을 지연 | 검색 색인 전환 우선. 우선 약 1초를 목표로 삼되 실제 요구로 예산 확정. 작은 회귀 표본을 P95로 해석하지 않음. |
| 첫 생성·무캐시가 반복해 30초 초과, 한 건 변경도 수초, 또는 제안 메모리 예산 512MiB 초과 | JSON 전체 읽기·쓰기와 증분 저장·후보 로딩 비교. 장치·실제 작업에 맞게 메모리 기준 조정. |
| 공통 항목의 유입 관계가 수천 개 | 간선 중복 set·ID별/유형별 인접 목록 비교. 양방향 발견·충돌·페이지·계속 조회 계약 유지. |
| 경로·어휘 개선 뒤에도 의역 누락 | 한국어 토큰화·질문 재구성, 필요하면 의미 후보 검색·재정렬 비교. 정확 ID·적용 조건 유지. 임베딩은 근거를 인증하지 않음. |

## 전환 후보와 수락

Markdown과 ID를 유지하며 로컬 메타데이터 테이블과 SQLite FTS5를 다음 후보로 비교한다. 가져오기·수정·삭제 감지를 질의 실행과 분리하고 영어 정본만 색인한다. 저장소·분야·확립된 맥락으로 걸러 텍스트 후보를 찾은 뒤 출처·상태·다양성을 확인한다. 접근·동일성 상태를 독립적으로 유지하고 원본 해시는 명시 검증으로 남긴다. 색인 갱신이 과거 근거를 고치면 안 된다.

FTS5도 언어·식별자 검사가 필요하다. trigram의 3문자 미만 전문 질의는 일치하지 않으므로 두 글자 한국어에 별도 경로가 필요하다. 내용 테이블을 투영하면 변경·삭제에 색인이 일치해야 한다. 공식 [토큰화 문서](https://www.sqlite.org/fts5.html#the_trigram_tokenizer), [BM25](https://www.sqlite.org/fts5.html#the_bm25_function), [외부 내용 일관성](https://www.sqlite.org/fts5.html#external_content_tables)을 참고한다. 이는 비교 후보이며 구현된 백엔드·입증한 가속이 아니다.

같은 판정 질문, 정확 식별자, 미상 경고, 상태 필터, 교차 저장소·충돌 관계, 출처 안내, 최신성·손상·삭제 검사를 통과하고 지연·메모리 이득을 측정한 뒤 전환을 수락한다. 전후 근거와 복귀·재생성 절차를 유지한다. 바쁜 작업 공간에서는 격리 색인·자료로 비교하며, 속도를 얻으려고 회수 기대값을 낮추거나 상충 변형을 지우지 않는다.
