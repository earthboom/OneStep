# 게임 개발 상황별 적용 평가 — 2026-11-07

가상 요청 6개를 독립된 맥락에서 실행해 **프로젝트 사실 → 질문 → 지식 검색 → 기술 선택 → 적용 판단 → 검증 계획**을 확인했다. 6개 모두 중요한 판단 조건을 충족했으며, 단순 오탈자 사례에서는 불필요한 검색 비용이 드러났다. 보완 후 새 맥락의 재평가 4개도 같은 조건을 충족했다. 실제 게임 실행·플레이테스트 결과는 아니다.

점프 사례의 단순화된 콜백 설명은 간헐적 성공 기록과 긴장이 있다. 수행자는 실제 쓰기 지점·순서 확인이 필요하다고 명시했고 Unity 실행 순서를 재현했다고 주장하지 않았다. 저장 사례도 옛 매핑만으로 작성 버전을 알아낼 수 없다는 공백을 별도로 발견했다.

## 발견한 부족한 점과 수정

1. “휴대폰에서 숲 장면만 가면 느려져요”, “벽 뒤에 가려진 총구로 적을 맞혀요”, “업데이트 뒤 불러오면 장비가 다른 아이템이 돼요”는 관련 지식이 있어도 검색 결과가 없었다. 숲·수목·식생, 총구, 저장의 한영 별칭과 조건부 저장 호환 검색을 추가했다.
2. 첫 저장 검색 규칙은 아이템 아이콘을 불러오는 UI 작업까지 저장 호환으로 추론했다. 업데이트·불러오기·장비라는 단어 외에 “다른·바뀐·엉뚱한 장비” 증상도 함께 있어야 확장하도록 좁히고 음성 대조 사례를 추가했다.
3. 입력만으로 답이 정해진 오탈자·서식 수정은 게임 파일이라는 이유만으로 기술을 검색하지 않도록 활용 규칙을 명확히 했다.

초기 검색 회귀 묶음은 **5/10 → 10/10**으로 개선됐다. 가까운 음성 대조군을 추가하며 중간 오탐을 찾아 고쳤고, 최종 확장 묶음은 **11/11**이다. 필요한 ID를 찾는 양성 7개와 특정 잘못된 ID를 배제하는 음성 4개다. 처음 누락된 자연어 요청 3개는 의도한 기술이 첫 결과다. 변형 검색 문구는 작성자가 알고 있는 회귀 사례이며 미공개 홀드아웃 성능이 아니다.

## 평가 근거와 검사

사례·평가 기준을 먼저 작성하고 수행자에게 기대 ID나 답안을 주지 않았다. 각자 해당 입력·스킬·영문 지식만 사용했다. 초기 정본 137개는 실행 중 바뀌지 않았음을 해시로 확인했다. [초기 실행 기록](baseline-run.json), [의미 평가](semantic-review.json), [재평가 기록](retest-run.json)에 답변·검색·적용 판단·근거를 남겼다. 평가는 AI가 실제 답변의 의미를 검토한 것이며 자동 키워드 점수나 사람의 플레이 검증이 아니다.

재평가는 숲·저장·총구·오탈자 4개를 같은 입력·기준으로 새 맥락에서 수행했다. 마지막 한국어 증상 조건 축소는 이후 적용됐으며 최종 검색 회귀·기록 질의 재실행과 블라인드 판단 결과를 구분한다.

[최종 검사 기록](validation-results.json): 신규 검색 11/11, 기존 검색 23/23, 검색 단위 검사 33/33, 게임 목록 69개 엄격 검사 오류·경고 0. 넓은 탐색 검사 75개 중 74개는 통과했고 1개는 Windows 권한 때문에 심볼릭 링크·정션을 만들 수 없어 실패했다. 해당 출처 루트 탈출 검사는 미해결이며 전체 자동 검사가 모두 통과했다고 보고하지 않는다. 검색 구현이나 그 검사를 바꾸지는 않았다.

처음 자동 검사는 제한된 시스템 임시 경로와 PyYAML을 주입한 PYTHONPATH 때문에 환경 오류가 났다. 작업 공간 안의 임시 폴더와 기존 패키지를 넣은 일회용 venv로 재실행해 해결했다. 네트워크 설치나 통과 기준 완화는 하지 않았다. 재현 명령과 독립 수행 절차는 영문 보고서·README에 있다.

엔진 실행, 실제 렌더링·네트워크·전원 차단·성능·플레이 검증은 수행하지 않았다. 제한된 사례가 미래 모든 조회·판단을 보장하지 않으며, 실제 적용 때는 버전·API 보장과 프로젝트별 검사를 다시 확인한다.
