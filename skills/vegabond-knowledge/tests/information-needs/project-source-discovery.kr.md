# 프로젝트 원문 탐색 검증

2026-11-22에 독립된 실행 세션에서 작업 프로젝트의 `AGENTS.md`와 기존 연결 설정으로 OneStep을 불러왔다. 요청에는 문서 경로를 주지 않았다. 첫 편집이나 초안 작성 전에 적용 근거가 되는 원문을 열었는지, 그 근거를 결과물에 반영했는지, 결과를 실제로 검사했는지 확인했다.

## OneStep에 연결한 테스트 프로젝트

두 테스트 프로젝트 모두 일반 문서만 있고 구조화된 지식·문제 기록 저장소는 없었다. 실행 전에 지정된 전략 체크아웃의 `link_project.py <project> --check`로 연결을 확인했다. 각 사례에서 기존 지침과 보완 지침에 동일한 시작 파일과 작업 요청을 줬다.

| 사례 | 수정 전에 확인한 원문 | 수정한 코드에서 확인한 결과 |
| --- | --- | --- |
| Parcel Desk의 배송 대기 표시 | README에서 `operations/field-guide.md`로, 다시 `operations/policies/transfer-board.md`의 승인된 표시 규칙 PD-17로 이동했다. 교육 예시에는 다른 표시가 있었다. | 수정 전 `queued`는 `Sent`로 표시됐다. 한 줄 수정 후 Python에서 `queued`는 `Awaiting carrier`, `sent`는 `Sent`, 알 수 없는 상태는 `Unknown`이었다. |
| Daybook의 보류 알림 재개 시각 | 연결된 문서 안내가 없었다. `resume_at`과 시각 관련 용어로 검색해 `operations/shift/12-boundaries.adoc`의 승인 규칙 WB-12와 인접 표시 규칙을 읽었고, 상반된 초안은 효력을 잃었음을 확인했다. | 수정 전에는 정각만 실패했다. `<`를 `<=`로 수정한 뒤 동일한 Python 검사에서 직전은 `waiting`, 정각·직후·시각 미지정은 `ready`였다. |

두 사례에서 기존 지침과 보완 지침 모두 적용 근거를 찾아 결과에 반영했다. 보완 지침에서는 링크를 따르는 경로와 프로젝트 내 검색을 모두 사용했다. 주 에이전트가 보완 지침으로 수정한 두 파일에서 Python 검사 일곱 건을 별도로 실행했다. 테스트 프로젝트의 실행 진입점은 Python 함수다. 검색 소요 시간과 일반적인 문서 발견율은 측정하지 않았다.

## 기존에 연결된 실제 프로젝트

기존 `Novel_0` 프로젝트에서는 제목으로 지정된 회차의 결말 교체 문단을 별도 세션에서 작성했다. 프로젝트·원고 색인을 따라 작품과 회차를 찾고, 문체 가이드, 현행 결말, 인물·시점 정본, 도입 개요를 읽은 뒤 초안을 썼다. 주인공이 동문을 따라잡아 돌아온 사형에 관해 묻게 해 호기심을 행동으로 드러냈다. 앞뒤 문맥과 대조해 시점, 인물이 이미 알고 있는 정보, 소품의 연속성, 다음 장면으로 이어지는 이동을 확인했다. 원고와 문체 가이드의 해시는 작업 전후 일치했다. 실제 독자 반응은 검사 범위 밖이었다.

## 소설·코드·게임 외 문서 작업

공통 정보 판단 절을 갱신한 뒤 별도 세션에서 두 과제를 실행했다. 작업 요청에는 문서 경로를 주지 않았다. 두 세션 모두 공통 지침을 읽은 뒤 초안 작성 전에 해당 프로젝트 원문을 찾아 열었다.

- **운영 의사결정 메모.** 카탈로그 없는 테스트 프로젝트에서 파일 목록과 키워드 검색으로 승인된 집계 기준과 원시 집계표를 찾았다. 72%(180/250)는 전체 적격자의 7일 수치, 84%(63/75)는 신청자 집단의 30일 수치임을 메모에 명시하고 동일 기준으로 비교할 때까지 확대를 보류했다. 주 에이전트가 숫자와 인용 링크를 원문에 대조했다. 변경 전 지침에서도 이 사례는 통과했고, 검색 시간은 측정하지 않았다.
- **콘텐츠 운영 인수인계.** 기존 OneStep 연결 프로젝트 `YoutubeShorts`에서 프로젝트 지침과 색인을 따라 요구사항, 제작 운영안, 업로드 장애 복구 문서, 실험 보고서를 찾았다. 승인 대본 소진 시 신규 제작을 보류하고, 업로드 응답이 불확실하면 기존 세션과 영상 ID를 먼저 확인하도록 초안에 반영했다. 독립 대조에서 ‘예정 시각에 공개된다’는 표현을 ‘기존 예약을 유지하고 실제 공개를 확인한다’로 고쳤다. 프로젝트 원문의 해시는 일치했고 게시나 예약은 실행하지 않았다.


## 쇼츠 인수인계 탐색 시간과 원문 반영

이전 느린 회차에서는 프로젝트 지침과 색인에 제작·업로드 문서 링크가 있었는데도 파일 목록과 키워드 검색을 추가로 실행했다. 로그에서 각 명령 자체는 0.1초 미만이었으며, 원문을 열기 전 지연은 주로 도구 호출 사이에 발생했다. 보완 지침은 알려진 원문을 묶어 먼저 열고, 답에 따라 결과가 달라질 질문만 추가로 찾게 한다. 예외 상황에서는 바뀌는 조치와 유지되는 기존 약속을 원문의 동사로 쓰고, 결과 확인을 따로 적는다.

같은 프로젝트 문서·요청·계측 도구로 직전 지침과 최종 지침을 각각 두 번 실행했다. 필수 원문 세 개를 모두 열 때까지 중앙값은 12.2초에서 4.8초로, 그때까지 연 고유 문서 수는 4.5개에서 4개로 줄었다. 탐색 전체는 37.8초에서 35.3초로 줄었고, 추가 확인으로 전체 문서 수는 7개에서 9개로 늘었다. 네 회차 모두 요구사항, 제작 운영안, 업로드 복구 문서를 열었다. 문서 링크가 없는 별도 메모 사례도 검색으로 필수 원문 두 개를 모두 찾았다.

직전 지침으로 다시 실행한 두 초안 중 하나는 예약 유지 규칙을 실제 공개가 이루어질 것처럼 표현했다. 최종 초안 두 건은 별도 취소가 없으면 기존 예약을 유지하고 실제 공개 여부를 나중에 확인하는 뜻을 모두 반영했다. 중간 보완에서 단정이 재발하거나 예약 유지 조치를 빠뜨린 경우가 있어 최종 지침에 구체적인 확인 문구를 추가했다. 결과는 이 비교에 사용한 사례의 범위로 해석한다.


## 필수 원문 확보 후 추가 열람

9개를 열었던 두 회차는 모두 종이 그래픽 재제작 조사를 읽었다. 한 회차는 화면 개선 조사도, 다른 회차는 조사 변경 기록도 읽었다. 후속 작업이 승인된 운영 결정을 바꾸거나 게시를 검증했는지 확인하려는 열람이었다. 두 에이전트는 사후 확인에서 이 문서들이 초안의 어느 문장에도 영향을 주지 않았다고 답했다. 시험한 항목과 시험하지 않은 항목은 실험 검증 보고서에서 확인했다. 일반적인 관련성 조건을 추가한 중간 지침에서도 추가 열람이 한 번 재현됐다. 최종 지침에서는 미검증이 명시된 경우 현재 상태 확인을 마치고, 같은 운영 단계의 후속 결과를 가리키는 구체적 근거가 있을 때 다시 확인하도록 했다.

동일한 입력 파일, 요청, 계측 도구로 두 버전을 각각 두 번 재실행했다. 양쪽 모두 매회 7개를 열었고, 필수 원문 세 개와 실험 검증 보고서를 읽었다. 네 번 모두 앞선 추가 문서 세 개를 열지 않아 이전의 9개 수치는 재현되지 않았다. 마지막 필수 원문을 연 뒤 걸린 시간은 중앙값 43.8초에서 21.1초, 탐색 전체는 48.9초에서 36.1초로 줄었다. 필수 원문까지의 시간은 5.0초에서 14.9초로 늘었다. 보완 후 한 회차는 링크가 있던 업로드 원문을 열기 전에 검색과 파일 목록 조회를 했다. 보완 후 두 초안 모두 실제 실험의 검증 범위를 유지했고, 기존 예약 유지와 실제 공개 확인을 따로 썼다.


## 색인을 읽은 다음 원문 열람 순서

필수 원문 확보 중앙값이 14.9초였던 두 회차는 제작 운영안을 먼저 열었다. 한 회차는 후속 구현·검증 기록을 검색하고 파일 목록을 조회한 뒤 20.1초에 업로드 복구 원문을 열었다. 다른 회차는 독립적으로 읽을 수 있는 업로드 복구 원문을 별도 호출로 열어 9.8초가 걸렸다. 두 에이전트는 색인에서 두 경로를 이미 확인할 수 있었다고 답했다. [보완한 탐색 절차](../../references/project-sources.kr.md)는 요청의 각 상황을 색인 링크에 연결해 다음 읽기에서 원문을 먼저 열고, 그 뒤 남은 질문을 검색한다.

동일한 문서·요청·계측 도구로 두 버전을 각각 두 번 실행했다. 제작·업로드 원문을 한 호출로 연 회차는 보완 전 두 건 중 한 건, 보완 후 두 건 중 두 건이었다. 필수 원문 세 개를 열기까지 중앙값은 6.5초에서 4.5초로 줄었다. 전체 탐색 시간은 29.4초에서 29.1초였다. 모든 회차에서 문서 일곱 개를 열었고, 필수 원문과 실험 검증 보고서에 누락이 없었다. 보완 후 두 초안은 미검증 운영 상태와 예약 유지·실제 공개 확인의 구분을 반영했다. 이번 대조군에서 이전처럼 원문 전에 검색한 지연은 재현되지 않았다.


## 필수 원문 확보 후 실험 보고서 찾기

색인 우선 비교에서 필수 원문을 연 뒤 걸린 시간은 중앙값 22.9초에서 24.7초로 늘었다. 당시 보완 후 두 회차 모두 묶음 출력에서 제작 운영안의 핵심 절이 잘려 그 절을 다시 읽었다. 직접 실험 보고서의 위치를 찾을 때는 `docs/` 조회 후 파일 목록을 다시 확인했다. 첫 조회는 한 회차에서 새 근거를 주지 않았고, 다른 회차에는 실험 위치의 단서만 줬다. 잘린 절과 실험 보고서는 실제 초안에 반영했다.

후속 보완에서는 남은 질문이 결과 보고서의 위치라면 파일명 조회를 한 번 먼저 실행한다. 링크된 원문을 먼저 여는 순서를 유지하고, 빠진 절을 다른 독립 근거와 함께 읽을 수 있게 했다. 같은 프로젝트·요청·계측 도구로 두 버전을 각각 두 번 실행했다. 검증 보고서를 열기까지의 검색·목록 조회는 회차마다 두 번에서 한 번으로 줄었다. 필수 원문 이후 시간은 중앙값 27.0초에서 22.5초, 전체는 32.2초에서 27.8초였다. 고유 문서 수 중앙값은 6.5개로 같았다. 네 회차에서 필수 원문 세 개와 직접 검증 보고서를 모두 열었다. 최종 초안 두 건에는 검증 범위와 예약 유지·실제 공개 확인의 구분이 남았다. 제작 운영안의 잘린 절은 두 최종 회차에서 여전히 별도 호출로 읽었다.


## 잘린 원문과 독립 검증 보고서를 함께 읽기

두 회차에서는 제작 운영안의 107행 부근부터 148행까지의 빠진 내용을 다시 읽었다. 그 구간에서 이후 검증 기록의 링크를 찾을 수 있을지 살피느라 운영안을 먼저 열었다. 사후 확인 결과, 빠진 구간과 보고서에서 확인할 대상은 이미 각각 알 수 있었다. 보완 지침은 구간을 알 수 있으면 첫 읽기에 포함한다. 출력이 잘리고 실험 결과를 독립적으로 확인할 수 있으면 먼저 보고서 위치를 찾고 두 자료를 묶어 읽는다. 보고서 식별에 필요한 ID나 버전이 잘린 구간에 있을 때 그 구간부터 읽는다.

같은 프로젝트 문서·요청·계측 도구로 두 지침을 각각 두 번 실행했다. 보완 후 두 회차 모두 제작 운영안의 빠진 절과 실험 검증 보고서를 같은 호출로 열었다. 운영안을 연 횟수는 회차당 두 번으로 같았다. 별도 재열람은 1회에서 0회, 읽기 호출은 4회에서 3회, 탐색 전체 호출은 6회에서 4회로 줄었다. 준비 및 탐색 종료 표시는 호출 수에서 제외했다. 이번 비교에서 보고서 위치 조회도 2회에서 1회로 줄었다. 전체 탐색 중앙값은 28.7초에서 17.6초였고, 고유 문서 열람 수 중앙값은 6.5개에서 6개가 됐다. 네 회차 모두 필수 원문과 보고서를 열었다. 보완 후 초안은 실험 검증 범위와 예약 유지·실제 공개 확인의 구분을 지켰다.


## 제작 운영안의 필요한 절을 첫 읽기에서 선택

색인에는 운영안 파일 전체로 연결되는 링크만 있었습니다. 여러 원문을 한 번에 통째로 열자 운영안 중간의 승인 및 게시 절차가 출력 한도에 걸렸습니다. 첫 읽기에서 제목으로 절을 고른 초기 회차에서는 출력이 잘리지 않았지만 선택 범위가 좁았습니다. 한 회차는 승인 규칙이 들어 있는 준비·검수·보관 절을 빠뜨렸고, 다른 회차는 비용과 대체 수단 제약을 별도로 읽었습니다. 보완된 절차는 적용할 결정, 자료 처리 단계, 전체 절차, 적용되는 제약을 첫 읽기에 포함합니다. 배포본의 읽기 도구로 링크된 원문 세 개를 다시 읽었을 때는 관련 제약을 포함하고도 출력이 32,474자에서 7,202자로 줄었습니다.

이전 회차의 내용을 모르는 에이전트가 두 버전을 각각 두 번 실행했습니다. 각 회차의 프로젝트 파일, 경로를 주지 않은 요청, 읽기 도구의 옵션은 같았습니다. 필수 원문을 모두 처음 열기까지 걸린 시간의 중앙값은 8.6초에서 6.0초로, 전체 탐색 시간은 30.0초에서 23.2초로 줄었습니다. 전체 호출은 5회, 고유 열람 문서는 6개로 같았습니다. 운영안 열람 횟수는 보완 전 두 번에서 보완 후 두 회차 모두 한 번으로 줄었습니다. 네 회차 모두 필수 원문과 직접 검증 보고서를 열었습니다. 보완 후 두 회차에서 검증 보고서를 다시 열어 운영안 재열람은 줄었어도 전체 호출 수는 같았습니다. 초안에는 로컬 샘플 검증과 실제 게시 미검증 범위가 반영됐습니다. 한 초안은 첫 읽기에 나온 수정본 재승인 규칙을 명시하지 않았습니다. 이 수치는 이번 표본의 결과입니다. 앞선 실험의 17.6초는 다른 읽기 방식과 별도 회차에서 측정했습니다.
