# 작업 요청부터 적용까지 평가

필요한 정보의 판단이나 사용하는 스킬을 변경할 때 사용합니다. 질문→ID 검사를 보완하며 검색어 개수로 판단 능력을 채점하거나 보편적 완전성을 주장하지 않습니다. 여섯 프로젝트와 이력은 합성 자료이며 실제 지식·문제 저장소로 승격하지 않습니다.

## 정답을 제외한 입력 준비

```text
python skills/vegabond-knowledge/tests/information-needs/prepare.py --project .
```

기존 목록·PyYAML 실행 환경을 사용하며 Git에서 제외한 `.cache/onestep/information-needs/<run>/` 아래에 새 격리 프로젝트를 만들고 사례 ID·스킬 이름·요청 경로를 반환합니다. --case ID로 선택할 수 있습니다. 정답표는 읽거나 복사하지 않습니다. 사람용 파일은 존재 경계 검사용 임시 파일이며 근거로 조회하지 않습니다. 기존 프로젝트를 덮어쓰지 않고 실제 저장소에 평가 결과를 넣지 않습니다.

새 실행자에게 해당 사례의 요청·프로젝트 경로, 스킬과 필요한 공통 지침만 제공합니다. 실제 요청·자료에서 스스로 질문과 검색어를 정하게 합니다. 기대 출처·누락 위험 힌트·이전 결론·검색어·[판정표](rubric.json)는 제공하지 않습니다. 사례별 프로젝트를 분리하고 블라인드 성능을 측정할 때는 사례마다 독립 문맥을 사용합니다. 스킬 로드는 가능하지만 외부 조사·실제 서비스·원본 수정은 범위 밖입니다.

요청한 한정 결과와 간결한 근거 추적을 받습니다. 결정·질문과 필요한 이유, 조회한 출처·ID·구간, 중요한 채택·조건부·제외·보류, 공백·의존 행동, 제안 점검과 실행 점검을 구분합니다. 작은 로컬 수정은 결과와 짧은 범위 설명이면 충분합니다. 대조 사례에 거대한 표나 추가 조사를 강요하지 않습니다.

## 의미와 실제 적용 판단

실행이 끝난 뒤 평가자가 사례 판정표와 실제 응답·조회 자료·추적을 비교합니다. 기대 단어나 ID의 등장 여부 대신 실질적 추론과 적용을 확인합니다. 동등하게 타당한 질문·근거 경로도 인정할 수 있지만 조건 없이 ID만 인용한 것은 충분하지 않습니다.

각 사례에서 다음을 구분합니다.

- 누락한 필수 질문과 영향을 받는 결정·보존 조건.
- 미조회·오독한 관련 근거와 허용한 동등 근거의 이유.
- 잘못된 적용 전이·근거 없는 확정·범위 밖 행동.
- 적용 행동·예시, 보존 여부, 검증·공백 상태.
- 요청 경계에 도움 되지 않는 조회·불필요한 중단.

중요한 질문·근거가 설명되고, 치명적 실패가 없으며, 한정 결과가 불확실성을 올바르게 다룰 때 통과합니다. 원본 부재가 의도된 조건일 수 있습니다. 이때 지지되지 않는 결정을 유보하면서 독립 분석을 완료하는 것이 성공입니다. 충분한 로컬 입력을 빈 저장소 때문에 막지 않습니다. 관찰한 실패를 면제하려 판정표를 바꾸지 않습니다. 기준이 모호하면 기준 입력으로 명확히 하고 이유를 남깁니다.

가독성만 고치는 콜백, 보장이 없는 제공자 교체와 비슷한 증상의 과거 사건, 권한이 충돌하는 판타지 증언·반전, 전투·경제·제작 역량의 복합 기획, 비교 불가능한 유지율 문구, 띄어쓰기만 고치는 대조 사례를 다룹니다. 평가자 전용 판정표에 기대 판단·실패 조건을 두며 입력에는 검색어·정답을 넣지 않습니다.

평가한 스킬 버전·내용 식별자, 실행 사례, 실제 산출물·응답 위치, 발견·수정·영향 재검사 결과를 기존 작업 근거나 한정 평가 보고서에 남깁니다. 의미에 대한 검토와 실행 가능한 자료·검색 검사를 구분합니다. 시뮬레이션은 컴파일·엔진·독자·실결제 검사를 뜻하지 않습니다. 변경 뒤 영향 사례를 반복하고 공통 판단 변경은 전체 세트를 확인합니다. 유한한 사례는 일부 실패 유형을 표본으로 검사하며 미래 누락·오판의 부재를 입증하지 않습니다.
