## 실제 요청부터 적용까지

### 코딩: 최초 생성과 보존

처음 생성할 카탈로그 대상의 누락은 허용하되 다른 누락은 거부하고 무관한 내용을 보존하는지가 질문이다. 증상 전에 예정 행동으로 `새 프로젝트 지식 카탈로그 최초 생성`, `처음 만드는 지식 목록`을 조회했다. 둘 다 기존 [최초 생성 사건](../../../../records/code/R-CATALOG-BOOTSTRAP.md)을 반환했다. 첫 검색 실패를 선례 부재로 취급하지 않았다.

사건의 생성 예정 출력 구분과 [안정된 동작 경계의 검증](../../../../knowledge/code/K-CODE-CHANGE-TESTS.md)을 채택했다. [데이터 불변식](../../../../knowledge/code/K-CODE-DATA-INVARIANTS.md)은 검토 관점으로만 사용하고 Python의 정적 보장이나 엔진 전용 조언으로 전이하지 않았다.

현재 실제 저장소의 격리 사본을 만들었다. 구조화 항목 70개·분야 목록 11개·추적 중인 비번역 파일 129개를 복사하고 번역은 존재 확인용 빈 파일로만 표현했다. 기본 build는 무변경이다. 사본의 목록 11개만 제거하면 읽기 전용 check가 올바르게 실패하고 build가 11개를 만들며 이후 check와 재실행 무변경이 통과한다. 목록 밖 변경은 0이다. 사본의 실제 code 목록 행 하나를 지운 별도 실험도 원래 색인 전체·앞뒤 안내·비목록 저장 Markdown 71개를 보존했다. 이는 현재 실제 자료 실험이며 보존되지 않은 과거 수정 전 판본의 재현이 아니다.

### 소설: 기존 Novel_0의 002·003

이미 확립한 손·검 상태, 장면 지칭, 작가 대사 선택, 인물과 독자의 정보 차이, 복구 인과 질문을 재사용했다. 지식과 해결·열린 문제를 함께 조회했다. 실제 `bandaging occupied hands`는 동작 사건과 관련 지식에 원본 상태를 붙여 반환한다. 첫 페이지를 원고 검토 전체로 간주하지 않고 필요한 후보를 확인한다.

사용자가 확인한 Novel_0 루트를 이번 호출에만 사용하여 앞선 검토의 핵심 원본 8개를 확인했다. BODY-MOTION, SPATIAL-BLOCKING, STYLE, N2-002-CURRENT, N2-003-CURRENT, N2-PREMISE, N2-POSSESSED-CHARACTER, N2-REVIEW-20261106의 모든 요청 ID에 결과가 있다. 연구 둘은 일치하고 나머지 6개는 읽을 수 있으나 과거 판본을 증명할 해시가 없다. 현재 바이트가 앞선 실제 읽기 manifest와 같아 해당 읽기를 재사용할 수 있으며, 이번에 원고 전체를 새로 통독했다고 주장하지 않는다. 검색 페이지가 연결한 9개 ID는 명시 선택한 핵심 배치 8개와 범위가 다르므로 수를 섞지 않는다.

현재 정본과 기록된 대사 선택을 채택한다. 신체 연속성과 공정한 공개 원칙은 적용 조건을 지키며 녹스의 초자연 금지를 무협에 강제하거나 작가 선호를 보편 결함으로 만들지 않는다. 기존 교정 판단은 변경 없는 원문 근거로 유지된다. [복구 인과 기록](../../../../records/fiction/R-FIC-N2-RECOVERY-GAP-20261106.md)은 open·unknown이다. 복구 결과 확정이 그 과정의 확정을 뜻하지 않는다. 원고·정본은 수정하거나 역사적으로 인증하지 않았다.
