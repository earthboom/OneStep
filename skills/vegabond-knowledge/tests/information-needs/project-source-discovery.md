# Project source discovery evaluation

On 2026-11-22, fresh agents started from each working project's `AGENTS.md` and resolved OneStep through the project's existing link. The task prompts gave no source paths. The test checked whether each agent opened the governing original before the first edit or draft, used it in the result, and verified the result against it.

## Linked fixture projects

The two fixtures had ordinary project documents and no structured knowledge or record stores. `link_project.py <project> --check` passed against the assigned strategy checkout before the runs. The baseline and revised runs received identical starting project files and task prompts within each case.

Both versions found and applied the governing sources in these two samples. The revised workflow exercised both its link-following route and its local search fallback. The primary agent separately ran all seven assertions on the revised runs' edited files. The fixtures expose Python functions as their runnable entry points. Retrieval time and general recall remain unmeasured.

## Document work beyond fiction, coding and games

Separate sessions ran two tasks after the [common information procedure](../../../vegabond-scout/references/information-needs.md#request-and-retrieve-evidence) explicitly put working-project originals first. The task prompts supplied no document paths. Both sessions read the revised procedure and opened the applicable project originals before drafting.

- **Operations decision memo.** In a linked fixture with no catalog, a filename inventory and a focused search found the approved reporting contract and raw CSV. The memo cited the two originals, reported 72% (180/250) for all eligible members at seven days and 84% (63/75) for opt-in members at 30 days, and deferred rollout pending a like-for-like comparison. The reviewer recalculated the rates and checked the cohort wording and links. A fresh run with the prior procedure also passed this case. Retrieval time remains unmeasured.
- **Content operations handover.** In the existing linked `YoutubeShorts` project, the agent followed the project entry point and index to the requirements, production workflow, upload recovery notes and experiment report. It used the originals to require a production hold when approved scripts run out and a check of the previous upload session and video ID when the outcome is uncertain. Independent review narrowed a sentence promising on-time publication to preserving the existing reservation and verifying the actual outcome. Source hashes matched, and the evaluation took no publishing or scheduling actions.

## Shorts handover timing and source fidelity

Earlier slow runs used inventory and keyword searches even though the project entry point and index already linked to the production and upload documents. Each command took less than 0.1 seconds in the captured trace. The extra sequential lookup rounds accounted for most of the wait before opening the originals. The revised guidance opens linked owners together, searches unresolved questions, and checks that exception instructions preserve both changed and retained actions. It preserves the original action verb and treats outcome verification as a separate step.

In a fresh comparison with identical project documents, prompt, and metered reader, two baseline runs and two final runs used snapshots differing only in the two revised references. Median time to all three predeclared originals fell from 12.2 to 4.8 seconds. The median unique documents opened by then fell from 4.5 to 4.0. The full discovery phase fell from 37.8 to 35.3 seconds, with total documents opened rising from seven to nine. Additional checks after opening the essential originals explain the larger final reading count. All four runs opened the requirements, production workflow and upload-recovery originals. A final pilot memo with no document links also found both required originals by search.

One of two fresh baseline handovers overstated the reservation rule. Both final outputs preserved existing reservations unless separately canceled and treated actual publication as a later check. Intermediate revisions still exhibited the overstatement or omitted the reservation-retention action, prompting the final explicit wording check. These comparisons cover the observed runs. They do not measure general retrieval or paraphrasing performance.

## Extra reads after the required originals

In the two nine-document handovers, both agents read the paper-graphics redesign. One also read the visual redesign and the other the research log. They were checking whether later work changed the approved operating decisions or verified publishing. In retrospective checks, both agents reported that these reads contributed no line to the handover. The experiment validation report supplied the actual tested and untested boundaries. One intermediate run repeated the same extra reads after a general relevance instruction, so the final guidance treats an explicit unverified state as an answered status question and requires a concrete pointer to a later result for that operation before reopening it.

A fresh comparison ran two trials per version with the same input files, request and reader. Both versions opened seven documents in both trials and read all three required originals and the direct experiment report. The three earlier extra files were absent from all four new traces, so the new trials did not reproduce the earlier nine-document count. Median time after opening the last required original fell from 43.8 to 21.1 seconds and total discovery time from 48.9 to 36.1 seconds. Median time to the required set rose from 5.0 to 14.9 seconds. One revised run searched and listed files before opening the linked upload original. Both revised drafts used the actual experiment limits and preserved reservations separately from checking the outcome.

## First read after the index

The two runs behind the 14.9-second median opened the production plan first. One deferred the linked upload-recovery document to search for newer implementation or validation evidence, then listed files and opened recovery at 20.1 seconds. The other treated recovery as a separate read and opened it at 9.8 seconds. Retrospectives confirmed that the index had already exposed both independent paths. The revised [project-source procedure](../../references/project-sources.md) maps each requested case to the index links, opens those originals in the next read, and uses search for remaining gaps after the linked reads.

Two fresh runs per version used identical project files, prompts and metered operations. Both revised runs opened the linked production and upload originals in the same tool round, compared with one of the two control runs. Median time to the three required originals fell from 6.5 to 4.5 seconds. Total discovery time was 29.4 and 29.1 seconds respectively. Each run opened seven documents, including all three required originals and the direct experiment report. Both revised drafts kept the report's unverified operating states and distinguished keeping a reservation from confirming publication. The earlier search-before-opening delay did not recur in the two fresh control runs.

## Clipped sections and independent verification reports

Both runs with a separate reread recovered production-plan lines around 107–148. They reopened the plan first to see whether it might link a newer result. Retrospective checks confirmed they already knew which missing passage they needed and what activity the result report had to cover. The shared procedure now covers known section locators in the first read and, for clipped output and independent verification, locates the report before opening it with the missing passage. A separate reread comes first when the omitted passage contains an identifier or version required to locate the report.

The plan was still opened twice per run. Median standalone reopen calls fell from one to zero, read calls from four to three, and all discovery calls from six to four, excluding setup and the end marker. The report-location lookup also fell from two calls to one in this sample. Median total discovery time moved from 28.7 to 17.6 seconds and the median unique document count from 6.5 to six. All four runs opened every required original and the report. Both revised drafts carried forward the experimental verification limits and separated keeping reservations from checking actual publication.

## Selecting operating-plan sections in the first read

The index linked to the whole operating plan. A batched full read clipped the middle, including approval and publication procedures. Early heading-based runs avoided clipping but selected sections too narrowly. One missed the preparation, review and storage section that contained the approval rules. Another read the cost and fallback constraints separately. The revised guide selects the governing decision, artifact lifecycle, workflow and applicable constraints in the first read. A replay using the bundled reader reduced the three linked originals from 32,474 characters to 7,202, including those constraints.

Two independent agents per version used identical project copies, path-free task text and reader options. The median time to first open every required original changed from 8.6 to 6.0 seconds. Total discovery time changed from 30.0 to 23.2 seconds. Total calls stayed at five and unique originals stayed at six. The operating plan went from two opens to one in both revised runs. All four runs opened all required originals and the direct verification report. Both revised runs reread the report, which accounts for the unchanged total discovery call count alongside any other batched reads. The drafts kept the same verification boundary between a local sample and still untested publication. One revised draft did not state the explicit reapproval rule for a modified script, although its first plan read included that rule. These numbers describe this sample. The previous experiment's 17.6-second median used a different reader and separate runs.
