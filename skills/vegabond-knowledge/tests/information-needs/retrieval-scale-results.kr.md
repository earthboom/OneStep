## 수정과 회귀 근거

- 조건 조합을 요구하는 질문 개념 3개와 일치 조건 안내를 추가했다. 실제 누락 3개·표현 변형 3개·기존 종료 의역을 버전 관리 사례에 담았다. 숫자·코드·독자 한 단어만으로 의도를 추정하지 않는다. 독립 검토에서 직접 계산·리소스 측정의 잘못된 확장이 발견되어 실패 부정 사례 3개를 유지하고 실제 삽입 행동·어절 시작을 요구하도록 좁혔다.
- 다른 본문이 반복 본문보다 먼저 한 번씩 노출된다. 모든 후보는 계속 조회할 수 있고 all-variants로 원래 순서를 확인한다. 상태·날짜·원인/예방·관계·미상 맥락과 명시 충돌/대체는 구분한다. context와 한정 변형 ID 안내를 유지하며 원본 기록은 병합·수정하지 않는다.
- 처음에는 같은 coverage 안에서만 다양화했으나 실제 1천 건에서 실패했다. 필수 소유권 자료는 두 용어 중 하나만 일치했다. 부분 일치 회귀로 전제를 검증하고 최종적으로 부분 일치하는 독립 답도 반복보다 먼저 보이게 했다. 원래 점수·coverage를 보존하며 의미적 확실성을 인증하지 않는다.
- 캐시 본문 지문과 페이지별 발췌를 사용한다. 카탈로그 형식·과거 근거 날짜·기대 출처 해시는 유지한다. 예산과 전환 기준은 [규모 참고 문서](../../references/search-scale.md), 조회 계약은 [조회 문서](../../references/retrieval.md)가 관리한다.

## 고정 자료 규모 재검증

앞선 감사의 실제 기록 70개와 ID·scope가 다른 순환 복제 자료를 재사용했다. 작은 프로젝트는 읽기 전용 하드링크 사본이고 번역은 존재 확인용 파일만 둔다. 3만 건은 기존 자료를 직접 재사용하고 임시 검색 캐시만 교체했다. 병행 추가와 비교를 분리했으며 처음 실패한 실행 근거를 보존했다. 같은 문서에 기준 커밋의 조회 함수를 적용하여 과거 GC 밀어내기도 재현했다.

시간은 색인 로딩·출처 안내를 포함한 도구 내부 값이며 Python 시작은 제외한다. 식별자는 3회 중앙값, 넓은 질의는 1회다. P95나 인과적인 가속을 주장하지 않는다. 앞선 최초 생성과는 파일시스템 캐시·병행 부하가 다르다. 전체 JSON·파일 순회·본문 검색이 남아 여전히 수초가 걸리므로 [전환 기준](../../references/search-scale.md)은 계속 필요하다.

- **기획:** 실제 문제 기록 설계 결정과 현행 카탈로그 경계·새 규모 기준을 대조했다. 실제 사본 엄격 검사와 내부 등록부 1회 읽기를 확인하고 역사적 19·20개 결과를 보존했다. 예산은 제안이며 SQLite는 미구현 후보다. 가상의 실제 게임 기획·사업성 검증을 꾸미지 않았다.
