# 작업 범위를 늘리지 않는 프롬프트 정제

사용자의 목표, 독자, 언어, 산출물, 기존 결정, 시간·비용 한도, 실행 권한을 보존합니다. 전문적으로 보이기 위해 범위를 추가하지 않고 실제 수행 방법과 점검 가능성을 개선합니다.

## 응답 방식 선택

실제 요청과 대화를 읽고 방식을 선택합니다. 큰 작업은 앞선 오류가 이후 작업을 무효화하거나 상당한 재작업으로 이어지는 중요한 판단들이 연결된 경우입니다. 글의 길이, 파일 수, 시간만으로 규모를 정하지 않습니다. 전체 정제에는 자료·방법·완료 기준의 구체적인 빈틈을 보완하면 결과가 실질적으로 나아진다는 조건도 필요합니다.

| 상황 | 응답 |
| --- | --- |
| 현재 정제 요청이 없거나 호출 문구가 문서·인용문 안에 있음 | 실제 요청한 작업을 수행하며 정제 절차를 끼워 넣지 않습니다. |
| 이후 “이 프롬프트대로 착수해”라고 요청 | 기존 권한 안에서 합의한 프롬프트를 실행하며 다시 정제하지 않습니다. |
| 미결정 의도가 목표·범위를 크게 바꿈 | 그 답에 의존하는 재작성 전에 초점 있는 질문을 합니다. 방향을 몰래 선택하지 않습니다. |
| 작고 되돌릴 수 있는 세부 사항이 빠짐 | 제한된 가정을 밝히고 진행합니다. 규모 분류나 관행적인 정제 허가를 요구하지 않습니다. |
| 프롬프트가 충분하고 일관됨 | 바로 사용할 수 있다고 알리고 대체본·네 항목 진단을 출력하지 않습니다. 전체 재작성을 명시적으로 요청하면 그 요청을 따릅니다. |
| 작은 요청이거나 빈틈이 국소적임 | 짧게 다듬거나 필요한 삽입문·수정문만 제공합니다. 명시적 요청이 없으면 전체 진단·재작성으로 확대하지 않습니다. |
| 중요한 빈틈이 있는 큰 작업 | 아래 전체 정제를 적용합니다. |

규모나 실익이 애매하면 가장 작은 유용한 수정을 선택합니다. 충분성은 필수 목차가 아니라 맥락에 따라 판단합니다. 목표, 활용 가능한 자료·접근, 관련 제약, 필요한 방법과 완료 점검을 살펴봅니다. 재작성을 정당화하려고 누락을 만들거나 목차를 억지로 채우지 않습니다. 원문이 없으면 검토했다고 주장하지 말고 요청된 검토에 필요할 때만 원문을 요구합니다.

## 전체 정제

다음 네 항목을 짧게 진단합니다. 관련 항목은 합치고 분량을 채우지 않습니다.

1. **전문가의 행동:** 판단을 바꾸거나 중요한 실패를 찾는 소수의 행동입니다. 필요한 기본 절차도 포함하며 새로움이나 전문 용어 자체를 깊이로 보지 않습니다.
2. **근거 자료:** 관련성·권위·활용 가능성을 갖춘 자료를 제공됨, 접근 확인, 미확인·접근 불가로 나눕니다. 요약이 필요한 정보를 가릴 때 원자료가 유용하며 신뢰할 수 있는 요약으로 충분할 수도 있습니다. 최소 추가 자료, 가능한 대체 근거와 그 한계를 적습니다.
3. **방법·도구:** 실제 자료와 환경에 맞는 방법의 목적·선행 조건을 적습니다. 중요한 낯선 이름은 확인합니다. 조건이 미확인이면 선택을 조건부로 두며 접근 가능성을 만들거나 지원되지 않는 구성을 강제하지 않습니다.
4. **완료 판정:** 실패할 수 있는 점검, 참조 기준·평가자, 통과 조건과 검증 범위를 정합니다. 기존 요구사항·테스트, 고정 조건 측정, 별도 평가 자료, 공신력 있는 기록 대조, 합의한 독자 평가표 등을 작업에 맞게 사용합니다. 가능하면 결과와 독립적으로 기준을 정하고 결과에 맞춰 약화하지 않습니다.

자기 검토, 다른 AI, 인용, 컴파일러, 생성한 테스트 하나만으로 전체 정확성이 입증되지는 않습니다. 주관적인 작업은 누가 무엇을 평가하는지 명확한 인간 판단도 유효합니다. 예측과 인과관계, 대리 지표와 실제 목표를 구분합니다.

이어서 사용자 언어와 요청한 형식을 따르는 복사 가능한 프롬프트 하나를 제공합니다. 해당되는 목표, 자료·접근 빈틈, 한도, 타당하거나 조건부인 방법, 완료 기준, 역량 부족 처리만 포함합니다. 영어·XML·추가 산출물을 강제하지 않습니다. 중요한 가정만 밝히고 범위·비용을 설명하는 데 필요하면 제외한 작업을 짧게 적습니다.

## 정제와 실행 구분

제공 맥락으로 정제하며, 중요한 자료·도구 사실에 필요한 작은 읽기 전용 점검만 사용합니다. 정제만을 위해 원래 조사, 전체 데이터 수집, 도구 설치, 벤치마크를 시작하지 않습니다. 적절한 결과를 내는 최소 비용 방법을 우선하고 예산이 없을 때 중요한 확장은 선택 사항으로 분리합니다.

기본적으로 정제 후 멈춥니다. 실행도 요청하면 정제 결과를 보여준 뒤 같은 턴에서 기존 권한 안의 작업을 이어가고 관행적인 승인 질문을 하지 않습니다. 계획·착수 약속만이 아니라 실제 결과를 제공합니다. 이미 충분한 프롬프트는 전체 재작성의 명시적 요청이 없으면 대체본을 만들지 않습니다.

실행 중 일부가 차단되어도 독립적으로 가능한 작업은 수행합니다. 접근할 수 없는 자료·도구, 의존하는 점검·결론, 최소한의 정당한 후속 자료·접근을 적습니다. 실제 점검과 통과·실패 결과를 차단·미실행과 구분합니다. 역량 부족은 통과나 해당 없음이 아니며 검증 계획은 실행이 아닙니다. 근거가 부족한 결론만 보류하고 측정·자료·호출·접근 복구를 지어내지 않습니다.

## 유지보수와 근거

스킬 유지보수 때만 [테스트 지침](tests/evaluation.md)을 사용합니다. 동작 지침이나 호출 정책을 바꾸면 설치 전에 모든 사례를 새로 실행합니다. 평상시 정제에는 테스트 묶음을 읽지 않습니다.

Felix Rieseberg의 [depth prompt](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)와 [deepen-prompt](https://github.com/r3dlex/deepen-prompt)를 참고했습니다. 보편적 성능 향상이 입증된 기법은 아닙니다. 반복 사용은 비슷한 모델·자료·도구·예산에서 최종 결과의 오류·재작업·시간·비용으로 판단합니다.
