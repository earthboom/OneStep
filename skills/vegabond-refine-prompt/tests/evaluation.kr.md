# 프롬프트 정제 회귀 테스트

스킬 유지보수 때만 이 절차를 사용합니다. [rubric.json](rubric.json)이 고정 입력과 의미 기반 통과 기준의 정본 목록이며 평상시 정제에서는 읽지 않습니다. 사례마다 다섯 기준이 있습니다. 정확한 문구나 출력 유사도가 아니라 행동과 의미로 판정합니다.

| 사례 | 검사할 경계 |
| --- | --- |
| RP-01 | 규모가 애매하면 검증 기준만 국소 삽입합니다. |
| RP-02 | 충분한 프롬프트에는 대체본을 내놓지 않습니다. |
| RP-03 | 중요한 빈틈은 전체 정제하되 실행하지 않습니다. |
| RP-04 | 정제 요청이 없으면 실제 분석을 수행합니다. |
| RP-05 | 인용문 속 호출 문구는 정제 대신 원문 요약 대상으로 취급합니다. |
| RP-06 | 이후 실행 요청에는 앞선 프롬프트를 한 번 실행합니다. |
| RP-07 | 작은 요청은 전체 진단 없이 짧게 다듬습니다. |
| RP-08 | 목표가 실질적으로 다르면 초점 있는 질문부터 합니다. |
| RP-09 | 작은 빈틈은 제한된 가정을 밝히고 국소 보완합니다. |
| RP-10 | 결합 요청은 정제본 후 관행적 승인 없이 실행합니다. |
| RP-11 | 자료·도구가 부족한 결합 요청은 가능한 작업과 의존 차단을 구분합니다. |

## 실행과 판정

1. 후보의 `SKILL.md`, `agents/openai.yaml`, 이 지침, 평가 기준, 사례 입력을 해시로 식별합니다. 동작 지침이나 호출 정책을 바꾸면 설치 전에 모든 사례를 실행합니다. 테스트만 추가했다면 후보·정책·입력·기준이 그대로인 기존 근거만 확인 후 참조할 수 있습니다. 그 범위는 부분 실행으로 표시하고 새로운 전체 실행이라고 하지 않습니다.
2. 사례마다 새 맥락의 수행자나 깨끗한 별도 세션을 사용합니다. 후보 스킬·정책 경로, 사례 경로 하나, 아래 중립 지시만 전달합니다. 이 지침, 판정 기준, 다른 사례, 과거 응답, 기대 판정은 숨깁니다. 독립 맥락이 없으면 앞선 사례를 잊었다고 가정하지 말고 `not_run`으로 기록합니다.
3. 실제 응답을 그대로 저장한 뒤 해당 기준마다 `pass`, `fail`, `not_run`과 관찰 근거를 적습니다. 모든 필수 기준을 통과해야 합니다. 형식 검증기는 구조만 확인하며 의미 검토를 대신하지 않습니다. 실패를 정당화하려고 통과 기준을 바꾸지 않습니다.
4. [results.json](results.json)에 출처·입력·기준 해시, 실행 범위, 원문 응답 파일의 경로·해시, 판정, 한계를 기록합니다. 이전 근거는 그 파일의 보관 참조를 통해 보존합니다. 과거 통과를 바뀐 후보의 검증으로 사용하지 않습니다. 입력을 고칠 때는 이전 입력·응답·실패를 남기고 변경을 설명합니다. 동작 지침을 바꾸면 모든 사례를 새로 실행합니다.
5. 통과한 동일 후보와 필요한 테스트 자료를 설치하고 해시를 비교합니다. 실제 입력 결함으로 별도 수정 기록이 필요한 경우를 제외하면 원래 한국어 요청과 대화 입력을 보존합니다. 사람이 읽는 `*.kr.md` 번역을 지시로 읽지 않습니다.

수행자에게 전달할 중립 지시의 뜻은 다음과 같습니다. 실제 경로를 대입합니다.

```text
<스킬 후보>/SKILL.md와 <스킬 후보>/agents/openai.yaml을 읽고, 해당 스킬의 적용 여부를 판단해 <사례 파일>의 사용자 요청에 답하세요. 사례마다 독립된 대화로 취급하세요. messages 배열이 있는 JSON이면 앞선 메시지를 대화 맥락으로 사용하고 마지막 사용자 메시지에만 답하세요. 다른 파일은 읽지 마세요. 테스트 지침, 저장된 결과, 다른 사례, *.kr.md 파일을 읽지 마세요. 웹 검색과 파일 변경은 하지 마세요. 제공된 정보로 실제 요청에 답하되, 프롬프트 정제만 요청한 경우에는 원래 작업을 실행하지 마세요. 평가자 해설 없이 실제 한국어 사용자 응답만 반환하세요.
```

## 근거의 경계

입력은 외부 서비스나 원래 프로젝트의 변경을 요구하지 않습니다. RP-04·RP-06·RP-10·RP-11은 제공된 가상 자료를 분석하고 RP-05는 제공된 글을 요약합니다. RP-06은 역할이 표시된 대화 입력이며 호스트 UI 통합 검사가 아닙니다. RP-08은 첫 확인 질문만 검사합니다. RP-11은 알려진 접근·도구 불가 조건이며 실제 실패 호출이나 연결 복구를 검사하지 않습니다.

응답의 통과는 실제 이탈 원인, 실제 리팩터링·보고서 품질, 자동 스킬 탐색, 모델 간 재현성, 실제 권한 처리를 증명하지 않습니다. 새로 실행한 사례만 새로운 테스트로 셉니다. 성공·실패 이력과 현재 후보의 검증 범위를 구별하고, 필요한 과거 기록만 참조해 읽습니다.
