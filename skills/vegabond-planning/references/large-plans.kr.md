# 대규모 기획: 분해·통합·변경 관리

사람 전용 번역. AI는 영문 [large-plans.md](large-plans.md)를 사용한다.

하위 기획들이 목표·한정된 자원·의존성·다른 부분에 영향을 주는 결정을 공유할 때 사용한다. [기획 방법](../SKILL.kr.md), [검토 점검](review.kr.md), [scout의 규모·단계 선택](../../vegabond-scout/SKILL.kr.md)을 재사용한다. 이 참고 문서는 기획 내용의 조정을 담당하고, 실행은 호출한 작업 절차가 담당한다. 문서 수만으로 단계·도구·위임·큰 양식을 늘리지 않는다. 국소 변경은 실제 의존성만 따라간다.

## 전체 목표와 기준 자료 설정

기존 브리프에 의도한 경험·성과, 대상, 경계, 우선순위, 공통 제약, 전체 기획의 수용 조건을 명시한다. 필수·제안·보류·미확정 사항을 구분한다. 지금 필요한 결정과 근거를 얻은 뒤 정해도 되는 세부 사항을 구별한다. 목차가 완성되었다고 모든 선택이 확정되지는 않는다.

중요한 결정마다 기준 자료와 현재 개정·상태를 찾는다. 기존 설계 문서·추적 도구·결정 이력을 재사용한다. 필요하면 연결된 결정에 안정적인 참조를 부여하고 논거·출처·책임자 또는 제안 책임자를 붙인다. 요약은 원자료에 연결하며 경쟁하는 사본이 되지 않는다. 문서의 최신성이나 AI 요약만으로 기존 결정 권한을 대체하지 않는다.

## 결정과 의존성을 기준으로 분해

전체 목표를 역량·시스템에 연결하고, 다시 다음 판단에 필요한 규칙·콘텐츠·제작 단위·실험으로 연결한다. 의미 있게 검증할 수 있고 공통 책임이 드러나는 경계를 선택한다. 모든 프로젝트에 같은 계층을 강제하거나 근거가 부족한 후속 세부 사항을 전부 확정하지 않는다.

중요한 하위 기획에서는 다음 관계를 산문·작은 표·기존 링크로 확인할 수 있게 한다.

- 상위 목표, 기대 기여, 범위, 기준 자료.
- 입력·출력·공통 규칙·자원과 이를 제공하거나 소비하는 다른 기획.
- 확정 또는 제안 책임, 핵심 가정, 미해결 선택, 관련 수용 근거.

상위 목표를 뒷받침하지 못하는 공백, 중복 소유·비용, 제공자가 없는 의존성을 찾는다. 순환 의존성이 있으면 이를 풀 공통 결정이나 범위를 한정한 실험을 식별한다. 문서 작성 담당을 나누는 것만으로 순환이 해결되지는 않는다.

## 구체화와 검증 순서 설정

확인된 중간 결과가 후속 작업의 전제라면 scout가 `staged`를 유지하거나 선택하도록 한다. 결과·점검·이를 통해 진행할 후속 결정을 명시한다. 방향 설정, 핵심 작동 방식, 대표 통합 구간, 제작 준비 등이 경계가 될 수 있지만 전부 강제하지 않고 실제 필요에 맞춰 선택한다.

불확실한 선택은 의존하는 세부 사항을 확정하기 전에 적정 조사나 허용된 시제품으로 구체화한다. 결과를 관련 기획으로 돌려보내고 브리프를 갱신한다. 막히지 않은 작업은 진행하면서 어떤 결정이 조건부인지 밝힌다. 내부 검증 지점을 두었다고 매번 사용자 승인이 필요한 것은 아니다. 기존 권한을 따르고 중요한 의도·결정 권한이 미해결인 경우에 필요한 사람의 판단을 구한다.

## 경계를 넘어 통합 검토

하위 기획 각각과 결합된 동작을 함께 검토한다. 대표적인 사용자·운영 흐름을 관련 기획에 걸쳐 추적한다. 각 부분이 무엇을 받고, 바꾸고, 전달하는지와 중요한 실패·복구 경로를 확인한다. 경계의 용어·수량·단위·시점·소유·가정을 맞춘다.

총수요를 공통 역량·예산과 대조하고 자원 중복 계산과 담당 없는 통합 작업을 찾는다. 되먹임과 지역 목표의 충돌을 검토한다. 한 부분의 최적화가 전체 목표를 무너뜨릴 수 있다. 영향받는 합계를 재계산하고 그럴듯한 불리한 사례로 검토한다. 모든 문서가 개별 점검을 통과했다고 통합이 완료된 것은 아니다.

상세 설계와 실제 검증은 이용 가능한 분야별 방법을 사용한다. 게임이라면 의도한 플레이 경험을 핵심 반복 구조·상호작용하는 시스템·필요 콘텐츠·제작 한계에 연결하고, 필요한 경우 관련 설계 방법과 플레이테스트를 적용한다. 일관된 문서·스프레드시트만으로 재미·균형·잔존·구현 준비를 입증할 수 없다. 기획만 허용받았다고 제안한 테스트의 제작·실행 권한까지 생기지는 않는다.

## 기획을 가로지르는 변경 관리

1. **변경 식별:** 제안 결정, 이유·새 근거, 현재 기준 개정, 유지할 요구사항을 연결한다. 수정과 목표·선호의 변경을 구별한다.
2. **영향 추적:** 상위 가정과 하위 소비자를 따라가며 공통 규칙·자원·지표·마일스톤·점검을 통한 교차 연결도 포함한다. 영향받는 자료·결과, 영향 밖의 경계, 추적이 끝나지 않은 범위를 명시한다. 편집 파일 목록은 영향 분석 자체가 아니다.
3. **결정 정리:** 기존 범위·권한을 적용한다. 가능하면 기준 유지도 포함해 관련 대안을 비교한다. 확립된 제약과의 충돌을 밝히며 조용히 완화하거나 제안을 채택된 결정처럼 취급하지 않는다. 통상적인 허용 범위의 선택에 승인 단계를 추가하지 않는다.
4. **일관되게 반영:** 권한 안에서 결정한 뒤 기준 자료와 영향받는 요약·하위 기획·추정·검증 계획을 갱신한다. 대체된 논거와 개정 이력은 기존 체계로 보존한다. 미해결 후속 기획과 변경으로 무효가 된 근거는 재점검 대기로 표시한다. 과거 결과를 새 개정판의 검증처럼 다시 붙이지 않는다.
5. **재검증과 종료:** 영향받는 개별·통합 점검을 반복한다. 새 기준, 실제 근거, 남은 조건, 다음 결정을 명시한다. 유효한 작업을 보존하며 영향이 더 퍼진 경우에만 검토 범위를 넓힌다. 일부만 반영한 변경을 전체 통합 완료로 보지 않는다.

예를 들어 게임의 전투 시간을 줄이면서 보상을 유지하면 단위 시간당 보상·성장·자원 소모처·세션 구성·필요 콘텐츠 생산량이 바뀔 수 있다. 어떤 값을 고칠지 정하기 전에 그 소비자들과 상위 경험을 추적한다. 보상률 계산은 영향 분석을 뒷받침할 뿐 수정 게임의 균형을 입증하지 않는다.

## 유지할 수 있는 기획으로 전달

전체 방향, 중요한 상충점, 근거가 있는 범위, 다음 결정을 먼저 제시한다. 유용한 경우 현재 기준 자료·의존 관계·관련 결정 이력으로 연결한다. 정의된 부분·잠정 부분·점검 대기·막힌 부분과 실제 검토한 통합 시나리오를 보여 준다. 완성된 하위 기획 묶음을 검증된 전체 범위와 동일시하거나 문서 전달을 실행 성공으로 취급하지 않는다. 남은 질문은 기존 기획에서 관리하며 별도 상태 체계를 만들지 않는다.
