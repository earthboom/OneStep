# 필요한 정보와 적용 판단

작업에 어떤 정보가 필요하고 조회한 자료가 어떤 행동의 근거가 될 수 있는지 판단하는 공통 절차입니다. 정찰·지식·작업·전문 스킬은 기존 작업 요약을 공유합니다. 별도 작업 흐름·보편 점검표·사용 장부를 만들지 않습니다. 조회·저장은 [지식 절차](../../vegabond-knowledge/SKILL.kr.md), 검색 방법은 [검색 참고 문서](../../vegabond-knowledge/references/retrieval.kr.md)가 담당합니다.

## 실제 작업에서 질문 도출

요청의 검색어나 넓은 분야명뿐 아니라 원하는 결과와 실제 제공 자료에서 시작합니다. 어떤 사실이 없거나 틀렸을 때 행동이 달라지고, 보존 조건을 위반하거나 수용 점검이 무효화되는지 묻습니다. 관련될 때 다음 관점을 사용합니다.

- 목표·사용자·독자·명시적 제약·이미 정한 결정.
- 실제 입력·상태·호출자·소비자·소유권·시간·버전과 경계를 넘는 의존성.
- 가능한 실패·충돌 근거·최종 점검에서 관찰해야 할 결과.

모든 작업이 채워야 할 필드는 아닙니다. 요청이 모든 중요한 의존성을 설명한다고 가정하기 전에 가까운 기준 원본을 확인합니다. 띄어쓰기 수정에 작품 설정집 전체가 필요하지는 않지만 일반 판타지 장면도 정보 공개와 공정한 단서 판단이 필요할 수 있습니다. 분야·기술·장르 이름만으로 관련성을 정하지 않습니다.

기존 요약에 중요한 필요를 `결정·행동 → 질문과 필요한 이유 → 기준 원본·맥락 → 근거 상태 → 관련 점검·영향`으로 연결합니다. 작은 작업은 한 문장이면 충분하고 여러 결정을 따라가기 어려울 때만 표를 씁니다. 표를 채우려고 사실을 만들지 않습니다.

의존 행동 전에 필수인 정보, 현재 선택에 유용한 정보, 보류·범위 밖 정보를 구분합니다. 필수 정보는 부재가 요구 계약·보존 의미나 설정·안전한 결정 가능성을 무효화할 수 있는 정보입니다. 취향이나 선택적 개선이 자동으로 필수는 아닙니다. 중요한 보류에는 경계나 재검토 조건을 붙이며 구하기 어렵다는 이유로 필수 선행 정보를 보류하지 않습니다.

## 실행 전문 스킬로 보완

정찰은 초기 질문과 시작 맥락을 준비합니다. 전문 스킬은 실제 코드·호출자·원고·계획·슬라이드 등을 살핀 뒤 중요한 결정과 의존성을 질문들이 다루는지 확인합니다. 드러난 필요를 추가하되 유효한 답은 재사용합니다. 전문 스킬을 직접 호출해도 별도 정찰 대화 없이 같은 점검을 적용합니다.

다음은 선택적 보완의 예이며 분야별 의무 목록이 아닙니다.

| 작업 | 실제 자료에서 드러나는 질문 |
| --- | --- |
| 콜백 헬퍼 단순화 | 무엇이 무엇보다 오래 살 수 있고 어느 스레드에서 종료 중 어떻게 호출되는가? 어떤 기존 동작을 보존해야 하는가? |
| 증언·반전 장면 편집 | 이 시점에 각 인물과 독자는 어떤 관찰로 무엇을 알고, 무엇이 공개되면 안 되는가? |
| 전투 시간·보상 변경 | 가정 아래 보상 속도·성장·소모처·세션 경험·콘텐츠 수요가 어떻게 달라지는가? |
| 비교 그래프 문구 수정 | 기간·집단·분모·단위가 비교 가능한가? 실제 요청한 결과 형식은 무엇인가? |

중요한 선택에 의존하기 전에 “어떤 조건을 빠뜨렸다면 이 행동이 잘못되는가? 무엇으로 발견할 수 있는가?”를 묻습니다. 상상 가능한 모든 위험 대신 구체적 의존성이나 반례를 따릅니다. 새 근거·변경 요구·무효화된 가정이 다른 의존성을 드러내면 영향 부분만 다시 살피고 유효한 작업은 보존합니다.

## 근거 요청과 조회

작업 프로젝트·실제 결정과 질문·관련 이유·적용 맥락·필요 근거·알려진 공백을 지식 스킬에 전달합니다. 증상이 없어도 계획 행동·발생 조건으로 지식과 문제 기록을 검색합니다. 일치 목록이 없으면 원본 검토나 집중 조사가 필요할 수 있습니다. 반복 검색이 빠진 질문의 식별을 대신하지는 않습니다.

지식 스킬은 원본 구간·조건·충돌·근거 및 예방 상태·공백을 붙인 후보를 반환하고 빠진 전제나 선행 조건을 드러낼 수 있습니다. 적용 여부와 실제 결과 검증은 사용하는 전문 스킬이 담당합니다. 검색 점수나 지식 요약은 작업 전체의 충분성을 인증하지 않습니다. 모르는 맥락은 그대로 남기며 관련·파생 자료가 독립 입증이 되지는 않습니다.

## 행동의 근거로 사용할지 판단

중요한 후보는 실제 작업의 프로젝트·작품·버전·시점·행위자·기전·제약·입증 근거와 비교합니다. 주장에 필요하면 원본 구간을 확인합니다. 해당 질문의 기준 원본과 권한을 적용합니다. 현재 사용자 지시·프로젝트 계약이나 설정·사실 근거·취향·잠정 제안은 역할이 다릅니다. 최신성·동의하는 요약 수·active 표시는 권한을 결정하지 않습니다.

기존 요약에 유용한 판단을 남깁니다.

- 채택: 확인한 조건에서 행동을 뒷받침하며 적용 행동·점검을 명시합니다.
- 조건부: 미확인 조건과 허용할 잠정 사용을 명시하고 사실로 승격하지 않습니다.
- 이번 행동에는 제외: 범위·기전·권한·근거의 불일치를 설명합니다.
- 보류: 현재 경계에 필요하지 않으며 중요하면 다시 필요한 시점을 명시합니다.

모든 검색 결과를 기록하는 절차가 아닙니다. 같은 증상이 같은 원인을 뜻하지 않고, 다른 저자의 선택이 보편 문체 규칙이 되지 않으며, 제안 예방책이 검증 상태가 되지 않습니다. 과거나 미래의 작품 사실이 현재 인물 지식이 되지도 않습니다. 교훈을 옮기기 전에 실제 기전과 조건을 추적합니다.

확인된 사실·지지되는 추론·가정·충돌·누락을 나눕니다. 필수 답을 구할 수 없으면 정당화할 수 없는 의존 행동과 최소 필요 근거를 밝히고 독립 검토나 명시적으로 한정한 제안은 계속합니다. 중요한 의도는 사용자에게 확인하되 일상 승인을 반복하거나 저장소가 비었다는 이유로 무관한 로컬 작업을 막지 않습니다.

## 검색 대신 실제 작업을 기준으로 마감

인계 전 중요한 결정의 근거·적용 행동·실제 수용 결과를 연결합니다. 산출물이 새 상태·의존성·사실 주장을 만들었는지 확인합니다. 질문을 답변됨·조건부·충돌·누락으로 마감합니다. 정당한 보류는 답변 완료의 근거가 아닙니다. 미해결 한계·무효 근거와 그 영향을 유지합니다. 검색 포함 정도는 용어 일치 수이며 필요한 정보의 완전성이 아닙니다.

스킬 유지보수는 [작업 요청부터 적용까지의 평가 사례](../../vegabond-knowledge/tests/information-needs/evaluation.kr.md)를 사용합니다. 질문 누락·잘못된 전이·근거 없는 확정·불필요 조회를 목록 무결성 및 질문→ID 검사와 구분해 평가합니다. 유한한 사례로 미래 누락의 부재를 입증할 수는 없습니다.
