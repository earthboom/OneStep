# 필요한 정보와 적용 여부 판단

이 공통 절차로 작업에 필요한 정보와 찾은 자료를 실제 조치의 근거로 쓸 수 있는지 판단한다. Scout, Knowledge, 작업 스킬, 전문 스킬은 기존 작업 요약을 공유한다. 별도 작업 흐름이나 일괄 체크리스트, 사용 이력은 두지 않는다. [Knowledge 절차](../../vegabond-knowledge/SKILL.kr.md)가 정보 검색과 저장을 맡고, [검색 안내](../../vegabond-knowledge/references/retrieval.kr.md)가 검색 방법을 다룬다.

## 작업에서 질문 도출하기

요청한 결과와 실제로 주어진 자료에서 시작한다. 잘못 알고 있거나 빠진 정보 중 조치를 바꾸거나, 유지 조건을 위반하게 하거나, 수용 검사를 무효로 할 수 있는 것이 무엇인지 살핀다. 필요한 관점만 사용한다.

- 의도한 결과, 사용자나 독자, 명시적 제약, 이미 결정된 사항.
- 실제 입력, 상태, 호출자·사용자, 소유권, 시각·리비전, 경계를 넘는 의존성.
- 발생 가능한 실패, 충돌하는 근거, 최종 검사에서 관찰해야 할 사항.

이 목록은 질문을 떠올리는 데 사용한다. 요청에 중요한 의존성이 모두 담겨 있다고 가정하기 전에 가까운 정본 입력을 살핀다. 맞춤법 한 곳을 고치는 데 설정집 전체가 필요한 경우는 드물다. 판타지 장면을 다룬다면 정보 공개 순서와 단서의 공정성이 중요할 수 있다. 관련성은 분야나 기술, 장르 이름에 더해 실제 문제와 문맥으로 판단한다.

기존 작업 요약에서 중요한 정보 요구를 **결정·조치 → 질문과 중요한 이유 → 정본 출처·문맥 → 근거 상태 → 영향받는 검사나 결과**로 연결한다. 작은 작업은 본문 한 문장이면 충분하다. 결정이 여럿이라 한눈에 보기 어려우면 짧은 표를 쓴다. 빈칸을 채우기 위해 사실을 만들어내지 않는다.

의존 작업 전에 꼭 알아야 하는 정보, 현재 결정에 도움이 되는 정보, 미루거나 범위를 벗어난 정보를 구분한다. 정보의 부재로 필수 계약, 보존할 의미나 설정, 안전하게 결정을 확정할 수 있는 조건이 무너질 수 있으면 필수로 본다. 선호나 선택적 개선은 실제 영향에 따라 판단한다. 미룬 질문은 어디까지 미루며 어떤 계기로 다시 살필지 정한다. 찾기 어렵다는 이유만으로 필수 전제를 미루지 않는다.

## 실행하는 전문 스킬과 질문 보완하기

Scout가 초기 질문을 정하고 필요한 첫 문맥을 찾는다. 전문 스킬은 실제 코드와 호출자, 원고, 계획, 슬라이드 또는 다른 원문을 살핀 뒤 중요한 결정과 의존성을 질문이 충분히 다루는지 확인한다. 새로 드러난 질문을 추가하고 유효한 답은 재사용한다. 전문 스킬을 직접 호출할 때도 이 확인을 같은 작업 안에서 진행한다.

| 작업 | 실제 자료가 드러내는 질문 |
| --- | --- |
| 콜백 도우미 단순화 | 무슨 객체가 무엇보다 오래 살아남을 수 있으며 어느 스레드에서, 종료 중에는 어떻게 되는가? 유지할 기존 동작은 무엇인가? |
| 증언·정보 공개 장면 편집 | 등장인물과 독자는 이 장면에 이르러 무엇을 어떤 관찰로 알 수 있는가? 무엇이 계속 드러나지 않아야 하는가? |
| 전투 시간·보상 변경 | 주어진 가정에서 보상률, 진행, 소비처, 세션 경험, 필요한 콘텐츠 양은 어떻게 바뀌는가? |
| 비교 차트 수정 | 출처의 기간·모집단·분모·단위가 비교를 허용하는가? 실제 요청한 최종 형식은 무엇인가? |
| 운영 인수인계 초안 | 어떤 절차와 예외가 승인됐는가? 정상 흐름이 멈추면 누가 다음 조치를 결정하는가? |

중요한 결정에 의존하기 전에 처음 정한 질문을 다시 살핀다. **어떤 조건을 놓치면 이 조치가 잘못되며, 어느 원문이나 검사로 그 조건을 발견할 수 있는가?** 구체적인 의존성이나 반례를 따라간다. 새 증거, 바뀐 요구사항, 무효가 된 가정에서 다른 의존성이 드러나면 영향을 받는 부분을 다시 확인하고 유효한 결과를 유지한다.

## 근거를 요청하고 찾기

작업 프로젝트, 실제 질문, 관련 문맥, 필요한 근거, 알려진 공백을 [Knowledge](../../vegabond-knowledge/SKILL.kr.md)에 전달한다. 현재 작업 프로젝트가 기준을 정하는 질문은 [프로젝트 원문 탐색](../../vegabond-knowledge/references/project-sources.kr.md)부터 적용한다. 일반 프로젝트 문서를 찾아 의존 작업 전에 해당 원문 절을 읽는다. Scout를 거치거나 전문 스킬을 바로 호출할 때, 사용자가 경로를 알려주지 않거나 프로젝트에 카탈로그가 없을 때도 같은 순서를 적용한다. 현재 결정에 대해 이미 확인한 원문은 재사용한다.

관련 지식 항목과 문제 기록으로 원문 확인을 보완한다. 증상이 아직 없어도 계획한 조치와 관련된 트리거를 확인한다. 실제 읽은 절, 결정에 미친 영향, 남은 공백을 기존 작업 요약에 남긴다. 추가 증거가 필요한 질문은 이미 확인한 근거와 함께 [집중 조사](../../vegabond-research/SKILL.kr.md)로 전달한다.

Knowledge는 후보 근거와 원문 위치, 적용 조건, 충돌, 증거·예방 상태, 공백을 반환한다. 그 과정에서 빠진 전제나 선행 조건이 드러날 수 있다. 사용하는 전문 스킬이 적용 가능성을 판단하고 결과를 검증한다. 검색 점수와 지식 요약은 후보를 고르는 데 활용하고 작업에 필요한 근거의 충분성은 별도로 확인한다. 누락된 문맥은 미확인으로 두고, 파생 항목은 독립 근거에 포함할 수 있는지 확인한다.

원문 접근, 내용 동일성, 주장 검증은 각각 확인한다. 항목의 날짜와 해시는 원문을 새로 확인했는지와 별개다. 등록 출처는 접근 불가·잘못된 ID를 포함해 요청한 모든 ID의 결과를 확인한다. 설정되지 않은 프로젝트 루트를 묻기 전에 작업이나 프로젝트 메타데이터에 이미 승인된 경로가 있는지 살핀다. 관련 프로젝트에 탐색을 한정하고 루트를 추측하지 않는다. 영구 설정을 요청한 경우를 제외하면 이번 조회에 임시 루트를 쓴다. 버전이 고정되지 않은 원문은 현재 확인한 내용의 근거로 사용할 수 있다. 과거 리비전을 입증할 수 있는지는 별도로 판단하고 요약과 최종 검증에 그 한계를 남긴다.

## 조치의 근거로 쓸 수 있는지 판단하기

중요한 후보는 출처의 프로젝트나 작품, 버전·리비전·시점, 관련 행위자, 작동 원리, 제약, 입증된 증거를 실제 작업과 대조한다. 주장에 필요하면 관련 원문을 직접 확인한다. 질문별로 기준을 정할 권한이 어디에 있는지 판단한다. 현재 사용자 지시, 프로젝트 계약·정본 설정, 사실을 보여 주는 증거, 선호, 임시 제안은 각각 역할이 다르다. 최신성, 일치하는 요약 수, `active` 표시도 원문의 권한과 함께 판단한다.

유효한 결론을 기존 작업 요약에 남긴다.

- **채택** — 확인한 상황에서 근거가 조치를 뒷받침한다. 그 결과로 수행할 조치와 검사를 적는다.
- **조건부 적용** — 해결되지 않은 조건과 허용되는 임시 적용 범위를 적고 사실과 구분한다.
- **이 조치에서는 제외** — 범위, 작동 원리, 출처 권한, 증거 중 맞지 않는 부분을 적는다.
- **연기** — 현재 범위에서 답이 필요하지 않은 이유와, 중요하다면 다시 살펴야 하는 시점을 적는다.

중요한 활용 결정을 기록한다. 증상이 같으면 원인도 같은지 확인하고, 다른 작가의 선택은 적용 범위를 따진다. 제안된 방어책은 별도로 검증한다. 과거 또는 미래의 이야기 사실은 현재 장면에서 인물이 알 수 있는지 확인한다. 교훈을 옮겨 적용하기 전에 실제 원리와 조건을 추적한다.

알려진 사실, 근거가 있는 추론, 가정, 충돌, 누락된 근거를 구분한다. 필수 정보가 없으면 아직 정당화할 수 없는 의존 조치와 필요한 최소 증거를 명시한다. 독립적으로 살필 수 있는 작업이나 범위를 명시한 제안은 이어간다. 중요한 의도가 불분명할 때 사용자에게 확인하고, 빈 저장소 때문에 관련 없는 작업을 멈추지 않는다.

## 실제 작업을 기준으로 마무리하기

전달 전에 중요한 결정마다 근거, 적용한 조치, 실제 수용 검사 결과를 연결한다. 결과물이 관련 상태, 의존성, 사실 주장을 추가했는지 살핀다. 질문별로 답변·조건부·충돌·미확인 상태를 정리하고, 미룬 사항은 그대로 표시한다. 해결되지 않은 한계와 무효가 된 근거는 그 영향과 함께 남긴다. 검색의 일치 범위와 작업에 필요한 정보의 충족 여부를 각각 확인한다.

초안의 중요한 진술을 인용한 원문과 대조한다. 조치에 영향을 미치는 주체, 범위, 조건, 예외, 확신 수준을 유지한다. 제안, 승인, 진행 중, 완료 확인처럼 근거가 뒷받침하는 상태에 표현을 맞춘다. 운영 예외를 설명할 때는 바뀌는 조치와 원문이 유지하라고 한 기존 약속을 모두 반영한다. 원문이 조치를 지시하면 그 동사를 살리고 결과를 확인하는 단계는 따로 적는다. 예를 들어 원문이 취소 시까지 예약을 유지하라고 하면 “별도로 취소하지 않는 한 기존 예약을 유지한다. 예정 시각이 지난 뒤 실제 이행 여부를 확인한다”라고 쓴다. 전달 전에 예측이나 완료 주장을 원문이 뒷받침하는 수준으로 고친다.

스킬 유지보수에는 [요청부터 적용까지의 평가 사례](../../vegabond-knowledge/tests/information-needs/evaluation.kr.md)를 사용한다. 카탈로그 무결성·검색어와 ID의 일치 여부와 별도로 누락 질문, 부적절한 적용, 근거 없는 확신, 불필요한 검색을 평가한다. 평가는 실행한 사례의 범위를 보여 준다.
