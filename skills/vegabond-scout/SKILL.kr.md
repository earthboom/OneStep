# Vegabond Scout

사용자가 원하는 결과에 맞춰 작업 방식과 규모를 정하고 연결된 작업 스킬로 실행을 조정한다. Scout는 작업 요약, 스킬·도구 연결, 전체 진행을 맡는다.

## 요청 파악과 분류

아직 읽지 않았다면 [영문 에이전트 지침](../../agents/vegabond-agent.md)을 읽는다. 요청, 관련 문맥, 원문 자료를 살펴 원하는 결과와 독자, 형식, 언어, 제약, 수용 조건을 파악한다. 빠진 의도가 작업을 실질적으로 바꿀 때 질문한다.

작업 방식은 분야, 매체, 도구와 별도로 선택한다. 저자의 배경과 여기의 사례는 작업 범위를 한정하지 않는다. 원본 입력과 결과물은 요청된 언어를 따른다. AI는 사용자 전용 번역본인 `*.kr.md`를 읽거나 검색하거나 불러오지 않는다. 자료 탐색 및 허용된 위임에도 같은 제외 규칙을 적용한다.

다음 네 질문에 답해 짧은 작업 개요를 만든다.

1. **대상** — 어떤 자료, 산출물, 동작이나 질문을 다루며 원하는 결과는 무엇인가. 관련 분야, 매체·형식, 실행 문맥을 포함한다.
2. **변경 의도** — 무엇을 추가하거나 고치거나 바꾸거나 확립해야 하는가. 현재 상태와 원하는 결과 사이의 구체적인 차이를 기술한다.
3. **유지 조건** — 의미, 동작, 어조, 사실, 형식, 원문 등 무엇을 유지해야 하는가. 요청과 문맥을 사용하고 중요한 충돌이나 불확실성을 해소한다.
4. **수행 방법** — 유지 조건을 지키며 그 차이를 해소하려면 어떻게 작업하고 무엇으로 확인해야 하는가. 실제 문제와 수용 조건에서 필요한 스킬, 도구, 검사를 고른다.

한 작업에 여러 분야와 방법이 필요할 수 있다. 소설을 바탕으로 피치 덱을 만들 때는 서사 분석, 슬라이드 제작, 시각 검사가 함께 필요할 수 있다. 검색은 어느 작업 방식에서나 쓸 수 있다. 작업 개요는 기존 작업 요약과 단계 연결에 담는다. 작업 스킬에서 이를 재사용하고 빠진 사항이나 증거 때문에 바뀐 가정만 보완한다.

공통 [필요 정보 판단](references/information-needs.kr.md)에 따라 중요한 결정, 유지 조건, 실제 입력에서 질문을 도출한다. 초안을 쓰거나 수정하기 전에 [knowledge](../vegabond-knowledge/SKILL.kr.md)를 사용해 질문의 근거가 되는 작업 프로젝트 원문을 찾아 읽는다. 사용자가 경로를 주지 않은 일반 문서도 포함한다. 확인한 절, 작업에 미치는 영향, 검사, 공백을 기존 작업 요약에 남긴다. 실행을 맡은 전문 스킬은 실제 입력을 살펴 질문이 빠졌는지 확인하고 유효한 답을 재사용한다. 중요한 판단에 의존하기 전과 전달 직전에 관련 근거를 다시 확인한다.

| 작업 스킬 | 선택 조건 |
| --- | --- |
| [vegabond-create](../vegabond-create/SKILL.kr.md) | 기존 자료를 바탕으로 만들 때를 포함해 새 산출물이나 기능을 제작한다. |
| [vegabond-revise](../vegabond-revise/SKILL.kr.md) | 기존 산출물이나 동작을 개선하거나 바로잡는다. |
| [vegabond-research](../vegabond-research/SKILL.kr.md) | 조사 대상 원문을 유지하면서 질문에 답하거나 선택지를 비교한다. |

요청한 결과를 보고 주 작업을 선택한다. 장이나 덱 작성에 지원 조사가 필요해도 주 작업은 제작이다. 소프트웨어 기능 추가는 create, 결함 수정은 revise로 분류하고 재현과 원인 조사를 거친다. 복합 작업은 단계마다 여러 작업을 조합할 수 있다.

규모는 작업 방식과 별도로 정한다.

- **single** — 한 번의 실행과 검증 주기에 끝나는 작업이다. 기본값으로 사용한다.
- **staged** — 의존 관계, 비용이 큰 미해결 가정, 최종 검사만으로는 부족한 규모 때문에 이름을 붙인 중간 결과를 다음 작업 전에 확인해야 한다. 각 이정표에 알맞은 작업 방식을 사용하고 종합 결과를 검사한다.

도구, 파일, 일상적인 단계가 여러 개이거나 기다리는 시간이 길어도 한 실행·검증 주기로 처리할 수 있다. 위험도가 높은 경우 검사 강도를 높인다. 필요한 중간 검사 지점이 없으면 single로 시작하고, 새로운 의존성이나 불확실성이 생겼을 때 재평가한다. 소설 한 편 전체는 create + staged가 될 수 있고, 장 하나의 편집은 revise + single이 될 수 있다.

허용된 게임 기획·개발에서는 [게임 근거 재사용 규칙](../../knowledge/game/K-GAME-RESEARCH-USE.kr.md)을 적용한다. 구체적인 결정이나 증상에서 검색을 시작한다. 선택한 지식 ID, 적용 조건, 채택 판단, 실제 검사를 같은 작업 요약에 남긴다. 증상 검색으로 찾기 어려우면 기법 안내를 사용하고 실행 전문 스킬과 질문을 다듬는다. 게임 참고 자료는 관련 작업에 사용한다.

## 짧은 작업 요약 제공

실행 전에 다음 내용을 대화에 몇 줄로 남긴다.

- **목표와 결과물** — 전달할 결과, 독자, 형식, 필요한 경우 언어.
- **작업 방식과 규모** — 선택한 방식·규모와 짧은 이유.
- **범위** — 대상, 변경 의도, 유지 조건, 중요한 제외 대상.
- **완료 조건** — 각각의 수용 조건을 확인할 검사에 연결하고 진행 중 결과와 증거를 붙인다. 작은 작업은 본문 한두 줄로 충분하다. 기존 요약이나 단계 연결에 남긴다.

staged에서는 A가 잘못되면 B를 다시 해야 하므로 B 전에 A를 검사한다는 식으로 경계를 한 문장으로 설명한다. 실제 중간 결과, 의존 작업과 영향이 드러나게 쓰고 단계 연결에 검사를 포함한다.

기존 권한 범위에서 진행한다. 후속 요청에는 기존 요약을 이어 쓰고 목표, 범위, 증거가 바뀌면 갱신한다.

## 작업 단계에 스킬·도구와 검사 연결

계획한 단계마다 필요한 능력, 쓸 수 있는 스킬이나 도구, 기대 결과와 검사를 정한다. single은 본문에서 간단히 쓰고 staged는 목록이나 표를 사용한다.

| 단계 | 사용 가능한 스킬 또는 도구 | 예상 결과와 검사 |
| --- | --- | --- |
| 수행할 단계를 적는다. | 카탈로그에서 확인한 이름 또는 직접 사용할 도구. | 무엇이 나오고 어떤 증거로 검사하는지 적는다. |

필요한 방법에 맞춰 아래 전문 스킬을 사용한다.

| 전문 스킬 | 관련 작업 |
| --- | --- |
| [vegabond-code](../vegabond-code/SKILL.kr.md) | 소프트웨어 구현, 결함, 시스템 설계, 리팩터링, 코드 조사. |
| [vegabond-fiction](../vegabond-fiction/SKILL.kr.md) | 소설 개발, 집필, 검토, 연속성. |
| [vegabond-presentation](../vegabond-presentation/SKILL.kr.md) | 슬라이드 서사 구성, 덱 제작, 내용이나 시각 요소 수정. |
| [vegabond-image](../vegabond-image/SKILL.kr.md) | 래스터 이미지 생성과 편집, 요청 충실도 검수. |
| [vegabond-planning](../vegabond-planning/SKILL.kr.md) | 기획·제안 내용, 실현 가능성, 성공 지표. |

작업 스킬이 작업 흐름을 맡고, 전문 스킬의 분야별 실행·검증·수정 방법은 그 단계 안에서 적용한다. 조사나 피드백은 검토 원문을 유지하며 발견을 뒷받침하고 분석을 바로잡는 검사로 확인한다. 산출물을 만들거나 바꿀 때는 실제 제작 결과를 검사한다. 제안 덱에 기획과 프레젠테이션이 함께 필요한 경우처럼 여러 방법이 요구될 때 전문 스킬을 조합한다. 필요한 전문 스킬만 불러오고, 환경이나 형식에 맞는 다른 스킬과 도구도 같은 방법으로 연결할 수 있다.

현재 스킬 카탈로그를 확인하고 실제 이름과 경로를 사용한다. 선택한 스킬은 해당 단계에서 읽는다. 플러그인 설치 여부를 확인한다. 맞는 전문 스킬이 없으면 적절한 직접 도구를 사용하고 대체 방법을 짧게 알린다. 연결을 위해 스킬을 만들거나 설치하거나 위임하는 일은 작업상 필요에 따르며, 필수 능력이 없으면 영향을 받는 작업을 특정한다.

본격 제작 또는 의존 작업에 앞서 필수 입력, 접근, 도구, 실행·검토 환경이 계획한 검사에 쓰일 수 있는지 확인한다. 불확실하면 작고 관련된 검사로 확인하고 공백을 작업 요약에 반영한다. 차단된 작업은 에이전트 지침에 따라 처리하고 최종 산출물은 따로 검증한다.

선택한 작업 스킬을 그 단계에서 읽는다. 기존 요약, 네 항목의 개요, 원문 자료, 수용 조건을 전달한다. 작업 스킬은 선택한 방법을 자기 흐름의 단계로 구체화하고 같은 연결을 통해 해당 전문 스킬을 고른다. 새 근거가 생기면 영향받은 개요와 단계 연결을 갱신한다.

작업 스킬을 바로 호출했으면 이 공통 파악·요약·연결 절에서 빠진 맥락을 보완하고 해당 스킬의 절차를 계속 따른다. 검증과 수용에는 연결된 에이전트 지침을 적용한다. Scout는 반환된 결과, 증거, 남은 문제를 받아 의존 단계와 전달을 조정한다. 스킬 열람 자체는 문서 참조다.

## 실행과 전달

실제 매체에 해당하는 에이전트 지침의 완료 증거 규칙을 따른다. 각 단계를 실행하고 결과를 검사한다. staged 작업은 이정표 검사를 통과한 뒤 의존 단계로 넘어가고 실패나 피드백은 [공통 복귀 지점 규칙](../../agents/vegabond-agent.kr.md)에 따라 영향받은 요약, 단계, 검사만 갱신한다.

각 단계 검사 지점에서 중간 결과, 검사와 증거, 통과·실패·차단 상태, 다음 조치를 한 줄로 알린다. 필수 검사를 통과하면 의존 작업을 이어 간다.

다음 단계에 연결된 작업 스킬과 전문 스킬을 사용한다. 유효한 맥락을 재사용한다. 최종 전달 전에는 수용 조건마다 최신 근거 또는 명시적인 미해결 상태가 있는지 확인하고 종합 결과를 검사한다.

결과, 수용 조건의 증거, 불확실성을 보고한다. 초안, AI 검증 완료, 사용자의 명시적 수용은 각각의 상태를 표시한다. AI 검증은 사용자가 독립적으로 검사하거나 검토하기 전에 한다.
