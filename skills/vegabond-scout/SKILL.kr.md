# Vegabond Scout

vagabond의 의도한 결과에 맞춰 작업 종류와 규모를 선택하고 연결된 작업 스킬로 실행을 조정합니다. 작업 요약·역량 연결·전체 진행을 담당합니다.

## 틀 잡기와 분류

읽지 않았다면 [영문 에이전트 지침](../../agents/vegabond-agent.md)을 읽습니다. 요청·맥락·원자료에서 결과·독자·형식·언어·제약·수용 조건을 파악합니다. 빠진 의도가 작업을 실질적으로 바꿀 때만 질문합니다.

작업 종류를 분야·매체·도구와 구분합니다. 저자의 배경과 예시는 지원 범위를 제한하지 않습니다. 원래 입력·산출물은 요청 언어를 따릅니다. 사람용 *.kr.md는 읽기·검색·로드와 위임 조회에서 제외합니다.

다음 네 질문으로 가벼운 작업 프로필 하나를 만듭니다.

1. 대상: 어떤 자료·산출물·동작·질문이며 어떤 결과가 필요한가? 분야·매체·형식·실행 맥락을 포함합니다.
2. 의도한 변화: 무엇을 추가·교정·변환·개선·확립하고 현재와 목표 사이의 어떤 차이를 닫아야 하는가?
3. 보존 조건: 의미·동작·목소리·사실·형식·원자료 중 무엇을 유지해야 하는가? 맥락을 사용하고 중요한 충돌·불확실한 의도만 확인합니다.
4. 방법: 조건을 보존하며 차이를 닫을 방법과 필요한 역량·검사는 무엇인가? 분야명·확장자보다 실제 문제와 수용 조건에서 정합니다.

열린 설명을 사용합니다. 소설 기반 피치 덱처럼 여러 분야·방법을 조합할 수 있고 검색은 모든 작업을 지원할 수 있습니다. 별도 파일·고정 세부 유형 목록 대신 기존 요약·단계 연결에 프로필을 유지합니다. 작업 스킬이 재사용하고 새 근거로 달라진 조건만 보완합니다.

[필요한 정보의 공통 판단](references/information-needs.kr.md)으로 결정·보존 조건·실제 입력에서 질문을 도출합니다. [지식 스킬](../vegabond-knowledge/SKILL.kr.md)에 집중된 요약을 요청하고 근거·조건·점검·공백을 전달합니다. 실행 전문 스킬이 원본을 살핀 뒤 빠진 질문을 확인하며 유효한 답은 재사용하고 실제 작업에서 드러난 필요만 추가합니다. 중요한 의존 결정 전과 인계 때 영향받는 판단을 재검토합니다.

| 작업 스킬 | 선택 조건 |
| --- | --- |
| [제작](../vegabond-create/SKILL.kr.md) | 새 결과나 기능, 원본에서 파생한 산출물 제작. |
| [수정](../vegabond-revise/SKILL.kr.md) | 기존 산출물·동작 개선과 교정. |
| [조사](../vegabond-research/SKILL.kr.md) | 조사 대상은 바꾸지 않고 질문 답변·비교. |

최종 요청 결과로 주 작업을 정합니다. 보조 조사가 있다고 장면·덱 제작이 조사 전용이 되지는 않습니다. 소프트웨어 기능은 제작, 결함은 재현·원인 조사를 포함한 수정입니다. 복합 작업의 단계마다 다른 작업 종류를 쓸 수 있습니다.

규모는 별도로 정합니다.

- single: 한 실행·검증 사이클에 들어가는 작업이며 기본값입니다.
- staged: 의존성·비용 큰 미확인 가정·범위 때문에 최종 확인만으로 부족하여 이름 있는 중간 결과를 후속 작업 전에 검사해야 할 때입니다. 단계마다 적절한 작업을 선택하고 통합 결과를 검사합니다.

여러 도구·파일·보통 단계·대기 시간이 길다는 사실만으로 staged가 되지는 않습니다. 위험이 강한 점검을 요구해도 여러 단계가 필요한 것은 아닙니다. 구체적 중간 관문이 없으면 single로 시작하고 새 의존성·불확실성에 따라 재평가합니다. 장편 전체 제작은 staged, 한 장면 편집은 single일 수 있습니다.

## 짧은 작업 요약

실행 전에 대화에서 몇 줄로 설명합니다.

- 목표·산출물: 사용자가 받을 결과와 필요한 독자·형식·언어.
- 작업 종류·규모: 선택과 짧은 이유.
- 범위: 대상·변화·보존 조건·중요 제외 사항.
- 완료: 수용 조건마다 검사와 연결하고 진행하면서 결과·근거를 붙입니다. 작은 작업은 기존 요약에 한두 줄이면 충분합니다.

staged라면 “A를 확인한 뒤 B를 진행한다. A가 틀리면 C를 다시 해야 하기 때문이다”처럼 실제 중간 결과·후속 작업·영향을 한 문장으로 설명하고 같은 점검을 단계 연결에 사용합니다.

기존 허용 범위에서 일상 승인 관문 없이 진행합니다. 후속 요청은 기존 요약을 재사용하고 목표·범위·근거가 바뀐 부분만 갱신합니다. 별도 요약 파일은 필요하지 않습니다.

## 단계와 역량·검사 연결

각 단계에 필요한 역량, 사용 가능한 스킬·직접 도구, 결과와 검사 근거를 연결합니다. single은 문장 안에, staged는 짧은 목록이나 `단계 | 스킬·도구 | 결과·검사` 표를 사용할 수 있습니다.

| 전문 스킬 | 적용 작업 |
| --- | --- |
| [코딩](../vegabond-code/SKILL.kr.md) | 구현·결함·설계·리팩터링·코드 조사. |
| [소설](../vegabond-fiction/SKILL.kr.md) | 발전·집필·비평·연속성. |
| [발표](../vegabond-presentation/SKILL.kr.md) | 논리 흐름·덱 제작·내용·시각 검토. |
| [기획](../vegabond-planning/SKILL.kr.md) | 기획·제안 내용·실현 가능성·성공 지표. 일정 관리만을 뜻하지 않습니다. |

작업 스킬은 흐름을, 전문 스킬은 분야 실행·검증·수정 방법을 담당합니다. 별도 두 번째 작업 흐름을 시작하지 않습니다. 조사·피드백 전용은 발견을 뒷받침할 검사만 쓰고 실제 제작 검사는 해당 결과를 만들거나 바꿀 때 적용합니다. 필요하면 기획과 발표처럼 조합합니다. 이 목록은 닫힌 지원 범위가 아니며 실제 필요한 전문 스킬만 읽습니다.

현재 스킬 목록에서 실제 이름·경로를 확인하고 단계에 필요할 때 읽습니다. 플러그인 설치를 가정하지 않습니다. 적합한 전문 스킬이 없으면 가능한 직접 도구를 쓰고 대안을 짧게 설명합니다. 연결표를 채우기 위해 스킬·도구를 만들거나 설치·위임하지 않습니다. 필요한 역량이 없으면 통과가 아니라 막힘입니다.

큰 제작이나 의존 작업 전에 핵심 원본·접근·도구·검사 환경이 실제로 사용 가능한지 확인합니다. 불확실하면 작은 관련 탐침을 사용하고 처음부터 전체 최종 검사를 돌리지 않습니다. 도구 목록만으로 실행 가능성이 입증되지는 않습니다. 공백은 기존 요약과 공통 막힘 처리에 반영합니다. 준비 확인이 최종 검증을 대신하지 않습니다.

필요한 연결 작업 스킬을 읽되 셋 모두를 한꺼번에 읽지 않습니다. 기존 요약·네 질문·원자료·수용 조건을 전달하고 작업 스킬이 방법을 실행 단계로 옮기며 같은 역량 연결에서 전문 스킬을 선택합니다. 근거가 바뀐 부분만 프로필·연결을 갱신합니다. 스킬을 읽는 것은 다른 에이전트 생성이 아닙니다.

작업 스킬 직접 호출도 이 공통 틀·요약·연결에서 빠진 부분만 채우고 그 스킬로 계속합니다. 정찰은 반환 결과·근거·열린 문제로 의존 단계와 인계를 조정합니다.

## 실행과 반환

실제 매체에 맞는 에이전트 완료 근거 계약을 따릅니다. 각 단계를 실행·확인하고 staged는 중간 검사 뒤에만 의존 단계를 진행합니다. 발견·피드백은 [공통 복귀 규칙](../../agents/vegabond-agent.kr.md)에 따라 영향 요약·단계·점검만 갱신합니다.

각 중간 확인에는 결과·검사 근거·통과/실패/막힘·다음 행동을 한 줄로 알립니다. 이는 승인 요청이 아닙니다. 다음 단계의 작업·전문 스킬은 달라질 수 있으며 유효한 맥락을 재사용합니다. 최종 인계 전 모든 수용 조건에 현재 근거나 미해결 상태가 있는지, 통합 결과가 맞는지 확인합니다.

결과·수용 근거·불확실성을 보고하고 초안·AI 검증 완료·vagabond의 명시적 수용을 구분합니다. AI 확인이 독립 사용자 검토보다 먼저입니다.
