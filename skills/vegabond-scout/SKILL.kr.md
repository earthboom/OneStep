# Vegabond Scout

vagabond가 원하는 결과에 맞춰 작업 방식과 규모를 선택하고, 연결된 작업 스킬을 통해 실행을 조정합니다. Scout는 작업 요약, 수행 능력 연결, 전체 진행을 담당합니다.

## 작업 파악과 분류

아직 읽지 않았다면 [영문 에이전트 지침](../../agents/vegabond-agent.md)을 읽습니다. 요청, 관련 맥락, 원자료에서 의도한 결과, 독자, 형식, 언어, 제약, 수락 조건을 확인합니다. 누락된 의도가 작업을 실질적으로 바꾸는 경우에만 질문합니다.

작업 방식은 분야, 매체, 도구와 별도로 판단합니다. 저자의 배경과 여기의 예시는 지원 범위를 제한하지 않습니다. 원본 입력과 결과물은 요청한 언어를 따릅니다. 사용자 전용 *.kr.md 번역본을 읽거나 검색하거나 불러오지 않으며, 검색과 허용된 위임 작업에서 제외합니다.

네 가지 질문으로 간단한 작업 특성을 한 번 정리합니다.

1. **대상:** 어떤 자료, 결과물, 동작, 질문을 다루며 무엇을 요청했는가? 관련 분야, 매체·형식, 실행 맥락을 포함합니다.
2. **원하는 변화:** 무엇을 추가, 수정, 변환, 개선, 확인해야 하는가? 현재 상태와 원하는 결과의 구체적 차이를 설명합니다.
3. **유지할 조건:** 의미, 동작, 문체, 사실, 형식, 원자료 중 무엇을 유지해야 하는가? 요청과 맥락을 활용하고 중요한 충돌이나 불확실성을 확인합니다.
4. **수행 방법:** 유지 조건을 지키면서 차이를 해소하려면 어떻게 작업해야 하며 어떤 능력과 검사가 필요한가? 분야 이름이나 확장자 대신 실제 문제와 수락 조건에서 선택합니다.

열린 설명을 사용합니다. 하나의 작업이 여러 분야와 방법을 포함할 수 있습니다. 소설 기반 발표자료에는 서사 분석, 슬라이드 제작, 시각 검사가 함께 필요할 수 있습니다. 검색은 모든 작업 방식을 지원할 수 있습니다. 별도 파일이나 고정 하위 유형 목록을 만들지 않고 작업 요약과 단계 연결에 특성을 담습니다. 작업 스킬은 이를 재사용하고, 누락된 세부사항이나 근거로 달라진 가정만 보완합니다.

작업 특성과 현재 질문을 사용해 [vegabond-knowledge](../vegabond-knowledge/SKILL.md)에 필요한 정보 요약을 요청합니다. 관련 출처, 적용 조건, 예방 검사, 공백을 작업 요약과 단계 연결에 반영합니다. 선택한 작업·전문 스킬에 전달하고, 질문이나 근거가 달라질 때만 추가 정보를 요청합니다.

| 작업 스킬 | 선택하는 경우 |
| --- | --- |
| [vegabond-create](../vegabond-create/SKILL.md) | 기존 자료를 활용한 결과물을 포함하여 새로운 결과물이나 기능을 만듭니다. |
| [vegabond-revise](../vegabond-revise/SKILL.md) | 기존 결과물이나 동작을 개선하거나 수정합니다. |
| [vegabond-research](../vegabond-research/SKILL.md) | 조사 원본을 변경하지 않고 질문에 답하거나 대안을 비교합니다. |

요청 결과에 따라 주된 작업 방식을 선택합니다. 보조 조사가 필요하다고 장이나 발표자료 제작을 조사 전용 작업으로 바꾸지 않습니다. 소프트웨어 기능 추가에는 create를, 결함에는 재현·원인 조사와 함께 revise를 사용합니다. 복합 작업은 단계별로 작업 방식을 조합할 수 있습니다.

규모는 별도로 선택합니다.

- **single:** 한 번의 실행·검증 주기로 처리할 수 있는 간결한 작업이며 기본값입니다.
- **staged:** 의존성, 틀렸을 때 비용이 큰 미확정 가정, 마지막 검증만으로 부족한 범위 때문에 후속 작업 전에 이름 붙일 수 있는 중간 결과를 확인해야 합니다. 각 중간 지점에 적합한 작업 방식을 적용하고 최종 통합 결과를 확인합니다.

도구·파일·일반 단계가 여럿이거나 대기 시간이 길다는 이유만으로 staged가 되지는 않습니다. 위험은 규모 변경 없이 더 강한 검사를 요구할 수 있습니다. 구체적인 중간 확인이 필요하지 않으면 single로 시작하고, 새로운 의존성이나 불확실성이 생길 때 재평가하여 작업 요약을 갱신합니다. 장편 소설 전체는 create + staged, 한 장 편집은 revise + single이 될 수 있습니다.

## 짧은 작업 요약

실행 전에 대화에서 몇 줄로 다음을 밝힙니다.

- **목표와 결과물:** 사용자가 받을 결과와 필요한 독자·형식·언어.
- **작업 방식과 규모:** 선택과 짧은 이유.
- **범위:** 대상, 원하는 변화, 유지 조건, 중요한 제외 범위.
- **완료:** 각 수락 조건을 검사에 연결하고, 진행하면서 결과와 근거를 붙입니다. 작은 작업은 한두 줄이면 충분합니다. 별도 추적 파일 대신 기존 작업 요약이나 단계 연결을 사용합니다.

staged에서는 경계를 한 문장으로 설명합니다. “A가 틀리면 C를 다시 작업해야 하므로 B 전에 A를 확인합니다.” 실제 중간 결과, 후속 작업, 영향을 이름 붙이고 해당 검사를 아래 단계 연결에 사용합니다.

일상적인 승인 단계를 추가하지 않고 기존 허용 범위에서 진행합니다. 후속 작업은 요약을 재사용하며 목표·범위·근거가 달라지면 갱신합니다. 별도 요약 파일은 필요 없습니다.

## 단계에 스킬과 검사 연결

계획한 단계마다 필요한 수행 능력, 사용 가능한 스킬이나 직접 도구, 예상 결과와 검사를 연결합니다. single은 본문에 간단히 적고, staged는 짧은 목록이나 다음 표를 사용합니다.

| 단계 | 사용 가능한 스킬 또는 직접 도구 | 예상 결과와 검사 |
| --- | --- | --- |
| 수행할 단계를 설명합니다. | 실제 제공되는 이름이나 직접 도구를 적습니다. | 산출물과 이를 확인할 근거를 적습니다. |

필요한 방법을 제공하는 다음 로컬 전문 스킬을 사용합니다.

| 전문 스킬 | 관련 작업 |
| --- | --- |
| [vegabond-code](../vegabond-code/SKILL.md) | 소프트웨어 구현, 결함, 시스템 설계, 리팩터링, 코드 조사. |
| [vegabond-fiction](../vegabond-fiction/SKILL.md) | 소설 구상, 집필, 비평, 연속성. |
| [vegabond-presentation](../vegabond-presentation/SKILL.md) | 슬라이드 서사, 발표자료 제작, 내용·시각 수정. |
| [vegabond-planning](../vegabond-planning/SKILL.md) | 기획·제안 내용, 실현 가능성, 성공 지표. 단순 작업 일정 수립은 제외합니다. |

작업 스킬이 절차를 맡고, 전문 스킬은 분야별 실행·검증·수정 방법을 제공합니다. 별도의 독립 절차를 두 번 실행하지 않고 작업 단계 안에 적용합니다. 조사나 피드백만 요청된 작업에서는 원본을 변경하지 않고 발견 사항을 뒷받침하고 분석을 바로잡는 검사를 사용합니다. 해당 결과물을 만들거나 바꿀 때 제작 검사를 적용합니다. 제안 발표자료의 기획 내용과 발표 제작처럼 필요한 곳에서만 전문 스킬을 조합합니다. 이 목록은 초기 구성이며 지원 범위를 닫아두지 않습니다. 관련 전문 스킬만 읽고, 같은 연결 방식으로 환경·형식별 가용 스킬과 도구를 활용합니다.

현재 스킬 목록을 확인하고 실제 이름과 경로를 사용합니다. 각 단계에서 필요해질 때 선택한 스킬을 읽습니다. 플러그인이 설치되어 있다고 가정하지 않습니다. 맞는 전문 스킬이 없으면 수행 가능한 직접 도구를 사용하고 대체 방법을 짧게 밝힙니다. 연결을 채우기 위해 스킬을 만들거나 설치하거나 위임하지 않습니다. 필수 수행 능력 부재는 통과가 아니라 장애입니다.

본격적인 제작이나 의존 작업 전에 계획한 검사에 필요한 핵심 자료, 접근 권한, 도구, 실행·검사 환경을 사용할 수 있는지 확인합니다. 가용성이 불확실하면 관련된 작은 실행 확인을 사용하되 시작할 때 전체 최종 검사 묶음을 돌리지는 않습니다. 도구 목록에 있다는 사실만으로 준비가 입증되지는 않습니다. 공백은 작업 요약에 반영하고 에이전트 지침의 장애 처리를 따릅니다. 준비 확인은 최종 결과물 검증을 대신하지 않습니다.

각 단계에 필요한 작업 스킬을 읽고 세 가지 모두를 기본으로 읽지 않습니다. 기존 작업 요약, 네 가지 특성, 원자료, 수락 조건을 전달합니다. 작업 스킬은 선택한 방법을 실행 절차로 구체화하고 공통 연결에서 전문 스킬을 선택합니다. 근거가 바뀌면 분류를 반복하지 않고 특성과 연결을 갱신합니다. 스킬을 읽는 것만으로 다른 에이전트가 생성되지는 않습니다.

작업 스킬을 직접 호출하면 여기의 공통 파악·요약·연결 절차로 빠진 맥락을 채운 뒤 scout로 다시 분기하지 않고 해당 스킬을 이어갑니다. 공통 검증·수락에는 연결된 에이전트 지침을 따릅니다. Scout는 반환된 결과, 근거, 미해결 문제를 바탕으로 의존 단계와 최종 전달을 조정합니다.

## 실행과 전달

실제 매체에 맞춰 에이전트 지침의 완료 근거 계약을 따릅니다. 각 단계를 실행하고 결과를 확인합니다. staged는 후속 작업 전에 중간 검사를 통과해야 합니다. 실패와 피드백은 [공통 복귀 위치 규칙](../../agents/vegabond-agent.md#respond-to-failures-and-feedback)에 따라 처리하고, 영향을 받은 요약·단계·검사만 갱신합니다.

staged의 각 확인 지점에서 중간 결과, 검사와 근거, 통과·실패·진행 불가, 다음 행동을 한 줄로 알립니다. 필수 검사가 통과한 뒤에만 의존 작업으로 진행합니다. 이 알림은 일상적인 사용자 승인을 요청하는 절차가 아닙니다.

다음 단계에 연결한 작업 방식과 전문 스킬로 이어갑니다. 이전 단계와 다를 수 있습니다. 분류를 처음부터 다시 시작하지 않고 유효한 맥락을 재사용합니다. 최종 전달 전에 각 수락 조건에 현재 유효한 근거나 명시적인 미해결 상태가 있는지 확인하고 통합 결과를 검사합니다.

결과, 수락 근거, 불확실성을 보고합니다. 초안, AI 검증 완료, vagabond의 명시적 수락을 구분합니다. AI 검사는 vagabond의 독립 테스트·검토보다 먼저 수행합니다.
