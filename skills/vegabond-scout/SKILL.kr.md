# Vegabond Scout

vagabond가 원하는 결과에 맞춰 작업 방식과 규모를 정하고, 해당 작업 스킬을 통해 실행을 조율합니다. Scout는 작업 요약, 수행 능력 연결, 전체 진행을 담당합니다.

## 요청 파악과 분류

이번 작업에서 아직 확인하지 않았다면 [영문 에이전트 지침](../../agents/vegabond-agent.md)을 읽습니다. 사용자가 이미 제공한 요청과 맥락부터 살핍니다. 가능한 해석에 따라 산출물, 보존할 사항, 완료 판정이 달라지는지 판단합니다.

- **해석에 따라 작업이 달라질 때.** 특정 해석에 의존하는 조사나 작업에 착수하기 전에 무엇을 만들지, 무엇을 유지할지, 어떻게 완료를 확인할지를 사용자에게 한두 문장으로 보여줍니다. 맥락을 근거로 정할 수 있고 되돌리기 쉬운 선택이라면 가정을 밝히고 진행합니다. 사용자가 정해야 하는 선택이라면 같은 메시지에서 핵심 질문 하나를 하고, 답을 받을 때까지 그 선택에 의존하는 작업을 보류합니다. 예를 들어 “확정된 변경 사항과 날짜를 유지해 릴리스 안내문을 작성하고, 독자가 자신에게 달라지는 점을 알 수 있는지 확인하겠습니다. 독자는 고객인가요, 고객지원팀인가요?”라고 물을 수 있습니다.
- **명확하고 단순한 요청.** 바로 수행하고 요청한 변경을 확인한 뒤 결과를 전달합니다. 착수 요약이나 확인 질문을 덧붙이지 않습니다. 명확한 여러 단계 작업은 목표·제약·검사를 기존 작업 요약에 유지하고 의미 있는 중간 확인 시점에 진행 상황을 알립니다.

후속 요청이나 새 근거로 해석이 달라지면 같은 기준을 적용합니다. 사용자가 이미 내린 결정은 재사용합니다. 결과를 전달할 때 중요한 완료 기준마다 확인 근거나 남은 공백을 밝힙니다.

작업 방식은 분야, 매체, 도구와 별도로 판단합니다. 저자의 배경과 아래 예시는 지원 범위를 제한하지 않습니다. 원본 입력과 산출물에는 요청한 언어를 사용합니다. 사람이 읽기 위한 *.kr.md 번역본은 읽거나 검색하거나 불러오지 않습니다. 허가된 위임 작업에서도 조회 전에 제외합니다.

네 가지 질문으로 간결한 작업 개요를 만듭니다.

1. **대상.** 어떤 자료, 산출물, 동작 또는 질문을 다루며 원하는 결과는 무엇입니까? 관련 분야, 매체·형식, 실행 환경을 포함합니다.
2. **원하는 변화.** 무엇을 추가·수정·변환·개선하거나 확인해야 합니까? 현재 상태와 원하는 결과 사이의 구체적인 차이를 설명합니다.
3. **보존 조건.** 의미, 동작, 문체, 사실, 형식, 원자료 등 무엇을 유지해야 합니까? 요청과 맥락을 살피고 중요한 충돌이나 불확실성만 확인합니다.
4. **방법.** 보존 조건을 지키면서 차이를 해소하려면 어떻게 작업하며, 어떤 능력과 검사가 필요합니까? 실제 문제와 수용 조건을 기준으로 선택합니다.

하나의 작업에 여러 분야와 방법이 필요할 수 있습니다. 소설을 바탕으로 제안 발표자료를 만들 때는 서사 분석, 슬라이드 제작, 시각 검토가 함께 필요할 수 있습니다. 검색은 어떤 작업 방식이든 지원할 수 있습니다. 개요는 기존 작업 요약과 단계별 연결에 담습니다. 별도 파일이나 고정된 하위 유형 목록을 만들 필요는 없습니다. 작업 스킬은 이 개요를 재사용하고 빠진 사항이나 근거로 달라진 전제만 갱신합니다.

공통 [정보 필요성 판단](references/information-needs.kr.md)에 따라 결정, 보존 조건, 실제 입력에서 질문을 도출합니다. 초안 작성이나 편집 전에 [지식 스킬](../vegabond-knowledge/SKILL.kr.md)로 작업 프로젝트에서 해당 질문을 판단할 기준 자료를 찾아 읽습니다. 사용자가 경로를 주지 않은 일반 문서도 대상입니다. 참고한 절, 작업에 미친 영향, 필요한 검사와 남은 공백을 기존 작업 요약에 담습니다. 실행 담당 전문 스킬은 실제 입력을 살핀 뒤 빠진 질문을 확인하고 유효한 답을 재사용합니다. 중요한 결정에 근거를 사용하기 전과 결과를 전달하기 전에 달라진 판단을 다시 살핍니다.

과거 결함이 이번 작업에 영향을 줄 수 있다면 검사를 정하기 전에 **하려는 동작과 그 동작이 일어나는 조건**으로 문제 기록을 검색합니다. 예를 들어 OneStep 체크아웃에서 다음과 같이 실행합니다.

```text
python skills/vegabond-knowledge/scripts/search.py search --project . --store records --query "repeated stop during audio fade" --no-cache
```

연결된 프로젝트에서는 작업 프로젝트를 현재 디렉터리로 유지하고 설정된 OneStep 체크아웃의 검색 도우미 경로를 사용합니다. `--project .`은 계속 작업 프로젝트를 가리킵니다. 프로젝트 자체 저장소나 웹 업로드본을 사용한다면 이용 가능한 문제 목록에서 해당 동작을 찾아 일치하는 상세 기록을 엽니다. 적용 범위와 재검증 근거를 읽고 기존 작업 요약에 한 줄로 남깁니다. 예를 들면 “두 번째 중단 요청이 재시작을 늦출 수 있는가? → R-CODE-UE-MUSIC-STOP → 페이드 동작 규약이 같은 플레이어에서 두 번째 중단 요청 후에도 원래 페이드 종료 시점과 재시작 시점이 유지되는지 검사한다.” 조건이 다르면 아직 결정하지 못한 사항이나 검사를 밝힙니다. 결과를 검증할 때 선정한 검사를 실행합니다.

입력만으로 판단이 끝나면 해당 입력으로 바로 작업합니다. 주어진 문장에서 공백 하나를 고치는 요청이라면 원문과 결과를 비교해 정확히 그 공백만 바뀌었는지 확인합니다.

| 작업 스킬 | 선택하는 경우 |
| --- | --- |
| [vegabond-create](../vegabond-create/SKILL.kr.md) | 기존 원자료에서 파생한 결과를 포함해 새로운 산출물이나 기능을 만듭니다. |
| [vegabond-revise](../vegabond-revise/SKILL.kr.md) | 기존 산출물이나 동작을 개선하거나 바로잡습니다. |
| [vegabond-research](../vegabond-research/SKILL.kr.md) | 조사 대상을 유지하면서 질문에 답하거나 선택지를 비교합니다. |

요청한 결과로 주 작업을 정합니다. 장이나 발표자료 제작에 조사가 포함되어도 주 작업은 제작입니다. 소프트웨어 기능 추가는 create, 결함 수정은 재현과 원인 조사를 포함한 revise를 사용합니다. 혼합 작업에서는 단계마다 방식을 달리할 수 있습니다.

규모는 별도로 정합니다.

- **single.** 한 번의 실행·검증 주기로 다룰 수 있는 작업의 기본값입니다.
- **staged.** 의존 관계, 잘못됐을 때 비용이 큰 전제, 최종 검증만으로 충분하지 않은 범위 때문에 이후 작업 전에 특정 중간 결과를 검사해야 할 때 사용합니다. 각 중간 결과에 맞는 작업 방식을 적용하고 최종 통합 결과도 검증합니다.

도구나 파일이 여럿이거나 일반적인 단계가 많거나 오래 기다린다는 이유만으로 staged를 선택하지 않습니다. 위험도에 따라 규모를 유지하면서 검사를 강화할 수 있습니다. 구체적인 중간 검사가 필요하지 않으면 single로 시작하고 새 의존 관계나 불확실성이 드러날 때 요약을 갱신합니다. 장편 소설 전체는 create + staged, 한 장 편집은 revise + single이 될 수 있습니다.

이 저장소의 허가 범위에서 게임을 기획·개발할 때는 [게임 근거 재사용 규약](../../knowledge/game/K-GAME-RESEARCH-USE.kr.md)을 적용합니다. 결정이나 증상에서 검색 질문을 도출하고 선택한 지식 ID, 적용 조건, 채택 여부와 실제 검사를 같은 작업 요약에 남깁니다. 증상으로 찾기 어려우면 기법 안내서를 활용하고 실행 담당 전문 스킬과 함께 범위를 구체화합니다. 관련 없는 작업에는 게임 자료를 요구하지 않습니다.

선택한 작업 방식과 규모, 완료 검사는 기존 작업 요약에 담습니다. staged에서는 검사할 중간 결과, 이에 의존하는 작업, 중간 결과가 틀렸을 때 다시 해야 할 일을 밝힙니다. 아래 단계별 연결에 그 검사를 사용합니다.

## 단계에 스킬과 검사 연결하기

계획한 단계마다 필요한 수행 능력, 사용 가능한 스킬이나 직접 도구, 기대 결과와 검사를 연결합니다. single은 한 줄로, staged는 짧은 목록이나 아래 표로 정리합니다.

| 단계 | 사용 가능한 스킬 또는 직접 도구 | 기대 결과와 검사 |
| --- | --- | --- |
| 할 일을 설명합니다. | 실제 제공되는 이름이나 도구를 적습니다. | 산출물과 이를 확인할 근거를 적습니다. |

해당 방법이 필요할 때 아래 전문 스킬을 사용합니다.

| 전문 스킬 | 관련 작업 |
| --- | --- |
| [vegabond-code](../vegabond-code/SKILL.kr.md) | 소프트웨어 구현, 결함, 시스템 설계, 리팩터링, 코드 조사 |
| [vegabond-fiction](../vegabond-fiction/SKILL.kr.md) | 소설 개발, 집필, 비평, 연속성 |
| [vegabond-document](../vegabond-document/SKILL.kr.md) | 이력서, 경력·경험기술서, 입사지원서, 자기소개서, 영문 커버레터, 지원동기 등 채용 서류 작성과 검토. |
| [vegabond-presentation](../vegabond-presentation/SKILL.kr.md) | 발표 논리, 슬라이드 제작, 내용·시각 요소 수정 |
| [vegabond-image](../vegabond-image/SKILL.kr.md) | 래스터 이미지 생성, 편집, 시각적 충실도 검사 |
| [vegabond-sound](../vegabond-sound/SKILL.kr.md) | 효과음, BGM, 말소리, 곡 등 오디오 자산의 제작, 편집, 검토. |
| [vegabond-planning](../vegabond-planning/SKILL.kr.md) | 기획·제안 내용, 실현 가능성, 성공 지표. 일정 작성만을 위한 스킬은 아닙니다. |

작업 스킬이 진행을 맡고 전문 스킬은 그 안에서 분야별 실행·검증·수정 방법을 제공합니다. 전문 스킬의 방법을 기존 단계에 적용합니다. 조사나 피드백만 요청한 작업은 발견 사항을 뒷받침하는 검사로 분석을 바로잡고 조사 대상은 유지합니다. 해당 매체를 제작하거나 변경할 때 제작 검사를 적용합니다. 제안 발표의 기획과 슬라이드 제작처럼 필요한 경우에만 전문 스킬을 조합합니다. 위 목록은 초기 구성이며 지원 분야를 한정하지 않습니다. 관련 전문 스킬만 읽고, 같은 단계 연결에서 환경·형식별 스킬이나 도구를 사용할 수 있습니다.

현재 스킬 목록에서 실제 이름과 경로를 확인하고 필요한 단계에서 선택한 스킬을 읽습니다. 플러그인 설치 여부를 추측하지 않습니다. 적절한 전문 스킬이 없으면 수행 가능한 직접 도구를 사용하고 대체 방법을 간단히 밝힙니다. 연결표를 채우기 위해 스킬을 만들거나 설치하거나 작업을 위임하지 않습니다. 필수 능력이 없으면 해당 검사는 차단 상태입니다.

본격적인 제작이나 의존 작업을 시작하기 전에 필수 원자료, 접근 권한, 도구, 실행·검토 환경을 실제로 사용할 수 있는지 확인합니다. 불확실하면 작은 관련 작업으로 확인합니다. 준비 단계에서 최종 검사 전체를 수행할 필요는 없습니다. 도구 목록만으로 준비가 끝났다고 판단하지 않습니다. 부족한 사항은 요약에 담고 에이전트 지침의 차단 처리 절차를 따릅니다. 최종 산출물 검증은 별도로 수행합니다.

각 단계에 필요한 작업 스킬을 그때 읽습니다. 기본적으로 세 가지를 모두 읽지 않습니다. 기존 요약, 네 가지 질문으로 파악한 개요, 원자료, 수용 조건을 전달합니다. 작업 스킬은 선택한 방법을 실행 절차로 구체화하고 같은 수행 능력 연결을 통해 전문 스킬을 선택합니다. 새 근거가 나오면 개요와 단계 연결에서 영향을 받은 부분만 갱신합니다.

작업 스킬을 직접 호출하면 여기의 요청 파악, 요약, 단계 연결을 사용해 빠진 맥락을 채운 뒤 해당 스킬에서 계속 진행합니다. 공통 검증과 수용에는 연결된 에이전트 지침을 따릅니다. Scout는 반환된 결과, 근거, 미해결 문제로 후속 단계와 최종 전달을 조율합니다.

## 실행과 결과 전달

실제 매체에 맞춰 에이전트 지침의 완료 근거 규약을 따릅니다. 각 단계를 실행하고 결과를 확인합니다. staged에서는 중간 검사를 통과한 뒤 의존 작업으로 진행합니다. 실패와 피드백은 [공통 복귀 기준](../../agents/vegabond-agent.md#respond-to-failures-and-feedback)에 따라 요약, 단계, 검사에서 영향받는 부분만 갱신합니다.

staged의 각 중간 확인 시점에는 중간 결과, 검사와 근거, 통과·실패·차단 상태, 다음 행동을 한 줄로 알립니다. 필요한 검사를 통과한 뒤에만 의존 작업으로 넘어갑니다. 이 알림으로 사용자에게 일상적인 승인을 요구하지 않습니다.

다음 단계에 연결한 작업 방식과 전문 스킬로 진행합니다. 앞 단계와 다를 수 있습니다. 유효한 맥락을 재사용합니다. 최종 전달 전 각 수용 조건에 현재 근거나 명시적인 미해결 상태가 있는지 확인하고 통합 결과를 검사합니다.

결과, 수용 근거, 불확실성을 보고합니다. 초안, AI 검증 완료, vagabond의 명시적 수용을 구분합니다. AI 검사가 끝난 뒤 vagabond가 독립적으로 테스트하거나 검토합니다.

작업 중 OneStep 전략 자체에 대한 중요한 피드백이 발견되면 최종 답변을 보내기 전에 [피드백 도착 확인 절차](../../feedback/README.kr.md)를 따릅니다. 인계문에 제출 상태와 확인한 파일의 링크를 담습니다. 두 파일을 모두 갖추지 못했다면 어떤 경로에서 무엇이 막혔는지 밝힙니다.
