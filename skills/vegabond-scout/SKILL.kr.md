# Vegabond Scout

의도한 결과에 맞는 작업 종류·규모를 선택하고 연결된 작업 스킬로 실행을 조정한다. Scout는 브리프·역량 매핑·전체 진행을 담당한다.

## 맥락과 분류

아직 읽지 않았다면 영문 에이전트 지침을 읽는다. 요청·맥락·자료에서 결과·독자·형식·언어·제약·완료 조건을 확인한다. 누락된 의도가 작업을 실질적으로 바꿀 때만 질문한다. 작업 종류와 도메인·매체·도구는 별도로 판단한다. 저자의 배경이나 사례는 지원 범위를 제한하지 않는다. 원본 입출력은 요청 언어를 따르며 *.kr.md 번역은 읽거나 검색·로드하지 않는다.

기존 브리프에 다음 네 질문으로 가벼운 프로필을 만든다.

1. 대상: 자료·산출물·동작·질문, 원하는 결과, 도메인·형식·실행 환경.
2. 변경: 추가·수정·변환·개선할 내용과 현재·목표의 구체적 차이.
3. 보존: 의미·동작·문체·사실·형식·출처 등 유지 조건과 중요한 충돌.
4. 방법: 보존하며 차이를 해소할 방법·역량·검사. 도메인 이름·확장자만으로 결정하지 않는다.

여러 도메인·방법이 함께 필요할 수 있다. 프로필은 별도 파일·고정 세부 유형 목록 없이 브리프·단계 매핑에 둔다. 전문 스킬은 이를 재사용하고 근거로 바뀐 부분만 갱신한다. 공통 정보 필요성 판단으로 결정·보존 조건·실제 입력에서 질문을 도출한다. 지식 스킬에서 근거·조건·검사·공백을 받는다. 실행 전문가는 소스 검사 후 누락 질문을 보완하고 중요한 의존·인계 전에 재확인한다.

- 생성: 출처에서 파생된 것을 포함한 새 산출물·기능 제작.
- 수정: 기존 산출물·동작 개선이나 교정.
- 조사: 조사 대상을 바꾸지 않고 질문·대안 비교.

결과를 기준으로 주 작업을 선택한다. 보조 조사가 있다고 조사 전용은 아니다. 소프트웨어 기능은 생성, 결함은 재현·원인 분석을 포함한 수정이며 혼합 작업은 단계를 나눈다.

규모는 별도로 정한다. 기본은 한 실행·검증 주기의 단일 작업이다. 의존성·큰 미해결 전제·범위 때문에 중간 결과를 검사해야 할 때만 단계 작업을 선택한다. 도구·파일·일반 단계·대기 시간 수만으로 단계화하지 않는다. 위험은 검사 강도를 높일 수 있지만 규모와 같지 않다. 시작 후 근거로 필요한 경계를 갱신한다.

이 저장소의 허가 범위 안의 게임 기획·개발에는 [게임 근거 활용 규칙](../../knowledge/game/K-GAME-RESEARCH-USE.kr.md)을 적용한다. 실제 결정·증상으로 조회하고 선택 ID·적용 조건·채택 결정·실제 검사를 같은 브리프에 연결한다. 증상 검색이 빗나가면 기술 안내서를 쓰고 실행 전문가가 보완한다. 무관한 작업에는 게임 지식을 강제하지 않는다.

## 짧은 브리프

실행 전에 대화에 목표·산출물(관련 독자·형식·언어), 작업 종류·규모와 이유, 대상·변경·보존·범위, 각 완료 조건과 검사를 간단히 밝힌다. 작은 작업은 한두 줄이면 된다. 별도 추적 파일은 필요 없다.

단계 작업은 “A를 B 전에 검사한다. A가 틀리면 C를 다시 해야 하기 때문이다”처럼 실제 경계를 설명하고 매핑에 검사로 넣는다. 기존 허가 범위에서는 관례적 승인 중단 없이 진행한다. 후속 작업은 브리프를 재사용하고 목표·범위·근거 변화만 갱신한다.

## 단계·역량·검사 연결

단계마다 필요한 역량, 실제 사용 가능한 스킬·직접 도구, 결과와 검사를 연결한다. 단일 작업은 문장, 단계 작업은 짧은 목록이나 표면 충분하다.

- 코드: 구현·결함·시스템 설계·리팩터링·코드 조사.
- 소설: 개발·집필·비평·연속성.
- 발표: 서사·제작·내용 및 시각 수정.
- 기획: 기획·제안 내용·타당성·성과 지표. 단순 일정 관리와 구분한다.

작업 스킬이 절차를 소유하고 전문가는 그 안에 실행·검증·수정 방법을 공급한다. 독립 절차를 중복 실행하지 않는다. 조사·피드백은 결과를 뒷받침하는 검사와 분석 수정을 적용하고 조사 대상을 바꾸지 않는다. 실제 제작·변경할 때 제작 검사를 적용한다. 필요한 전문가만 조합하고 환경·형식별 스킬·도구도 같은 매핑으로 선택한다. 이 목록은 지원 범위를 닫지 않는다.

현재 스킬 목록의 실제 이름·경로를 확인하고 해당 단계에 필요한 스킬만 읽는다. 플러그인 설치를 가정하지 않는다. 맞는 전문가가 없으면 가능한 직접 도구를 쓰고 대안을 밝힌다. 매핑을 채우려고 스킬을 만들거나 설치·위임하지 않는다. 필수 역량 누락은 통과가 아닌 차단이다.

본격 제작·의존 작업 전에 필수 출처·접근·도구·실행 및 검사 환경의 사용 가능성을 확인한다. 불확실하면 작은 관련 탐색으로 확인하며 도구 목록만으로 준비를 입증하지 않는다. 처음부터 전체 최종 검사를 돌리지 않는다. 공백은 브리프와 에이전트의 차단 처리로 전달한다. 준비 확인은 최종 검증을 대신하지 않는다.

각 단계에 필요한 작업 스킬만 읽고 기존 브리프·프로필·출처·완료 조건을 전달한다. 세 작업 스킬을 항상 모두 로드하지 않는다. 근거 변화는 기존 프로필·매핑을 갱신하며 스킬을 읽는 것만으로 에이전트를 생성하지 않는다.

작업 스킬이 직접 호출되면 이 공통 설정으로 누락 맥락만 채우고 Scout로 다시 라우팅하지 않는다. 공통 검증·수락은 에이전트 지침을 따른다. Scout는 반환된 결과·근거·미해결 문제로 후속 단계·인계를 조정한다.

## 실행·인계

실제 매체의 완료 근거 계약을 따른다. 각 단계를 실행하고 결과를 검사한다. 단계 작업은 필수 중간 검사가 통과해야 의존 작업을 진행한다. 실패·피드백은 공통 복귀 규칙으로 영향받는 브리프·단계·검사만 갱신한다.

중간 점검은 결과·검사 근거·통과/실패/차단·다음 행동을 한 줄로 알린다. 이는 관례적 승인 요청이 아니다. 다음 단계의 작업·전문가는 달라질 수 있고 유효한 맥락을 재사용한다. 최종 인계 전 모든 완료 조건의 최신 근거나 미해결 상태와 통합 결과를 확인한다.

결과·완료 근거·불확실성을 보고한다. 초안·AI 검증 완료·vagabond의 명시적 수락을 구분한다. AI 검사가 독립 테스트·검토에 앞선다.
