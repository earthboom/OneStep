# 베가본드 이미지

OneStep의 생성 또는 수정 작업에서 이 전문 스킬을 사용한다. Codex에서 이미지 생성과 편집에는 내장 imagegen 스킬의 실행 지침을 따른다. 매체, 구도, 시리즈 일관성, 글자 또는 출력 조건을 구체화할 때는 [스타일 및 검수 사례](references/style-and-review.kr.md)를 참고한다.

기존 캐릭터나 제작 사양에 의존하는 작업에서 직접 호출되면 [Scout 공통 준비 절차](../vegabond-scout/SKILL.kr.md)를 적용한다. 기존 브리프를 재사용하고, 필요한 경우 [지식 스킬](../vegabond-knowledge/SKILL.kr.md)에서 프로젝트의 식별 특징과 검수 기준을 찾는다. 공급사별 치수는 해당 제품의 승인 사양서에서 확인한다. 중요한 규격이 여전히 빠졌다면 허용된 자료 범위에서 [조사 단계](../vegabond-research/SKILL.kr.md)를 수행하고 그 규격에 의존하는 제작 검수는 미확정으로 둔다. 자체적으로 충분한 시각 요청은 바로 진행한다.

## 이미지가 보여 줄 것 정하기

- 원 요청에서 필수 조건, 선호, 위임된 선택을 구분한다. 필수 조건은 실제 결과에서 관찰할 수 있는 간단한 검수 항목으로 적는다. 정확한 문구·수량·속성·위치·제외 요소·납품 규격을 보존한다. 화면 기준 좌우를 지정했다면 그 기준을 쓰고, 여러 물체의 재질·색·개수·위치는 각 대상에 연결한다.
- 장면의 내용과 표현 매체를 각각 정한다. 빛과 질감, 선과 형태, 붓질, 팔레트나 공간 규칙으로 스타일을 기술한다. 사용자의 창작 결정을 보존하고 맡긴 부분은 직접 정한다. 짧고 명확한 요청은 바로 생성한다. 누락이나 충돌이 결과를 크게 바꿀 때만 짧게 질문한다.
- 문구용 마스코트, 캐릭터 스티커, 표정 세트, 메모지 일러스트처럼 작게 쓰는 자산에는 [문구 캐릭터 가이드](references/stationery-characters.kr.md)를 적용한다. 캐릭터를 알아보게 하는 특징을 정하고 실제 표시 크기나 제품 레이아웃에서 완성 그림을 확인한다.
- 인물의 자세, 접촉, 표정이나 피부가 중요하면 [인물 그리기](references/drawing-people.kr.md)로 장면을 연출하고 요청한 매체에서 인물을 점검한다.
- 의미, 색 처리, 설득력이 핵심이면 [시각 연출 질문](references/style-and-review.kr.md)을 사용해 요청을 전달할 단서 몇 가지를 고른다. 특별히 지정되지 않은 연출은 조정할 수 있다.
- 유색 조명에서 넓은 재질 위의 작은 강조점이 눈에 들어와야 하면 [재질과 첫인상 점검](references/style-and-review.kr.md)을 함께 적용한 뒤 수용 여부를 판단한다.
- 각 입력이 식별 특징, 배치, 자세, 표현 매체, 색 중 무엇을 결정하는지 적고 편집 원본과 구분한다. 참조가 겹치면 어느 자료가 그 특징을 결정하는지 정한다. 시리즈는 승인 프레임이나 공통 캐릭터 참조를 쓰되 각 프레임을 독립 장면으로 설명한다. 수량이 중요하면 프레임당 주체 수와 시리즈 길이를 분리해 지정한다.
- 편집에서는 생성기 호출 전에 변경점과 보존 조건을 적는다. 원본 또는 마지막 승인본을 입력으로 사용한다. 구도가 중요하고 모호함을 해소할 수 있다면 스케치나 배치 참조를 쓴다.

## 생성 및 검수

1. 검수 기준을 시각 지시로 옮긴다. 복잡한 장면은 구도, 대상과 속성, 표현, 출력 규격을 짧게 묶어 쓴다. 수량에 민감한 대상은 또렷이 구별한다. 특정 시점이 필수면 대상에 대한 카메라 위치와 보여야 할 면을 지정한다. 단순 요청은 자연스러운 문장으로 쓰고, 글자 원문은 위치와 줄바꿈을 포함한다. 방향 선택이 실제로 필요할 때 여러 시안을 만든다.
2. 실제 이미지에서 원래 요구를 충족·실패·미검증으로 판정한다. 개수, 대상과 속성의 연결, 공간 관계, 시점을 개별 확인한다. 개수가 엄격하면 전경과 배경을 모두 살핀 뒤 시리즈 일관성을 비교한다. 글자는 읽을 수 있는 배율로 보고, 편집본을 원본과 나란히 놓아 변경과 보존을 확인한다. 시리즈는 공통 참조 및 인접 프레임과 비교한다. 미적 판단과 필수 요건은 각각 평가한다.
3. 납품 파일의 형식, 픽셀 치수, 종횡비, 실제 알파 투명도를 요청에 맞게 검사한다. 목표 치수를 바로 만들 수 없으면 여백을 확보한 뒤 캔버스를 맞추거나 자른다. 변환 후 배치·디테일·알파를 다시 확인한다. 정확한 글자가 중요하고 레이아웃 편집이 가능한 형식이면 영역을 남겨 별도 글자 레이어로 렌더링한다. 요청 형식으로 내보내 최종본을 본다.
4. 관찰한 실패를 해결하는 최소한의 수정을 한다. 같은 조건을 반복해서 놓치면 [실패에 맞는 수정법](references/style-and-review.kr.md)을 고른다. 마지막 승인 원본이나 레이아웃과 비교하고 영향받는 주변 요소까지 재검수한다. 남은 실패나 미검증 조건을 밝히고 사용할 수 있는 파일 위치를 전달한다.

표현이 핵심인 작업은 완성 이미지가 전달하는 인상을 먼저 적고 의도와 비교한다. 눈에 보이는 단서와 의미를 바꾸는 다른 해석을 짚는다. 모순이나 누락된 효과를 수정하되 의도만큼 또렷한 표현 선택은 유지할 수 있다.

2D 게임 캐릭터 초상, 인게임 이미지, 애니메이션 스프라이트에는 브리프 단계에서 [2D 캐릭터 자산 가이드](references/2d-game-characters.kr.md)를 따른다. 납품물을 정하고 시점 간 식별 특징을 유지하며 실제 표시 크기나 재생 속도로 본다.

2D 게임 이펙트나 이펙트를 일으키는 스프라이트 동작에는 [움직이는 이펙트 그리기](references/2d-effects-and-motion.kr.md)를 사용한다. 핵심 그림을 계획하고 효과를 게임 이벤트와 연결하며 내보낸 레이어를 재생해 확인한다.

열리는 소품, 독립된 폭발 효과, 바람에 날리는 파티클에는 [스프라이트 제작 지침](references/2d-effects-and-motion.kr.md#소품폭발파티클-스프라이트-그리기)을 사용한다. 셀 안에서 움직이는 부분, 게임 공간에서 이동하는 부분, 재생 후 남는 모습을 정한다.

HUD·인벤토리·메뉴용 아이콘이나 컨트롤을 제작할 때는 [게임 UI 이미지 제작 지침](references/game-ui-art.kr.md)을 사용한다. 용도에 맞는 레이어를 나누고 상태별 기하를 유지하며 실제 슬롯에 넣어 확인한다.

## 창의적 탐색

서로 다른 시각적 아이디어를 원하거나, 결과가 반복되거나, 그림의 의미가 달라지는 선택을 맡겼다면 [창의적 탐색 가이드](references/creative-exploration.kr.md)를 사용한다. 핵심 조건을 유지하고 어떤 해석이 실제 그림에서 읽히는지 비교한다. 완성본 한 장이 필요한 경우 적절한 방향을 골라 진행하고, 범위가 정해진 부분 편집에는 기존 절차를 따른다.

## 공통 리뷰 시점

image 기준으로 [공통 리뷰 시점](../vegabond-review/SKILL.md#review-checkpoints)을 적용합니다. 중요한 시각 설계·제작 명세를 만들거나 바꾸면 후속 생성 전에 요구사항과 실행 가능성을 검토하며 아직 없는 이미지를 보았다고 주장하지 않습니다. 전달 전 실제 이미지·출력 검사를 최종 리뷰에 포함합니다. 원본 비교와 유효한 지식·문제 근거를 재사용하고 선택적인 취향 차이만으로 재생성하지 않습니다.
