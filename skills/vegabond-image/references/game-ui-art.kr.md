# 게임 UI에 적용할 이미지 생성

## 플레이어의 판단에서 시작하기

슬롯의 용도, 플레이어가 알아보거나 실행할 일, 화면에서 가장 작게 표시될 크기, 혼동할 만한 이웃이나 상태를 정한다. UI 캡처는 배치, 승인된 자산은 화풍, 스케치는 실루엣이나 기하의 참조로 쓴다. 치수가 없으면 작업 크기를 명시하고 큰 원본을 보존한다. 프로젝트의 매체·입력 장치·UI 배율에 맞춘다. 화면 콘셉트는 전체를 합성한다. 구현용 UI 키트는 게임에서 따로 배치하거나 늘리거나 교체할 부품을 제공한다.

## 무엇을 그릴지 고르기

| 자산 | 생성·보존할 것 | 맥락에서 검사할 것 |
| --- | --- | --- |
| 아이템·스킬·상태 아이콘·지도 핀 | 기능을 눈에 보이는 상징으로 바꾼다. 혼동할 기능끼리는 외곽이나 내부 표식을 달리한다. 작은 묶음을 먼저 승인하고 세트를 확장한다. 윤곽 무게, 시점, 광원, 체감 크기를 공유한다. 수량·희귀도·선택 상태가 바뀌면 분리한다. 지도 표식은 끝점이나 중앙 기준점을 정한다. | 최소 크기로 비슷한 이웃과 함께 보여 준다. 무엇을 뜻하는지와 어디에서 찾는지를 따로 묻는다. 밝고 어둡고 복잡한 배경에서 본다. 색상만 다르면 상징이나 실루엣을 바꾼다. 두 그림은 구별되는데 행동을 모르겠다면 익숙한 표식이나 실시간 라벨을 시험한다. |
| 버튼·슬롯·탭 | 기본 면을 한 번 만든다. 필요한 보통·호버·눌림·비활성 면은 정렬을 유지해 파생한다. 동시에 나타날 수 있는 포커스와 지속 선택은 독립 오버레이로 둔다. 가장 긴 상태 문구를 위한 공간을 확보한다. | 선택된 항목과 선택되지 않은 항목에 포커스를 번갈아 놓는다. 눌렀을 때 의도한 굴곡이나 내용만 움직이고 포커스 링이 잘리지 않는지 본다. 잠금 여부가 중요하면 별도 단서를 준다. 입력 영역과 탐색은 실제 컨트롤에서 설정한다. |
| 늘어나는 창·대화창·툴팁·카드 | 모서리 장식은 네 고정 구역 안에 둔다. 가장자리와 중앙에는 늘리거나 반복할 수 있는 재질을 쓴다. 문양이나 삽화가 왜곡되면 분리한다. 좌·상·우·하 순서와 단위를 적은 슬라이스 여백, 내용이 들어갈 안쪽 여백을 따로 기록한다. | 최소 사용 크기·보통·넓은 창으로 나인슬라이스를 재구성한다. 모서리 형태와 타일 이음새, 긴 번역문이 들어가는지 확인한다. 라벨과 장식 둘 다 본다. |
| 게이지·원형 재사용 대기 표시 | 같은 캔버스에서 빈 홈, 전체 채움이나 마스크, 윗 프레임을 분리한다. 채움의 시작과 방향, 원형이면 중심과 시작 각도를 명시한다. 현재 값·수치·경고 상태는 게임에서 정한다. | 비움·극소량·절반·가득 참을 합성한다. 장식이 남은 값처럼 보이지 않는지, 프레임이나 아이콘을 찌그러뜨리지 않고 채움 끝만 이동하는지 확인한다. |
| 입력 안내·화폐 수량·번역 라벨 | 주변 아트를 그리고, 현재 바인딩·문구·가변 숫자·배지에 교체용 자리를 남긴다. 정확한 장치 기호는 프로젝트나 플랫폼에서 제공하는 글리프를 쓴다. | 긴 문구, 실제 대상 문자, 키 재설정이나 기기 변경을 시험한다. RTL에서는 화면 탐색 방향과 월드의 절대 방향을 구분한다. |

## 생성·내보내기·수정

1. 생성기에 독립 자산, 비교용 이웃, 보존할 기하를 명시한다. 예를 들어 32 px 슬롯의 둥근 회복 물약병에 큰 십자 하나와 투명 여백을 주고, 승인한 세트의 왼쪽 위 조명을 따르게 한다. 어느 참조가 형태를 정하는지 적는다. 검수용 이웃은 납품 이미지 바깥에 둔다.
2. 소수의 첫 후보를 실제 배포 크기로 비교한 뒤 전체 세트로 늘린다. 상태 변형은 승인한 면을 편집하거나 정렬된 오버레이를 합성한다. 정밀 마스크·테두리·실시간 문자·조작 글리프는 레이아웃·슬라이싱·승인된 원본으로 정확한 기하를 맞춘다. 비트맵 시안만으로 편집 가능한 벡터 경로가 생기지는 않는다.
3. 독립 이미지나 아틀라스에 실제 셀 사각형, 패딩, 배율, 알파, 필요한 상태·슬라이스·채움 정보를 붙인다. 자동 자르기 전 셀 사이 여백의 실제 알파를 확인한다. 의도한 배경에서 최종 필터와 혼합을 보고 가능하면 압축·패킹을 거친 뒤에도 확인한다.
4. 합성한 컨트롤을 1배, 최소 지원 배율, 대표 시청 거리에서 본다. HUD 뒤에 복잡한 게임 장면도 놓는다. 최종 합성 명도 대비를 확인하고 중요한 정보가 색에 의존하면 형태·테두리·무늬를 더한다. 접근성과 행동 이해는 해당 플랫폼 검사와 관찰자 시험으로 확인한다. 회색조 미리보기만으로 둘을 입증할 수 없다.
5. 처음 실패한 층을 고친다. 기능을 오해하면 상징을 바꾸고, 축소해서 뭉개지면 틈을 열거나 내부 명암을 단순화한다. 창이 찌그러지면 여백과 슬라이스를, 포커스가 묻히면 오버레이를 고친다. 영향 없는 부품은 마지막 승인본을 재사용한다.
