# 게임 UI 이미지 제작

플레이어가 무엇을 이해하거나 할지, 슬롯과 최소 표시 크기, 혼동할 이웃이나 상태를 먼저 정한다. UI 캡처는 배치에, 승인 에셋은 화풍에, 스케치는 실루엣과 기하에 쓴다. 크기가 없으면 작업 가정을 밝히고 더 큰 원본을 보관한다. 콘셉트 화면은 통째로 구성할 수 있다. 구현용 키트는 배치·조절·상태 변경에 쓸 부품으로 납품한다.

| 대상 | 제작과 보존 | 실제 사용 조건에서 확인 |
| --- | --- | --- |
| 아이템·능력·상태 아이콘, 지도 핀 | 기능을 나타내는 모티프와 구별되는 외곽·내부 표식을 정한다. 작은 세트를 먼저 승인하고 윤곽 굵기, 시점, 빛, 시각적 크기를 맞춘다. 수량·등급·선택은 분리하고 핀의 끝이나 중심을 고정한다. | 가장 작은 크기에서 무엇을 뜻하는지와 어디 있는지를 따로 묻는다. 밝고 어둡거나 복잡한 배경에서 비슷한 아이콘과 비교한다. 색에만 의존하면 형태를 바꾸고, 다르게 보이지만 뜻이 모호하면 익숙한 표식이나 레이블을 시험한다. |
| 버튼·슬롯·탭 | 기본판을 한 번 만들고 같은 정렬에서 기본·호버·눌림·비활성을 파생한다. 포커스와 지속 선택을 독립 표시하고 가장 긴 레이블 영역을 남긴다. | 선택된 항목과 선택되지 않은 항목 각각에 포커스를 올린다. 눌림 변화, 잘린 링, 잠금과 사용 가능 구분을 본다. 입력 범위와 탐색은 실제 컨트롤에서 확인한다. |
| 창·대화창·툴팁·카드 | 고정 장식은 네 모서리 안에, 반복하거나 늘릴 재질은 가장자리와 가운데에 둔다. 변형되면 안 되는 문장 장식은 분리한다. 네 절단 여백의 단위와 내용 여백을 구별한다. | 최소·보통·넓은 크기에서 모서리와 반복 경계를 확인하고 가장 긴 문구가 들어가는지 본다. |
| 게이지·방사형 쿨다운 | 같은 캔버스에서 트랙·전체 채움이나 마스크·프레임을 분리한다. 채움 원점과 방향, 필요하면 중심·시작각을 정한다. | 빈 상태, 거의 빈 상태, 절반과 가득 참을 합성한다. 장식이 잔량으로 보이거나 마스크 대신 프레임이나 아이콘이 찌그러지는지 본다. |
| 입력 안내·수치·현지화 레이블 | 주변 장식만 생성하고 바인딩, 숫자, 글자, 배지가 바뀔 공간을 둔다. 정확한 기기 기호는 플랫폼 글리프를 사용한다. | 가장 긴 문구, 실제 글리프, 기기·바인딩 변경을 시험한다. RTL 탐색 화살표와 절대적인 세계 방향을 구분한다. |

## 생성·내보내기·수정

1. 생성할 한 에셋과 검수용 이웃을 구분하고 지킬 기하를 명시한다. 예를 들어 32 px 회복병의 넓은 배와 십자, 승인 세트의 좌상단 광원, 투명 여백을 정한다.
2. 첫 소량 시안을 실제 크기로 본다. 상태 변형은 승인본 편집이나 오버레이를 우선한다. 정밀 마스크·글자·기기 기호는 레이아웃과 기존 자산을 쓴다. 비트맵은 편집 가능한 벡터 경로를 제공하지 않는다.
3. 잘라낼 영역·패딩·배율·알파·상태·슬라이스·채움 정보를 지정한다. 자동 트림 전에 거터의 알파를 확인하고 가능한 경우 압축·패킹 뒤 최종 필터와 블렌딩으로 합성한다.
4. 1배율과 최소 UI 배율, 실제 시청 거리와 복잡한 플레이 화면에서 확인한다. 색에 의미가 실리면 형태·테두리·패턴을 보조로 쓴다. 접근성과 동작 이해는 플랫폼 요구 및 관찰자 검수로 확인한다.
5. 처음 실패한 층을 수정한다. 의미 혼동은 상징, 작은 세부의 합침은 명도와 틈, 프레임 변형은 슬라이스와 공간, 포커스 소실은 오버레이부터 고친다.
