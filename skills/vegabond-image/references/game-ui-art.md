# Generate artwork for game UI

## Start at the player's decision

Name the slot, what the player should understand or do, its smallest on-screen size, and the item or state it can be confused with. Use the supplied UI capture for placement, an approved asset for style and a sketch for silhouette or geometry. If dimensions are missing, use an explicit working size and retain a larger master. Follow the project’s medium, input devices and UI scale. For a concept screen, compose the whole scene. For an implementable UI kit, give the consumer the individual parts it will place, scale or change.

## Choose what to paint

| Asset | Generate and preserve | Test in context |
| --- | --- | --- |
| Item, ability, status icon or map pin | Translate the function into a visible motif. Give competing functions different outer shapes or internal marks. Approve a small family before expanding it. Share contour weight, viewing angle, light and optical scale. Keep live counters, rarity badges and selection separate when they vary. For a marker, define the tip or center anchor. | Show at the smallest intended size among similar neighbors. Ask what it means, then ask where it is. Inspect on light, dark and busy gameplay. If only the hues distinguish two icons, change the motif or silhouette. If they differ but the action is obscure, try a more familiar sign or a live label. |
| Button, inventory slot, tab | Make the base plate once. Derive the requested normal, hovered, pressed and disabled faces from the same registered art. Treat focus and lasting selection as independent overlays when they can coexist. Reserve room for the label and its longest state. | Display focus on the selected and an unselected item. Check that pressing moves only the intended relief or content, and that the ring survives clipping. Give locked and available different cues when the distinction matters. Keep hit targets and navigation in the actual controls. |
| Resizable window, dialogue, tooltip or card | Keep fixed ornament inside the four corner regions. Put stretchable/tileable material on edges and center. Output a separate crest or illustration if scaling would distort it. Record slice margins (left, top, right, bottom, units) and separate content insets. | Reconstruct a nine-slice at the minimum usable, normal and wide sizes. Corners should keep shape, repeated patterns should join, and the longest supported string should fit. Inspect both the label and the ornamental frame. |
| Meter or radial cooldown | Separate track, full fill or mask, and foreground frame on one canvas. Specify fill origin, direction, and radial center/start if relevant. A live value, number or warning belongs to the game. | Composite empty, almost empty, half and full. Check that decoration cannot imply remaining value and that clipping moves the fill edge without squeezing the frame or icon. |
| Input prompt, currency count, localized label | Generate the surrounding art. Reserve replaceable slots for current bindings, text, changing numbers and optional badges. Use the project or platform glyph when an exact device symbol is required. | Try the longest label, actual target-script glyphs and a binding or device change. For RTL, distinguish a navigation arrow from an absolute world direction. |

## Generate, export and repair

1. Give the generator the requested asset in isolation, its neighbors as comparison references, and the protected geometry. For example, ask for a round healing flask with a single large plus, upper-left light shared with the approved set and transparent padding for a 32 px slot. State which reference controls the shape. Keep review-only neighbors out of the deliverable.
2. Compare a small first batch at shipping size before enlarging a set. For state variants, prefer editing the approved face or compositing a clean overlay. For precise masks, borders, live text and controller glyphs, use layout, slicing or existing approved artwork to supply exact geometry. A bitmap preview does not supply editable vector paths.
3. Export the requested individual images or atlas with usable crop rectangles, padding, scale, alpha and relevant state/slice/fill information. Check the actual alpha across gutters before automatic trimming. Inspect the final filtering and blend over the intended background, including after compression or atlas packing if available.
4. Review the composed control at 1×, the smallest supported UI scale and a representative viewing distance. Include a high-detail scene where the HUD overlaps gameplay. Inspect value contrast on the final composite and offer a shape, border or pattern where color carries important information. Confirm accessibility and action comprehension with the relevant platform checks and observers. A grayscale preview establishes neither.
5. Repair the first failing layer. Rework the symbol if players infer the wrong action, open a gap or flatten interior values if small details merge, reserve room or re-slice if a frame warps, and fix the state overlay if focus disappears. Reuse the last accepted art for unaffected parts.
