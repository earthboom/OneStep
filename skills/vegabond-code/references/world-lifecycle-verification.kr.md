# 게임 데이터, 스트리밍과 NPC 검증

기존 [검증 절차](verification.md)에서 해당 항목을 적용한다. 구현과 독립적인 기대 결과와 프로젝트의 실제 진입점을 사용한다. 작은 국소 변경은 영향받은 항목만 확인할 수 있다.

| 주장 | 실행 | 남길 증거 |
| --- | --- | --- |
| 카탈로그 변경이 유효하다 | 새 항목이나 변경·폐기 항목을 실제 검증·등록 경로에 넣는다. 관련 있으면 연결 콘텐츠, 중복 ID, 선택 콘텐츠가 실제로 없는 경우를 확인한다. | 영향을 받는 카탈로그와 엔진 대상, 수락·거부된 항목, 해석된 참조, 영향받은 게임 동작 |
| 기존 데이터의 호환성을 유지한다 | 변경 이전 원본을 실제 로더로 열고 변경·폐기 ID와 해당 호출자를 실행한다. 지원할 경우 마이그레이션 결과를 다시 열고, 잘못된 입력과 미래 버전을 확인한다. 쓰기를 바꾸면 실패나 중단 뒤 원본을 확인한다. | 입력 버전과 출처, 해석한 ID, 보존된 값과 동작, 출력 버전과 재로딩, 거부나 복구 결과. 현재 형식의 생성 데이터는 현재 형식을 확인한다. |
| 콘텐츠가 실제로 상주 상태를 벗어난다 | 실제 씬·레벨·객체·에셋 경계에서 요청, 준비·활성화, 언로드·종료를 관찰한다. 재방문하고, 지원할 경우 폐기된 작업이나 소유권 변경을 확인한다. 선택 콘텐츠가 실제 없는 경우를 실행한다. 풀 재사용에서는 오래된 콜백·구독·상태도 확인한다. | 씬·레벨·표시 객체의 실제 식별자, 주장에 맞는 로드·언로드·상주 증거, 요청 순서. 메모리 해제 주장은 상주 바이트나 핸들을 확인한다. 렌더러를 숨겼을 때 확인되는 것은 가시성이다. |
| 캐시 데이터의 정확성을 유지한다 | 반복 조회하고 의존 데이터나 버전을 바꾼 뒤 축출과 재생성을 실행한다. 사용 중 재생성할 수 있으면 이전 작업의 늦은 완료도 확인한다. | 무효화 전후 값, 기대한 적중·실패 또는 재생성, 주장과 관련된 연산 절감이나 메모리 상한의 증거 |
| 스트리밍이나 렌더링이 예산에 들어온다 | 같은 대상·기기·렌더러·부하에서 전이 반복을 포함한 동일 경로를 캡처한다. 새 프로세스 첫 방문, 재방문, 확인된 캐시 상태를 구분한다. 요청부터 준비·활성화까지의 시간과 프레임·단계 비용을 각각 잰다. 관련 GPU 실행과 시각 출력도 캡처한다. | 캡처 조건, 표본 수, 범위나 긴 프레임, 시한 초과, 관련 메모리와 품질. 워밍업·상한·누락 단계를 표시한다. 헤드리스 측정의 범위는 해당 CPU와 활성화이며, 렌더링과 배포 예산은 실제 대상에서 잰다. |
| NPC 상태가 표시 객체 없이 유지된다 | 정상 행동으로 상태를 바꾸고 표시 객체나 지역을 제거한 동안 권한 상태를 읽는다. 화면 밖 진행이 계약이면 표시 객체 없이 관찰한다. 표시가 없는 NPC도 명령이나 이벤트를 받을 수 있다면 실제로 실행해 약속된 횟수에 맞게 효과가 발생하는지 확인한다. 새 표시 객체를 연결해 ID, 상태, 후속 동작을 확인한다. 영속성 주장에는 재시작을 별도로 확인한다. | 전투 전, 변경 직후, 표시가 없는 동안, 새 표현을 연결한 이후의 데이터와 독립적인 수명 관찰. 타이머·중복 이벤트·늦은 콜백·다른 관찰자도 관련 시 확인한다. |

Unity에서는 주장에 맞는 에디터나 실제 Player로 `SceneManager`나 Addressables 작업을 관찰한다. Prefab·직렬화·메타데이터·카탈로그 변경도 해당되는 경우 확인한다. Unreal에서는 필요한 Game·PIE·패키지 월드에서 실제 레벨·스트리밍 상태, 액터 수명과 권한 세션 소유권을 본다. 성능 결론을 내기 전에 엔진과 실행 구성이 작업에 맞는지 확인한다.

중요한 검사는 잘못된 마이그레이션, 언로드 후 살아 있는 표시 객체, 재진입 때 초기화되는 상태 같은 현실적인 고장으로 탐지 여부를 확인한다. 실제 결과와 실패 이유, 차단·해당 없음·미측정을 구분해 전달한다. 계약 선택은 [게임 런타임 설계](../../vegabond-code-design/references/world-lifecycle.md)를 참고한다.
