# 소프트웨어 검증과 인계

코드를 바꾸거나 소프트웨어 결과를 판정하기 전에 [vegabond-code](../SKILL.md)에서 이 절차를 사용합니다. 공통 완료, 수락, 실패 반환은 [에이전트 지침](../../../agents/vegabond-agent.md)이 담당하고 소프트웨어별 점검은 이 참조 문서가 담당합니다.

## 점검 준비

구현 전에 정보 요약의 관련 예방책을 포함하여 완료 조건과 보존 계약을 실행 가능한 점검에 연결합니다. 영향받는 경로의 기준 상태를 확인하고 기존 실패를 구별합니다. 실용적인 로컬 테스트 경로가 있는 버그는 수정 전에 의도한 이유로 실패하는 회귀 점검을 확보합니다. 그렇지 않으면 가장 가까운 관찰 가능한 재현과 그 한계를 남깁니다.

프로젝트의 기존 검증 명령과 실행 체계를 먼저 사용합니다. 명령이 의도한 테스트를 실제로 발견하고 변경된 동작에 도달하는지 확인합니다. 관련 단언 없이 종료 코드 0으로 끝난 실행은 증거가 아닙니다. 명령, 대상·구성, 코드 개정 또는 관련 diff, 관찰 결과를 기존 작업 근거에 남깁니다. 반복 가능한 경로가 없어 필요한 동작을 검증할 수 없다면 범위 안에서 가장 작은 재사용 점검을 추가하고 처음부터 끝까지 실행해 입증합니다.

## 검증

해당되는 경우 다음 네 단계를 유지합니다.

1. **빌드·준비:** 영향받는 대상과 구성에 대해 프로젝트의 실제 빌드, 컴파일 또는 동등한 준비를 실행합니다.
2. **자동 테스트:** 관련 기존 테스트를 실행합니다. 실질적인 보호가 되는 경우 구현과 독립적인 기대값으로 회귀·행동 검증을 추가합니다. 영향받는 경계와 오류 경로를 포함합니다.
3. **실행 준비:** 애플리케이션이나 필요한 환경을 실행하여 초기화 실패 없이 변경 경로에 도달할 수 있는지 확인합니다.
4. **실제 사용:** 공개 인터페이스로 변경 동작을 실행합니다. 언리얼·유니티 게임은 에디터와 실제 플레이를 실행하며 관련 멀티플레이 역할을 포함합니다. CLI는 실제 명령을, 라이브러리는 실제 사용 주체나 검증 환경을 실행합니다.

결함은 원래 재현과 영향받는 주변 동작도 다시 실행합니다. 명령, 대상·구성, 결과, 관찰한 실행 동작을 기록합니다. 각 단계에 에이전트 지침의 차단과 해당 없음 구분을 적용합니다. 구현 변경 없는 코드 조사는 관련 없는 전체 빌드 대신 주장을 입증하는 점검을 사용합니다.

## 검수와 반복

일관된 변경 단위마다 영향받는 빌드·준비와 자동 검증을 실행한 뒤 요구사항에 맞추어 diff와 관련 호출부를 검토합니다. 빠진 동작, 깨진 계약, 상태·생명주기 오류, 변경 고유의 위험을 찾습니다. 테스트가 구현을 반복하는 데 그치지 않고 잘못된 동작을 탐지하는지 검토합니다. 관련 역량을 더하는 경우 사용 가능한 검수·테스트 스킬을 활용합니다. 검수 발견이 수정을 유도하려면 구체적인 작동 원리나 근거가 있어야 합니다.

테스트와 검증 설정 변경도 패치의 일부로 검토합니다. 단언 삭제, skip, 제외, 완화된 기대값, 린트·타입 검사 억제, 비활성화에는 계약에 근거한 이유가 필요합니다. 유효한 실패를 숨기는 데 사용하지 않습니다. 점검이 잘못되었다면 충돌하는 요구나 근거를 밝히고 수정 이유를 설명한 뒤 보존할 계약을 검증합니다. 차단되거나 제외된 필수 점검은 통과로 세지 않고 인계에 명시합니다. 실용적인 회귀 점검이나 중요한 예방 장치는 원래 실패 또는 통제된 오류 사례를 탐지함을 입증하고 기대값은 구현과 독립적으로 유지합니다.

예외 무시, 성공처럼 보이는 기본값, 무조건 재시도, 임의 대기, 호환 경로가 정당한 상태를 처리한다는 근거를 확인합니다. 대체 동작은 계약이 요구하고 실패 동작이 점검된 경우에만 유효합니다. 예를 들어 허용된 설정 누락 때문에 잘못된 설정 내용까지 조용히 성공 처리해서는 안 됩니다. 근거 없는 임시방편은 조사할 가설이며 완료된 수정이 아닙니다. 근거에서 배제된 추측성 변경은 관련 없는 작업을 버리지 않으면서 제거합니다.

확인된 실패나 결함은 명령, 단언, 로그, 상호작용으로 원인을 좁힙니다. 수정한 뒤 원래 실패 점검과 영향받는 주변 점검을 반복하고 수정 diff를 검토합니다. 필요한 검증이 통과하고 범위 안의 확인된 결함이 남지 않을 때까지 반복합니다. 잘못된 동작을 받아들이도록 유효한 점검을 약화하지 않습니다. 잘못된 점검은 요구사항에 따라 고치고 이유를 명시합니다.

진단, 근거, 범위, 역량을 재평가해야 할 때는 에이전트 지침의 [공통 실패·피드백 규칙](../../../agents/vegabond-agent.md#respond-to-failures-and-feedback)을 사용합니다.

국소 반복 뒤에는 최종 결과물의 필수 통합·실제 사용 점검을 실행합니다. 실패하면 진단과 수정으로 돌아가며 이후 편집은 영향받는 근거를 무효화합니다. 재현 가능한 기존 실패와 새로 유발한 실패를 구별하고 기존 실패를 완료의 증거로 삼지 않습니다.

## 장기·단계별 작업 이어가기

단계 경계, 인계, 맥락 초기화 전에는 기존 요약을 갱신합니다. 목표와 보존 조건, 완료·미완료 항목, 현재 코드 상태, 근거 위치, 다음 단계를 제약하는 결정, 다음 행동을 남깁니다. 판단과 점검을 기록하며 비공개 사고 과정이나 모든 도구 호출을 기록하지 않습니다. 재개 시 현재 diff와 유효한 근거를 대조한 뒤 계속합니다. 중간 변경으로 무효화된 근거를 재검증하고 미완료 조건을 조용히 삭제하거나 기본적으로 완료된 작업 전체를 다시 수행하지 않습니다.

## 유용한 예방책 유지

반복되는 중요한 실수는 기존 지식·문제 기록 흐름에서 패턴을 찾고 문구 경고 추가보다 범위가 한정된 구조 개선, 타입 제약, 린트·CI 검사, 행동 테스트를 우선합니다. 프로젝트의 기존 강제 경로를 재사용하고 실제 실수나 통제된 동등 사례를 탐지함을 입증합니다. 자동으로 강제되는 내용과 문서에만 있는 내용, 남은 한계를 보고합니다. 이 스킬에 쓰여 있다는 이유만으로 강제된다고 주장하거나 작은 작업마다 새 기반 시설을 도입하지 않습니다.
