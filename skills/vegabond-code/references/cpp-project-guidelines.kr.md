# C++ 프로젝트 작업 지침

> 사람이 읽는 한국어 번역본이다. 코딩 에이전트는 영문 `cpp-project-guidelines.md`를 지침으로 사용한다.

공통 규칙은 모든 C++ 코드에 적용한다. Unreal C++ 코드에는 하단의 추가 규칙도 적용한다. 작업 프로젝트의 지침과 관례가 우선한다.

새 문법 기능이나 소유권 모델을 도입하거나, 공개 API를 설계하거나, 디자인 패턴을 고르거나, 성능을 개선할 때는 [C++ 구현 가이드 한국어판](cpp-implementation.kr.md)의 해당 항목을 참고한다.

## AI의 C++ 코드 작성 공통 규칙

1. **기존 호출 경로를 확인하고 경계를 넓힐 이유를 밝힌다.**
   - **적용 기준** — 수정 전에 구현과 호출부를 읽고 상태 소유자를 확인한다. 요구사항을 충족하는 API를 재사용한다. 공개 API, 확장점, 기반 클래스, 모듈 의존성을 추가하거나 범위를 넓히면 필요한 호출자나 요구사항을 변경 요약에 적는다.
   - **순수 C++ 예시** — `Inventory::TryAdd()`가 공간 부족을 어떻게 처리하는지 확인한 뒤 퀘스트 보상 지급에 재사용한다.
   - **Unreal C++ 예시** — 퀘스트 보상 호출 경로에서 `UInventoryComponent`를 찾아 기존 지급 연산을 재사용한다.

2. **책임과 의존성을 정해진 모듈 경계 안에 둔다.**
   - **적용 기준** — 규칙은 그 결정을 소유한 모듈에 두고, 여러 모듈을 조율하는 정책은 호출부에 둔다. 공개 API로 연결하고 기존 의존 방향을 따르며 순환을 피한다. 선택 기능을 바꿀 때는 영향받는 지원 구성에서 해당 기능을 꺼도 핵심 동작이 유지되는지 확인한다.
   - **순수 C++ 예시** — 선택 기능인 텔레메트리를 꺼도 파서는 같은 결과를 반환한다.
   - **Unreal C++ 예시** — 지원하는 전용 서버 구성에서는 HUD 없이도 퀘스트 보상을 지급할 수 있다.

3. **현재 요구를 충족하는 가장 단순한 구조를 쓴다.**
   - **적용 기준** — 함수나 구체 타입으로 시작한다. 필요한 값만 전달하고 협력 객체를 명시한다. 독립적으로 바뀌는 동작은 조합한다. 구현을 교체하거나 의존 방향을 뒤집어야 할 때 인터페이스를 추가한다. 호출자가 기반 타입 자리에 파생 타입을 사용할 필요가 있고 파생 타입이 기반 계약을 지킬 때 `public` 상속을 쓴다.
   - **순수 C++ 예시** — `CalculateReward()`에 플레이어 레벨과 보상 설정을 넘기고, 이벤트별 공식이 필요하면 함수로 제공한다.
   - **Unreal C++ 예시** — 상호작용이 필요한 Actor에 `UInteractionComponent`를 붙인다.

4. **내부 상태를 감추고 호출자가 의존할 계약을 명시한다.**
   - **적용 기준** — 상태와 구현은 기본적으로 `private`에 두고, 필요한 연산은 `public`, 의도한 파생 클래스 확장점은 `protected`로 둔다. 상태는 소유 객체의 연산으로 변경한다. 필요한 경우 스레드·수명·실행 순서·권한 조건을 명시한다. 실패하거나 취소되면 무엇이 바뀔 수 있는지, 무엇이 유효한지, 재시도가 안전한지 정한다.
   - **순수 C++ 예시** — `ReloadConfig()`가 실패해도 마지막으로 유효했던 설정을 계속 사용한다.
   - **Unreal C++ 예시** — 서버는 보상을 한 번 지급하고, 지원하는 재시도 기간 내에 중복 요청이 오면 기록된 결과를 반환한다.

5. **실제 호출 경로에서 동작을 검증한다.**
   - **적용 기준** — 버그는 가능하면 먼저 재현하고, 수정 후 같은 입력과 초기 상태로 다시 실행한다. 새 동작은 공개 API나 기능 진입점에서 기대 결과를 확인한다. 실행하지 못한 검증 단계는 이유와 함께 남긴다.
   - **순수 C++ 예시** — 인벤토리가 가득 찼을 때 보상 지급이 실패하고 아이템 수량이 그대로인지 확인한다.
   - **Unreal C++ 예시** — PIE에서 수정 전후에 같은 방식으로 아이템을 획득하고 화면에 표시된 수량을 확인한다.

6. **품질 목표가 충돌할 때 실행 가능한 설계 대안을 비교한다.**
   - **적용 기준** — 요구사항을 충족하는 대안이 둘 이상이고 중요한 목표가 충돌한다면, 같은 대표 시나리오와 수용 기준으로 비교한다. 불확실한 결과가 선택을 바꿀 수 있을 때 측정한다.
   - **순수 C++ 예시** — 설정을 제자리에서 갱신하는 방식과 스냅샷을 교체하는 방식을 최대 메모리와 갱신 실패 시 동작으로 비교한다.
   - **Unreal C++ 예시** — 같은 기기에서 인벤토리 아이콘을 미리 로드하는 방식과 필요할 때 로드하는 방식의 첫 열기 프레임 시간과 최대 메모리를 비교한다.

## Unreal C++ 추가 규칙

1. **기존 엔진 진입점과 수명주기를 따른다.**
   - **적용 기준** — Actor, Component, Subsystem을 수정하기 전에 생성·초기화·종료 경로를 확인하고 기존 수명주기 훅을 사용한다.
   - **Unreal C++ 예시** — `UInteractionComponent`의 기존 초기화와 정리 경로를 사용한다.

2. **Blueprint 호출자에게 필요한 연산만 노출한다.**
   - **적용 기준** — 실제 Blueprint 호출자가 필요한 조회나 연산만 공개한다. C++과 Blueprint의 상태 변경은 같은 검증 경로를 거치게 하고, 노출 범위를 넓히면 변경 요약에 이유를 적는다.
   - **Unreal C++ 예시** — 검증을 거치는 보상 지급 함수를 Blueprint에 노출하고 스택 배열은 `private`으로 둔다.
