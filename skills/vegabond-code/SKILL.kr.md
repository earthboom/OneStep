# Vegabond Code

현재 작업 안에서 소프트웨어 작업을 실행합니다. 기존 요약과 프로필을 재사용하고 공통 경계와 완료 기준은 [에이전트 지침](../../agents/vegabond-agent.md)을 따릅니다. 직접 호출되면 [scout의 공통 준비](../vegabond-scout/SKILL.md#frame-and-classify)와 연결된 작업 스킬을 적용하며 분류를 다시 시작하지 않습니다.

## 작업 환경 식별

저장소 지침, 소스와 관련 호출부, 프로젝트·의존성 설정, 테스트, 스크립트, CI로 변경 대상의 언어, 엔진·프레임워크와 버전, 도구 체계·플랫폼·대상, 실제 빌드·테스트·실행·검사 경로를 확인합니다. 새 작업에서는 제안한 도구 체계와 관찰한 환경을 구별합니다. 충돌하는 근거는 좁혀 조사하고 설정을 도구 실행의 증거로 보지 말고 scout의 준비 확인을 재사용합니다.

확장자나 저장소의 주 기술 대신 실제 구성 요소를 분류합니다. 언리얼 C++과 독립 C++에는 각각의 도구 체계가 필요하며 Unity는 프로젝트·패키지 계약을 따릅니다. 언리얼 저장소 안의 Python 도구는 자체 런타임을 따르고 에셋이나 엔진 동작에 영향을 주면 엔진 검증을 추가합니다. 혼합 작업에서는 영향받는 구성 요소와 경계 점검을 식별합니다. 결과와 출처 위치는 별도 환경 보고서 대신 기존 요약에 둡니다.

기존 정보 요약을 재사용하면서 [vegabond-knowledge](../vegabond-knowledge/SKILL.md)에 관련 계약, 버전별 출처, 이전 실패·예방 점검을 요청합니다. scout의 연결 절차로 사용 가능한 환경별 스킬이나 직접 도구를 선택합니다.

## 설계 깊이 선택

구현 전에 상태 소유권, 생명주기, 다른 호출부가 사용하는 인터페이스, 동시성, 영속화, 외부 연동, 이전에 대한 중요한 선택을 확정해야 하면 [vegabond-code-design](../vegabond-code-design/SKILL.md)을 사용합니다. 확립된 패턴을 따르는 국소 수정은 관련 계약과 보존 조건을 짧게 적고 진행할 수 있습니다. 파일 수만으로 결정하지 않습니다. 유효한 기존 설계는 재사용하고 근거가 바꾼 결정만 재검토합니다.

현재 요약, 환경, 영향받는 소스·계약, 제약, 미해결 결정을 전달합니다. 설계는 이 작업 흐름 안에서 범위가 정해진 구현 방향과 점검을 반환하며 scout를 다시 시작하거나 별도 실행 반복을 만들지 않습니다. 설계만 요청받았으면 구현을 추가하지 않고 그 결과로 마칩니다.

## 구현 또는 조사

코드를 바꾸거나 결과를 판정하기 전에 [검증과 인계](references/verification.md)를 읽습니다. 상세한 준비, 빌드·테스트·실행·실제 사용 점검, 검수·수정 반복, 검증 변경 검토, 장기 작업 상태, 입증된 예방책은 이 참조 문서가 담당합니다. 일관된 변경 단위와 최종 통합 결과물에 적용하며 읽기를 완료 시점까지 미루지 않습니다.

- **Create:** 선택한 설계나 기존 국소 패턴을 따르고 완전하게 사용할 수 있는 경로를 구현합니다. 기존 scout 규모 판단을 활용하여 중요한 가정을 의존 구현 전에 작은 통합 단위로 확인합니다.
- **Revise:** 결함을 재현하고 원인을 추적한 뒤 수정합니다. 의도적인 구조 변경은 확정된 동작과 공개 계약을 유지하며 일관된 단위로 수행합니다. 관련 없는 정리는 범위 밖에 둡니다.
- **Research:** 코드, 데이터 흐름, 실행 근거를 추적하고 질문에 맞추어 대안을 비교하며 파일·심볼·로그·관련 출처를 인용합니다. 조사 대상 코드는 유지하고 실험은 격리된 검증 환경에서 합니다.

구현 근거가 설계를 반박하면 해당 결정과 근거를 code-design에 돌려보내고 기존 요약과 점검을 갱신합니다. 목표나 전제의 변화는 공통 반환 규칙을 따릅니다. 구현에 맞추어 완료 조건을 조용히 재정의하지 않습니다.

## 결과 반환

패치나 조사 결과, 실제 최종 코드의 완료 근거, 검수 결과, 명시적인 미해결 조건을 현재 작업 스킬에 반환합니다. 확인된 수정과 유용한 방법 또는 입증된 예방책은 허용된 저장을 위해 지식 스킬에 전달합니다. 제공할 소프트웨어 근거는 검증 참조 문서가 정의합니다. 공통 지침에 따라 AI 점검 완료와 vagabond의 독립 수락을 구분합니다.
