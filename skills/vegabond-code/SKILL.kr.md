# Vegabond Code

진행 중인 작업 방식에 소프트웨어 방법을 제공합니다. 작업 요약과 특성을 재사용하고 공통 경계와 완료에는 [에이전트 지침](../../agents/vegabond-agent.md)을 따릅니다. 직접 호출되면 [scout의 공통 설정](../vegabond-scout/SKILL.md#frame-and-classify)과 연결된 작업 스킬을 사용한 뒤, 분류를 다시 시작하지 않고 여기서 이어갑니다.

## 작업 환경 파악

실제로 변경하거나 조사하는 파일, 모듈, 동작에 맞춰 scout의 작업 특성을 구체화합니다. 저장소 지침, 프로젝트·의존성 설정, 관련 호출부, 테스트, 스크립트, CI를 근거로 다음을 파악합니다.

- 대상의 언어, 엔진·프레임워크, 관련 버전.
- 작업에 영향을 주는 빌드 시스템, 컴파일러·런타임, 플랫폼, 대상·설정.
- 실제 빌드, 테스트, 실행, 검사 경로와 환경별 계약·관례.

확장자나 저장소의 대표 기술만으로 분류하지 않습니다. 언리얼 C++과 독립 C++ 라이브러리는 다른 방법이 필요할 수 있습니다. 언리얼 저장소 안의 Python 도구는 자체 실행 경로를 따르되, 영향이 엔진 에셋이나 동작에 미치면 엔진 검사를 추가합니다. 복합 작업에서는 영향을 받는 각 구성요소와 그 경계의 검사를 파악합니다.

| 환경 예시: 지원 범위를 제한하는 목록이 아님 | 파악한 대상을 다음에 연결 |
| --- | --- |
| 언리얼 | 적용되는 엔진·모듈 계약과 프로젝트 빌드, 테스트, 에디터, 플레이 경로. |
| 유니티 | 적용되는 엔진·패키지 계약과 프로젝트 컴파일, 테스트, 에디터, 플레이 경로. |
| 독립 C++ | 실제 컴파일러·빌드 설정, 테스트, 실행 프로그램이나 라이브러리 소비자. |
| 다른 언어 또는 복합 환경 | 기존 도구 구성, 실행 경로, 영향을 받는 통합 검사. |

판단 결과와 근거 위치를 기존 작업 요약이나 단계 연결에 담으며 별도 환경 보고서를 만들지 않습니다. 이를 사용해 scout의 연결 방식으로 가용 환경별 스킬이나 직접 도구를 선택하고 아래 검사를 정합니다. 설정이 있다는 이유로 도구가 실행된다고 보지 않고 scout의 준비 확인을 따릅니다. 근거가 없거나 충돌하면 필요한 범위만 조사하며, 미확정 의도가 수행 방법을 바꾸는 경우에만 질문합니다. 저장소 근거가 없는 새 작업은 명시적 요구사항과 가용 맥락을 사용하고, 제안한 도구 구성과 실제 확인한 구성을 구분합니다.

## 실행

위 환경 파악을 바탕으로 변경에 필요한 깊이로 계약, 상태 소유권, 수명주기, 영향을 받는 통합 지점을 파악합니다.

현재 정보 요약을 재사용하면서 [vegabond-knowledge](../vegabond-knowledge/SKILL.md)를 통해 관련 계약, 버전별 참고 자료, 알려진 실패·예방 검사를 요청합니다.

- **Create:** 작은 기능은 기존 패턴을 따라 완전히 사용할 수 있는 경로로 구현합니다. 시스템 작업은 구현 전에 경계, 인터페이스, 의존성, 이전 요구사항을 정합니다. scout가 정한 규모에 따라 의존 작업 전에 작은 통합 구현으로 위험한 인터페이스나 가정을 확인합니다.
- **Revise:** 결함은 코드를 바꾸기 전에 재현 가능한 실패와 원인을 확인합니다. 의도적인 구조 개선은 유지할 동작과 공개 계약을 정하고 일관된 단위로 구조를 바꿉니다. 관계없는 정리를 수정에 묶지 않습니다.
- **Research:** 관련 코드 경로, 데이터 흐름, 실행 근거를 추적합니다. 질문의 제약에 따라 기술 대안을 비교하고 파일, 심볼, 로그, 적용 가능한 문서를 인용합니다. 조사 코드는 유지하며 필요한 실험은 격리된 실행 환경을 사용합니다.

## 검사 준비

구현 전에 수락 조건과 유지할 계약을 실행 가능한 검사에 연결하며 정보 요약의 관련 예방책도 포함합니다. 영향받는 경로의 기준 상태를 확인하고 기존 실패를 구분합니다. 현실적인 로컬 테스트 경로가 있는 버그는 수정 전에 의도한 이유로 실패하는 회귀 검사를 확보합니다. 그렇지 않으면 가장 가까운 관찰 가능한 재현을 보존하고 한계를 밝힙니다.

## 검증

해당되는 경우 다음 네 단계를 유지합니다.

1. **빌드·준비:** 영향받는 대상과 설정으로 프로젝트의 실제 빌드, 컴파일 또는 이에 해당하는 준비를 실행합니다.
2. **자동 테스트:** 관련 기존 테스트를 실행합니다. 의미 있는 보호를 제공할 때 구현과 독립적인 기대 결과를 사용해 회귀·동작 검사를 추가합니다. 영향을 받는 경계와 오류 경로를 포함합니다.
3. **실행 준비:** 애플리케이션이나 필요한 환경을 실행하고 초기화 실패 없이 변경 경로에 접근할 수 있는지 확인합니다.
4. **실제 사용:** 공개 인터페이스로 변경 동작을 사용합니다. Unreal·Unity 게임에서는 에디터를 실행하고 관련 멀티플레이 역할을 포함해 실제 플레이를 수행합니다. CLI는 실제 명령을 실행하고, 라이브러리는 실제 소비자나 테스트용 실행 프로그램으로 사용합니다.

결함은 원래 재현과 영향을 받는 주변 동작을 다시 확인합니다. 명령, 대상·설정, 결과, 관찰된 실행 동작을 기록합니다. 각 단계에 에이전트 지침의 진행 불가와 해당 없음 구분을 적용합니다. 구현 변경 없는 코드 조사는 관계없는 전체 빌드 대신 주장을 뒷받침하는 검사를 사용합니다.

## 검수와 반복

일관된 변경 단위마다 영향을 받는 빌드·준비와 자동 검사를 수행하고, 변경 내용과 관련 호출부를 요구사항에 대조해 검수합니다. 누락된 동작, 깨진 계약, 상태·수명주기 오류, 변경 고유 위험을 확인합니다. 테스트가 구현을 되풀이하지 않고 잘못된 동작을 탐지하는지 검토합니다. 유용한 능력을 제공할 때 가용 검수·테스트 스킬을 사용합니다. 검수 발견 사항은 변경 근거로 삼기 전에 구체적 작동 원리나 증거가 있어야 합니다.

확인된 실패나 결함은 명령, 단언, 로그, 상호작용으로 원인을 좁힙니다. 수정하고 원래 실패 검사와 영향을 받은 주변 검사를 반복한 뒤 수정 내용을 다시 검수합니다. 필수 검사가 통과하고 범위 내 확인된 결함이 남지 않을 때까지 반복합니다. 잘못된 동작을 받아들이기 위해 유효한 검사를 약화하지 않습니다. 검사 자체가 잘못됐다면 요구사항에 근거해 명시적 이유와 함께 바로잡습니다.

진단, 근거, 범위, 수행 능력의 재평가가 필요하면 에이전트 지침의 [공통 실패·피드백 규칙](../../agents/vegabond-agent.md#respond-to-failures-and-feedback)을 사용합니다.

국소 반복 후에는 최종 결과물로 필수 통합·실제 사용 검사를 수행합니다. 실패하면 진단·수정으로 돌아가고, 후속 변경은 영향을 받은 근거를 무효화합니다. 재현 가능한 기존 실패와 새로 유발한 실패를 구분하며, 기존 실패라는 이유로 수락이 입증됐다고 보지 않습니다.

확인된 수정, 기술적 근거, 입증된 예방책 또는 구체적으로 재사용할 검사를 vegabond-knowledge에 전달해 허용된 기록을 갱신합니다. 조사나 피드백만 요청된 작업에서는 원본을 편집하지 않고 발견 사항을 수정합니다. 패치나 조사 결과를 검수 결과, 기술적 근거, 예방 참조, 남은 한계와 함께 진행 중인 작업 스킬에 반환합니다.
