# Vegabond Code

현재 작업 절차 안에서 소프트웨어 작업을 수행한다. 기존 브리프·프로필과 [에이전트 지침](../../agents/vegabond-agent.kr.md)을 따른다. 직접 호출되면 Scout의 공통 설정과 연결된 작업 절차로 누락된 맥락만 채우고 분류를 재시작하지 않는다.

## 작업 환경 파악

저장소 지침, 소스·호출자, 프로젝트·의존성 설정, 테스트·스크립트·CI에서 언어, 엔진·프레임워크 버전, 도구·플랫폼·대상, 실제 빌드·테스트·실행·검사 경로를 확인한다. 신규 작업은 제안한 도구와 관찰한 도구를 구분한다. 설정만으로 실행 가능성을 단정하지 않고 Scout의 준비 확인을 재사용한다.

확장자나 저장소의 대표 기술이 아닌 실제 구성 요소를 분류한다. Unreal C++·독립 C++·Unity는 각 계약을 따른다. Unreal 저장소의 Python 도구는 자체 런타임을 검사하고 자산·엔진 동작에 영향을 줄 때 엔진 검사도 추가한다. 혼합 작업은 구성 요소와 경계 검사를 식별한다. 별도 환경 보고서 대신 기존 브리프에 근거 위치와 결과를 둔다.

기존 정보 브리프를 재사용하며 지식 절차로 관련 계약·버전별 출처·과거 실패 및 예방 검사를 요청한다. 환경별 스킬·도구는 Scout의 매핑으로 선택한다. 구성 요소와 호출자 검사 후 정보 필요성 판단으로 상태·소유권·수명·실패·검증 질문을 보완한다. 검색된 API 보장이나 수정안을 적용하기 전에 실제 버전과 원리를 확인한다.

게임 구현·디버깅·최적화에는 [게임 근거 활용 규칙](../../knowledge/game/K-GAME-RESEARCH-USE.kr.md)을 적용하고 유효한 기존 조회를 재사용한다. 구체적 기능·재현 증상으로 검색하고 엔진·플랫폼·상태 권한 조건을 확인한다. 선택 기술을 코드 변경과 관찰 가능한 검사에 연결한다. 기각 이유를 보존하고 측정 결과를 지식으로 반환한다. 원작 사례만으로 현재 구현을 입증하지 않는다.

## 설계 깊이 선택

상태 소유권·수명·외부 호출 인터페이스·동시성·영속성·외부 연동·마이그레이션에 중요한 결정이 있으면 코드 설계를 사용한다. 기존 패턴을 따르는 국소 수정은 계약과 보존 조건을 간단히 밝히고 진행한다. 파일 수로 판단하지 않는다. 유효한 설계는 재사용하고 근거가 바뀐 결정만 재검토한다.

현재 브리프·환경·영향받는 소스와 계약·제약·미해결 결정을 전달한다. 설계는 이 작업 안에서 구현 방향·검사를 반환하며 독립 작업 절차를 만들지 않는다. 설계 전용 요청이면 구현까지 임의 진행하지 않는다.

## 구현 또는 조사

코드를 바꾸거나 결과를 판단하기 전에 [검증·인계](references/verification.kr.md)를 읽는다. 준비, 빌드·테스트·런타임·실사용 검사, 검토·수정, 검사 변경 검토, 장기 상태, 입증된 예방책의 세부를 따른다. 일관된 변경 단위와 최종 통합 결과에 적용한다.

- 생성: 선택 설계·기존 패턴으로 완전한 사용 경로를 구현한다. 의존 작업 전에 작은 통합 실험으로 핵심 가정을 확인한다.
- 수정: 결함을 재현하고 원인을 추적한 뒤 고친다. 구조 변경은 기존 동작·공개 계약을 보존하고 무관한 정리는 제외한다.
- 조사: 코드·데이터 흐름·런타임 근거를 추적하고 기준에 따라 비교한다. 파일·심볼·로그·출처를 인용한다. 조사 대상은 변경하지 않고 실험은 격리한다.

구현 근거가 설계를 반박하면 관련 결정과 근거를 설계로 반환하고 브리프·검사를 갱신한다. 목표·전제 변화는 공통 복귀 규칙을 따른다. 구현에 맞춰 완료 조건을 몰래 바꾸지 않는다.

## 반환

최종 코드의 패치·조사 결과, 완료 조건 근거, 검토 결과, 미해결 조건을 현재 작업에 반환한다. 확인된 수정과 유용한 방법·입증된 예방책은 지식 절차로 저장한다. AI 검사 완료와 vagabond의 독립 수락을 구분한다.
