# Vegabond Code

진행 중인 작업에서 소프트웨어를 다룹니다. 기존 요약·프로필과 [에이전트 지침](../../agents/vegabond-agent.kr.md)을 따릅니다. 직접 호출되면 [정찰 공통 설정](../vegabond-scout/SKILL.kr.md)과 연결 작업 스킬로 빠진 맥락만 채우고 분류를 반복하지 않습니다.

## 작업 환경 확인

저장소 지침·소스·관련 호출자·프로젝트 및 의존성 설정·테스트·스크립트·CI로 변경 구성요소의 언어·엔진·버전·도구체인·플랫폼·대상과 실제 빌드·테스트·실행·검사 경로를 확인합니다. 새 작업은 제안 도구와 관찰한 도구를 구분합니다. 충돌 근거를 좁혀 해결하고 설정만으로 실행을 단정하지 않고 정찰의 준비 확인을 재사용합니다.

확장자나 저장소 주 기술보다 실제 구성요소를 분류합니다. Unreal C++·독립 C++은 각 도구체인이, Unity는 해당 프로젝트·패키지 계약이 필요합니다. Unreal 안의 Python 도구도 자체 환경을 따르며 엔진 자산·동작에 영향이 있을 때 엔진 검사를 추가합니다. 혼합 작업은 영향 구성요소와 경계 점검을 식별하고 기존 요약에 원본 위치·결과를 남깁니다.

[지식 스킬](../vegabond-knowledge/SKILL.kr.md)로 관련 계약·버전별 원본·과거 실패·예방 점검을 요청하며 기존 정보 요약을 재사용합니다. 정찰 연결에 따라 환경 스킬·직접 도구를 선택합니다.

구성요소·호출자를 살핀 뒤 [필요한 정보의 공통 판단](../vegabond-scout/references/information-needs.kr.md)을 적용해 관련 상태·소유권·수명·실패·검증 질문을 보완합니다. 조회한 API 보장·사건 수정책은 실제 버전·기전을 확인한 뒤 적용합니다.

## 설계 깊이 선택

상태 소유권·수명·다른 호출자의 인터페이스·동시성·영속성·외부 통합·이전의 중요한 선택이 필요하면 [코드 설계](../vegabond-code-design/SKILL.kr.md)를 사용합니다. 확립 패턴을 따르는 로컬 변경은 계약·보존 조건을 짧게 명시하고 진행할 수 있습니다. 파일 수만으로 깊이를 정하지 않으며 유효한 설계를 재사용하고 근거가 달라진 결정만 재검토합니다.

기존 요약·환경·영향 소스와 계약·제약·미답 질문을 전달합니다. 설계는 이 흐름 안에서 구현 방향·점검을 반환하며 두 번째 실행을 시작하지 않습니다. 설계 전용 요청은 설계로 마칩니다.

## 구현과 조사

코드를 바꾸거나 결과를 판단하기 전에 [검증과 인계](references/verification.kr.md)를 읽습니다. 준비·빌드·테스트·실행·실사용·검토 교정·검증 변경 검토·장기 상태·입증 보호장치의 상세 기준이며 각 일관된 변경과 최종 결과에 적용합니다.

- 제작: 선택 설계나 확립 패턴으로 실제 사용할 수 있는 경로를 완성합니다. 핵심 가정은 작은 통합 경로로 의존 구현 전에 확인합니다.
- 수정: 결함을 재현하고 원인을 추적한 뒤 고칩니다. 의도적 구조 변경은 동작·공개 계약을 보존하고 무관한 정리는 제외합니다.
- 조사: 코드·데이터 흐름·실행 근거를 추적하고 기준에 따라 대안을 비교합니다. 파일·기호·로그·출처를 인용하며 소스는 그대로 두고 실험에는 격리 환경을 사용합니다.

구현 근거가 설계를 반박하면 영향 결정·근거를 설계 스킬에 반환하고 기존 요약·점검을 갱신합니다. 목표·전제가 바뀌면 공통 복귀 규칙을 따르며 구현에 맞춰 목표를 조용히 바꾸지 않습니다.

## 반환

패치·조사, 실제 최종 코드의 수용 근거, 검토 결과와 미해결 조건을 반환합니다. 확인한 수정·유용한 방법·입증 보호장치는 허용된 저장을 위해 지식 스킬에 전달하고 상세 근거 기준은 검증 참고 문서를 따릅니다. AI 점검과 vagabond의 독립 수용을 구분합니다.
