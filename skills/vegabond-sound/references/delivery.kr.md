# 믹스·납품·도구

## 제작 경로 선택

| 요건 | 방법과 확인 근거 |
| --- | --- |
| 정밀한 타이밍, 재현 가능한 변주, 편집 가능한 스코어, 정렬된 스템 | DAW 타임라인, 사용할 악기와 렌더 방법이 적힌 MIDI, 오프라인 합성, 지원되는 게임 오디오 저작 도구를 쓴다. 납품할 파일을 렌더해 비교한다. MIDI를 소리로 렌더하려면 재생 악기가 필요하다. |
| 사람의 연기와 공간의 특성 | 가능한 연주자·연기자나 폴리를 녹음한다. 후속 편집이 필요하면 드라이 소스와 편집 여유 구간을 보존한다. |
| 대량의 음성 대본 | 녹음하거나 요청 언어와 연기에 맞는 허용된 TTS를 쓴다. 일괄 생성 전에 정확한 대사와 어려운 발음을 확인한다. |
| 효과음이나 음악 생성 | 도구에 있는 제어 기능, 접근 가능 여부, 허용 입력, 내보내기 옵션을 확인한다. 생성본을 후보로 사용해 편집하고 측정한다. 재사용에 필요하면 모델, 설정, 개별 음원의 출처를 기록한다. |
| 기존 파일 검사와 간단한 복구 | DAW, 파형·스펙트럼 편집기, 또는 사용 가능한 FFmpeg/ffprobe 등으로 처리한다. 복구 파일이 디코딩되는지와 문맥에서 수정 전후 차이를 확인한다. |

사용자가 지정한 서비스는 기능, 약관, 지원되는 접근 방식이 맞을 때 쓴다. 외부에 입력하는 데이터는 해당 자산을 위해 허용된 내용으로 제한한다. OneStep의 제한된 Suno 데이터 경로가 필요한 작업이라면 전체 체크아웃에서 이용할 수 있는 `prototypes/SunoRestricted/README.md`의 요청 처리 규칙을 따른다. 자산을 선택하거나 배포할 때 [도구와 권리 자료](sources.kr.md#도구와-권리)에서 제공자별 기능과 약관을 확인한다.

## 출력 규격 정의

- 실제 사용처의 규격을 먼저 확인한다. 별도 사양이 없는 게임·영상 작업에는 48 kHz PCM WAV를 작업 기본값으로 쓸 수 있다. 허용되면 24비트 PCM을 사용하고 최종 납품은 지정된 샘플레이트와 비트 깊이를 적용한다. 편집에 유용하면 소스 품질의 마스터를 보관한다. 런타임에서 점음원에 모노를 요구하면 모노를, 의도한 공간 이미지가 있으면 스테레오나 요청된 채널 구성을 쓴다.
- 소스 세션, 드라이·웻 버전이나 인스트루멘털, 짧은 편집본, 대체 테이크, 루프 지점 메타데이터, 편집 가능한 스템이 필요한지 확인한다. 길이가 정해진 루프나 스템은 시간 원점, 샘플레이트, 종료 프레임을 포함하지 않는 정확한 범위를 기록한다. 사용처가 인식하는 형식일 때 루프 마커를 삽입하고, 임포트 도중 사라질 수 있으면 인계 메모에도 경계를 남긴다.
- 샘플, 라이브러리, 생성본, 연주·연기 자료에 필요한 출처를 기록한다. 자산·페이지 ID, 원본이나 권리자, 해당 라이선스나 계약과 저작자 표시, 사용 제한을 확인한다. 작곡, 가사, 녹음된 연주, 모델 체크포인트에는 서로 다른 조건이 적용될 수 있다. 실제 사용처에 맞는 조건을 확인한다.

## 실제 납품 파일 확인

1. 비슷한 체감 볼륨에서 비교한다. 맥락 안에서 명료도와 신호 기능을 듣고 솔로로 결함을 확인한다. 요청에 중요한 재생 장치나 모노 폴드다운에서 검토한다. 수정 작업은 같은 레벨 기준으로 원본과 비교해 요청된 변경을 확인한다.
2. 포맷, 길이 또는 정확한 프레임 수, 채널, 샘플레이트, 필요한 비트 깊이를 검사한다. 내보낸 파일을 디코딩해 끊김, 클리핑, 잘못된 시작점, 불필요한 테일, 무음을 확인한다. 손실 포맷은 디코딩 결과와 목표 앱의 타이밍 및 갭리스 재생을 확인한다.
3. 필요에 따라 샘플 피크나 트루 피크를 측정하고 사용처별 라우드니스 기준을 적용한다. 통합 LUFS는 프로그램용 척도로 짧은 효과음에서는 값을 구하기 어렵거나 판단에 도움이 적을 수 있다. 같은 종류의 효과음은 맥락 속 가청성과 기능을 맞춘다. ITU-R BS.1770은 측정 알고리즘, EBU R 128은 해당 방송 환경, Spotify 안내는 재생 정규화에 관한 것이다. [측정과 납품 자료](sources.kr.md#측정과-납품)
4. 루프는 디코딩한 범위를 반복하면서 타이밍과 불연속을 살핀다. 파형 경계 측정으로 클릭이 나는 위치를 찾을 수 있다. 음악적 이어짐과 겹치는 여운도 듣는다. 인터랙티브 자산은 대표적인 게임·미들웨어 출력을 캡처해 타이밍, 가청성, 상태 전환을 납품 규칙과 비교한다.

FFmpeg 도구가 PATH에 있으면 아래 예시로 최종 파일을 검사한다. 통합 라우드니스와 트루 피크 값은 해당 측정 조건에 맞춰 해석한다. WAV는 검사한 시간 단위와 길이로 정확한 환산이 가능할 때 프레임을 계산하고, 필요하면 디코딩한 PCM에서 샘플 프레임을 센다.

```text
ffprobe -v error -select_streams a:0 -show_entries stream=codec_name,sample_rate,channels,channel_layout,bits_per_sample,bits_per_raw_sample,duration_ts,time_base:format=duration -of json "output.wav"
ffmpeg -hide_banner -i "output.wav" -af "ebur128=peak=true" -f null -
```

인계 메모에는 파일 경로, 필요한 배치나 임포트 설정, 실제로 수행한 검사를 담는다. 청취, 런타임, 서비스 기능 중 확인할 수 없었던 항목도 기록한다.
