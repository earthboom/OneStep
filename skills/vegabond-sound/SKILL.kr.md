# Vegabond Sound

실제 청취 환경을 기준으로 요청받은 오디오, 편집본, 제작 브리프를 만든다. OneStep에서는 진행 중인 제작이나 수정 작업에 이 전문 스킬을 적용한다.

## 필요한 절차 선택

| 산출물 | 절차 |
| --- | --- |
| 게임 신호음, 폴리, UI 효과음, 타격음, 환경음, 절차적 효과음 | [효과음](references/sound-effects.kr.md) |
| 배경음악, 이음새 없는 루프, 스템, 적응형 게임 음악 | [배경음악과 적응형 음악](references/background-music.kr.md) |
| 대사, 보이스오버, 후시 녹음, 내레이션, 말소리 편집과 TTS | [말소리](references/spoken-voice.kr.md) |
| 한국 발라드, 알앤비, 힙합 등의 오리지널 곡과 비트 | [곡 제작](references/song-production.kr.md) |
| 파일 규격, 믹스와 내보내기 확인, 출처 및 권리, 생성 오디오 | [믹스·납품·도구](references/delivery.kr.md) |

기법을 조사하거나 논문, 표준, 구현, 현업 사례가 뒷받침하는 범위를 확인할 때 [근거 자료](references/sources.kr.md)를 본다. 산출물에 필요한 레이어의 절차만 조합한다.

## 제작과 검증

1. 요청과 프로젝트에서 용도, 전달할 소리나 감정, 길이 또는 동기화 지점, 보존할 원본이나 문구, 최종 사용처를 파악한다. 결과에 영향이 있으면 루프와 재생 트리거, 음성과 언어, 편집 가능한 소스나 스템, 파일 규격을 포함한다. 규격이 없으면 사용처에 맞고 되돌리기 쉬운 기본값을 정하고 중요한 가정을 알린다.
2. 가장 까다로운 조건에 맞춰 제작 방법을 고른다. 타이밍, 정밀 편집, 소스의 동일성, 스템 정렬이 중요하면 DAW, MIDI, 녹음, 결정론적 합성을 활용한다. 많은 변주나 음색 탐색이 중요하면 실제 제어 기능이 맞는 생성 도구를 고려한다. 편집할 때는 시작 파일과 비교하고 지정된 타이밍, 프레이징, 캐릭터, 편곡을 보존한다.
3. 방향을 잘못 잡았을 때 다시 할 작업이 많다면 대표 효과음, 구절, 구간부터 제작한다. 영상, 플레이, 다른 소리 레이어, 리드 보컬과 함께 확인한다. 팩을 만들 때는 검증한 신호의 기능을 유지하고 요청한 속성을 변주한다. 곡은 전체 편곡을 채우기 전에 훅과 보컬 음역을 정한다.
4. 최종 렌더를 브리프에 맞춰 듣고 가능한 경우 목표 믹스에서도 확인한다. 실제 납품 파일에서 형식, 길이, 레벨, 경계, 내용을 검사하고 중요한 단어와 전환, 신호를 정상 속도로 확인한다. 청취, 측정, 런타임 재생으로 확인한 항목과 확인할 수 없었던 항목을 구분해 기록한다.
5. 문제를 일으킨 레이어나 전환을 수정하고 영향을 받는 내보내기 결과와 적용 환경을 다시 확인한다. 요청된 파일을 제공하고, 미리보기나 소스 세션도 요청에 맞춰 제공한다. 프롬프트, 큐시트, MIDI 스케치, 제작 절차까지만 가능했다면 실제 산출물과 완성 음원에 필요한 기능을 밝힌다.
