## Produce and verify

1. Recover the brief from the request and existing project. Identify the use, intended audible signal or feeling, duration or sync point, source or wording to preserve, and destination. Include loop and trigger behavior, voice and language, editable sources or stems, and file specs when they affect acceptance. If specs are absent, choose reversible defaults that fit the destination and state material assumptions.
2. Match the production method to the hardest requirement. Use DAW, MIDI, recording, or deterministic synthesis when timing, edits, source identity, or aligned stems matter. Consider a supported generator when variation and texture matter and its actual controls fit. For an edit, compare with the starting file and preserve specified timing, phrasing, character, or arrangement.
3. Build a representative cue, phrase, or section first when a wrong direction would multiply work. Check it against the picture, gameplay, other sound layers, or lead vocal as applicable. For a pack, carry the accepted cue function across variations and change only the attributes varied in the brief. For a song, settle the hook and vocal range before filling the arrangement.
4. Listen to the delivered render against the brief and in its target mix when available. Check the exact exported files for the required format, duration, levels, boundaries, and content. Check critical words, transitions, and cues at normal playback speed. Record which checks used listening, measurements, or runtime playback, and mark unavailable checks as unverified.
5. Correct the layer or transition responsible for a failure, then recheck the affected export and context. Deliver the requested files and an appropriate preview or source session when requested. When only a prompt, cue sheet, MIDI sketch, or production recipe was feasible, identify the actual deliverable and the capability missing for a finished render.
