# Vegabond Code Design

호출한 작업이나 코드 스킬의 소프트웨어 설계 결정을 해결한다. 브리프·환경·출처·정보 브리프를 재사용한다. 실행·검증은 호출자가 담당하며 별도 작업 절차를 만들거나 소프트웨어 실행을 인증하지 않는다. 에이전트 지침을 따르고 스킬을 읽는 것만으로 에이전트를 생성하지 않는다.

직접 호출되면 Scout 공통 설정과 코드 환경 파악으로 누락된 맥락만 채운다. 설계 전용 요청은 설계와 근거를 제공하고 제품 코드를 변경하지 않는다. 허가되고 결정에 필요한 격리 실험만 수행한다.

게임 아키텍처·기술 선택에는 직접 호출 때도 [게임 근거 활용 규칙](../../knowledge/game/K-GAME-RESEARCH-USE.kr.md)을 적용한다. 기존 조회를 재사용하고 롤백의 상태 복원 같은 선행 조건을 확인한다. 엔진·플랫폼·게임플레이 조건에 따른 채택·조건부·기각을 기록한다. 선택 항목 ID·구현 경계·예정 검증을 설계에 반환한다.

## 설계 해결

공통 정보 필요성 판단으로 필요한 보장·경계·반례가 드러내는 질문을 확인한다. 채택 계약·조건부 가정·기각 유추를 관련 선택에 붙인다.

1. 결정을 근거에 고정한다. 기존 브리프에서 결정·결과·보존 조건·경계를 식별하고 진입점·호출자·데이터·검사·관례를 살핀다. 구체적 공백만 지식으로 보완한다. 필요한 보장과 제안한 절충을 구분하며 충돌·불가능한 능력을 숨기지 않는다.
2. 형태를 정의한다. 구현 단계 전에 데이터 모델·상태 소유자·불변 조건·수명·인터페이스를 명시한다. 관련 실패·동시 접근·재시도·영속성·정리·통합 경계를 포함한다. 실제 언어·프레임워크 계약을 사용하고 순수 함수에 불필요한 상태 머신을 강제하지 않는다.
3. 근거로 선택한다. 실제 절충이 있을 때만 대안을 비교한다. 적합성·비용·중요한 기각안을 설명한다. 실증 불확실성이 선택을 뒤집을 수 있으면 근거나 가장 작은 실험으로 확인한다. 접근 불가한 필수 검사는 차단, 미검증 가정은 불확실로 표시한다. 그럴듯한 도식은 실행 증거가 아니다.
4. 구현·검사 가능하게 만든다. 관련 인터페이스·호출자·이전 순서·호환 의무를 식별한다. 핵심 불변 조건·가정을 실제 검사·예상 관찰·환경에 연결하고 성능 주장은 측정 예산을 정한다. 반환·의존 구현 전 설계 검토로 요구→원리→근거를 추적하고 실패 순서·모순을 고친다. 실제 구현에는 호출자의 코드 검증이 별도로 적용된다.

## 결정 반환

공통 독자 중심 설계 전달 지침을 따른다. 관찰 가능한 동작·실패를 먼저 설명하고 구조·소유권·인터페이스·저장·이전·근거·검사를 그 결정에 연결한다.

지원하는 보장, 남은 구현 검사, 이름 붙인 의존 작업을 막는 전제를 밝힌다. 유용한 부분 제안이 보장 충족은 아니다. 호출자가 실제 구현의 검증을 수행하며 근거가 설계를 바꿀 때만 관련 결정을 재검토한다.
