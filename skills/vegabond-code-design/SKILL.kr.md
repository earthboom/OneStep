# Vegabond Code Design

호출한 작업 스킬이나 [vegabond-code](../vegabond-code/SKILL.md)를 위해 소프트웨어 설계 결정을 확정합니다. 기존 요약, 환경, 출처, 정보 요약을 재사용합니다. 호출한 스킬이 실행과 검증을 맡으며 설계는 두 번째 작업 흐름을 시작하거나 작동하는 소프트웨어를 인증하지 않습니다. 문서 경계와 공통 완료 기준은 [에이전트 지침](../../agents/vegabond-agent.md)을 따릅니다. 이 스킬을 읽는다고 에이전트가 생성되지는 않습니다.

직접 호출되면 [scout의 공통 준비](../vegabond-scout/SKILL.md#frame-and-classify)와 [코딩 환경 평가](../vegabond-code/SKILL.md#identify-the-working-environment)를 통해 부족한 맥락만 채웁니다. 설계만 요청받은 경우 제품 코드를 바꾸지 않고 설계와 뒷받침 근거를 제공합니다. 격리된 실험은 허용되었고 결정을 내리는 데 필요할 때만 수행합니다.

## 설계 결정

1. **결정의 근거 확인:** 기존 요약에서 확정할 결정, 필요한 결과, 보존 조건, 영향받는 경계를 식별합니다. 관련 진입점, 호출부, 데이터, 테스트, 프로젝트 관례를 살펴봅니다. 정보 요약에 구체적인 빈틈이 있을 때만 [지식 스킬](../vegabond-knowledge/SKILL.md)을 통해 출처나 이전 교훈 질문을 구체화합니다. 필수 보장과 제안한 절충을 구별하며 목표를 조용히 약화하는 대신 충돌하는 요구나 없는 역량을 밝힙니다.
2. **구조 정의:** 구현 단계를 정하기 전에 관련 데이터 모델, 상태 소유자, 불변 조건, 생명주기, 인터페이스를 밝힙니다. 실패 동작을 포함하고 중요한 경우 동시 접근, 재시도, 영속화, 정리, 통합 경계를 다룹니다. 실제 언어·프레임워크 계약을 사용합니다. 작업에 필요한 것만 결정하며 순수 함수에 인위적인 상태 기계를 덧붙이지 않습니다.
3. **근거에 따른 선택:** 실제 절충이 있을 때 대안을 비교하며 명확한 국소 패턴에 여러 설계를 억지로 만들지 않습니다. 선택한 구조의 적합성, 비용, 중요한 기각 대안을 설명합니다. 경험적으로 확인할 불확실성이 선택을 뒤집을 수 있다면 의존 작업 전에 근거를 확인하거나 범위가 가장 작은 프로토타입을 실행합니다. 접근할 수 없는 필수 점검은 차단, 점검하지 않은 가정은 불확실로 표시합니다. 그럴듯한 스케치는 실행 증거가 아닙니다.
4. **구현·검증 가능하게 정리:** 관련된 인터페이스·호출부, 이전 순서, 호환성 의무를 식별합니다. 중요한 불변 조건이나 가정마다 구체적인 점검, 기대 관찰, 필요한 환경을 연결합니다. 성능·자원 주장이 중요한 경우 측정 가능한 기준을 정합니다. 설계를 반환하거나 의존 구현을 진행하기 전에 [설계 검수](references/review.md)를 읽고 적용하여 요구사항을 메커니즘과 근거에 연결하고 관련 실패 순서를 검토하며 모순을 수정합니다. 상세 점검은 이 검수가 담당하며 실제 구현에는 호출한 스킬의 소프트웨어 검증도 계속 적용합니다.

## 결정 반환

기존 요약이나 요청된 설계 결과물에 선택한 구조와 소유권, 인터페이스와 실패 동작, 핵심 이유·절충, 영향받는 구현·이전 단위, 점검, 미해결 가정·차단을 담습니다. 관계가 명확해질 때만 작은 표나 다이어그램을 사용합니다. 새 파일, 승인 단계, 고정 양식은 필수가 아닙니다.

설계가 뒷받침하는 보장, 남은 구현 점검, 어떤 의존 작업을 막는 미해결 전제인지 명시합니다. 유용한 부분 제안이 요구 보장 충족을 뜻하지는 않습니다. 호출한 스킬이 실제 구현에 [코딩 검증 절차](../vegabond-code/references/verification.md)를 적용하고 근거가 설계 결정을 바꿀 때만 여기로 돌아옵니다. 실패할 때마다 전부 다시 설계하지 말고 유효한 맥락을 보존합니다.
