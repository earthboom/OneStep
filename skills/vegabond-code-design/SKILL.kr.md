# Vegabond Code Design

호출한 작업 스킬이나 [vegabond-code](../vegabond-code/SKILL.md)를 위해 소프트웨어 설계 결정을 확정합니다. 기존 요약·환경·출처·정보 요약을 재사용합니다. 실행·검증은 호출한 스킬이 맡고 설계는 두 번째 작업 흐름을 시작하거나 작동하는 소프트웨어를 인증하지 않습니다. 문서 경계와 공통 수락은 [에이전트 지침](../../agents/vegabond-agent.md)을 따릅니다. 스킬을 읽는다고 에이전트가 생성되지 않습니다.

직접 호출되면 [scout의 공통 준비](../vegabond-scout/SKILL.md#frame-and-classify)와 [코딩 환경 평가](../vegabond-code/SKILL.md#identify-the-working-environment)에서 부족한 맥락만 채웁니다. 설계만 요청받으면 제품 코드를 바꾸지 않고 설계와 근거를 제공합니다. 격리 실험은 허용됐고 결정에 필요한 경우에만 수행합니다.

## 설계 결정

1. **근거 확인:** 기존 요약에서 확정할 결정, 필요한 결과, 보존 조건, 영향 경계를 식별합니다. 관련 진입점·호출부·데이터·테스트·프로젝트 관례를 살핍니다. 정보 요약에 구체적 빈틈이 있을 때만 [지식 스킬](../vegabond-knowledge/SKILL.md)로 출처·이전 교훈 질문을 구체화합니다. 필수 보장과 제안한 절충을 구별하고 목표를 조용히 약화하지 말고 충돌하는 요구나 부족한 역량을 밝힙니다.
2. **구조 정의:** 구현 단계 전에 관련 데이터 모델, 상태 소유자, 불변 조건, 생명주기, 인터페이스를 밝힙니다. 실패 동작을 포함하고 중요한 동시 접근·재시도·영속화·정리·통합 경계를 다룹니다. 실제 언어·프레임워크 계약을 사용합니다. 작업에 필요한 것만 정하며 순수 함수에 인위적인 상태 기계를 더하지 않습니다.
3. **근거에 따른 선택:** 실제 절충이 있으면 대안을 비교하되 명확한 국소 패턴에 여러 설계를 억지로 만들지 않습니다. 적합성·비용·중요한 기각 대안을 설명합니다. 경험적으로 확인할 불확실성이 선택을 뒤집을 수 있으면 의존 작업 전에 근거를 확인하거나 최소 범위의 프로토타입을 실행합니다. 접근 불가능한 필수 점검은 차단, 점검하지 않은 가정은 불확실로 표시합니다. 그럴듯한 스케치는 실행 증거가 아닙니다.
4. **구현·검증 가능하게 정리:** 관련 인터페이스·호출부·이전 순서·호환성 의무를 식별합니다. 핵심 불변 조건·가정마다 구체적 점검, 기대 관찰, 필요한 환경을 연결합니다. 성능·자원 주장이 중요하면 측정 가능한 기준을 정합니다. 반환이나 의존 구현 전에 [설계 검수](references/review.md)를 읽어 요구·메커니즘·근거를 연결하고 실패 순서를 검토하며 모순을 수정합니다. 상세 점검은 이 검수가 맡으며 실제 구현에는 호출한 스킬의 소프트웨어 검증도 적용됩니다.

## 결정 반환

작성과 인계 시 [공통 독자용 설계 지침](../../agents/references/design-communication.md)을 적용합니다. 타입·저장 필드·트랜잭션 상세보다 관찰 가능한 동작과 중요한 실패 상황을 먼저 설명합니다. 이후 선택한 구조·소유권, 인터페이스, 구현·이전 단위, 근거, 점검을 그것이 뒷받침하는 결정과 연결합니다.

설계가 뒷받침하는 보장, 남은 구현 점검, 어떤 의존 작업을 막는 미해결 전제인지 명시합니다. 유용한 부분 제안이 요구 보장 충족을 뜻하지 않습니다. 호출한 스킬이 실제 구현에 [코딩 검증 절차](../vegabond-code/references/verification.md)를 적용하고 근거가 설계 결정을 바꿀 때만 여기로 돌아옵니다. 실패마다 전부 다시 설계하지 말고 유효한 맥락을 보존합니다.
