# Vegabond Code Design

호출한 작업이나 [코딩 스킬](../vegabond-code/SKILL.kr.md)을 위해 설계 결정을 정리합니다. 기존 요약·환경·원본·정보 요약을 재사용합니다. 호출자가 실행·검증을 소유하며 설계는 별도 흐름을 시작하거나 동작하는 소프트웨어를 인증하지 않습니다. [에이전트 지침](../../agents/vegabond-agent.kr.md)의 경계·완료 조건을 따릅니다. 읽는 것만으로 위임하지 않습니다.

직접 호출되면 [정찰 공통 설정](../vegabond-scout/SKILL.kr.md)과 [코딩 환경 확인](../vegabond-code/SKILL.kr.md)으로 빠진 부분만 채웁니다. 설계 전용은 운영 코드를 바꾸지 않고 설계·근거를 제공합니다. 허용되고 결정에 필요할 때만 격리 실험을 합니다.

## 설계 해결

[필요한 정보의 공통 판단](../vegabond-scout/references/information-needs.kr.md)으로 요구 보장·경계·반례가 빠진 질문을 드러내는지 살핍니다. 채택한 계약·조건부 가정·배제한 유추를 영향 결정에 연결합니다.

1. 결정의 근거: 기존 요약에서 결정·결과·보존 조건·경계를 확인하고 진입점·호출자·데이터·테스트·관례를 살핍니다. 구체적 공백이 있으면 [지식](../vegabond-knowledge/SKILL.kr.md)으로 원본·교훈 질문을 보완합니다. 필수 보장과 제안 상충관계를 구분하고 충돌·역량 부재를 드러냅니다.
2. 구조 정의: 구현 단계 전에 도메인 모델·상태 주체·불변식·수명·인터페이스를 정합니다. 중요한 경우 실패 전파·동시 접근·재시도·영속성·정리·통합 경계를 포함합니다. 실제 언어 계약을 사용하고 순수 함수에 가상 상태 기계를 더하지 않습니다.
3. 근거로 선택: 실제 상충관계가 있을 때 대안을 비교합니다. 명확한 로컬 패턴에 여러 설계를 꾸며내지 않습니다. 선택 구조의 적합성·비용·중요한 제외 대안을 설명합니다. 경험적 불확실성이 결정을 뒤집을 수 있으면 근거나 최소 실험으로 확인합니다. 접근 불가 필수 점검은 막힘, 미실험 가정은 불확실성으로 남기고 그럴듯한 설계를 실행 증거로 삼지 않습니다.
4. 구현·검증 가능하게 정리: 영향 인터페이스·호출자·이전 순서·호환 의무를 명시하고 핵심 불변식·가정을 구체적 점검·관찰·환경에 연결합니다. 성능·자원 주장이 중요하면 측정 가능한 예산을 둡니다. 반환이나 의존 구현 전에 [설계 검토](references/review.kr.md)로 요구→기전→근거를 추적하고 실패 순서·모순을 교정합니다. 구현 검증은 코딩 스킬이 담당합니다.

## 설계 반환

[독자 중심 설계 전달](../../agents/references/design-communication.kr.md)을 따릅니다. 관찰할 동작·중요 실패를 먼저 설명하고 구조·소유권·인터페이스·구현 및 이전 단위·근거·점검이 어떤 결정을 뒷받침하는지 연결합니다.

설계가 지지하는 보장, 남은 구현 검사, 어떤 의존 작업을 막는 전제를 명시합니다. 유용한 일부 제안이 모든 보장 충족은 아닙니다. 호출자가 실제 구현에 [코딩 검증](../vegabond-code/references/verification.kr.md)을 적용하며 근거가 설계 결정을 바꿀 때만 돌아옵니다. 매번 처음부터 재설계하지 않고 유효한 맥락을 보존합니다.
