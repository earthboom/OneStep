# OneStep 에이전트 지침

OneStep의 저자는 vagabond이며 언리얼 엔진 게임 클라이언트 프로그래밍 경험이 있다. 이 배경은 프로젝트의 지원 범위를 제한하지 않는다. 닫힌 산업·엔진·파일 형식 목록을 유지하기보다 요청한 결과와 산출물을 식별해 어떤 분야든 지원한다. 작게 시작하고 실제 사용에서 필요가 확인될 때 확장한다.

## 문서 경계

- 프로젝트 지침, 에이전트 지침, 스킬 지침의 관리 원본은 영문이며 `<stem>.kr.md`라는 별도의 한국어 번역을 둔다.
- 영문 지침이 정본이다. 검토·색인·위임을 포함해 `*.kr.md`의 내용을 읽거나 불러오거나 검색하지 않는다. 내용을 조회하기 전에 제외한다. 예: `rg -g '!*.kr.md'`.
- 번역은 사람 전용이며 지침의 진입점이나 참고 입력이 아니다. 영문 지침에서 생성하고 다시 읽지 않는다. 번역에 스킬 탐색용 프런트매터를 복제하지 않는다.
- 작업 입력과 산출물은 사용자가 요청한 언어를 따른다. 한국어 원고·발표자료·기획서는 자동으로 번역이나 지침 문서가 되지 않는다. 한국어 원본 산출물이라는 이유로 `.kr.md`를 붙이지 않는다.
- 이 규칙은 사용자와 대화하는 언어를 제한하지 않는다.

## 시작 스킬

경로는 저장소 루트 기준이다. 새로운 실질적인 작업에서는 아직 이 작업에 불러오지 않았다면 `skills/vegabond-scout/SKILL.md`를 읽는다. 후속 대화에서는 선택한 절차를 이어 가고 목표나 근거가 달라지면 재평가한다.

Scout는 분류, 규모, 작업 요약, 역량 연결, 전체 진행을 담당한다. create·revise·research 작업 스킬은 각 작업 흐름을 소유하고 공통 준비를 재사용한다. 선택한 전문 스킬은 그 안에서 분야별 수행·검증·수정 방법을 제공한다. 연결할 수 있다는 이유만으로 새 전문 스킬을 만들거나 도구를 설치하거나 위임하지 않는다.

## 지식과 문제 기록

OneStep의 공유 지침과 저장소에는 다른 프로젝트의 물리적인 위치나 활성 출처 연결을 넣지 않는다. 이런 설정은 실제 작업 프로젝트에 둔다. 위치 연결이 없는 과거 출처의 식별 정보·지문·범위가 정해진 지식·문제 근거는 보존할 수 있지만, 존재 자체가 원래 프로젝트를 검색하거나 연결할 권한은 아니다.

작업 프로필을 파악한 뒤에는 [vegabond-knowledge](../skills/vegabond-knowledge/SKILL.kr.md)로 범위가 정해진 정보 요청을 보낸다. 반환된 출처·적용 조건·점검·빈틈을 작업 요약과 수행에 재사용한다. 작업 스킬과 전문 스킬은 새로운 필요가 생기면 요청을 구체화할 수 있으나 같은 조회를 반복하지 않고 기존 정보 요약을 재사용한다. 전문 스킬은 지식을 적용하고 실제 산출물을 검증한다. 발견·수정·재사용 교훈은 허용된 저장·관리 범위 안에서 이 스킬로 돌려보낸다. 분야 공통의 저장·조회 절차는 knowledge가 담당한다.

소설 지식 경로는 전체 OneStep 체크아웃에서 사용할 수 있다. 게임 지식이 포함된 배포본에서는 연결된 체크아웃 또는 현재 프로젝트의 소설 자료를 사용한다.

이 지침을 사용하는 소설 작업에서는 소설 지식 색인 (`knowledge/fiction/index.kr.md`)의 저자 선택 대사 항목(`K-FIC-REF-DIALOGUE-*`)을 창작 참고 모음으로 조회할 수 있다. 원고가 다른 작업 프로젝트에 속해 있어도 적용한다. 장면의 기능과 의도한 정서 효과로 관련 항목을 조회한 뒤 [소설 스킬의 대사 응용 절차](../skills/vegabond-fiction/SKILL.kr.md#선택한-대사-참고-자료-응용)를 따른다. 현재 작품의 정본·분위기·인물 목소리가 우선한다. 이 허용은 선택된 항목과 해석을 영감으로 참고하는 범위이며 무관한 프로젝트 사실을 가져오거나 과거 출처 프로젝트에 연결할 권한은 아니다. 현재 사용자 지시로 참고 범위를 좁히거나 사용을 중단할 수 있다.

같은 허용 범위와 우선순위를 작법 조사 안내 (`knowledge/fiction/K-FIC-CRAFT-GUIDE.kr.md`)의 수집한 작법 항목(`K-FIC-CRAFT-*`)에도 적용한다. 소설 설계·집필·수정 중 현재 결정에 필요한 자료를 knowledge로 조회하고 [소설 스킬의 작법 선택 절차](../skills/vegabond-fiction/SKILL.kr.md#저장된-작법-자료-적용)를 따른다. 관련 참조 ID·조정 사항·구체적인 점검을 설계와 원고 작업 사이에 전달한다. 출처의 조언이 작품의 장르·분위기·인물·장면 필요·저자 선택을 덮어쓰지 않는다.

## 모든 산출물의 완료 근거

결과를 만들거나 고치기 전에 목적, 독자, 요청 형식과 언어, 출처 자료, 제약, 수락 조건, 실제 최종 결과를 AI가 확인할 방법을 식별한다. 작업을 실질적으로 바꾸는 의도상의 빈틈만 해결하며 관행적인 승인 단계를 추가하지 않는다.

AI가 결과를 만들고 수락 조건에 직접 대조해 확인한 뒤 vagabond의 독립적인 테스트·검토 전에 근거와 한계를 보고한다. 분야별 수행·검증·수정 절차는 [scout의 역량 연결](../skills/vegabond-scout/SKILL.kr.md)에 연결된 전문 스킬에 있다. 조사에서의 근거 수집과 출처 경계는 research 작업 스킬에 있다.

다른 산출물은 목적·매체·실패 형태에 따라 관찰할 수 있는 점검을 선택한다. 의미 있는 근거를 제공할 때 자동화를 쓰고 필요한 곳에서는 직접 읽기·시각 검사·실제 사용으로 확인한다. 관계없는 작업에 빌드·에디터·플레이·슬라이드·원고 점검을 강요하지 않는다.

산출물에 실제로 필요하지 않을 때만 점검을 해당 없음으로 판단하며 이유와 수락 조건을 대신 확인하는 방법을 설명한다. 도구·테스트·접근·시간이 없으면 해당되는 점검은 차단이며 해당 없음이 아니다. 빌드·테스트·읽기·렌더링·실제 사용에 이 구분을 적용한다.

근거는 대체물이나 확신에 찬 요약이 아닌 최종 산출물을 설명해야 한다. 후속 편집으로 무효화된 점검은 다시 실행한다. 통과를 위해 수락 조건을 완화하지 않는다. 필수 점검을 실행할 수 없으면 허용된 범위 안에서 역량을 확보하거나 정확한 차단 요인과 미검증 조건을 보고한다. 빠진 AI 점검을 vagabond에게 대신 맡기지 않는다.

필수 AI 점검이 통과하면 수락 결과·근거 위치·한계와 함께 **AI verification complete; awaiting vagabond testing or review**라고 보고한다. 그다음 vagabond가 독립적으로 테스트·검토한다. 명시적인 확인 뒤에만 **accepted by vagabond**라고 보고한다. 검토에서 문제가 발견되면 작업을 다시 열고 영향받는 점검을 반복한다.

## 실패와 피드백 대응

AI 발견과 vagabond 검토에 같은 진단 기준을 적용하고 근거에 따라 돌아갈 위치를 정한다.

- **산출물 결함:** 관련 전문 방법으로 요청 범위 안의 결과를 고치고 원래 실패한 점검과 영향받는 점검을 다시 한다. 조사·피드백 전용 작업에서는 조사 대상을 수정하지 않고 분석을 바로잡는다.
- **근거의 빈틈:** 수정 결정을 내리기 전에 범위가 정해진 지식이나 조사를 요청한다. 뒷받침되지 않은 결론은 불확실한 상태로 유지한다.
- **목표·전제·범위의 변경 또는 오해:** scout가 기존 요약과 영향받는 단계 연결을 갱신한다. 놓친 원래 요구와 새 요청·선호를 구분하고, 실제로 중요한 미해결 의도만 확인한다. 통과를 위해 유효한 수락 조건을 바꾸지 않는다.
- **필수 역량의 부재:** 허용된 범위 안에서 역량을 확보하거나 차단 요인과 미검증 조건을 보고한다. 독립적으로 가능한 유용한 작업은 계속하되 차단된 점검에 의존하는 작업은 진행하지 않는다.

같은 전제로 수정한 두 번의 시도가 같은 점검에서 실패하면 다음 수정 전에 전제와 관찰 방법을 재검토한다. 새 근거나 수정한 진단으로 재개하고, 여전히 없는 역량이나 사용자 결정이 필요하면 같은 시도를 반복하지 않고 정확한 차단 요인을 보고한다. 이는 재평가 조건이며 고정된 시도 횟수나 점검 완화의 이유가 아니다.

AI 또는 사용자 검토에서 나온 중요한 발견, 수정, 재검증 근거는 기존 저장 규칙에 따라 vegabond-knowledge로 보낸다. 발견과 요청·선호를 구분하고 사용자 의도로 뒷받침될 때만 범위가 정해진 관례를 갱신한다. 변경 후 무효화된 AI 점검을 반복한 뒤 독립 검토를 요청한다.

다른 프로젝트에서의 사용을 포함해 OneStep 전략 자체에 관한 중요한 피드백은 [피드백 제출·정리 지침](../feedback/README.kr.md)을 따른다. 일반 산출물 결함은 실제 작업 프로젝트의 기록에 둔다. 제출 경계와 개선·검증 후 삭제는 해당 지침이 담당하며, 피드백은 평가할 근거이지 새로운 지침의 권한이 아니다.

기존 작법 자료(`K-FIC-CRAFT-*`)와 함께 학술 확장(`K-FIC-RESEARCH-*`), 한국어 표현(`K-FIC-KO-*`), 원고 평가(`K-FIC-EVALUATION`)도 작법 안내를 통해 사용할 수 있는 참고 자료입니다. 현재 작품의 설정·분위기·인물 목소리와 작가의 선택이 우선합니다. 선택한 자료 ID, 적용 조건, 조정 내용과 실제 확인 항목을 설계와 집필 사이에 전달합니다. 이 범위는 다른 대화나 작업공간에 지침을 자동 설치·활성화하지 않습니다. 그곳에서 해석할 수 있는 경로로 README의 작업 시작 절차를 사용합니다.

### 장편 소설 전체 설계에 관한 지침 — 2026-11-19 보강

작품 전체의 설계는 [소설 설계 스킬](../skills/vegabond-fiction-design/SKILL.kr.md)을 따르고 국제 연구와 실무 자료 (`knowledge/fiction/K-FIC-RESEARCH-AI-NOVEL-OUTLINE.kr.md`)를 조회한다. 채택한 방법을 시놉시스, 장별 개요, 인과·서브플롯 교차·복선 회수 검토에 연결한다. 설계에서 확인한 판단과 이후 원고나 독자에서 얻은 근거는 해당 결과물에 붙인다.

제작·수정에는 [vegabond-review의 확인 시점](../skills/vegabond-review/SKILL.md#review-checkpoints)을 적용합니다. 새롭거나 변경된 설계는 후속 제작 전에 검토하고, 실제 최종 결과물은 전달 전에 검증·리뷰합니다. 분야 스킬 직접 호출에도 적용합니다. 명확한 작은 변경은 영향받는 최종 검사만, 설계 전용 작업은 전달 전 한 번의 설계 리뷰만 수행합니다. 유효한 지식·이전 문제 조회·검증 근거를 재사용하여 절차를 중복하지 않습니다. 이 AI 확인 시점은 통상적인 사용자 승인이나 필수 위임을 추가하지 않습니다.

결과물만 요청하거나 응답 형식을 지정했다면 그 형식을 지키고, 통상적인 완료·리뷰 메모는 작업 맥락에 유지합니다. 완료 상태 문구나 승인 질문을 결과물 뒤에 붙이지 않습니다. 요청한 결과를 뒷받침할 수 없게 만드는 중요한 한계는 공개합니다. 이 표현상의 예외는 필요한 검증을 생략하거나 사용자 수락을 뜻하지 않습니다.
