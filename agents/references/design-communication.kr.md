# 독자가 이해할 수 있는 설계 문서

코딩·소설 설계 문서를 작성하거나 반환할 때 사용합니다. 이 문서는 설명과 가독성을 담당하고 각 설계 스킬은 근거와 정확성 검수를 유지합니다. 기존 요약이나 요청된 결과물을 사용하며 고정 양식, 별도 요약 파일, 일상적인 승인 단계는 필요하지 않습니다.

## 결정을 먼저 설명

독자가 누구이며 무엇을 판단하거나 수행해야 하는지 확인합니다. 첫 부분에 목표, 선택한 방향, 달라지는 것과 유지되는 것, 핵심 이유와 대가, 미해결 조건이나 결정을 간결하게 설명합니다. 작은 설계는 한 문단이면 됩니다. 실현 가능성·보장·정본·범위의 의미를 바꾸는 한계는 부록에만 두지 말고 첫 부분에 밝힙니다. 사람이 해야 할 결정과 남은 구현·원고 점검을 구별하고, 관련되면 그 결정의 영향과 근거 있는 선택지를 설명합니다.

독자가 모든 API·필드·이론 용어·요소 이름을 먼저 배우지 않아도 첫 부분에서 선택과 결과를 설명할 수 있어야 합니다. 필요한 용어는 설명하는 동작 옆에서 소개합니다. 독자가 아는 표현을 활용하고 낯선 용어는 처음 쓸 때 짧게 풀며 기본적으로 큰 용어집을 추가하지 않습니다.

## 필요한 순서로 상세 공개

첫 설명 뒤에는 동작이나 서사 순서를 보여주고 이를 수행할 구조와 논거를 설명합니다. 내부 단계나 점검표 항목을 전부 나열하기보다 중요한 결정별로 상세를 묶습니다. 독자가 머릿속에 유지할 설명을 줄이는 경우에만 작은 예시·그림·비교를 사용합니다.

근거, 중요한 기각 대안, 반례, 검증 계획은 설명 아래나 기존 출처의 정확한 링크로 확인할 수 있게 둡니다. 각 상세가 어떤 선택·조건을 뒷받침하는지 밝혀야 합니다. 분량 목표를 맞추려고 필요한 근거를 지우거나 같은 주장을 여러 절에서 반복하거나 설계 사실의 사람용·에이전트용 사본을 나란히 만들지 않습니다. 관리되는 프로젝트 지침은 기존 영문·한국어 번역 경계를 따르며 작업 결과물은 요청된 언어를 따릅니다.

수정 뒤에는 첫 요약과 상세 논거의 일관성을 유지합니다. 짧은 요약에서도 중요한 불확실성과 절충을 보존하고 부분적이거나 차단된 설계를 전부 뒷받침된 것처럼 표현하지 않습니다. 반복 설명은 합치고 보고서나 설정 전체를 복사하는 대신 출처 위치를 유지합니다.

## 인계 전 이해 관점 검사

의도한 독자 입장에서 최종 결과물을 읽습니다. 첫 부분으로 목표·선택·영향·중요한 한계를 설명할 수 있는가? 낯선 용어는 처음 필요한 위치에서 이해되는가? 상세 절이 필요한 이유와 근거 위치가 보이는가? 사람이 결정할 항목을 찾기 쉬운가? 가독성 편집이 요구를 조용히 약화하거나 차단을 숨기지 않도록 요약과 상세 설계를 대조합니다.

관련된 실제 피드백이 있으면 독자가 선택·대가·불확실성을 자신의 말로 설명할 수 있는지 활용해 문서를 개선합니다. 작업마다 이해도 시험이나 승인을 요구하지 않습니다. AI 자기 검토나 가상 독자는 혼란을 찾는 데 도움이 될 수 있지만 사용자의 이해를 입증하지는 못하므로 실제 근거 수준으로 보고합니다.
