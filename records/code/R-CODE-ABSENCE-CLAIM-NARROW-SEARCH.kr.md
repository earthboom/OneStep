# 전용 종류 태그만 검색한 뒤, 설계가 한 부류의 객체에 종류 식별자가 없다고 적었다

- **ID:** R-CODE-ABSENCE-CLAIM-NARROW-SEARCH
- **종류:** error
- **상태:** resolved
- **근거 확인일:** 2026-11-24
- **범위:** 데이터 주도 Unreal Engine 게임의 설계 근거. 식별자, 필드, 연결 지점이 없다고 하는 모든 주장
- **키워드:** absence claim, negative claim, search scope, design evidence, data row schema, identity tag, gameplay tag, FGameplayTagContainer, data component, allowlist, selection rule, unverified assumption
- **요약:** 설계가 한 부류의 런타임 객체에 종류 식별자가 없다고 주장했고, 그 때문에 더 넓은 선택 규칙을 골랐다. 식별자는 데이터 행의 식별 태그로 존재했고, 공용 데이터 컴포넌트가 객체에 올려 두고 있었다. 검색은 작성자가 예상한 태그 이름만 다뤘다.
- **발생 조건:** 작성자가 예상한 이름으로 검색한 결과를 근거로, 무언가가 없다는 설계 주장을 쓸 때
- **증상:** 주장이 틀렸고, 읽는 사람이 그 선택을 데이터로 설정할 수 있는지 묻기 전까지 설계가 그 위에 더 넓고 비용이 큰 선택 규칙을 세웠다
- **원인 확신도:** confirmed
- **예방 조치:** 없다는 주장을 쓰기 전에 그 객체의 데이터 행 스키마 필드와 런타임 객체가 행 데이터를 올려 두는 곳을 모두 나열하고, 주장 옆에 검색어와 검색 범위를 적는다
- **예방 상태:** proposed
- **관계:** 예방 K-CODE-UE-TAGQUERY-EMPTY-MATCH

## 기대와 관찰

설계 문서는 무엇이 있고 무엇이 없는지를 각각 근거와 함께 적는다. 그래야 고른 구조가 지금의 코드베이스에서 나온다.

"이 위험 요소가 한 종류의 객체를 부순다"는 설계가, 그런 객체는 런타임에 종류 식별자를 갖지 않는다고 적었다. 그래서 대상을 일반 규칙(충돌 오브젝트 타입과 남은 내구도 검사)으로 골랐는데, 이 규칙은 다른 종류도 함께 고르게 되어 따로 제외 조건이 필요했다. 읽는 사람이 부술 수 있는 객체 묶음을 데이터로 설정할 수 있는지 물었다. 데이터 행 스키마를 다시 읽어 보니 모든 행에 식별 태그가 있었고, 공용 데이터 컴포넌트가 객체를 초기화할 때 그 태그를 객체의 게임플레이 태그 컨테이너에 더하고 있었다. 설계가 없다고 한 식별자는 처음부터 있었다.

## 원인과 해결

원인은 확인되었다. 주장의 근거가 된 검색은 전용 종류 태그와 상태 태그 묶음을 예상한 이름으로 찾았다. 객체를 기술하는 데이터 행의 필드를 나열하지 않았고, 행 데이터를 런타임 객체에 옮기는 코드도 찾지 않았다. 그래서 일반적인 이름(행의 식별자)으로 저장된 식별자는 검색에 보이지 않았고, "이 검색으로 찾지 못함"이 "없음"으로 적혔다.

설계를 고쳤다. 대상은 데이터 에셋에 담긴, 디자이너가 작성하는 태그 조건으로 고르고 객체의 태그 컨테이너와 비교한다. 없다는 주장은 태그를 올리는 코드의 위치와 조건에 맞는 데이터 행 수로 바꿨다. 이 수정은 코드와 데이터를 읽어 확인한 문서 변경이다. 빌드하거나 실행한 것은 없다.

## 재확인과 예방

수정 확인, 2026-11-24: 태그를 올리는 줄과 데이터 행을 다시 읽었고, 새 조건이 맞춰야 할 행을 내보낸 데이터에서 셌다.

제안한 장치이며 실증하지 않았다. 설계에서 없다는 주장은 (1) 객체를 정의하는 데이터의 스키마 필드를 나열하고, (2) 런타임 객체가 그 데이터를 받거나 올려 두는 곳을 찾고, (3) 주장 옆에 검색어와 검색 범위를 적어 읽는 사람이 그 검색으로 찾을 수 없었던 것을 알 수 있게 한 뒤에만 쓴다. 이를 채우지 못하는 주장은 확인하지 않은 가설로 표시한다. 이렇게 찾은 식별자로 대상을 고르면 보통 태그 조건을 허용 목록으로 쓰게 되는데, 그 조건을 설정하지 않은 경우에는 따로 검사가 필요하다. 연결된 지식 항목을 본다.

이 장치를 두 번째 사례에 적용해 보지 않았으므로 탐지 능력은 시험하지 않은 상태다.
