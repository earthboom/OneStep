# Windows 체크아웃 중단 후 인덱스와 참조의 상태를 따로 확인한다

Git for Windows 브랜치 전환이 중단되면 파일과 임시 인덱스는 바뀌었지만 HEAD는 이전 브랜치를 가리킬 수 있다. 복구 전에 각 상태를 확인한다.

- 식별자 · R-CODE-GIT-INDEX-LOCK-RENAME
- 종류 및 상태 · 오류, 해결됨. 당시 확인일 2026-11-18.
- 범위 · Git for Windows, Git LFS 필터를 사용하는 깨끗한 연결 작업 트리의 체크아웃 중단
- 검색어 · Git for Windows, index.lock, GIT_INDEX_FILE, reflog, symbolic-ref, HEAD, git worktree, Git LFS, 인덱스
- 발생 조건 · 체크아웃 중 인덱스 교체 재시도 프롬프트가 나왔으나 입력할 수 없을 때
- 증상 · 새 파일과 임시 인덱스가 있지만 예상한 브랜치 참조 및 HEAD 갱신이 없었다
- 원인 확신도 · 추정
- 예방 · 대형 체크아웃에는 입력 가능한 터미널을 쓰고 전환 중 동시 상태 조회를 줄인다 (제안)

## 기대와 관찰

체크아웃이 인덱스 교체 단계에 도달했지만 재시도 입력을 받지 못했다. 작업 트리·인덱스·브랜치 참조·심볼릭 HEAD의 갱신 단계가 달랐다. 일시적 파일 점유를 의심했으나 소유 프로세스는 확인되지 않았다.

## 원인과 해결

Git 인덱스는 경로와 객체를 스테이징한다. `index.lock`에는 교체 대기 중인 인덱스가 있을 수 있다. `GIT_INDEX_FILE`로 복사본을 대체 인덱스로 지정해 읽기 전용 비교를 할 수 있다. reflog는 로컬 참조 이동을 기록하므로 원격 추적 참조가 갱신된 경우 원래 의도한 커밋을 확인하는 데 도움이 된다. 보통 `HEAD`는 현재 브랜치를 가리킨다. 잠금을 오래된 것으로 판단하기 전에 소유 작업 트리·실행 중인 쓰기 작업·로컬 변경·목표 커밋을 확인한다.

## 재검증과 예방

기록된 깨끗한 작업 트리에서는 두 인덱스를 보존하고 대기 인덱스 복사본과 목표 커밋의 일치를 확인한 뒤 쓰기 작업을 종료하고 인덱스와 브랜치·HEAD 갱신을 마쳤다. 상태·브랜치·LFS 실물 파일·잠금을 확인했다. 재시도 입력이 가능하면 원래 작업을 완료하도록 한다. 수동 복구는 체크아웃 훅을 건너뛸 수 있고, 보존해야 할 변경이 있으면 커밋 트리와의 단순 비교로 충분하지 않다. 상태 조회 축소는 예방 제안이다.
