# 서로 일치하는 이벤트 값이 잘못된 전환을 가릴 수 있다

전환 검사는 짧아진 실제 경과 시간과 앞뒤가 일치하는 잘못된 이벤트 값을 통과시켰다. 경과 시간과 이벤트 전후 값을 각각 독립적인 기대값과 비교한다.

- 식별자 · R-CODE-UE-EVIDENCE-PROXY
- 종류 및 상태 · 오류, 해결됨. 당시 확인일 2026-11-12.
- 범위 · 네이티브 실시간·고정 단계 전환 검증. 과거 관찰 환경은 Win64 UE 5.8.3
- 검색어 · test oracle, monotonic clock, std::chrono::steady_clock, simulation time, negative control, easing, transition, wall age, event continuity, 검증
- 발생 조건 · 검사 대상이 기록한 시간·카운터·인접 이벤트 값만으로 전환 결과를 판정할 때
- 증상 · 경과 시간을 줄이거나 0으로 만들거나 이벤트 양쪽에 똑같이 잘못된 값을 넣어도 통과했다
- 원인 확신도 · 확인됨
- 예방 · 이벤트 기대값을 독립적으로 계산하고 계약에 해당하는 시계로 경과 시간을 검사한다 (당시 검증됨)

## 기대와 관찰

잘못된 속도로 전환하거나 이벤트 앞뒤를 같은 오답으로 바꿔도 샘플끼리는 일치했다.

## 원인과 해결

테스트 오라클은 검사 대상 출력과 독립적으로 기대값을 정한다. 이벤트 값은 일정과 곡선에서 유도한다. 실시간 계약은 단조 시계로 잰 경과 시간 및 샘플링 오차를, 고정 단계 시뮬레이션은 시뮬레이션 시간을 기준으로 삼는다. C++의 `std::chrono::steady_clock`은 단조 경과 시간을 제공한다. 이를 원래 실험에서 사용했다고 단정하지 않는다.

## 재검증과 예방

과거 음성 대조 실험에서는 관측 구간 단축, 경과 시간 제거, 이벤트 양쪽 값의 동시 변조를 각각 적용했다. 수정 전 통과한 변형을 수정 후 검출했다. 세 실패 유형을 각각 유지한다. 측정의 정합성은 프레임 성능이나 체감 품질을 검증하지 않는다.
