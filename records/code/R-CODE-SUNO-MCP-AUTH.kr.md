# Suno MCP 서버 등록 후 인증 확인

- ID: R-CODE-SUNO-MCP-AUTH
- 종류: 오류 기록
- 현재 상태: 해결
- 확인일: 2026-11-10 (Asia/Seoul)
- 범위: Windows의 Codex CLI 0.163.0에서 시작한 Suno MCP 베타 연결과 후속 전용 클라이언트 인증
- 원인: 최초 권한 범위 불일치와 계정 내부 제한의 정확한 원인은 추정 상태
- 예방: 설정·이용 자격·동의·인증·실제 생성의 별도 확인을 제안함. 이 예방 절차 자체의 효과는 미검증.

## 기대와 관찰

사용자는 Suno를 연결해 AI가 직접 곡을 만들 수 있는지 확인하도록 요청했습니다. 플러그인 검색은 비어 있었지만 공식 문서에서 MCP 주소를 확인했습니다. 검색 결과만으로 직접 연동 가능 여부를 판단할 수는 없습니다.

Codex에 공식 서버를 등록했습니다. 최초 인증 요청은 invalid_scope로 거절됐고 CLI가 자동 재시도해 로그인 화면에 도달했습니다. 첫 대기는 OAuth 콜백 시간 만료로 끝났습니다. 사용자 로그인 후 새 요청으로 권한 승인 화면에 도달했고, 전체 권한에 대한 명시적 동의를 받은 뒤 연결을 시도했습니다. Suno가 Account Linking Error와 계정에서 아직 AI 앱을 Suno에 연결할 수 없습니다라는 메시지를 표시했습니다. 화면 전환 중 도구 오류가 있었으나 새 화면 조회로 제공자의 실제 거절을 확인했습니다.

이후 사용자가 별도 플러그인 추가를 요청했습니다. 정상 웹 생성 경로로 개인 클라우드 Suno 플러그인을 추가했지만 계정 연결은 같은 이용 자격 오류로 거절됐습니다. 설치 항목의 존재와 실제 인증 성공은 별개입니다.

조기 접근 신청 진행 요청 때 기존 공식 신청서 탭은 이미 제출 완료 화면이었습니다. AI는 새 신청서를 제출하지 않았고, 당시 제출 계정·답변·시간·접수 번호·승인 여부는 확인할 수 없었습니다. 이후 공식 신청서를 읽기 전용으로 확인해 입력 이메일로 접근 권한 안내를 보내며 24~48시간 안에 연락한다는 문구를 확인했습니다. 이 예상 시간은 승인 보장이 아닙니다.

## 원인과 해결

최초 거절된 권한 항목과 서버 내부 원인은 확인되지 않았습니다. 공식 베타 조기 접근 안내를 근거로 계정 자격 미부여를 의심했습니다. 무료 플랜도 지원하므로 결제만으로 해결된다고 판단할 수 없습니다.

사용자가 승인 메일 수신을 알린 뒤, 채팅·메모리를 보내지 않는 전용 연결을 요청했습니다. 별도 공식 SDK 클라이언트에서 인증과 도구 41개 조회, DPAPI로 암호화된 자격 증명 재사용에 성공했습니다. 기존의 제한 없는 Codex MCP 항목은 비활성화했고 클라우드 플러그인은 미연결입니다. 인증 문제는 이 전용 경로에서 해결됐으며 실제 곡 생성은 미검증입니다.

승인 메일 자체를 읽지 않았고, 베타 승인과 클라이언트 경로 변경 중 어느 요소가 유일한 원인인지 분리 검증하지 않았습니다. 자격 증명·인증 코드·콜백 주소·계정 식별자는 프로젝트 기록에 저장하지 않습니다.

## 재확인과 예방

서버 등록, 계정 로그인, 사용자의 권한 동의, 제공자의 이용 자격, 인증된 도구와 실제 음원 결과를 각각 확인해야 합니다. 만료된 인증 대기에는 새 요청의 승인과 콜백이 필요합니다. 확정된 자격 거절에 같은 요청을 반복하거나 접근 제한을 우회하지 않습니다.

최종 전용 클라이언트의 인증·도구 조회·인증 재사용을 확인했습니다. [문맥 제외 기록](R-CODE-SUNO-CONTEXT-BOUNDARY.kr.md)에는 콘텐츠 경계 검증 9개와 적용 한계를 별도로 보관했습니다. 이 검증은 기존의 베타 자격 문제에 대한 재발 방지 검증과는 구분합니다. 일반 Suno 웹사이트 생성과 실제 곡 생성은 이번 점검에서 실행하지 않았습니다.
