## 기대와 관찰

당시 기대는 실행 전에 Scout가 네 항목의 요약을 대화에 표시하는 것이었다. 같은 조사 요청을 새 세션에서 세 차례 실행했지만 첫 조사 도구 호출 전에 요약이 나오지 않았다. 로컬 지침으로 두 가지 표현을 시험했으며 그중 하나는 다음 도구를 호출하기 전에 요약을 보내도록 명시했다. 이 경우 에이전트는 요약 게시를 할 일로 추가하고 실제로 글을 쓰지 않은 채 완료로 표시했다. 같은 요약은 최종 보고서 첫머리에는 일관되게 나타났다.

## 근거와 추정 원인

에이전트 메시지와 도구 호출 시각을 기준으로 대화 기록을 점검했다. 감사 방법은 knowledge/code/K-CODE-AGENT-INSTRUCTION-AUDIT.md에, 사건 기록은 records/code/R-CODE-AGENT-BRIEF-ORDER.md에 있다. 해당 실행 환경이 매 메시지에서 도구 호출을 우선하고 호출 사이 설명을 짧게 하도록 유도하며, 할 일 목록 갱신을 지침 이행으로 간주했을 가능성이 있다. 이 환경 지침을 제거한 통제 비교는 수행하지 않았다.

## 개선 제안

각 완료 조건의 결과를 붙인 요약을 최종 보고서 첫머리에서 전달할 수 있게 하고, 해석에 따라 작업이 달라질 때만 착수 전 요약을 요구한다. 순서를 강제하려면 도구 수준의 훅이 필요하다는 설명도 선택적으로 고려한다. 새 세션의 최종 보고서에 요약과 조건별 결과가 실리는지 검사한다.

## 검토와 검증

2026-11-23에 [Scout의 요청 파악 지침](../skills/vegabond-scout/SKILL.kr.md)을 변경했다. 해석에 따라 결과가 달라질 때 착수 요약을 보여준다. 명확한 여러 단계 작업은 기존 작업 요약에 검사를 유지하고, 단순 교정은 바로 결과를 전달한다.

새 실행 맥락에서 사용자에게 보낸 메시지 순서를 확인했다.

- 행사 안내문은 독자에 따라 입구가 달랐다. 작성에 앞서 확정된 날짜·시각·장소를 밝히고, 입구를 한 곳만 안내하는지 확인하겠다고 한 뒤 누구에게 배포할지 물었다. 시험 사용자가 운영진이라고 답한 뒤 북문과 확정된 행사 정보를 담은 안내문 한 편을 전달했다.
- 기존 띄어쓰기 사례는 지침과 요청을 읽은 뒤 교정 문장만 반환했다. 파일을 사용한 두 사례에는 처음에 지침을 읽겠다는 안내가 있었다. 관련 Scout 지침을 이미 제공한 별도의 대화 내 시험에서 공백 하나를 고쳐 달라고 하자 사전 메시지나 질문 없이 교정한 문장만 반환했다.

검증 범위는 위 대화 사례다. 처음 문제가 보고된 Claude Code 데스크톱 환경에서의 순서와 유지관리자의 수용 여부는 아직 확인되지 않았다.
