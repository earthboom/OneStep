# 피드백: 지식 항목 하나를 더해도 도메인 카탈로그 번역 전체를 다시 만들어야 한다

- 날짜: 2026-11-25
- 사용한 OneStep 버전: a9fb9f8 (2026-11-24) 체크아웃, 작업 트리 상태는 확인하지 않음
- 관련 스킬과 지침: skills/vegabond-knowledge/references/storage.md ("Refresh and validate catalogs" 절: 저장 순서, `catalogs_written` 에 나온 영어 경로마다 번역 다시 만들기), 카탈로그 번역에 스크립트로 행을 끼워 넣지 말라는 작업 프로젝트의 로컬 규칙
- 종류: suggestion
- 상태: received
- 작업 맥락: 게임 프로젝트의 Claude Code 세션이 도구 작업을 마친 뒤, 일반화한 작은 Git 참고 항목 하나를 `code` 지식 도메인에 저장했다

## 기대와 관찰

기대: 새 항목 하나를 저장하는 비용은 항목, 그 번역, 그리고 변경에 비례하는 카탈로그 갱신 정도다. 관찰: `catalog.py build` 는 `knowledge/code/index.md` 에서 세 줄만 바꿨다. 그런데 저장 순서상 약 4만 1,700자인 영어 카탈로그에서 `knowledge/code/index.kr.md` 전체를 옛 번역을 읽지 않고 다시 만들어야 한다. 분량이 커서 세션은 이 재번역을 서브에이전트에 맡겼다. 재번역 분량이 나머지 지식 저장 작업을 모두 합친 것보다 컸다. 또 바뀌지 않은 37개 행도 다시 쓰기 때문에, 내용이 그대로인 행의 문구가 저장할 때마다 달라질 수 있다.

## 근거와 추정 원인

이 세션의 관찰: `build` 는 `catalogs_written: ["knowledge/code/index.md"]` 를 보고했고, `git diff --stat` 은 그 파일에 `3 insertions(+)` 를 보였다. `wc -c` 는 41,685바이트였다. 저장 안내서는 "`catalogs_written` 에 나온 영어 경로마다 사람용 번역을 다시 만들라"고 하고, 바뀐 번역은 다시 열지 말고 영어에서 만들라고 한다. `*.kr.md` 를 절대 읽지 않는다는 규칙과 합치면, 지키는 방법은 전체 재번역 하나뿐이다. 이 비용은 도메인 카탈로그가 커질수록 늘어난다. `code` 는 현재 구조화된 항목이 38개다. 추정 원인: 규칙은 카탈로그 번역을 한 덩어리로 다루지만, 실제 변경 단위는 행이다. 측정하지 않은 것: 다른 하네스에서의 토큰 비용, 카탈로그를 얼마나 자주 다시 만드는지.

## 개선 제안

각각 점검이 필요한 선택지:

1. 항목마다 번역된 메타데이터(예: 각 항목 `.kr.md` 머리말이나 별도 파일의 `title_ko`, `summary_ko`)를 두고, `catalog.py` 가 번역 카탈로그를 직접 생성한다. 그러면 카탈로그를 다시 만들 때 자유 문장 재번역이 필요 없다. 점검: 항목 하나를 더하면 두 카탈로그 모두 그 행만 바뀐다.
2. 바뀐 ID의 행만 번역 카탈로그에 ID 기준으로 끼워 넣는 일을 도구가 맡고, 에이전트에게는 옛 문구를 보여 주지 않는다. 점검: 에이전트 기록에 `.kr.md` 읽기가 없고, 바뀌지 않은 행은 바이트 단위로 같다.
3. 카탈로그 번역에서는 표 행을 빼고, 번역한 설명과 영어 표 링크만 둔다. 점검: 사람이 여전히 항목을 찾을 수 있고, `check` 가 여전히 번역 쌍의 존재를 검사한다.

관련되지만 다른 건: `2026-11-20-translation-regeneration-vs-write-tool.md` 는 기존 번역을 어떻게 바꿔 넣는지를 다루고, 이 보고서는 다시 만들어야 하는 분량을 다룬다.
