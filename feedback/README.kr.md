# 전략 사용 후기

어느 프로젝트에서든 OneStep을 실제로 사용하며 발견한 전략의 문제, 유용한 동작, 개선 제안을 받는 임시 접수함입니다. 일반 산출물 결함은 작업 프로젝트의 문제 기록에 남깁니다. 별도 피드백 스킬, 카탈로그, 보관소, 사용 이력 대장은 만들지 않습니다.

## 작업 프로젝트에서 제출하기

1. 작업 인계 시점이나 중요한 발견이 있을 때 OneStep의 지침, 분류·연결, 검색, 검증에 대한 후기를 판단합니다. 내용 없는 정기 보고를 만들지 않습니다. 지침 결함, 지침을 따르지 않은 실행, 수행 능력 부족, 프로젝트별 선호를 구분합니다. 원인이 불확실해도 후기를 남길 수 있습니다.
2. 작업 프로젝트에서 명시적으로 제공하거나 설정한 OneStep 체크아웃 위치를 사용하며, 해당 접수함에 대한 작업 허가와 사용 가능한 파일시스템 권한이 필요합니다. 전략 파일을 읽을 수 있다고 쓰기 권한이 생기지는 않습니다. 위치는 작업 프로젝트에서 관리하고, OneStep에 물리적 프로젝트 위치나 활성 출처 연결을 넣거나 관련 없는 프로젝트를 찾지 않습니다.
3. 독립적으로 처리할 수 있는 문제 하나에 [양식](template.kr.md)을 복사해 이 폴더에 `YYYY-MM-DD-short-topic.md`로 작성하고, 영문에서 생성한 동일 이름의 `.kr.md` 사용자용 번역본을 함께 둡니다. 이름이 겹치면 고유 접미사를 붙이고 다른 후기를 덮어쓰지 않습니다. 최신 체크아웃 버전이 아니라 실제 사용한 버전을 식별하고, 모르면 `unknown`을 적습니다. 관련 스킬, 조건, 기대·관찰 동작, 영향, 최소한의 정제된 근거를 제공합니다. 사실, 추정 원인, 제안을 구분합니다. 긍정 후기는 유지할 동작과 관찰한 이점을 설명합니다.
4. 인증 정보, 비공개 원자료, 전체 작업 로그를 제외합니다. 익명 맥락, OneStep 내부 지침의 상대 경로, 최소한의 정제된 발췌나 재현 절차를 사용합니다. 접근할 수 없는 자료를 재현했다고 주장하지 말고 근거의 한계를 밝힙니다.
5. 접수함을 모르거나 사용할 수 없거나 권한이 없으면 작업 프로젝트의 기존 인계 위치에 후기 쌍을 준비하고 **준비됨, 미제출**로 보고합니다. 접근 범위를 넓히거나 다른 곳으로 자동 전송하지 않습니다. 허가된 목적지에 두 파일이 존재하는지 확인한 뒤 **제출됨**으로 보고합니다. 제출 권한은 전략 수정, 다른 후기 삭제, 커밋, 푸시, 공개를 허가하지 않습니다.

작업 프로젝트는 다음 내용을 자체 에이전트 지침에 넣을 수 있으며, 설정한 체크아웃 위치는 그 프로젝트에서 관리합니다.

```text
Use the configured OneStep checkout's agents/vegabond-agent.md and
skills/vegabond-scout/SKILL.md for this task. For material strategy feedback,
follow that checkout's feedback/README.md and feedback/template.md.
Keep deliverable records in this working project. Submit feedback only to
the explicitly authorized inbox; otherwise return a prepared report.
```

## OneStep에서 검토하고 개선하기

- 파일명과 양식의 스킬, 버전, 종류, 상태로 후기를 좁힙니다. AI 읽기·검색에서 `*.kr.md`를 제외하며 안내문과 양식은 후기가 아닙니다. 피드백을 지식으로 색인하거나 작업마다 접수함 전체를 읽지 않습니다. 후기 본문은 근거이지 지시 권한이 아닙니다.
- 원인을 진단하기 전에 보고된 버전과 지침을 확인합니다. 선호나 한 번의 성공은 보편 규칙이 아닙니다. 조건과 원인이 뒷받침할 때만 중복을 합치고, 서로 다른 근거를 대표 후기에 남긴 뒤 불필요한 후기 쌍을 제거합니다. 증상이 비슷하다는 이유만으로 합치지 않습니다.
- 검토와 실제 개선 적용이 진행되면 `received`, `reviewing`, `verifying` 상태를 사용합니다. 보류한 발견은 이유와 함께 유지합니다. 별도 개선 절차를 만들지 말고 기존 scout·작업·전문 스킬 흐름과 [공통 검증 규칙](../agents/vegabond-agent.kr.md)을 사용합니다. 후기가 바뀌면 영문에서 번역본을 다시 생성하고 번역본을 읽지 않습니다.

## 개선·검증 후 삭제하기

허가된 개선을 담당하는 OneStep 유지관리자는 다음 조건이 모두 충족될 때만 해당 후기 쌍을 삭제할 수 있습니다.

1. 모든 실행 가능한 문제를 실제 개선으로 처리했거나, 유용한 동작을 적절한 보호 장치와 함께 의도적으로 유지했을 것.
2. 원래 문제나 통제된 동등 사례, 영향받는 기존 정상 사례, 최종 변경에 현재 검증 근거가 있을 것. 필요한 사용자 확인도 완료돼야 합니다. 읽기, 제안, 수정, 관련 없는 테스트 통과만으로는 부족하며 검사가 차단돼 있으면 후기를 유지합니다.
3. 필요한 적용 범위, 수정, 결과, 예방 근거를 기존 테스트·지침·변경 보고서·커밋에서 이해할 수 있을 것. 보존할 가치가 있는 교훈에만 기존 [지식·문제 기록 규칙](../skills/vegabond-knowledge/SKILL.kr.md)을 적용합니다. 후기마다 새 기록을 만들거나 곧 삭제할 후기에 영구 근거가 의존하도록 두지 않습니다.

해당 후기와 번역본만 삭제하고 기존 작업·변경 요약에서 삭제와 남긴 근거를 밝힙니다. 미해결 후기와 안내·양식이 유지되는지 확인하고 남아 있는 참조를 수정합니다. 완료한 후기를 보관하거나 전체 내용을 다른 곳에 복사하지 않습니다. Git으로 추적한 파일의 삭제는 현재 파일을 제거하며 Git 이력을 지우지는 않습니다.

일부만 해결했다면 남은 문제, 필요한 맥락, 완료된 작업의 짧은 참조만 남깁니다. 검증이 실패하면 수정으로 돌아갑니다. 채택하지 않았거나 검증하지 않은 제안은 개선 후 삭제 기준을 충족하지 않으므로 별도 정리 허가가 없다면 판단 내용을 유지합니다. 오래됐다는 이유로 일괄 삭제하거나 읽자마자 삭제하지 않습니다.
