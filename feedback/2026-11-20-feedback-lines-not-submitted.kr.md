# 피드백 — 전략 문제가 세션 보고에만 남고 접수함에 도달하지 않은 사례

- 날짜: 2026-11-20
- 사용한 OneStep 버전: 0d0053a까지의 커밋(2026-11-20). 세션별 정확한 커밋은 알 수 없음
- 관련 지침: agents/vegabond-agent.md의 실패·피드백 대응, feedback/README.md의 작업 프로젝트 제출 절차
- 유형: 문제
- 상태: verifying (검증 중)
- 작업 맥락: 게임 프로젝트의 로컬 지침은 각 결과 보고에 OneStep 전략 피드백 한 줄을 요구하고, 중요한 피드백을 보낼 곳으로 이 접수함을 지정했음

## 기대와 관찰

중요한 전략 문제는 영문 보고서와 한국어 번역본으로 접수함에 도달해야 한다. 여러 세션의 결과 보고에 착수 전 요약 순서 문제 같은 구체적인 피드백이 있었지만, 이번 보고가 제출되기 전까지 접수함에는 후기가 없었다. 소유자가 전략 문제를 알아차리려면 대화의 결과 보고를 직접 읽어야 했다.

## 근거와 추정 원인

2026-11-20에 확인한 접수함에는 안내문과 양식만 있었다. 대화 기록 감사에서는 세션 보고에 피드백 문구가 있었음을 확인했다. 에이전트가 결과 보고에 적는 것으로 피드백을 전달했다고 판단했거나, 접수함의 명시적 쓰기 허가를 요구하는 지침으로 인해 파일 작성을 주저했을 가능성이 있다. 당시 로컬 지침만으로 쓰기를 허가한 것으로 간주할 수 있었는지는 검증하지 않았다. 같은 날 중요한 피드백의 목적지로 이 접수함을 명시한 로컬 지침으로 다시 시험했지만, 결과 보고에는 접수함에 제출하지 않았다는 문장이 남았다.

## 개선 제안

작업 프로젝트에서 접수함을 설정했을 때 중요한 전략 피드백은 두 파일로 제출한다는 의미임을 밝힌다. 결과 보고에는 `submitted` 또는 `prepared, not submitted`와 파일 경로를 적는다. 중요한 피드백이 발생한 세션 뒤에 접수함에 두 파일이 남는지 확인한다.

## 검토와 검증

2026-11-23에 Scout의 최종 인계 단계에서 중요한 전략 문제를 [도착 확인 절차](README.kr.md)로 연결했다. 접수를 확인하면 해당 접수함의 두 파일 링크를 보고한다. 작업 프로젝트에만 준비했다면 그곳에서 확인한 두 파일의 링크와 제출할 수 없었던 이유를 제시한다.

[명령행 회귀 테스트](../tools/test_check_feedback.py)는 별도의 작업 프로젝트를 현재 디렉터리로 사용했다. 그곳에 두 파일이 있어도 접수함 확인은 실패했다. 접수함에 영어 파일만 있거나 한국어 파일이 비어 있어도 실패했다. 비어 있지 않은 번역본을 보완하자 같은 검사에서 두 접수 경로가 반환되고 통과했다. 파일 자리에 디렉터리가 있는 경우와 접수함 밖의 경로를 입력한 경우도 거부했다. 실제 체크아웃에서는 이전에 제출된 이 보고서와 번역본이 존재하는지 확인했다.

이 테스트는 목적지와 파일 상태를 검증한다. 원래 게임 프로젝트의 인계에서 새 절차를 따르는지와 유지관리자의 수용 여부는 아직 확인하지 않았다.
