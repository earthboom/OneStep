# 실행한 검증

2026-11-13, Windows x64, .NET SDK 10.0.404 / .NET 8, UAssetAPI 1.1.0 환경에서 검증했습니다. 범위는 통제된 사례의 직렬화 구조·선택한 속성·참조입니다. vagabond의 별도 검수는 남아 있습니다. 이 번역본은 사람을 위한 문서이며 AI는 영문 원본을 읽습니다.

## 실제 엔진과 비교

격리한 UE 5.8.0-0+UE5 테스트 프로젝트에서 uncooked 에셋 5개를 저장했습니다. **별도 에디터 프로세스**가 저장된 파일을 다시 열어 저장 없이 네이티브 리플렉션·속성 텍스트로 기준값을 만들었습니다. 파서는 기준값 파일을 입력으로 사용하지 않았습니다. 파서 JSON과 기준값의 비교는 **31개 통과, 실패 0개**입니다.

모든 패키지의 SHA-256이 네이티브 읽기와 CLI 검사 전후에 일치했습니다. 엔진 원본 튜토리얼 애니메이션·스켈레톤의 해시도 처음 수집한 값과 일치합니다. 생성한 바이너리와 보고서는 로컬에서 제외하며 엔진 콘텐츠를 배포하지 않습니다. 재현 방법은 [엔진 테스트 프로젝트](tests/engine/README.kr.md), [비교 검증기](tests/verify_engine_assets.py)에 있습니다.

## 재현한 문제와 수정

- PrimaryAssetLabel이 generic으로 분류되던 문제를 스크립트 패키지까지 포함한 클래스 식별자로 수정했습니다.
- 애니메이션의 `RawStructPropertyData` 68개를 해석 완료로 표시하던 문제를 고쳤습니다. 속성은 unsupported, export는 partial이며 트랙 바이트는 해석하지 않습니다.
- FBX 임포트 메타데이터의 속성 앞 접두부 때문에 읽지 못하던 문제를 선언된 스크립트 오프셋으로 해결했습니다. 태그 영역의 정확한 소비량을 검사하며 접두부·후행 데이터는 불투명하게 유지합니다. 비기본 임포트 이동값은 네이티브 읽기와 일치합니다.
- 실제 TextBlock 2개가 raw로 남았습니다. 라이브러리 진단에서 Base 이력 FText의 원문 뒤에 추가된 편집용 개발 메모가 누락되어 다음 속성 위치가 어긋남을 확인했습니다. 작은 TextProperty 하위 클래스가 직렬화된 FortniteMain 버전 260 이상이고 편집 데이터가 있을 때만 해당 FString을 읽습니다. 확인한 엔진의 `FTextHistory_Base::Serialize`와 같은 조건입니다. 원본 파일을 바꾸지 않고 텍스트와 뒤따르는 불투명도를 읽습니다. 중첩 텍스트 이력은 기존 라이브러리 지원에 의존하므로 모든 FText 형식 지원을 뜻하지 않습니다.
- 검토에서 검증 보고서 출력 위치로 원본 `Content` 자체를 허용함을 발견했습니다. 동일 경로도 출력 생성 전에 거부하며 회귀 검사로 확인합니다.

관련 수정 전 실제 비교 실패를 확인했고 수정 후 통과했습니다. 원시 트랙은 의도적으로 partial입니다. 별도의 UE4.27 파생 합성 사례로 기존 FText와 뒤따르는 정수도 검증하며 이를 엔진 저장 형식의 독립 검증이라고 주장하지 않습니다.

## CLI 회귀 검증

CLI와 테스트 전용 writer의 Release 빌드는 경고·오류 0개입니다. 실제 CLI 프로세스를 실행하는 **26개 테스트가 모두 통과**했고 생략은 없습니다. 실제 UE4.27·UE5.7 블루프린트 속성·참조, 합성 분류·행·타입별 참조, 정확한 선택, 손상·cooked·unversioned 거부, export 경계, 잘못된 이름 인덱스, 인접 파일 격리, 입력 보존을 확인합니다. 신규 검사는 검증기 출력 보호와 기존 텍스트 정렬을 다룹니다. 의존성 잠금은 유지했고 초기 locked restore와 빈 디렉터리의 고정 fixture 다운로드는 통과했습니다.

초기 검토에서 찾은 export 크기 우회와 소프트 경로 하위 타입 누락도 수정·검증했습니다. [이름 인덱스 문제 기록](../../records/code/R-CODE-UE-PARSER-NAME-INDEX.kr.md)은 재발 방지 근거를 보존합니다. [네이티브 구조체 지침](../../knowledge/code/K-CODE-UE-NATIVE-STRUCT-DECODING.kr.md)은 불투명 래퍼 처리 사례를 담으며 과거 레이아웃 표를 이번에 재검증했다고 주장하지 않습니다.

## 근거와 한계

로컬 제외 경로 `.cache/onestep/asset-reader/native/`에 생성 결과, 별도 프로세스의 `oracle.json`, 수정 전·후 비교 결과, JSON, 빌드·테스트 로그, 원본 해시 검사, 최종 코드 해시를 남겼습니다. 엔진 보조 모듈은 UBT로 컴파일·링크했고 공식 WriteMetadata 단계로 프로젝트 로딩 메타데이터를 만들었습니다. 일반적인 프로젝트 전체 빌드가 완료됐다고 주장하지 않습니다. 생성·별도 읽기는 오류 0개로 종료했고 선택적 ACL/PDB 경고는 로그에 남습니다. Win64 도구 체인으로 보조 모듈을 빌드한 뒤 에디터 실행 프로세스에서만 중복 SDK 탐색을 생략했습니다. 이들은 작업별 근거이며 설치된 프로젝트 연결 설정이 아닙니다.

CLI는 에디터 없이 오프라인으로 동작합니다. 이번 엔진 실행은 직렬화 기준값 비교이며 애니메이션 재생·몽타주 게임 동작·위젯 렌더링·PIE 검증이 아닙니다. 전체 그래프 의미, 압축·원시 트랙, 다른 네이티브 데이터, 모든 엔진 포크와 대규모 실제 프로젝트 호환성은 미검증입니다. 임포트·애니메이션 네이티브 데이터가 partial인 것은 정상일 수 있습니다. 다른 export가 partial이어도 해석된 위젯 속성 단독 조회는 complete일 수 있습니다. 새 성능 벤치마크를 주장하지 않습니다. 커밋·푸시는 하지 않았고 관련 없는 기존 변경은 보존했습니다.
